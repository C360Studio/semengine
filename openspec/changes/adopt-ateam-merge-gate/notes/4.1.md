# Task 4.1 notes

Sentences of the old `.agents/protocol.md` "Cross-agent review" item that were dropped or changed, and why:

- "What "documents only" means is this repository's reading of that ruling ... every file the pull request changes
  is a Markdown file or is under `openspec/`": replaced by the gate's classifier (`.md`, or `.yml`/`.yaml`/`.json`
  under `openspec/`), design D3. A script under `openspec/` now makes a code pull request.
- "The check below provides for this only when GitHub reports the author as a bot": kept, now about the gate.
- "A code pull request by a user with no `implemented-by:` line naming an agent fails the check once it is not a
  draft": folded into the check bullet (both lines required).
- "The rule applies to every pull request not yet merged, one already open included": dropped; design D5 says no
  transition period and the only open pull requests at merge time are bot pull requests.
- "The reviewing session answers with a PR comment headed `Review record`: its reviewer's report as written": replaced
  by ateam's record grammar (`reviewed-by:`, `Reviewed at <sha>`, `Verdict:`).
- "The implementer writes one `reviewed-by:` line in the PR body ... beside the model or persona taken from the
  record": changed to ateam's flow (review-pr § 5): the reviewer adds the line after an approving record, and the
  description edit reruns `Merge check`.
- The check bullet's line grammar ("A line starts in the first column; an agent name is `claude`, `codex`, or
  `gemini` in any letter case, not part of a longer word such as `codex2` ...; nothing else in either line is read"):
  dropped; these are the gate's mechanics, whose oracle is now the pinned release's tests (design D3).
- "On a draft the findings are printed and fail nothing ... Marking a draft ready starts the CI run that applies the
  check; editing the description or adding a comment starts no run, so after the edit run the failed `merge-check`
  job again": replaced; the workflow skips drafts and reruns on `edited`.
- Review-only list: "that a review record exists, the commit it read, and the re-review after a later content commit
  (once written, the line satisfies the check through every later push); the record's verdict" dropped, since the gate
  now checks the record, its commit and its verdict. "a pull request that changes the script, the workflow or their
  tests, which runs its own copies" narrowed to `merge-check.yml`: the script and the review policy now come from the
  base commit. "the moment after marking ready before the new run registers, when a draft's green `Required` may
  still be the newest result" dropped: a draft carries no `Merge check`, which the ruleset requires.
