# Task 2.1 notes

## Where `npx --no-install openspec` finds a CLI

Design D1 says the validate line fails closed because `npx --no-install` exits non-zero when the pinned CLI is
missing. Measured on 2026-10-29 (npm 10.9.3): with this tree's `node_modules` moved aside, `npx --no-install`
(which npm reads as `--yes=false`) still runs an `openspec` it finds in any of these places:

- `node_modules/.bin` in any parent directory: a worktree under `.worktrees/` finds the main checkout's;
- npm's global prefix, which comes from where `node` is installed (here nvm's, openspec 1.7.0), even with that
  directory off `PATH`;
- a package already in the npx cache (`~/.npm/_npx`; three held `@fission-ai/openspec` here).

Only with none of them, a copy of the tree outside the checkout, `NPM_CONFIG_PREFIX` and `NPM_CONFIG_CACHE` set to
empty directories, did `task spec:check` stop on its first line: `npm error could not determine executable to run`,
`task: Failed to run task "spec:check": exit status 1`; `ateam state spec-check` did not run. In the same copy with
the prefix and cache left alone, the first line passed using another openspec, and `ateam state spec-check` printed
`openspec: strict validation skipped (...)`.

So the line fails closed when no openspec is reachable, as on a fresh CI runner, but on a developer machine it can run
an openspec of another version than `package.json` pins. ateam's own check searches `node_modules/.bin` and `PATH`
only, so the Task line is never weaker than it. The wiring is as ruled; the design's wording "the pinned CLI" is
stronger than what the command checks.
