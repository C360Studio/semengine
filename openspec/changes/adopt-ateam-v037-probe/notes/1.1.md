# Task 1.1: the probe's tool tests, shown able to fail

`mergeCheckWorkflowViolations` (`internal/harness/toolcheck/mergegate_test.go`) now holds both jobs of
`.github/workflows/merge-check.yml`. What the two jobs share (the `if:` condition, the 5-minute limit, exactly three
read permissions, a checkout of the base commit without credentials, an ateam install line) is one helper,
`gateJobViolations`. The probe job `awaiting` must be named `Merge check probe`, run under
`!github.event.pull_request.draft`, set `outputs.awaiting` from `steps.probe.outputs.awaiting`, and have a step
`id: probe` that runs `ateam review gate --awaiting "$PR_NUMBER"` and writes its answer with
`grep -xE 'awaiting=(true|false)' >> "$GITHUB_OUTPUT"`. The `merge-check` job must need `awaiting` and run under exactly
`always() && !github.event.pull_request.draft && needs.awaiting.outputs.awaiting != 'true'`: `always()` runs it when the
probe failed, and the `!= 'true'` test runs it in full when the probe gave no answer.

The per-job install check is new: with two install lines in `merge-check.yml`, `ateamPins` still finds a version when
one job's line is removed, so "merge-check.yml installs no ateam" would have passed without it.

The checker compares the `merge-check` job's `name:` expression with nothing. ateam v0.3.6's notes say GitHub lists a
skipped job under its raw `name:` expression, so the rename does not decide whether `Merge check` is absent; task 2.2
observes that on this pull request.

## Plants in the fixture (`TestCIWorkflowPinnedSensitivity`)

Thirteen new `merge-check.yml/` cases, each a single replacement in the clean fixture that must yield a named
violation: awaiting skip dropped, skipped without an answer (`== 'false'`), skipped when the probe fails (`always()`
dropped), merge-check does not need the probe, probe removed, probe named Merge check, probe runs on a draft, probe
checks out the head, probe installs no ateam, probe output unwired, probe step renamed, probe runs the full gate, probe
answer not written. The fixture lists `merge-check` before `awaiting`, so the older plants that replace the first match
still hit the `merge-check` job.
