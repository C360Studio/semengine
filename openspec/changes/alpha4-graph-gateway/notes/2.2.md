# Task 2.2 notes: schema and executor

## Choices the design leaves open

- **Package.** `gateway/graph-gateway`, Go package `graphgateway` (as `processor/graph-query` is `graphquery`). The
  schema is D2's SDL verbatim in `schema.graphql`, embedded and loaded once with `gqlparser.MustLoadSchema`.
- **The seam to task 2.3.** Unexported: `execute(ctx, resolvers map[string]resolver, request) (response, refused
  bool)`, with `type resolver func(ctx, args map[string]any) (any, error)`. A resolver answers one root field with a
  value keyed by schema names (`map[string]any`, `[]any`, and `string`, `int`, `float64`, `bool`, `uint64` or any
  JSON-encodable value for `JSON`). `refused` is D6's 400 row; 2.3's handler maps it. A resolver error becomes
  `data.<field>: null` and an error at `[<key>]` that wraps the error (`gqlerror.Error.Err`), so 2.3 can read the
  class and code into `extensions` and choose 500/504 there. No exported surface.
- **Fitting the schema.** Every value is checked against its type while it is projected: null for a non-null type,
  a list where none is declared or the reverse, an object where a scalar is declared, a scalar of another Go type, an
  `Int` outside 32 bits, a non-finite `Float`, a `JSON` value that does not encode. Any misfit nulls the root field
  (not the nearest nullable parent), so no partial value is returned (spec, "A reply that does not fit").
- **Refusals beyond D6's list.** A document with several operations and no `operationName`, or an unknown one, is
  refused 400. `subscription` is refused like `mutation` (the schema declares neither). Introspection is refused when
  `__schema` or `__type` is reached at the root, through fragments too.
- **One root field** is counted by response key after fragments and `@skip`/`@include`; one field written twice
  under one key merges (GraphQL field merging) and is one root field.
- **`@skip` and `@include`** are honoured, since validation accepts them and ignoring them would answer fields the
  client excluded.
- **Key order.** Objects are Go maps, so `encoding/json` writes keys sorted, not in selection order (GraphQL says
  "should" keep selection order). Clients read by key; the size target wins.
- **Size.** `execute.go` is 222 non-comment lines against the design's ~150 target: the scalar checks and the
  operation refusals above account for the difference.
- Not here (2.3): `predicates` refusing a null item with 400 needs the path resolver; the 405/500/503/504 rows.
