# Task 2.1 notes: config, declarer, factory and `Register`

Choices the design leaves open, and what task 2.1 did not do.

## The factory builds nothing yet

The registry lists the factory and the port declarer, but `create` refuses every configuration. A configuration that
passes every check gets `errNotBuilt`, an error that is not of the invalid-config class
(`output/websocket/websocket.go`, marked `// shortcut:`). The component manager builds a `Discoverable` that is not a
`LifecycleComponent` and never starts it (`service/doc.go:230-231`), so a component without `Start` would claim its
network port and serve nothing. Refusing keeps that from happening. Task 3.1 replaces the refusal with the component,
and deletes `TestFactoryBuildsNothingYet`.

Because of this, the refusal tests at 2.1 fail a mutant on "want an invalid-config error" rather than on "factory
accepted": the factory refuses either way, and the test tells the two refusals apart by class and by the key or port
the message names. After 3.1 the same mutants fail on "factory accepted".

## `gorilla/websocket` is not in `go.mod` yet

Nothing imports `github.com/gorilla/websocket` until the server exists, and `task tidy:check` (`go mod tidy -diff`)
removes a requirement nothing imports. Measured on c9b8571a: `go get github.com/gorilla/websocket@v1.5.3` added the
line as `// indirect`, and `go mod tidy -diff` printed its removal from `go.mod` and `go.sum`. The requirement lands
with its first importer, in task 3.1. The other choice was a blank import to keep it, which is an import nothing uses.

## Refusals the design did not list

- **A subject input with a `queue`.** D1 refuses "anything else" as the input. `natsclient.Client.Subscribe` takes
  no queue group (`natsclient/client.go:1057`), so a queue would be silently ignored; and a queue group would split
  messages between instances, while each instance sends every message to its clients. Refused, naming the port and
  the queue.
- **An output that is not `http`.** Kept from the pin (`websocket.go:429` at `8b99efe9`).
- **Port 0 and above 65535.** The component port codec refuses these while it decodes the configuration
  (`field "port" must be between 1 and 65535`), naming the port, before this package's own 1024-65535 check runs.
  `TestConfigRefusals` covers both through raw JSON, since a `PortDefinition` with such a port cannot be marshalled.
- **The pin's `endpoint` key** (`rejectRetiredEndpoint`, pin `:1917`) is not carried as a hint: strict decoding
  refuses it as an unknown key, naming it.

## Defaults and decoding

- Strict decoding goes through `component.SafeUnmarshal` (D5). `path` and `ping_interval` start at their defaults
  before decoding, so an explicit `""` is refused rather than defaulted (as the pin, which decoded over its defaults).
  `ports` starts empty: a ports block that is present is used as written, never merged with the default ports
  (ruling K, #91 comment 6062681355). The pin's decode over `DefaultConfig` kept the default output when a ports block
  gave only inputs.
- Default input name `entity_watch` (as graph-clustering); default output name `websocket_server` (the pin's).
- `ping_interval` is a Go duration string, above zero, with no upper bound.

## Declarer and constructor parity

Both call `resolveConfig`. At 2.1 `TestRegisterDeclaresWhatTheFactoryResolves` compares the registered declarer's
ports with what the factory's derivation (`newSettings`) resolves; from 3.1 it compares them with the built
component's `InputPorts` and `OutputPorts`, as graph-clustering's `TestRegisterAddsGraphClustering`.

## Shown to fail

`task mutate:check -runs 1`, one mutant in a copy outside the tree per guard, 21 detections, no survivor in the final
set: each removed key's table entry, the jetstream hint, the kv-watch bucket, keys and history conditions, the queue
refusal, the input and output counts, the 1024 floor, the http protocol, `ping_interval` zero and negative, the path's
leading `/` and whitespace checks, the nil NATS client, `path` and `ping_interval` read, the default port and
interval, declarer parity, and the not-built refusal's class.

Three earlier mutants survived and were fixed in the tests, not recorded as detections: `path "ws"` is refused by
ServeMux as well, so the case now uses `example.com/ws`, which ServeMux accepts; `path "/a b"` is refused by ServeMux as
well, so the case now asserts the package's own "whitespace" message; and a `< 0` mutant of the interval check was
not a wrong change for `-1s`.

Not mutated: port 0 and above 65535, unknown keys and data after the object (the port codec's and `SafeUnmarshal`'s
refusals, not this package's), the "another kind" and "not network" fallbacks, and the empty and control-character
path and empty and unparsable `ping_interval` cases, whose guards the mutated cases already cover.

Generated checks: not used. The configuration has no law or order-dependent history; each key is checked on its own,
and the cases are each refused value the design names.

Fuzzing: no target. The only exported symbol is `Register`; the configuration bytes are decoded by
`component.SafeUnmarshal` and the port codec, which this package does not add to.
