# Task 3.3: T8, Close ends a reconnect dial

Choices the design ("Tests that replace the probes", T8) and the design review (r2-2, MEDIUM on `netDial`) do not spell
out.

- **T8 sits in `client_close_held_test.go`** with T1: both show `Close` ending a wait that holds nats.go's connection
  lock. It talks to the embedded server directly; it needs no proxy.
- **The stand-in for `netDial`.** The first dial goes through `(*net.Dialer).Dial` with the dialer nats.go was given,
  so `Connect` reaches the server. Every later dial signals `entered` (a channel of one, sent without blocking), then
  waits for the dialer's `Cancel` or for `testEnded`. The test closes `testEnded` in a cleanup registered after
  `closeInCleanup`, so it runs first. A run that fails therefore releases nats.go's reconnect goroutine and its lock
  before the client's `Close` in cleanup, and nothing is left holding the lock for the rest of the test binary.
- **The server drops the client** with `DisconnectClientByID`, as T5 does. T8 requires that call to succeed: the
  client is connected and has finished its handshake.
- **The test's 3 s wait** is under nats.go's 5 s default dial timeout, which held `Close` before the cut (P23: 4.69 s).
  With `Cancel` removed, the stand-in waits until the test ends, so the failure does not depend on that timeout.
- **Citations.** `Close`'s doc comment and `cleanup`'s comment now cite T1, T8; `socketDialer.Dial`'s comment cites
  T4, T8. As design D1 says, T8 dials through a stand-in, so it shows that the cut closes `Cancel`, not that Go's net
  package honours it; the comment keeps P23, P25 for that.
