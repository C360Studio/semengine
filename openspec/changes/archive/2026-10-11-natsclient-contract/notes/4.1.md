# Task 4.1: T9, the write timeout and ping interval options

Choices the design (D4; "Tests that replace the probes", T9) does not spell out.

- **T9 lives in its own file**, `natsclient/client_write_timeout_test.go`, and reuses T1's set-up from
  `client_close_held_test.go`: `newHeldClient` now takes client options, after `WithHealthInterval(0)`, and T1, T2 and
  T8 call it as before.
- **The proxy can read again.** `heldProxy` gains `resume`. Once a client sends `heldSubject`, `forward` now waits for
  `resume` or `close` instead of returning, then reads on; a later `heldSubject` does not stop it again. `close` closes
  every socket before it releases a held `forward`, so T1 and T2, which never resume, end as before: the released
  read fails at once.
- **What the first subtest asserts, in order.**
  - The held publish returns within the test's 10 s wait (`lifecycleBound`), with an error matching
    `os.ErrDeadlineExceeded`: the socket's write deadline, which is how nats.go's write timeout ends a write
    (`timeoutWriter`, `nats.go:6919-6923` at v1.54.0). Any other error, such as the proxy's cleanup closing the socket,
    fails it.
  - Then the test calls `resume`, and `probe.Await` retries an echo request every 20 ms, each bounded by 300 ms, until
    one returns the data it sent, within 10 s.
  - The connection's reconnect count is then above zero. The write the timeout ended partway leaves the server waiting
    for the rest of a 16 MiB payload, so nothing after it reaches the server as a request on the old socket: only a
    reconnect carries the echo (P24: no echo for 5 s without the ping option).
- **The echo goes over the native connection** (`GetConnection().RequestWithContext`), as in P24. `Client.Request`
  counts each timed-out attempt as a circuit-breaker failure, which would tie the test to the breaker's threshold.
- **The responder** connects to the server directly, not through the proxy, and answers with the request's own data.
- **The refusal subtest** calls `NewClient` with each option at 0 and at -1 s. It requires a nil client, an error
  `errs.IsInvalid` reports, and the option's own words in the message ("write timeout", "ping interval"). It does not
  pin the whole message, which `pkg/errs` formats and #93 rewrites.
- **No sleeps, ephemeral ports:** the server binds port -1 and the proxy `127.0.0.1:0`; every wait is a channel or
  `probe.Await` under a 10 s context.
