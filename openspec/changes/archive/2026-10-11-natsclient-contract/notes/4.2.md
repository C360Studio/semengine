# Task 4.2: WithWriteTimeout and WithPingInterval

Choices design D4 and `fix-prototype.diff` do not spell out.

- **The refusal is wrapped once.** Each option returns a plain `fmt.Errorf` ("write timeout 0s is not positive"), and
  `NewClient` classifies it as invalid ("apply option"), as it does for every option. The prototype wrapped it with
  `errs.WrapInvalid` as well, so the message carried two prefixes (design review 2-2, NIT, accepted by the owner).
  `options.go` does not import `pkg/errs`.
- **The default stays nats.go's.** `NewClient` sets `writeTimeout` to `nats.DefaultFlusherTimeout`, one minute, the
  value nats.go used before natsclient passed the option. The ping default stays 30 s.
- **What each doc comment rests on** (design review 2-2, L1). The write timeout's own effect and the refusal cite T9.
  "Connected but unable to carry anything" and "the stale-connection check closes it and reconnects" cite T9 and P24.
  The 1.2 s at 300 ms cites P20 and P24. "Other calls wait behind a held write" cites T2 and P17. The timing of the
  stale check at the 30 s default, and at any value but 300 ms, is marked not promised. "While a write is held this
  check does not fire" cites P20 (inventory N-P4: 2 of 2 at 5 s). Commit 56d17a8 left it out, wrongly saying no probe
  shows it; a later commit of this slice adds it to `WithPingInterval`'s comment, as the reason it names
  `WithWriteTimeout`.
- **Each comment names the other and says why:** P24 showed a 300 ms write timeout alone leaves the connection
  connected and carrying nothing for 5 s after the server reads again.
