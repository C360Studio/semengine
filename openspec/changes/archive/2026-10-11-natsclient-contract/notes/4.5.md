## The branch's test (stop-3 review, MEDIUM)

An earlier version of this note said no test could reach `CreateKeyValueBucket`'s `ErrBucketExists` branch, the
`errors.Is` this task writes, without another creator winning a race between the client's get and its create. That
was wrong, as the stop-3 review found (`/tmp/pr177/review/impl-stop3.md`, local only). A plain stream named
`KV_<bucket>` sends every call down the branch: it is not a KV bucket (`MaxMsgsPerSubject < 1`), so the first get
returns `ErrBadBucket` (`jetstream/kv.go:523-524` at v1.54.0), the create collides on the stream name and carries
`ErrBucketExists` (`:545`), and the branch's second get returns `ErrBadBucket` again, wrapped as `access existing
bucket <name>`.

`TestCreateKeyValueBucketGetsAgainWhenItsStreamExists`, beside T6 in `natsclient/kv_bucket_exists_test.go`, does
this through `NewClient` and asserts both: `ErrBadBucket` in the chain, and the wrap's text. It follows the
reviewer's scratch test (`/tmp/rev-stop3/scratch-tests/`, local only), with the bucket named `plain`.

```text
go test -race -count=3 -v -run 'TestCreateKeyValueBucketGetsAgainWhenItsStreamExists' ./natsclient/
--- PASS: TestCreateKeyValueBucketGetsAgainWhenItsStreamExists (0.04s)    (and 0.02s, 0.02s)
ok  github.com/c360studio/semengine/natsclient 1.501s
```

Each run logs the branch's "KV bucket already exists (race condition)" line.

Mutation: the branch disabled, `if stderrors.Is(...)` changed to `if false && stderrors.Is(...)` at `client.go:1967`,
