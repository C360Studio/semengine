# Task 2.1 notes

Choices the design does not spell out, and the failing-first record.

## Choices

- **One predicate.** Start's inline condition (`fixture.go`, the attempt loop) became `retryable(err)` in
  `fixture.go`; Start and Restart both call it. Restart's errors never carry `Cleanup`, so the clause only matters
  for Start.
- **Attempt numbers.** Restart's errors say attempt 1 for the first stop, start and read, and attempt 2 for the
  second; a connect or JetStream failure after a second read also says attempt 2.
- **Both failures are returned.** When the second try fails too, Restart returns `errors.Join(first, second)`, as
  Start does with its two attempts. The first failure's inspect detail is not lost, and `errors.As` still finds a
  mapped-port `*Error`. If the second try fails in another phase (stop or start), that error is joined the same way.
  A connect or JetStream failure after a good second read is returned alone, without the first failure (Codex review
  on PR #200, M1).
- **The inspect runs under the caller's context.** The design says "under a bounded context". The caller's context is
  that bound (Restart's doc: "The caller must bound ctx"; Start runs every operation under ctx). A detached context
  (the `rollback` helper) was not used: the contract allows detaching only for cleanup or finalization, and the
  retry the detail serves only happens with a live parent. When the parent has ended, the detail says the inspect
  failed with the context's error.
- **How the detail is attached.** `Fixture.mappedPort` (`fixture.go`) wraps the read's error with `%w` and adds
  `(inspect: <shown>)` or `(inspect failed: <error>)`; the inspect's error is formatted with `%v`, so `errors.Is` on
  the result never matches the inspect's own error. Each inspect is counted as `inspect`.
- **`deps.inspect` returns a string.** The default (`deps.go`) calls `Container.Inspect` and formats
  `state <State.Status>, ports <NetworkSettings.Ports>`, writing `unknown` for a missing part. Docker's types stay
  out of the fixture's signatures and `go.mod` is unchanged (moby's API module stays indirect).
- **Test setup.** `TestRestartLaterPhaseFailuresAreNamed` now builds its fixture with the new `restartOnFakes`, the
  same fakes it wrote inline plus a fake inspect: its container is an empty struct, which cannot be inspected, and
  its mapped-port case now reaches the inspect.
- **Generated checks are not used.** The input space is two facts, whether each read fails and whether the parent is
  live; the four named cases (second read succeeds, second read fails, cancelled, and the inspect showing or failing)
  cover every combination the requirement names.

## Not covered

- The default `deps.inspect` formatting has no test that reads its text. It runs against a real container in
  `TestS1_1PartialStartupCleanup/mapped-port` (the injected failure comes after a real read), which does not assert
  the detail.
- A Restart that recovers on its second try leaves no record in the evidence file (Restart writes no attempt
  records, unlike Start); the only trace is the fixture's in-process call counts. The ruling and design add none.
  Reviewer's call whether the contract's "a skip, drop or degrade is declared" rule wants one here.
