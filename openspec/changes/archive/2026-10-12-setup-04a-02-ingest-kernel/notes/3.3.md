# Task 3.3 notes: the sweep of the `graph` root's test-only exports

The part of task 3.3 its hold kept back: every export of the `graph` root (the package itself, not its sub-packages)
read only by tests is unexported or moved into a `_test.go` file, and every export nothing reads is removed. The
readers ported by tasks 3.4–3.12k are in the tree, so the sweep runs on the tree as it now is. A reader is the
package's own non-test code, an admitted package (the 65 of `docs/tier1-cross-check.md`) or a consumer (semsource,
semconnect, semteams, semboids); a test is not a reader (`inventory.md` §2).

## Result

Of 144 identifiers (exported package-level names, and exported methods of exported types, interface methods
included), 138 are kept and 6 are removed:

- **Removed (no reader anywhere):** `QueryDirection`, its constants `QueryDirectionOutgoing`, `QueryDirectionIncoming`
  and `QueryDirectionBidirectional`, and its `String` method, with the file that held them, `graph/query_types.go`.
- **Removed (only its own test read it):** the function `GetPropertyValue`, with its test `TestGetPropertyValue`. A
  test is not a reader, and #132 item 7 drops the function. The method `EntityState.GetPropertyValue` stays.
- **Kept:** 93 with a non-test reader in this tree outside the root; 33 whose only readers here are tests or none,
  with a non-test reader in an admitted package at the pin; 8 read by the root's own non-test code or named in the
  signature of a kept export; 4 methods of standard-library interfaces (`Error`, `Unwrap`), which are not candidates.

No identifier the sweep would remove or unexport is named by D9, D15, D16, D18 or D20 or by a requirement under
`specs/` or `openspec/specs/`, so nothing stopped the task. Ruling 2 (`design.md:1523`) says "`GetTriple` and
`GetPropertyValue`"; D15, which applies it (`design.md:880`), and `graph-entity-writes` (`spec.md:63`) name the methods
`EntityState.GetTriple` and `EntityState.GetPropertyValue`, both kept.

## Choices the brief left open

1. **`GetPropertyValue` removed.** Its readers were two tests: its own `TestGetPropertyValue` and
   `TestIntegration_MergeEntity_SamePredicateReplaces` (`processor/graph-ingest/merge_entity_integration_test.go:148`).
   graph-ingest's test now reads the value through the method `stored.GetPropertyValue("flock.position.x")`; the
   statement it reads is a property (`"3"`, not an entity ID), where the method and the function pick the same
   statement. That leaves the function's own test as its only reader, and a test is not a reader (`inventory.md` §2),
   so it has none; #132 item 7 says "3.3 drops the function and keeps the method". The function and
   `TestGetPropertyValue` are removed.
2. **`Provider` kept.** #132 item 7 proposed moving it with `graph/clustering` and `graph/structural` (change 7). Both
   are admitted packages and read it at the pin (`graph/clustering/types.go:82`, `graph/structural/kcore.go:15`, type
   aliases; its three methods are called in both), so the method gives keep.
3. **An export whose only non-test reader is the root itself is kept.** Eight have no reader by name outside the root:
   four are the type of a kept export's constants, field or return value (`EntityStateContractField`,
   `InvalidEntityPredicate`, `QueryVerb`, `ReplaceResult`), and four are called by kept root code
   (`EntityState.GetTriple`, `GraphStateReasonNoncanonicalPredicate`, `SourceIndexingProfile`,
   `ValidateEntityPredicates`). They are not test-only, so 3.3 does not narrow them; five of the eight are also read
   by graph-ingest's tests.
4. **One of the root's package comments went with `query_types.go`** (eight before, seven now). #132 item 6, the
   package comments, is otherwise untouched.

The README line that named the function (`graph/README.md:19-20`) now names the two methods only. No doc comment named
`QueryDirection` or the function outside the code removed.

## How readers were found

A `go/packages` program (local only: `/tmp/pr93-3.3/tool/main.go`, not committed) loads every package of a module with
its tests and `-tags=integration`, lists the target package's exported package-level identifiers and the exported
methods of its exported types (struct fields are wire shape and out of scope), and resolves every identifier in every
loaded file through `types.Info.Uses`, generic instantiations mapped to their origin. A use inside the identifier's
own declaration (a type's constants or methods naming the type) is not counted. A concrete method also counts as read
where a method of the same name on an interface it implements is read, the way §2 counted interface reads.

```bash
# This tree, at f0b0bad and again after the change (worktree root)
sweep -dir "$PWD" -pkg github.com/c360studio/semengine/graph ./...
# The pin: a fresh copy of the tarball, loaded offline from the module cache
gh api repos/C360Studio/semstreams/tarball/8b99efe9 > pin.tar.gz   # unpacked to /tmp/pr93-3.3/pin
GOFLAGS=-mod=mod GOPROXY=off GOWORK=off sweep -all -dir "$PWD" -pkg github.com/c360studio/semstreams/graph ./...
# Consumers: the files that import the root (97), then the names; each hit read by hand
grep -rln --include='*.go' '"github.com/c360studio/semstreams/graph"' semsource semconnect semteams semboids
xargs grep -n -E '\bQueryDirection(Outgoing|Incoming|Bidirectional)?\b|\bGetPropertyValue\b|\bGetTriple\b'
```

A pin reader counts when it is non-test code in one of the 65 admitted package directories; the pin's readers in other
packages (`test/e2e/client`, `processor/research-graph-*`, `processor/gated-dag`, `gateway/graph-gateway`,
`agentic/agentrun`) are not readers. The consumer grep found no `QueryDirection` and no call of the function
`GetPropertyValue`: every hit (semteams `cmd/semteams/loop_runtime_integration_test.go:162` and six lines of
`test/contract/autoresearch_reply_integration_test.go`, and the same lines in two copies under `semteams/.worktrees/`)
calls the method on an entity value, in a test.

## What was not checked

- Consumers were searched only for the six identifiers that changed; every other identifier was kept on a reader in
  this tree or in an admitted package. Consumers were read at their working trees, without git.
- A read by reflection or a name built at run time is not seen by `types.Info.Uses`.
- The tree was loaded for darwin/arm64 only; the root has no platform-specific files.
- Exported names declared in the root's `_test.go` files, the sub-packages and struct fields are outside the sweep.
