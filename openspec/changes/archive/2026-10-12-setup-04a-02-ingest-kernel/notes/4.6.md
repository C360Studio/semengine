## Choices

1. **The wording.** Only the symbol in the parentheses changed; the rest of the message, its `errs.WrapInvalid` class
   and its operation names stay as they were. The message already named the missing type, which the spec also asks
   for.
2. **The two doc comments** now say what this module does: a consumer calls `RegisterPayloads` on the registry it
   gives graph-ingest, at process bootstrap, and a test on the registry it builds. They name no aggregator, since
   this module has none (03B Q1 ruling, #3).
3. **The negative assertion is on `payloadbuiltins`**, the one symbol the old text named that this module lacks. It
   cannot prove the message names no other missing symbol; the positive assertion and the compiler check above are
   what tie the message to a symbol that exists.
