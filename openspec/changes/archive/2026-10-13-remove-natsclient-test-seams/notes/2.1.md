# Task 2.1 notes: remove `opHook`

Choices task 2.1 made that the design does not spell out. Row numbers are `inventory.md` § 3 rows; line numbers are
on this task's commit.

## Row 13 moved in this task, not in 2.3

Task 2.1 removes `opHook`, and row 13 (`TestClientConnectThatLosesAdmissionLeavesStatus`,
`client_lifecycle_test.go:287`) held its losing Connect through `opHook`. The tasks give row 13's move to 2.3, but
without that move the package does not build once `opHook` is gone. So row 13 takes the end state the design's
Recommendation table gives it, in this task:

- `netDial` holds the first socket dial (the losing Connect's) until the winner has connected, then dials for real.
  Later dials pass straight through.
- The loser calls `Connect`, not `connectWith`, and must return `ErrAlreadyStarted`.
- The test no longer waits for the rejected connection's closed handler, and its comment no longer claims the window
  before the Connecting write, which it stops testing (`client.go:729`'s guard, left to review by the design).

What task 2.3 still has to do for row 13: nothing. Its other moves (row 1's `dial-error` and `canceled-dial`, row 11,
`connectScripted`) are untouched.

## Rows 3 and 14: no dial, through `silentListener`

Both tests build their client on `silentListener`'s URL and call `Connect`. After it returns they read `accepted`
without blocking, as `client_connect_test.go:141`-`:158` does. That read is reliable here: a Connect that dialled the
listener waits for a server greeting that never comes, until its connect timeout, so the accept has happened before it
returns.

- Row 3 no longer builds a `clientOwner`: it read the adapter only for the dial count.
- Row 3 no longer records the status seen during a dial. It still checks the status after the refused Connect.

## Rows 15, 25, 26 and 17

- Row 15: the second Connect goes through `Connect`. The doc comment drops "never dials", which the test no longer
  checks. The ledger's line 1583 still says "before it dials"; that text is task 5.1's.
- Row 25: the `dials` map and both dial reads go. `tableClient.owner` and its construction in `buildTableClient` go
  too, because the dial column was their only reader (design: "Test helpers whose last user goes are deleted"). The
  `tableState` comment above `tableClient` is task 4.2's and is unchanged.
- Row 26: `clientOwner` keeps its type and constructor, because other tests read its `Unresolved`. Its `mu` and
  `calls` fields go, and `Observe` returns no `Calls`. Its doc comment says the suite's call counts do not cover Client.
- Row 17: the comment says why `Failures()` staying 15 shows no dial. A dial to the refused port fails, and
  `connectFailed` (`client.go:832`) counts a failure even while the circuit is open.
