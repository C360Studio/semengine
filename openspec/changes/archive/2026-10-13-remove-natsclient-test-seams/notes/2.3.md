# Task 2.3 notes: remove `connectWith`'s `dial` and `carriesClientHandlers`

Choices task 2.3 made that the design does not spell out, and the two mutation verdicts. Row numbers are
`inventory.md` § 3 rows; line numbers are on this task's commit.

## Production code

- `connectWith` folds into `Connect`, which calls `nats.Connect` itself. `connectWith`'s doc comment goes with it:
  `Connect`'s doc comment and the admission comment in its body say the same thing.
- `discardCandidate` always waits for the discarded connection's closed handler (`client.go:825`).
- `cleanup` hands its connection to the joiner as it is (`go m.join(joined, conn)`, `client.go:982`). `join` already
  skips the wait when the connection is nil, which is what `carriesClientHandlers` returned for a nil connection.

## Row 13: unchanged

Task 2.1 moved row 13 (`client_lifecycle_test.go:287`) onto `netDial` (`notes/2.1.md`). It matches the design's end
state: `netDial` holds the first Connect's socket dial until the winner has connected, then dials for real; the first
Connect must return `ErrAlreadyStarted`; the test no longer waits for the rejected connection's closed handler; and its
comment says the hold is after the Connecting write. This task does not touch it.

## Row 1: `dial-error` and `canceled-dial`

`netDial` holds the first socket dial, the losing Connect's, and returns an error once released; later dials, the
winner's, go to the embedded server. In `canceled-dial` the test ends the losing Connect's context before the release,
as it did before. The assertions are unchanged. The doc comment (`client_close_final_test.go:448`-`:451`) adds one
sentence saying where the hold is.

## Row 11: a connection made after Close returned

The client dials the embedded server. `netDial` holds the first socket dial until Close has returned, then dials for
real. Three choices:

- The old test checked `candidate.IsClosed()` on a connection it had built itself. The connection is now Connect's
  own, so the test keeps the socket `netDial` returned and, after Connect returns, checks that a write to it fails with
  `net.ErrClosed` (`client_connect_test.go:58`-`:59`). Without that check, a Connect that refuses the connection but
  leaves it open would pass. The check holds because nats.go's `Close` closes the socket before it returns (nats.go
  v1.54.0, `close`, its deferred `nc.conn.Close()`; read, and the test passing shows it).
- The hold is once only, as in row 13: if a wrong change installed the connection, a later reconnect's dial passes
  through instead of closing `dialEntered` a second time.
- The waits use `await`, `awaitErr` and `awaitValue` (bounded by `lifecycleBound`) instead of bare receives, and the
  `sync.WaitGroup` goes: the result channel is buffered. `require.ErrorIs` gains a message for `-expect-text`.

## Rows 10 and 12, `newConnectCandidate`, the loser-dial wrappers

Rows 10 and 12 and `newConnectCandidate` are deleted. The tree has no named loser-dial helper: the wrappers were the
inline functions passed to `connectWith` as the losing Connect's dial. Row 1's is replaced by its `netDial`; rows 7 and
13 lost theirs in task 2.1.
