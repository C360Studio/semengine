Choices task 4.1 made that the design does not spell out, the mutation verdict, and what the removal leaves without a
test. Row numbers are `inventory.md` § 3 rows; line numbers are on this task's commit.

## Production code

- `subscribeWith` folds into `Subscribe`, which calls `subscribeOwned` itself (`client.go:1269`).
- `subscribeOwned` loses its `subscribe` parameter and calls `conn.Subscribe` (`client.go:1330`).
  `SubscribeForRequests` stops passing `nativeSubscribe` (`request.go:411`-`:413`).

  before using it when `conn.Subscribe` fails, so it needs no such guard.

## What has no test now, as the design accepts

The design accepts this loss: the refusal is shared code, still proved by `ack-explicit` and `ack-none` (design,
"Other deletions").

- **A core subscription's late delivery.** The `transport-client` requirement "A delivery after the recorded end is
  refused, and counted" (`spec.md:143`) names a subscription's end as well as a consumer's. Its only scenario is the
  consumer one (`:149`). No test now delivers to a core subscription after its end.
- **The `ack_policy` value `core`** that `subscribeOwned` gives its refusals (`client.go:1313`). No test reads it
  (`git grep -n '"core"' -- 'natsclient/*_test.go'` finds nothing). A wrong value would go unnoticed. This was not
  run as a mutation; it follows from the grep.
- **`newSubscription`'s born-invalid branch on a subscription the client owns** (`client.go:1165`-`:1169`).
  `TestSubscriptionDrainBornInvalidIsSuccessful` (`subscription_test.go:117`) still reaches the branch, but with a
  nil `onEnd`. No test reaches it from `subscribeOwned`, where `onEnd` is the delivery's `end`. Reaching it needs the
  subscription to end between `conn.Subscribe` and `SetClosedHandler`. Nothing in this code makes that happen, and
  no hook was added to force it.
