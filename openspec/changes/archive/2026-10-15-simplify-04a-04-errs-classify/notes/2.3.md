# Task 2.3 notes: guard tests for "transient on purpose" (design D3)

Base commit: `401e050` (tasks 2.1 and 2.2's tests; no production line changed). Tests only.

## What changed

- `pkg/projection/commit_ambiguity_test.go` `TestTransportOutcomesKeepTheirCommitState`, row `no responders`: every
  write operation's `MutationError` must have `Class` `errs.ErrorTransient`. Only the field is asserted (spec
  requirement "A request no responder took keeps the transient class"); `errs.IsTransient` on the whole error is not,
  because it reads through to the raw, unclassified `nats.ErrNoResponders` (D3).
- `pkg/lifecycle/manager_test.go`: new `TestUpdateRetriesExhaustedIsTransient`. Each write is exhausted by the fake
  emitter's `forceRevisionMismatch` after a real `Create`, and must match `ErrUpdateRetriesExhausted`. Subtest
  `classify` asserts `errs.Classify` is transient; subtest `is_transient` asserts `errs.IsTransient` is true.

## Choices the design does not spell out

- **"`Update`'s exhaustion path" is two paths.** There is no `Manager.Update`; the name survives in the
  `ErrUpdateRetriesExhausted` doc comment (`errors.go:106`). `manager.go:656-657` is the transition loop
  (`transitionWithOutcome`, behind `Transition` and `TransitionWith`). `manager.go:768-769` is the same budget in
  `UpdateFromOperator`. D3 says "every error matching `lifecycle.ErrUpdateRetriesExhausted`", so the new test drives
  both. The third site, Create's attach path (`manager.go:453-454`), is the existing test below.
- **Two subtests, not one.** On the base commit `errs.IsTransient` is false for this error: it is a plain
  `errors.New` sentinel wrapped by `fmt.Errorf("%w ...")`, with no `*errs.ClassifiedError` and no listed transient
  sentinel in its chain, and the revision mismatch is formatted with `%v`. It reads transient only through
  `Classify`'s unclassified default. So the `IsTransient` half cannot "pass on the base commit" as the task's gate
  says: it is a failing-first test for task 3.2 ("`lifecycle.ErrUpdateRetriesExhausted` is transient"). The `classify`
  half is the guard the gate describes. Splitting them lets each half be run and mutation-checked on its own
  (`task mutate:check` refuses a test that fails on the unchanged code).
- **`manager_test.go:1745` is the same guard on a different path.** `TestCreateAttachRereadDecidesTheOutcome`, row
  `no phase` (the check is at `:1745`, its message at `:1746`), covers Create's attach path (`manager.go:453-454`) by
  `errs.Classify` only. The new test covers the transition and operator-update paths, by `Classify` and by
  `IsTransient`. Neither replaces the other. The existing test gets no `IsTransient` assertion here: the task names
  only the new test for it.
