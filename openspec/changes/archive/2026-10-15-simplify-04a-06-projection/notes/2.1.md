# 2.1 `TestClassifyMutationErrorMapsEachOutcome`

File: `pkg/projection/classify_mutation_error_test.go`, package `projection_test`, so it calls the function the
way a product does. Expected values are written from design D1's table, one row per table line and one per
pre-write refusal code (nine), plus `nats.ErrTimeout`, a bare unclassified error, a transient `internal` reply and
an invalid `response_too_large` reply. The two rows for natsclient's `ErrNotConnected` and `ErrCircuitOpen`
wrapped as transport `commit_unknown` expect commit-unknown, fatal: they stay unknown until #268.

Choices the design does not spell out:

- The test imports `internal/graphmutation` to build the transport errors. A product cannot, but the inputs are
  the errors this repository's wire client returns, and 9b's caller (`pkg/lifecycle`) receives exactly these.
- `errs.Classify` is asserted fatal only on commit-unknown rows. For a request that was not delivered only the
  `Class` field is promised: the raw `nats.ErrNoResponders` underneath stays unclassified, as
  `TestTransportOutcomesKeepTheirCommitState` already states.
- Two small companions: `TestClassifyMutationErrorReturnsNilForNil` and
  `TestClassifyMutationErrorCopiesTheReplysDetail` (the detail is a copy, design D1).
