# 3.4 Dead layers and the nil-client refusal

`pkg/projection/mutation_client.go`, design D4:

- `canonicalizeTriples` returns `([]message.Triple, error)`; `canonicalizeGroupMutation` returns no metadata. The
  callers read `request.Metadata`, which the removed return value only echoed.
- `Create`'s response-entity check and `Append`'s `default:` are gone; `graphmutation.Client` refuses both replies
  (task 2.4 shows it). `Append` is now one `switch` over the failed and not-found outcomes, then the receipt, with a
  comment saying the wire client has refused any other outcome.
- `cloneDetail` is `maps.Clone` (nil stays nil). `isNilRequester` and the `reflect` and `sort` imports are gone.
- `NewMutationClient` refuses a nil NATS client with `errors.New("NATS client is required")`, a plain error like its
  other construction errors, where it returned a create-operation `*MutationError`. `newMutationClient` no longer
  checks its requester: its only production caller passes a non-nil `*natsclient.Client` once
  `NewMutationClient` has refused nil, and `graphmutation.NewClient` refuses a nil interface.
- `mutationFailure`'s comment says the receipt is zero and the error carries the commit state (Codex batch-2 NIT).
