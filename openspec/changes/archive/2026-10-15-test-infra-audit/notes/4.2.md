## Choices

- Zero-value `Shared` embedding an unexported `f Fixture`. `Shared` needs no constructor in `TestMain`: `var shared
  natsfixture.Shared` is ready to use. On the first `Reset`, `s.f` runs the same phased `Start` as `New(t)` (Ryuk off +
  sweep once per process, labelled container, host-port read, ready wait, JetStream check) under a 5-minute context
  derived from `t.Context()`, then closes and clears `s.f.nc` / `s.f.js` before `Reset` dials its own connection and
  counts client connections.
- No new test seam. `TestSharedFailedStartFailsLaterResetsAtOnce` reuses `s.f.readPort`, the single kept seam from task
  3.3 (`Shared.Reset` sets `s.f.readPort = readMappedPort` only when nil).
- Connection count wait (`connWaitBudget = 2 * time.Second`). When a test closes its client on cleanup (for example via
  `Open`, whose cleanup runs before `Reset`'s post-test check), the TCP close crosses Docker Desktop's port forwarder
  asynchronously. Polling `$SYS.REQ.ACCOUNT.PING.STATZ` via `probe.Await` until `conns == 1` absorbs that teardown lag
  in a few milliseconds on the happy path while failing a genuinely leaked connection after 2 seconds with the last
  observed count of other client connections.
- `Open` refuses an empty URL (`url == ""`) before calling `open`, replacing the old unstarted-fixture check (`f == nil
  || f.URL() == ""`), because an unstarted `Fixture.URL()` returns `""`. The 12 existing external `natsfixture.Open(t,
  f, ...)` call sites in `component`, `graph/kvcatalog`, `pkg/lifecycle`, and `processor/graph-ingest` pass `f.URL()` in
  this commit so `task verify` compiles and passes before task 4.4 moves those packages to `shared.Reset(t)`.
- Named examples rather than generated checks (`docs/testing.md`). Both `Shared` (`unstarted -> started | failed ->
  stopped`) and `Reset`'s four scenarios have a small fixed state space where each scenario exercises a distinct real
  Docker/NATS interaction (stream/KV/object-store deletion, recreated fixed stream sequence, post-test leaked
  connection, pre-reset leaked connection); generated sequences over real containers would add wall time without a
  second oracle beyond `AccountInfo` and `STATZ`.
