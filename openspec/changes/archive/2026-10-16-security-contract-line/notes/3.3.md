# Task 3.3: `pkg/security/doc.go`

The task names `:65-78`, `:83`, `:101-106`, `:120`, `:129` and `:130`. Four more places in the same comment said
something the spec no longer allows, so they changed too:

- `:10` and `:13`, the "Key features" list, advertised "ACME-managed certificates" and "ACME integration for
  automatic certificate management". They now say server TLS comes from certificate and key files, and that the ACME
  settings are applied by nothing yet and refused by the TLS loaders.
- `:25-26`, the diagram, labelled both `Mode` fields "(manual/acme)". The label is now `Mode`; the field list below it
  says which values are accepted.
- `:96`, `AllowedClientCNs`, now says that with a CN allowlist a client presenting no certificate is refused even with
  `ClientCertOptional`: the qualification Codex's batch-1 finding added to the spec's requirement 1.
- `:110-112`, "Validation", named `internal/tlsutil`, which products cannot import. It now says what is checked when
  a TLS configuration is built, including the ACME refusal, without naming the internal package.

The "See Also" list names `component.Dependencies` (how a factory receives the configuration) and `metric.NewServer`
(the call that applies `TLS.Server`), and says no exported call applies `TLS.Client` yet, as requirement 3 does.
The package comment names the spec by its path, `openspec/specs/security-config/spec.md`, which exists once the
change is archived (task 5.3).
