Choices the design does not spell out:

- Generated checks: exhaustive small-scope enumeration, as design D6 says; all 81 (Offset, Limit) pairs in -1..7
  run, and the test fails if fewer than 81 reach the assertions. No seed: the enumeration is deterministic.
- The read bound is checked as an upper bound, `min(len(links), max(Offset,0) + Limit + 2)` for Limit > 0, and as
  exactly every link for Limit <= 0. The page itself is checked against the oracle, so a reader that stopped too
  early fails the page check.
- A negative Offset panicked on base; `callChildren` recovers the panic into an error so one case fails instead of
  the whole binary.
- The parent links are stored in reverse order so the result order comes from Children's sort.
