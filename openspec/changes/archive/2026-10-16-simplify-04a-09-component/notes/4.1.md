## Choices the design does not spell out

- `TestRegisterRefusesAnIncompleteRegistration` is a fifth test beside the four D4 names. D4 lists four refusals and
  the spec requires each to name the factory; the named tests cover the type and the duplicate, so this one covers a
  name `ValidateComponentName` refuses, a nil `Factory` and a nil `Ports`, each required to be invalid-class and to
  name the factory.
- "Naming the factory" is checked as the error text containing the registration's `Name`.
- `TestComponentTypeValidate` adds `"Processor"` beside `""` and `"procesor"`: the check is case-sensitive, as the
  five constants are lower case.
- `TestRegisterKeepsItsOwnCopy` also creates a component after the caller's change, so the stored copy is shown to
  keep the factory (`ListFactories` drops it from what it returns).
- The oracle in every test is a literal written from the requirement, never a value read back from the registry or
  the component under test.
- Generated checks are not used. `ComponentType.Validate` takes a closed set of five values, and the test checks all
  five plus the empty, misspelled and wrong-case near misses; a fuzz target would only repeat the switch. Each of
  `Register`'s refusals is tested on its own, and they do not interact: the first failing check refuses.
