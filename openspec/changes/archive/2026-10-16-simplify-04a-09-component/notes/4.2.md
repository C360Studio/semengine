## Choices the design does not spell out

- `Register` checks, in order, the name, the factory, the port declarer and the type before taking the lock, then the
  duplicate under it. Every refusal is `errs.WrapInvalid` around `factory "<name>": <reason>`, so each names the
  factory; a `ValidateComponentName` or `ComponentType.Validate` error is kept in the chain.
- `cloneRegistration` copies the schema (`cloneConfigSchema`) and the dependency list and keeps `Factory` and `Ports`.
  `ListFactories` calls it and then clears `Factory`, as it did before; the stored copy keeps the factory.
- `ComponentType.Validate` reports `"ComponentType"` / `"Validate"` as its source and quotes the type (`%q`), so an
  empty type reads as `""`. `ComponentConfig.Validate` keeps its own empty-type and empty-name checks first, then
  returns `c.Type.Validate()`.
- `TestRegisterFactory` and `TestRegisterFactoryValidation` in `registry_integration_test.go` move to `Register` as
  `TestRegister` and `TestRegisterValidation`. Their "nil registration" row goes: `Register` takes a value, so there is
  no nil to pass. Each remaining row now sets the fields it is not testing, so it fails for its own reason.
- The `component/README.md` lines that name the registration call move to `Register` now, because D4 names the README.
  The rest of the README and `doc.go` work stays with task 6.1.

## Codex stop B finding: the schema copy was shallow (BLOCKING)

`clonePropertySchema` left `Default`, `PortFields` and `CacheFields` shared, so a change to the caller's registration
or to one `ListFactories` result reached later listings. Test first:
`TestRegisterAndListingsShareNoSchemaValue` (commit cf391cd) changes every mutable value of a probe schema through the
original registration and then through a listing, and compares each next listing against a fresh probe built by the
same constructor (the oracle shares nothing with the registry). It failed at the merge commit 1496a65 (local only:
`.enjoy-logs/simplify-component/4.2-fix-base-fail-1496a65.txt`).

What `Default` holds, and how each is copied (`cloneDefault`, a plain type switch):

- Schema generation (`convertDefault` in `schema_tags.go`) writes nil, `string`, `int`, `bool`, `float64` or
  `[]string`. The scalars are values and need no copy; `[]string` is copied.
- A schema decoded from JSON holds `[]any` and `map[string]any`; each is copied recursively.
- `Default` is `any`, so a hand-written schema can hold anything else. The set is not closed there; such a value is
  kept as is and stays shared, and the `PropertySchema.Default` doc comment says so. Refusing it at `Register` would be
  a refusal D4 does not list, so it is not added.

`PortFieldInfo` is copied recursively by `clonePortFieldInfo` (its pointers, slices, `AnyRequired`,
`RequiredByDirection`, and the nested `Properties`, `Variants` and `Items`); `CacheFieldInfo` copies `Enum` and `Min`.
Two small generic helpers, `cloneMap` and `clonePointer`, replace the repeated pointer blocks. A nil map, slice or
pointer stays nil.

Shown able to fail (`task mutate:check`, each verdict `detection`, logs `4.2-fix-mut-m5/m6/m7.txt`): dropping the
`Default` copy, dropping the `PortFields` copy, and dropping the nested `Variants` copy.
