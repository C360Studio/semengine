# 2.2 TestBaseMessageValidateRefusesTypeGrammar and FuzzDecoderStrings

Test: `message/base_message_test.go`, `TestBaseMessageValidateRefusesTypeGrammar`. A message whose category is `a.b`
must be refused with an invalid-data error (`errs.IsInvalid`) by both `Validate` and `MarshalJSON`, as the
message-codec spec delta's "A dotted type component" scenario states.

`FuzzDecoderStrings` (`message/decoder_fuzz_test.go`): the oracle now expects marshal to be refused, with invalid
data, exactly when the test's own grammar check (empty, not valid UTF-8, or holding `.`) refuses the type, so the
separate `wantMarshal` flag and the `default:` read-back branch for a dotted type are gone. The doc comment's second
bullet says the same. `oracleEnvelope` stays: `decoderCase` still uses it.

Both fail on the base commit `cfba65a8acaf0bbe92b9dd87132366cbe0358a36` (tests changed, `message/base_message.go`
unchanged), go1.26.9 darwin/arm64.
