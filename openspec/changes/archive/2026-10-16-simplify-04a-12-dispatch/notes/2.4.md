# Task 2.4 notes

Every caller moves to the new signatures (design D2–D4): `SubmitBlocking(ctx, key, work)`, `NewKeyedPool(ctx, cfg)`
with `Logger` and `MetricsRegistry` in `KeyedConfig`, and a `Process` that returns nothing. Files:
`internal/dispatch/keyed_pool_test.go`, `internal/dispatch/shutdown_test.go`,
`processor/graph-ingest/lifecycle_owner_test.go` and `processor/graph-ingest/interrupted_work_test.go`. The "nil KeyOf"
case leaves `TestKeyedPool_RejectsBadConfig`.

## Choices the design does not spell out

- **2.5 rides the same edit.** Moving `keyed_pool_test.go` to the new signatures rewrites every test body, and task 2.5
  rewrites the same bodies onto the bubble clock, so both land in one edit of the file (`notes/2.5.md` covers the
  bubble side). The base failure below is of that edit.
- **Keys at the call sites.** Where a test's old `KeyOf` returned a constant, the submit passes that constant
  (`"key"`, `"one-key"`, `"sticky"`, `"same"`, `"k"`, `"entity"`); where it returned the work itself, the submit
  passes the work as its key. `interrupted_work_test.go` passes the entity ID it builds the input for, as
  graph-ingest does.
- **`lifecycle_owner_test.go`'s `Process`** drops its returns; its `select` still ends on the release or on the
  pool context.
