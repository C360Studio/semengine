Choices the design does not spell out:

- The table replaces `TestUnmarshalEntityStateReturnsTypedResetReason` (its three rows are rows of the new table)
  and task 2.1's base-API stand-in `TestUnmarshalEntityStateRefusalIsClassifiedOnce`.
- Beyond the per-reason and double-fault rows, the table has an empty-bytes row (graph-ingest's "an empty value is
  poison, never absence") and one accepted value, so a decoder that refuses everything fails.
- Stored bytes are built by hand (`storedEntityBytes`), not by the encoder, so the input is not shaped by the code
  under test.
- One layer is counted above the `*StateContractError`, not along the whole chain. The canonical contract's
  entity-ID violation wraps `pkg/types.ValidateEntityID`'s own classified error (code `entity_id_invalid`) as its
  cause, so a whole-chain count is 2 for the `noncanonical entity ID` row whatever the decoder does. The spec's "one
  classification" is the refusal's classification; the cause is the violation. The graph-ingest reconcile test
  counts the same way. Its base run still reports 2 layers (re-run on a `4cca411` worktree with the final test file).
- Callers with no key in scope gained one: graph-ingest's test helpers `decodeEntity(t, key, data)` and
  `stateValue(t, key, stored)`; the bench hoists its entity ID to `benchmarkEntityID` and stamps `Source`; the
  trusted-decode contrast passes the ID the trusted decode read, so the canonical contract, not the key, refuses.
- `vocabulary/export`'s round trip stamps a copy of each statement with `Source` and `Timestamp`; the serializer reads
  neither.
