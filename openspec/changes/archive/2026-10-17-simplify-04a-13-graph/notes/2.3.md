Choices the design does not spell out:

- The one constructor is `graph.stateRefusal(entityID, reason, err)` in `graph/state_contract.go`: `errs.ClassifiedCode`
  (fatal, `graph_state_reset_required`) over the `*StateContractError`. The canonical-contract step is
  `checkCanonicalState`, shared by `UnmarshalEntityState` and `ValidateDecodedEntityState`; step 4 is the exported
  `ValidateStatementMetadata` itself, shared by both and by graph-ingest's `requireStatementMetadata`.
- The aggregate family's refusals carry no entity ID (it has no key), as before.
- `rejectFromError` returns any error `graph.IsStateContractError` accepts unchanged. Every state error that reaches
  it now comes from the stored-value rule, which classifies once.
- `decodeStoredForWrite` on a key mismatch calls `decodeStoredEntity(key, current)` and records its refusal, on the
  failing path only.
- The sweep's fallback is gone; `sweepEntityStateGuardEntry` keeps the `errors.As` with a comment that every refusal
  of the rule is a state error.
- `pkg/lifecycle`'s interface is `exactEntityReader` in `manager.go`; the test double `bucketExactEntityReader` and
  the integration responders call `graph.UnmarshalEntityState` directly.
- The unexported requester interface is named `classifiedRequester`, not `requester`, so the constructor's
  parameter does not shadow its type.
- Added tests beyond 2.1/2.2: `TestZeroExactEntityReaderRefusesReads` (D2 states the zero value refuses; it does not
  compile on the base commit, where `ExactEntityReader` is an interface), and
  `TestValidateDecodedEntityStatesRefuseStatementWithoutMetadata` (the aggregate validators' step 4, owner question 1).
- `graph/README.md` still says "`StateContractError` and its classifiers"; with `ClassifyStateContractError` gone,
  `IsStateContractError` is the one left. Left for D7 (task 4.x, text follows the code), which lists the README.
