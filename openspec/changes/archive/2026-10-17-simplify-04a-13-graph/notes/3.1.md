# Task 3.1 notes

Base commit: `4ccbbe4`. Both tests were added to the base tree (test files only) and run with
`go test ./processor/graph-ingest -run '<name>' -count=1`. Each failed by assertion.

| Test | Base failure (assertion, verbatim) |
| --- | --- |
| `TestCanonicalMutationOutcomeLabelIsTheClassifiedCode` | `outcome "message_type_unregistered" delta = 0, want 1`, `outcome "internal" delta = 1, want 0`; `outcome "invalid_request" delta = 0, want 1`, `outcome "invalid" delta = 1, want 0` |
| `TestExactEntityReplyCarriesKVRevision` | `reply kv_revision = "", want 2; reply {"entity":{...},"kvRevision":2}` |

Choices the design does not spell out:

- The label test takes the create route from `canonicalMutationRoutes` and wraps it with `meteredCanonicalMutation`,
  the same two calls `mutation_runtime.go` makes before subscribing. It also asserts the base labels (`internal`,
  `invalid`) do not move, so a counter bumped twice fails too.
- The wanted labels are string literals from ruling L and the spec delta, never the `graph.ErrorCode*` constants the
  handler uses.
- The wire test's requester calls `handleQueryEntityNATS` directly and keeps the reply bytes. The test reads the key
  from those bytes as a `map[string]json.RawMessage`, so the oracle for `kv_revision` is the reply itself, and the
  revision oracle is the one the mock bucket's `Put` returned. The value is written twice so that revision (2) is not
  the first one.
- A rename on one side only was shown to fail after task 3.3; see `notes/3.3.md`.
