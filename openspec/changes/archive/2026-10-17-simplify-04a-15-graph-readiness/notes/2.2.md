# Task 2.2 notes

## Choices the design does not spell out

- `Read` computes age as `time.Now().Sub(w.lastArrival)` and `apply` stamps `time.Now()`, as D2 says; the
  `freshnessWindow` method on `Watcher` is gone and both call sites call `freshnessWindow(w.heartbeat)`, because the
  unexported function and the method would share a name.
- The rebind wait constant is `rebindDelay` (it was `defaultRebindDelay`), since nothing overrides it now.
- `Run`'s new refusals come after the three existing ones, in the order nil context, nil source, empty key,
  non-positive heartbeat, nil logger. The heartbeat refusal names the value it got.
- `Reading.Fresh`'s doc comment said "within FreshnessMultiplier heartbeats"; it now says "within three
  heartbeats", since the constant is unexported.
- `TestWatcher_RunValidatesWiring` runs `Run` under a one-minute context in its bubble, so a mutant that accepts the
  wiring returns at the deadline and the open count names the failure, instead of looping forever in bubble time.
- No repo caller of `NewWatcher`, `WithHeartbeat`, `WithLogger`, `FreshnessWindow` or `FreshnessMultiplier` exists
  outside `graph/readiness` (`gopls references` on each at `ad6b0f7`). One comment outside the package still names
  `readiness.FreshnessMultiplier`: `processor/graph-ingest/readiness.go:16`. That file is in open PR #286, so it is
  left for batch 3 (D6's comment pass) rather than edited here.

## How the new tests fail on the base

The new `TestWatcher_RunValidatesWiring` rows (zero heartbeat, negative heartbeat, nil logger) and the reduced
`TestFreshnessWindow` fail to compile on the base: `NewWatcher` takes `opts ...Option` there and `freshnessWindow`
does not exist.
