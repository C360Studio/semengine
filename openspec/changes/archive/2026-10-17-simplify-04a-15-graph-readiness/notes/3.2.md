# Task 3.2 notes

## Choices the design does not spell out

- `EvaluateReadinessGate`'s parameter is named `r`, as in the design's signature. Its doc comment now says the caller
  proceeds on `DeferNone` and names the two reader shapes (`w.Read()`, `Reading{Status: s, Fresh: true}`), which
  were on `StatusReading`'s doc comment.
- `DeferReasons()` returns a slice literal built on each call, in `AllDeferReasons`' order. It keeps
  `AllDeferReasons`' doc comment, with its first sentence saying the slice is new on every call.
- Comments that named `StatusReading.Fresh` (`watcher.go:88`, `watcher_test.go`'s `TestFreshnessWindow` comment) now
  name `Reading.Fresh`; they would otherwise name a type that no longer exists. No other comment was edited (D6 is
  batch 3).
- Every gate test now compares one `DeferReason`. Rows that proceeded expect `DeferNone`; checks that asserted
  "proceed carried no reason" go, since a single result cannot disagree with itself.
  `TestWatcher_UndecodableValueRevokesFreshness` loses its local `gate` adapter and calls
  `EvaluateReadinessGate(h.watcher.Read())`, the Watcher-reader shape D1 names.
  `TestComputeBacklogStatus_ObservationFailureCannotReportReady` now asserts the reason is `hard_stop`, not only that
  the gate did not proceed.
