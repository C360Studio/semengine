# Task 3.3 notes

## Choices the design does not spell out

- `NewPublisher`'s two refusals are `readiness: nil status bucket` and `readiness: empty producer key`, checked in
  that order. Its doc comment states the refusals and that a typed-nil bucket is not detected (D3).
- `createStatusBucket` wraps `NewPublisher`'s error with `errs.Wrap(err, "Component", "createStatusBucket",
  "readiness publisher")`, the same shape as the provisioning error beside it, with a message naming the publisher
  rather than the bucket. `Start` wraps it again as "readiness status bucket", as it does the provisioning error.
- `publishReadinessStatus` loses its `c.statusPublisher == nil` guard. The status loop starts after
  `createStatusBucket` succeeds (`component.go:1004`), and `clearLifecycleHandles` sets the publisher to nil only
  after `cleanup` has joined `statusDone` (`component.go:1088-1096`, `:1136-1141`), so the loop never sees a nil
  publisher. Its `c.readinessGauges != nil` guards were not part of D3 and stay.
- The `BucketGraphStatus` alias's doc comment went with it; the const block's comment now says the bucket's name is
  `graph.BucketGraphStatus`. `fakeEntry.Bucket` in `watcher_test.go`, the Watcher's `bucket` field, the publisher's
  error messages and graph-ingest's log line and integration test now name `graph.BucketGraphStatus`.
- `TestEnsureBucket_OneShapeIsTheCatalogRow` tests the catalog row, not `EnsureBucket`, so it stays, renamed
  `TestGraphStatusBucketShapeIsTheCatalogRow`, with its comment saying producers call
  `kvcatalog.EnsureCatalogBucket`. `TestEnsureBucket_NilClientErrors` goes with `EnsureBucket`;
  `kvcatalog.EnsureCatalogBucket` is not this package's to test.
- `TestPublisherKey` goes: its nil-publisher row tested the nil-receiver check D3 removes, and its other row is now
  the control in `TestNewPublisherRefusesIncompleteWiring`. The publisher tests build through a
  `newTestPublisher(t, writer, key)` helper that fails the test on a refusal.
- `Gauges` holds `subsystem string`; `Register` keys each collector under it directly. `metricNamespace`'s comment
  named the removed name-pinning test and now says only that every collector uses the one namespace.
- Comments still left for batch 3 (D6): the `graph/readiness` ledger row names `StatusReading` and
  `bucket_alias_test.go` (`docs/admission-ledger.yaml:2007`, `:2025`); `publisher.go`'s cite of
  `graph/kvcatalog.go` (#293, task 4.2); `processor/graph-ingest/readiness.go:17`'s `readiness.FreshnessMultiplier`.
