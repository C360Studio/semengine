# Task 2.2: `TestHealthMonitorTickReturnsStatusAndClose`

File: `natsclient/health_monitor_integration_test.go`. The client is built on the shared server's reset URL with a
5 ms health interval, no reconnects and the fixture dial timeout. After `Connect`, the test stores
`StatusDisconnected` into `client.status` (in-package, as `kv_key_contract_integration_test.go` does) and awaits
`Status() == StatusConnected` with `probe.Await` under `failureBound`, then calls `Close` under `closeBudget`.

Choices the design does not spell out:

- **Every call that can block on `mu` runs beside the test's own deadline** (`withinDeadline`, a helper in the
  test file): `Connect`, the await, the `Close` and the cleanup `Close`. `probe.Await` calls `Status()` on the test
  goroutine, so under the mutant the await itself would block and the test would never reach its deadline; a hung
  call's goroutine is left blocked. The cleanup `Close` is bounded the same way so the run ends rather than reaching
  `go test`'s timeout (which `mutate:check` reads as inconclusive: first attempt, with only the await bounded).
- **`Connect` is bounded too**, because on base it also calls `Status()` with `mu` held (`resetCircuitLocked`,
  from `Connect`). With the mutant on base the test therefore fails at `Connect` (line 46), before the first tick.
  Once task 3.1 removes `resetCircuitLocked`, the tick is the remaining caller under `mu`; the check is re-run then
  to show detection at the await (line 59).

Base: passes (`go test -tags integration -race -count=3 -run 'TestHealthMonitorTickReturnsStatusAndClose$'
./natsclient/`, ok).

Mutation check, mutant: `Status()` takes `m.mu.RLock()` / `defer m.mu.RUnlock()` before loading the status
(copy of `natsclient/client.go` outside the repository). Command:

```bash
GOFLAGS=-tags=integration task mutate:check -- -pkg ./natsclient -test TestHealthMonitorTickReturnsStatusAndClose \
  -file natsclient/client.go -mutant "$TMP/client.go" \
  -expect health_monitor_integration_test.go:46 -expect health_monitor_integration_test.go:60
```

(`:60` was a typo for the await's line `:59`; it matched nothing, and the detection rests on `:46`.)

```text

  failure locations: health_monitor_integration_test.go:46, health_monitor_integration_test.go:40, shared.go:150
verdict: detection: each of the 3 mutant runs failed the named test with an expected line, and the after-run passed
```

`:40` is the bounded cleanup `Close` and `shared.go:150` the reset's open-connection check, both after the test's
own failure. Earlier runs of the same mutant: with only the await bounded, `inconclusive: go test's whole-run
timeout ended the run` (hung in `Connect` via `resetCircuitLocked`); with `-expect :59` only after bounding
`Connect`, `inconclusive: the named test failed with no expected line` (failed at `:46`).

Orchestrator ruling (2026-10-17): accepted.
