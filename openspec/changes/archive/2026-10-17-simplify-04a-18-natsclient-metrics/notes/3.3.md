# Task 3.3 notes

## Shape chosen

- `streamJetStream()` makes the checks every synchronous stream publish makes: the client is connected, and it has
  a JetStream context. Its errors reach each caller unchanged and uncounted.
- `streamMsg(ctx, subject, data, msgID)` is the one message builder, synchronous and async. It adds ctx's trace, or
  a new one, and a Nats-Msg-Id header when `msgID` is not empty.
- `PublishToStream`, `PublishToStreamWithMsgID` and `PublishToStreamWithAck` each call
  `js.PublishMsg(ctx, streamMsg(...))` themselves. Only `PublishToStreamWithAck` counts a failure of the publish
  as `publish_to_stream` and wraps it as transient. The other two return nats.go's error unchanged. These are the
  per-call errors D3 option A keeps, and 2.2's oracle holds them.
- `publishToStreamAsync` keeps its order (status, `ctx.Err()`, JetStream), so it does not use `streamJetStream`.
  It shares only the builder.
- `PublishToStreamWithAck`'s doc comment loses the `AutoCreate` line. It gains one saying which errors are counted
  and classified.

Why this shape: each caller's error handling is in that caller, in plain sight, and no parameter changes what a
shared function returns.

Departure from D3's wording: D3 says "`publishToStream` becomes the one path, returning `(*jetstream.PubAck,
error)`". No `publishToStream` is left. The checks and the build are written once, as D3 asks, and `js.PublishMsg` is
called three times, one per exported call. D3's "no change in behaviour" holds (2.2's oracle, and its mutation check
re-run on this shape).

## Considered

- A `publishToStream(ctx, subject, data, msgID, classify bool) (*jetstream.PubAck, error)` that all three callers
  used, with `classify` switching on the count and the wrap. It matched D3's wording, but a bool that switches error
  handling is a less plain shape than the one above. It was replaced in a later commit, before review.

## Orchestrator ruling

The first shape put `PublishToStreamWithAck` through `publishToStream` with a `classify bool` parameter. The
orchestrator asked for the helper shape instead: a bool that switches error handling is the kind of cleverness the
owner's style rule ranks against plain Go. Design D3's first line now describes the helper shape. Behaviour is the same
and the 2.2 mutant is still detected.
