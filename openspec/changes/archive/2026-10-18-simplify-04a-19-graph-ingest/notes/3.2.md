# Task 3.2 notes

Choices the design does not spell out:

1. **The scope function.** `latchBootstrap` becomes `bootstrapScope(outstanding, observationFailed) uint64`
   (`readiness.go`). It keeps one branch: when a bind read failed, the first successful full observation replaces the
   partial capture, once. #139 B4's fallback (`bootBacklog == 0 && outstanding > 0`) goes as D2 says: every bound
   consumer gets its bind read inline (`setupJetStreamConsumer`), so a zero capture with no partial flag is a clean
   capture of an empty backlog, and the branch only overwrote it with later work.
2. **Which unit tests stay.** The latch tests go: `TestLatchBootstrap_DrainedIsALatchNotALiveRead` (the latch),
   `TestLatchBootstrap_ScopeCapturedOnce` and `TestLatchBootstrap_NoBindReadRanTakesTheFirstObservation` (both drove
   their scope through the removed fallback and asserted `complete`). The scope tests stay, renamed
   `TestBootstrapScope_*`: `PartialBindCaptureIsDiscarded` (now also the captured-once check), `CompleteBindCaptureIsKept`,
   `ZeroScopeIsAuthoritativelyNothingToDo` (which now also checks a later backlog does not become the scope: the case
   the fallback got wrong), and `ObservationFailureNeverLatches`, renamed `ObservationFailureCapturesNothing` and given
   a partial capture so its second read reaches the replacement branch.
3. **Where the failed observation is kept.** `backlogObservationFault atomic.Pointer[string]` on `Component`: nil when
   the latest tick read every consumer, else a message naming each consumer (`stream/name`) it could not read.
   `computeBacklogStatus` stores it after its loop, so the one compute feeds envelope, gauges and `Health()`; the
   shutdown early return stores nothing. It is a field because `Health()` must read it without I/O (design D3, option
   b rejected). It is not cleared on `Stop` (review LOW, 15c9852): graph-ingest is one-shot, and
   `internal/lifecycleguard` refuses a second `Start` (`guard.go:37`), so no later run can read a stale value; after
   `Stop`, `Health()` reads `running` false and reports neither stuck state.
4. **`Health()`'s message.** `LastError` joins the states that hold with `"; "`: the poison sample as before, then the
   backlog message. `Status` is `degraded` while either holds, `running` otherwise, `stopped` when not running.
5. **Comments that said the error count is what Health reads** (`component.go`, `keyed_ingest.go`, two test files)
   now say it is what Health reports, matching the `graph-ingest-recovery` delta.
