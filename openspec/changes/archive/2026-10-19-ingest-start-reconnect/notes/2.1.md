# Task 2.1 notes: the relay, T1 and T2

Choices the design does not spell out, and the fail-first runs on today's code.

## Choices

- **Where the code lives.** The relay (`brokerRelay`), the client's open function (`openReconnectingClient`), the
  setup (`newRelayedComponent`) and both tests are in `processor/graph-ingest/lifecycle_integration_test.go`, after
  `refusingBrokerURL`, as design D2 places them.
- **Relay shape.** Each accepted connection is recorded before the relay dials the broker, and the broker connection
  is recorded after the dial, so a `Cut` that lands during a dial closes the client side and the broker side is
  closed as soon as the dial returns. Either copy direction ending closes both sides. The dial to the broker is bounded
  by `relayDialTimeout` (5 s), so the cleanup's join waits at most that long for a dial in flight.
- **Client options.** `openReconnectingClient` sets only `WithReconnectWait(50 ms)` and `WithHealthInterval(0)`;
  reconnects stay at natsclient's default (unlimited), and the request timeout stays at its default (5 s).
- **Restore always runs.** Both tests `defer restoreUntilConnected` right after the cut, so the relay is restored and
  the client observed Connected before the client's cleanup runs, on every path including `t.Fatalf`. A defer runs
  while `t.Context()` is still live; a `t.Cleanup` would run after it is cancelled.
- **Failure bounds.** The status waits (`statusBound`) and both tests' Start bounds are 10 s. T1's observation window
  is 1 s (listed in design D2). When T1's bound fires, the test cancels Start's context and joins Start; when T2's
  fires, it restores the relay and joins Start.
- **T2 keeps going after a wrong error.** The error check is `t.Errorf`, so the held check and `Stop` still run.
