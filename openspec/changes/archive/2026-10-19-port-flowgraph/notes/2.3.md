# Task 2.3 notes

Choices task 2.3 made that the design does not spell out.

- `TestMatchNATSPatternIsSymmetric` lives in `declarations_test.go` with the change's other new tests. Its subjects
  are `a`, `a.b`, `a.c`, `a.b.c`, `*`, `a.*`, `*.b`, `a.*.c`, `*.*`, `>`, `a.>`, `a.b.>`, `*.>`, checked over every
  ordered pair, the equal pairs included. It also fails if the set gives only one answer, so the law is not checked
  over a set that never matches. It passed on the pin's matcher at a590761, before any caller changed; M15
  (`return matchTokens(subjectTokens, patternTokens)` on the "subject has wildcards" line) was detected by
  `task mutate:check` on that commit. The formal M1-M16 run is task 2.5's.
- The `events.*` case of `TestBuildFromDeclarationsConnectsDeclaredPorts` was written in task 2.1, so there was no
  new test to add first: it passed on fe6d236, before the builder merge, as it should for a same-behaviour change.
- `concreteID` tests with `strings.ContainsAny(a, "*>")`, the same answer as the pin's
  `strings.Contains(a, "*") || strings.Contains(a, ">")`. `matchNATSPattern`'s own wildcard checks are left as the pin
  wrote them: R8 changes only its callers.
- `matchNATSPattern`'s doc comment now says its answer does not depend on argument order and names the symmetry
  test, since the callers rely on that.
- `connectComponentsByPatterns`' refusal still passes the string `"ConnectComponentsByPatterns"` to
  `errs.WrapInvalid`. R12 renames only the function; R14 (task 2.4) removes that wrapping and its method name.
