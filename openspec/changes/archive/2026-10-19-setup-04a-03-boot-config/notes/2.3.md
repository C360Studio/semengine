# Task 2.3 notes: sensitivity for D2, D3 and the prefix

Each of the five wrong changes D5 names was made in a copy of `config/config.go` kept outside the repository (a
`/tmp` directory, local only), and run through `task mutate:check`. The tool runs the named test three times on the
unchanged code, three times with the copy swapped in by a build overlay, and once more on the unchanged code. Nothing
in the tree was edited. Base commit: `95cf058`; go1.26.9 darwin/arm64.

Every command had this form, with the mutant file, test and expected line from the table:

```bash
task mutate:check -- -pkg ./config -test <Test> -file config/config.go -mutant /tmp/<dir>/<mutant>.go \
  -expect <load_test.go:N>
```

| Mutant (D5) | The wrong change in the copy | Test | Expected line | Verdict |
| --- | --- | --- | --- | --- |
| m1: one key out of the refusal table | `"tls"` removed from `unappliedNATSKeys` (`config.go:693`) | `TestLoad_RefusesUnappliedNATSKeys` | `load_test.go:70` | detection |
| m2: one variable out of the env refusal | `"_NATS_PASSWORD"` removed from `unappliedNATSEnv` (`config.go:568`) | `TestLoad_RefusesNATSCredentialEnv` | `load_test.go:112` | detection |
| m3: `mergeFromMap` returns `base` on error | the typed decode's error branch returns `base, nil` (`config.go:498`), the pin's swallowing shape | `TestLoad_RefusesMalformedDocument` | `load_test.go:175` | detection |
| m4: the prefix back to `STREAMKIT` | `NewLoader` sets `envPrefix: "STREAMKIT"` (`config.go:348`) | `TestLoad_EnvOverrideNames` | `load_test.go:141` | detection |
| m5: `LoadFromBytes` skips the refusal | `LoadFromBytes` calls `decodeObject(data)` in place of `l.loadRawJSONFromBytes(data)` (`config.go:372`) | `TestLoad_RefusesUnappliedNATSKeys` | `load_test.go:70` | detection |

Each run printed `verdict: detection: each of the 3 mutant runs failed the named test with an expected line, and the
after-run passed` and exited 0. No survivor, invalid or inconclusive run.

## Choices the design does not spell out

- **m5's shape.** Since the Codex review fixes in 2.2, both loaders parse through one function,
  `loadRawJSONFromBytes`, which runs the refusals. So "LoadFromBytes skipping the refusal" is written as `LoadFromBytes`
  bypassing that shared function and decoding directly. In the mutant runs only the 14 `LoadFromBytes/...` subtests
  failed; every `LoadFile/...` subtest passed. That is the case the two-loader table exists to catch.
- **m3's shape.** The design says "returning `base` on error". The mutant returns `base, nil` at the typed decode,
  which is where both malformed documents fail and where the pin swallowed the error.
- Each mutant edits a line the named test reaches, and no mutant removes the only use of an import, so all five built.
