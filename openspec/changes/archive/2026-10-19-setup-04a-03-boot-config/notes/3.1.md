## Pre-Codex review fixes (review of `164cebf`, one MEDIUM, two LOW)

1. **Letter case (MEDIUM).** The docs said a key the document sets replaces the default. That is false for a key in
   another letter case, a pin merge defect tracked in #325. Probed through `LoadFromBytes` with a scratch program in
   `/tmp` (local only): `"Components"` gave 0 components; nats `"URLs"` kept `nats://localhost:4222`; nats
   `"JetStream":{"enabled":false}` left JetStream enabled; platform `"Type"` and `"ID"` were ignored. The probe also
   showed that "ignored" is not the whole rule: a case variant of a key the defaults leave out is applied, because the
   decoder matches it case-insensitively (`"Streams"` gave 1 stream, platform `"Capabilities"` gave `[radar]`, jetstream
   `"MAX_MEMORY":5` gave 5). So both docs now say: write every key in lowercase; a key in another case is not reliably
   applied and is silently ignored where the defaults carry that key (#325); the refused keys are refused in any case.
2. **`null` (LOW).** `decodeObject` now refuses a document that is `null`, which decoded into a nil map and loaded as
   the defaults, with "the document is null, not a JSON object". New test `TestLoad_RefusesNullDocument`, through both
   loaders. Before the fix (`go test -count=1 -run TestLoad_RefusesNullDocument ./config/`), both subtests failed at
   `load_test.go:311` with "An error is expected but got nil". After it, the package passes, and the probe prints
   `null: err=failed to parse config: the document is null, not a JSON object`.
3. **Spaces in `SEMENGINE_NATS_URLS` (LOW).** Behaviour unchanged. The probe with `nats://a.invalid:1, nats://b.invalid:2`
   gave `["nats://a.invalid:1" " nats://b.invalid:2"]`; both docs now say spaces are not trimmed, so write `a,b`.
