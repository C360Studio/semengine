## Choices the design does not spell out

- The coverage document for each path is minimal: only the objects along the path, with the last key upper-cased and
  the value `json.Marshal` wrote for it. The full populated document would also work, but a minimal one keeps each
  subtest about one key.
- 110 paths, against the design's 118 probed at `7414453`: the design counted every key `json.Marshal` writes; the
  test leaves out the 8 placeholder keys (`components.PH`, `services.PH`, `streams.PH`,
  `stream_migration_overrides.PH`, `archival_streams.PH`, `model_registry.capabilities.PH`,
  `model_registry.endpoints.PH`, `model_registry.endpoints.PH.options.PH`), which are names a deployment chooses.
- The filler handles `uint` and `float` leaves besides D3's list: `model.EndpointConfig` reaches a `float64`, and the
  filler panics on a kind it has no value for, so a new leaf kind fails loudly rather than being skipped.
- The test asserts four deep paths are present (a pointer's struct, a map of pointers, the deepest security struct, a
  service `config`), so a filler that stopped early fails rather than shrinking the oracle.
- The guard is a helper, `letterCaseWalkerGaps`, with a paired sensitivity test that feeds it each shape the walker
  does not handle (embedded struct; slice of structs; array of maps; slice of struct pointers; a type with its own
  `json.Unmarshaler` behind a pointer; a type with its own `json.Marshaler`) and asserts exactly one gap naming it.
- Generated checks: the coverage test is the generated part (every declared path, from reflection); the hand cases
  are the second, independent oracle (D3). No randomness, so no seed.
