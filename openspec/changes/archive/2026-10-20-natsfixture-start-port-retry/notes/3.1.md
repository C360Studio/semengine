## 1. HIGH — Recreate configuration readers before retrying (#352)

- **Location:** `internal/harness/natsfixture/fixture.go:217-225`
- **Cause:** `testcontainers-go` v0.44.0 (`lifecycle.go:145-163`) copies `req.Files` in a `PostCreates` hook before
  `ContainerStart`, draining `req.Files[0].Reader` to EOF on attempt 1. When attempt 1 failed `ContainerStart` with
  `"address already in use"`, attempt 2 reused the exhausted `strings.Reader` and copied a 0-byte
  `/etc/nats/semengine-fixture.conf`, dropping `WithMaxPayload`.
- **Fix:** Construct `req.Files` with a fresh `strings.NewReader(fmt.Sprintf("max_payload: %d\n", f.maxPayload))`
  inside each iteration of `for attempt := range startAttempts` when `f.maxPayloadSet` is true.
- **Verification:** Extended `TestStartRetriesOnceOnPortInUse/recovers_on_second_attempt` to pass
  `WithMaxPayload(4096)` and assert `nc.MaxPayload() == 4096` and `nc.Publish("payload.bound", make([]byte, 4097))`
  returns `nats.ErrMaxPayload`. Confirmed the test failed on `eb84b7a` (`broker announces max_payload 1048576 after
  retry, want 4096`), passes 5/5 with the fix, and `GOFLAGS=-tags=integration task mutate:check` on mutant (e)
  (`if attempt == 0 && f.maxPayloadSet`) returned `verdict: detection` at `start_port_integration_test.go:102`.
