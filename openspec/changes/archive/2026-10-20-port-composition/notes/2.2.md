`go test -race ./composition/ -run 'TestValidateExclusiveClashMatchesAdmission|TestValidateSelfClashIsPortDeclarationError'`
prints:


A build failure shows nothing about the rule, so a second run used the pin's exclusive check as ported before the

Both controls passed on that run, as they should.

`TestValidateSelfClashIsPortDeclarationError` passed on that run. A self-clash is refused by `Registry.Declare`
(task 2.1's `checkSelfClash`), whatever composition's own check does. Its pin outcome, a `connection_pattern_error`
from the flowgraph's bind refusal (design "Inventory correction"), cannot be reproduced on the tree, because #324
removed that refusal. The test pins down the tree's outcome. Composition reports it as a `port_declaration_error`
with `Declare`'s text, and never as an `exclusive_resource_conflict`.

After the change, `go test -race -count=1 -cover ./composition/` passes: coverage 90.3% (pin baseline 89.6%).

## Choices the design does not spell out

- **Clash test rows.** The spec scenario's four pairs, the same-text pair, and two controls: `udp`/`http` on one port,
  and one host on two ports. Each row runs through `Validate` and then `CreateComponent` on the same registry. A
  clashing row also checks that the refused component stays out of `Graph.Nodes`. The components use a small
  constructible test type (`portsComponent`), because `fakeSpec`'s factories refuse construction on purpose.
- **Holder order.** `exclusiveConflict` calls `ConflictWith` over the declarations already accepted, in
  instance-name order, and returns on the first error. The finding keeps the pin's two suggestions, naming the holder.
- **Edge order.** The shared comparator is `compareEdges(a, b Edge) int` (`cmp.Or` over the six keys), used through
  `slices.SortStableFunc` by `graphOf` and by `Mermaid`.
- **Catalog test.** The pin's test used `shippedRegistry` from `shipped_configs_test.go`, which is not ported. It now
  uses two fakes, one that declares ports for `{}` and one that refuses it, as the spec scenario says. It checks that
  there is exactly one of each and that the refusal text is carried.
- **`fmt_test.go` not ported.** Its one function, `fmtSprintf`, was read only by `assert_test.go`.
- **`doc.go`** names `service`'s component manager as the boot caller to come. It adds one sentence for products:
  call `Validate` and require an empty `Errors` list (ruling 1).
- **A pin test comment** naming SemStreams' `docs/operations/migration-beta162-to-beta163.md` now says it is
  SemStreams' document.
- **The vocabulary stays at 13 types in this task.** `TestValidateFindingsVocabularyIsClosed` lists the pin's 13 and
  did not force the 14th. Task 2.3 adds `reserved_subject_capture` and its case.
- **Ledger.** The `composition` row's contract has no reserved-subject clause yet; task 2.3 adds it with
  `SubjectsOverlap`. The `component/flowgraph` row's "no importer until composition lands" now reads "imported by
  composition", and the `internal/flowgraph` row in `docs/repository-map.md` was updated the same way.
- **Cover gate sensitivity.** `TestCoverCheckSensitivity` (`internal/harness/contract/cover_test.go`) keeps its own
  copy of the cover targets. Adding `"composition unit"` to `scripts/cover-check.sh` without updating that copy made
  the test fail ("composition: no statements in the unit profile"), so the copy has the row too.
- **Generated checks: none.** The clash rule's combinations are proven in `component`. Composition only calls
  `ConflictWith`, so the named rows are enough (design "Generated checks", clash parity).
