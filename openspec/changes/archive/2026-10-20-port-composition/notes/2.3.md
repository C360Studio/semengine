## Enumeration counts

`TestReservedSubjectOverlapMatchesEnumeration` is exhaustive, so it has no seed: every run checks the same inputs.

- Filters: 8,200 (1 to 4 tokens over `graph, ingest, query, mutation, entity, batch, prefix, z, *`, plus `>` last).
- Captured: 425; of these, 35 capture more than one reserved subject, so the first-in-table-order rule decides the
  reported subject. Clear: 7,775.
- Witnesses (concrete subjects of up to 5 tokens over the eight plain tokens) per reserved subject, in table order:
  1, 1, 1, 584 (the mutation family: 8 + 64 + 512).
- Each filter is checked against each of the four reserved subjects in both argument orders (65,600
  `SubjectsOverlap` calls), and all 8,200 filters go through one `Analyze` call as explicit streams. The test fails if
  the filter count is not 8,200 or if the captured, clear or several-captured count is zero, so every branch is shown
  to run. Read from the `-v` log line: `filters 8200: captured 425 (of which 35 capture several reserved subjects),
  clear 7775; witnesses per reserved subject [1 1 1 584]`.
- The reserved list is read from `graph.QueryVerbs()` and `graphmutation.SubjectFamily`; the test fails if a reserved
  subject has no witness over the alphabet, so a verb added later with a new token fails the test until the alphabet
  widens, rather than passing vacuously.

## Choices the design does not spell out

- **The check runs before `Analyze`'s early returns.** It reads only the explicit streams and port facts, so an
  explicit stream that captures a reserved subject is refused even when no component is enabled (the empty
  composition still gets its warning) or when the flow graph cannot be built. The first two rows of the refusal test
  have no components and pin this.
- **Explicit-stream findings carry no port**; component `config`, as the spec says. JetStream-output findings carry the
  instance and port name.
- **Message text:** `stream "<name>" subject filter "<filter>" captures reserved request subject "<subject>"`. The
  enumeration test reads it back with `fmt.Sscanf`, so the stream, filter and subject are all checked.
- **An unnamed output whose first subject derives no name** (for example `>`) is reported with stream `""`.
  Provisioning refuses such a port anyway (`config/stream_bounds.go:378-381`); the finding still names the filter.
- **No fuzz target for `SubjectsOverlap`.** It is exported only inside `internal/flowgraph`, and the enumeration is
  exhaustive over the grammar's classes within the stated bound (plain token, `*`, final `>`, lengths 1-4 against
  reserved subjects of 4 tokens and a family of any length). Malformed subjects (an empty token, `>` not last, a
  token mixing a wildcard with text) go through the existing `validSubjectTokens`, which `SubjectCovers` already uses,
  and overlap nothing.
- **Docs:** `composition/doc.go` names the refusal; `internal/flowgraph/doc.go` names `SubjectsOverlap` beside
  `SubjectCovers`. Ledger rows `composition` and `component/flowgraph` gain their contract clauses and proving tests.
