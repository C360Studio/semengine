# Task 2.2 notes: mutation checks

Each wrong change is the design's ("Proving tests and mutants"), made in a copy under `/tmp/rp-mut/` (outside the
repository) of `pkg/rulepack/identity.go` at commit `27007463b271b058d93c97079514a24192fadddd` (target sha256
`7fe6e03698c1f254edfe3d75fdcfb26c7b6c0e355ad69e3c70bbbe6f2c052cdb` before and after every run). The design cites pin
lines; the table names the pin line and the tree line it maps to. Every run used the same command shape:

```bash
task mutate:check -- -pkg ./pkg/rulepack -test <Test> \
  -file pkg/rulepack/identity.go -mutant /tmp/rp-mut/<ID>.go -expect identity_test.go:<N>
```

Defaults: seed 1, three baseline runs, three mutant runs, one after-run. The reports were written to
`/tmp/rp-mut/<ID>.task.log`, on the developer's machine only. `git status --porcelain` printed nothing after the
runs.

## Choices the design did not spell out

- The test: each mutant names the one test whose assertion its wrong change should break. The bound mutants (M1-M3)
  name `TestValidateIDBounds`; the empty check (M4) and S1 name the pin's `TestValidateID`, which is the only test
  that sends an empty ID or reads message text; the KV-token mutants (M5, M6) name `TestValidateIDKVTokenRefusal`;
  the alphabet and pattern mutants (M7-M10) name `TestValidateIDEveryByte`.
- The expected location: `identity_test.go:40` (wrong or missing error text in `TestValidateID`), `:60` (a byte the
  oracle accepts is refused), `:63` (a byte the oracle refuses is accepted), `:71` (the 65-byte count), `:79` (246
  bytes refused), `:82` (247 bytes accepted), `:97` (no `*errs.ClassifiedError` through `errors.As`).
- M5: the design says "delete the KV call". Deleting `:34-39` leaves the `natsclient` import unused, so the copy
  does not build and the run would be invalid. The copy instead turns the check off in place:
  `natsclient.ValidateKVLiteralToken(packID); err != nil {` becomes `...; false {`, which has the same effect (no
  value is refused by the KV check) and builds.
- M7 uses the spelling `[A-Za-z0-9_=/-]`, as the design says: `/` after `-` would make the range `=-/`, which panics
  when the package loads.
- S1 rewords the `/` message at `:41` from `must use only %s` to `byte outside %s`, keeping `invalid pack_id`.

## Uncovered cases

S1 is a survivor: no test reads the `/` refusal's text past `invalid pack_id`. The design accepts this; only the
substrings the pin test asserts are part of the contract.

## Why there is no `Fuzz*` target

The developer contract asks for a native fuzz target on surface that validates external strings, or the reason it
does not apply. It does not apply here (design, "Generated checks"): every refusal rule in `ValidateID` is per byte
and does not depend on position (`natsclient.ValidateKVLiteralToken` and the pattern), or depends on length alone.
`TestValidateIDEveryByte` places each of the 256 byte values in `"a"+b+"a"`, which decides every alphabet case, and
`TestValidateIDBounds` decides the bound at 246 and 247. A fuzzer can reach no input class those two tests leave
undecided.
