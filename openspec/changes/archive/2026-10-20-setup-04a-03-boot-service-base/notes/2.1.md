## Choices the design leaves to the developer

- **Adapter.** `baseServiceOwner.Observe` reads `BaseService.healthDone` under `BaseService.mu` and lists
  `health-loop` while that channel is open; `Calls` is empty (config design D2's reason). `mustFail` is a
  `BaseService` stopped before Start (design D2). A subtest, `StartedOwnerReportsTheHealthLoop`, shows a started
  service reports the loop and a nil Stop clears it (lifecycle-suite, "Started owner reports its handles"), since the
  suite judges only what is left after a Stop. The suite test is a unit test: `BaseService` needs no NATS.
- **`synctest`.** The D2 tests, `_CustomHealthCheck` and `TestFailingHealthCheckMakesTheServiceUnhealthy` run in
  `synctest.Test` with no NATS client: the clock advances with `<-time.After`, and `synctest.Wait` settles the health
  goroutine before each assertion. Health checks are counted by the check function the test sets
  (`countingCheck`), not read back from `GetStatus`, so the count does not come from the code under test.
- **Healthy direction.** `TestFailingHealthCheckMakesTheServiceUnhealthy` also lets the check pass after 30 s and
  requires healthy again; `_CustomHealthCheck` requires healthy after a passing check; `_HealthMonitoring` has a
  second subtest, a client that was never connected, which must fail the check (the spec's "or when its NATS client
  is not healthy").
- **`WithMetrics` and `WithLogger`.** `TestService_Lifecycle` reads the service-status gauge on the injected registry
  (Stopped, Running, Stopped), so an ignored `WithMetrics` fails it; `TestService_FunctionalOptions` gains a
  "service with logger" subtest (developer contract: a kept option gets the test that fails when it is ignored).
- **pprof tests.** Each test hands `startPProf` a `127.0.0.1:0` listener, except the bind-failure test, which holds
  `net.Listen("tcp", ":0")` as the design says. The in-flight test reads the response body after the release, so a
  Shutdown that cut the connection also fails it, and its cleanups release the handler and shut the server down if
  an assertion fails first.
- **`WireGraphRuntime`.** `projection.NewMutationClient` refuses an empty contract list ("no contracts"), so both D4
  tests pass one valid contract, shaped as `pkg/projection`'s `projectionTestContract`, with its predicates registered
  under `vocabulary.SnapshotRegistry`. Both are integration tests, so the nil-context test shows the refusal with a
  real client, not a nil one.
- **Rapid generator** (design, Generated checks). Objects of 0 to 4 members with keys in generated order (duplicates
  possible) and generated whitespace between tokens; values are strings (`rapid.String`, written with
  `json.Marshal`), numbers from a fixed list (`0`, `-0`, `1.50`, `1e3`, `-2.5E-4`, a 20-digit integer and others),
  booleans, null, arrays and objects, nested to depth 3. Every input is valid JSON, so both assertions (idempotence
  and the `UseNumber` decode oracle) run on every case. The empty and whitespace-only inputs, which the generator does
  not write, are named examples (`{}`).
- **Extra tests beyond D6's list.** `TestTypeNameFromReflect` (kept surface `TypeNameFromReflect`, read by PR 2's
  OpenAPI document code).
