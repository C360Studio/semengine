# Notes: task 2.3 (sensitivity)

Status: every mutant D7's sensitivity table lists, plus one each for the two Codex round 1 regressions (#356, #357),
was run on `66a5d30` (Go 1.26.10). Each outcome is a detection. One test changed (below); no production code changed.

## How the checks were run

Each wrong change was written into a copy of the file outside the repository (`$TMPDIR/mut23/<name>.go`, on this
machine only; each wrong change is spelled out in the table so it can be made again). Every named test is a unit test,
so none needed the by-hand integration overlay (#129). All but one ran through `task mutate:check` with its
defaults (`-runs 3`, `-seed 1`, `-timeout 2m`):

```bash
task mutate:check -- -pkg ./service -test <test> -file <file> -mutant "$TMPDIR/mut23/<name>.go" \
  -expect <file_test.go:N> # or -expect-text '<text>'
```

`-pkg` is `./service` for every row, the `internal/keycase` mutant included: an overlay replaces the file in
whatever package the test builds. The one exception is M2: its wrong change spans two files, which
`task mutate:check` does not take, so it ran by hand through Go's `-overlay` with both copies (below).

"Detection" means what the command prints: all three baseline runs passed, all three mutant runs failed with the
expected line, and the after-run passed. The target file's SHA-256 checksum and the tree fingerprint were the same
before and after each check.
