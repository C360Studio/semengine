## Choices the design does not spell out

- T1-T3 live in `natsclient/request_handler_root_test.go` (unit tests, embedded server through
  `embeddedServerURL`, not inside synctest). T2 and T3 share `heldRequestHandler`, which holds the handler after its
  context ends so the test can show Close has not returned while the handler runs (see the correction below).
- T1 sends its request on the client's own connection (`GetConnection().Request`); the server routes it like any
  other connection's request, and the subscription's registration is already proven by the subscribe round trip.
- T-G4 keeps its name and becomes the two-row table; the row's subject check (`querySubjects`) is kept from the
  sibling test so a reordering of query and mutation registrations fails loudly instead of silently testing the wrong
  loop.
- T6 builds its dependencies with `testDependencies` and sets `deps.Logger`; no new field or option.

## Correction in task 2.2

The 2.1 commit had T2 and T3 check Close's join with `requireJoinPending(..., joinOnOwnedWork, ...)`. With the fix in
place that check failed on a correct client: Close with a live context is still draining the connection, which waits
for the held handler, so its joiner never reaches the client-owned-work wait point that helper observes. The 2.2
commit replaces it with a non-blocking read of Close's result while the handler is held, which no correct client can
fail. On the base both tests still fail first at `the handler's context ending once Close began: not within 10s`, the
line before the replaced check, so the base failures above stand.
