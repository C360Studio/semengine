# 2.2 Subscribe handler root

`Subscribe` now makes its handlers' parent with `clientOwnedHandlerContext` and passes the cancel to `subscribeOwned`
(design D1). The tests are in `natsclient/subscribe_handler_root_test.go` and reuse `request_handler_root_test.go`'s
helpers (`connectedRequestClient`, `heldRequestHandler`, `requireContextEndsOnClose`); `subscribeHeld` adapts the held
handler to `Subscribe`'s handler shape. They use a real connection to an embedded server, not `synctest` (#156).

## How each test fails on the base

Run with the new test file and the unmodified `natsclient/client.go` and `stream.go` at `437bf8b`:
`go test -race -count=1 -run 'TestSubscribeHandlerContext' ./natsclient/`, which exits FAIL.

| Test | Base failure, verbatim |
| --- | --- |
| T1 `TestSubscribeHandlerContextOutlivesSetupContext` | `Error: Received unexpected error: context canceled` / `Messages: the handler's context ended with the setup context` |
| T2 `TestSubscribeHandlerContextEndsWhenCloseBegins` | `subscribe_handler_root_test.go:53: the handler's context ending once Close began: not within 10s` |
| T3 `TestSubscribeHandlerContextEndsWhenCloseBeginsAfterUnsubscribe` | `subscribe_handler_root_test.go:68: the handler's context ending once Close began: not within 10s` |
| T4 `TestSubscribeHandlerContextCarriesOnlyTheMessageTrace` | `Error: Should be false` / `Messages: the header-free message's handler carries trace &{TraceID:d7c4803b12f25bd7a049d7e942640c68 SpanID:f07eaf51521b24ad ParentSpanID: Sampled:true}; setup trace &{TraceID:d7c4803b12f25bd7a049d7e942640c68 SpanID:f07eaf51521b24ad ParentSpanID: Sampled:true}` |

Each matches the design's "Base failure" column: T1 sees `context.Canceled`, T2 and T3 see a context that stays live,
and T4's first handler sees the setup trace.

## Choices the design does not spell out

- T4 checks the traced message's `TraceID` and `SpanID` against the trace injected into its headers, and tags each
  message by its data so a reordering would fail on the data check rather than pass on the wrong message.
- `subscribeOwned` keeps its nil-cancel default (`client.go`, "cancelHandlers, when not nil"). No production caller
  passes nil after this task; the branch is left as it is, and mutant M2 (a nil cancel from `Subscribe`) runs through it.

## After the code review at `21f4cc8`

The reviewer found the nil-cancel default dead and the reason above not holding: M2 can be written as `func() {}` in
place of the cancel, with the same effect. The branch and its "when not nil" wording are removed, `subscribeOwned`'s
doc now says every caller gives a cancel, and M2 was re-run in that form (`notes/2.4.md`, "M2 re-run after review").
The `Subscribe` and `SubscribeForRequests` docs now say the client cancels the owned context "after Close has begun",
as the `transport-client` delta does, not "when Close begins".
