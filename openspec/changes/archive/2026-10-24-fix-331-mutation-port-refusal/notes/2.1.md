# Notes on task 2.1

Base: `b3c4aed` (the design-accepted commit), go1.26.10 darwin/arm64.

## Assertion line

Task 2.2's mutants M1 to M4 all name one line with `-expect`:

- `mutation_port_contract_test.go:110`: the `Fatalf` in the table loop of
  `TestConfigValidateMutationProviderRefusals`, which checks that `Validate()` returns an invalid-class error
  containing the case's literal. The design gave `:99`; the line moved to `:110` because the one `const malformed`
  became a two-name `const` block and the added case sits above the loop.

## Choices the design leaves open

- The added case, `malformed before a non-member`, sits after the two `untyped` cases, so the four cases where the
  malformed input is last stay together and the one where it is first follows them. It carries a two-line comment
  saying why it exists (a refusal naming the last input fails here).
- The two literals use raw strings (backquotes), as the design writes them, so the quotes around the port name need no
  escaping.
