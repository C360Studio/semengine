# Task 3.2: the pins, shown failing before the code

The pins are in `internal/harness/toolcheck/mergegate_test.go`.

- `TestUnitInvocationsPinned` now reads each test task's `vars` as well as its `cmds`. The five pinned tasks
  (`pinnedTestTasks`) and what each must hold:
  - `test:unit`: `PKGS` from `scripts/test-pkgs.sh unit`, then `go test -race -count=1 -cpu 1 {{.PKGS}}`.
  - `test:repeat`: `PKGS` from the `unit` list, then
    `go test -count=5 -cpu 1 -shuffle=on {{.CLI_ARGS | default .PKGS}}`.
  - `test:integration`: `PKGS` from the `integration` list; the three commands as before, with the go test line
    ending `{{.CLI_ARGS | default .PKGS}}`.
  - `test:tools`: `PKGS` from the `tools` list, then `go test -race -count=1 -cpu 1 {{.PKGS}}`.
  - `test:tools:changed`: no `vars`, and the one command `scripts/tools-changed.sh`.
- A task's `vars` must be exactly `PKGS: {sh: scripts/test-pkgs.sh <list>}`, with no other variable.
- `scripts/verify.sh` must list `test:unit`, `test:tools:changed` and `test:repeat`, with `test:tools:changed` after
  `test:unit` and `test:repeat` last.
- `TestCIWorkflowPinned`: the verify job's first `actions/checkout` step must set `fetch-depth: 0`.

## Choices the design does not spell out

- `test:tools:changed` must set no `vars`. The spec says it runs exactly `scripts/tools-changed.sh`. A variable
  would run a command before it, so the pin refuses one.
- The order check, `test:tools:changed` after `test:unit`, has its own sensitivity case ("tool step before the unit
  step"). The proposal's list does not name that case. Without it nothing shows the order check can fail.
- The sensitivity Taskfile is now built from `pinnedTestTasks`, and each case replaces one task's body. The existing
  cases keep their names and expected fragments. Only the fixture text changed, to the new command lines.

## Sensitivity cases

Each is a subtest of `TestUnitInvocationsPinnedSensitivity` that plants one wrong file and expects the violation that
names the task:

- unit reads the tool list
- repeat has no PKGS and defaults to every package
- integration reads the unit list
- tools reads the unit list
- tools:changed runs the tool tests directly (`task test:tools`)
- tool step removed from verify
- tool step before the unit step
- tools command drift (`-race` dropped)

`TestCIWorkflowPinnedSensitivity` has one new case, "fetch-depth dropped".

All 19 subtests of `TestUnitInvocationsPinnedSensitivity` and all of `TestCIWorkflowPinnedSensitivity` passed
before the code was written, so the checker finds each planted fault.
