## Choices the design does not spell out

- The helpers keep their names from `service/component_manager.go`, `isInputNode` and `reachableFrom`, and their
  bodies are unchanged. The `reachableFrom` doc comment now says it walks the graph's edge order. The old comment said
  "edges arrive sorted from the projection", which `FlowPaths` does not assume: it takes edges in the order its
  argument holds them, as the ADDED requirement says.
- Expected values in the tests are hand-written maps, worked out from the requirement's wording, not from the code:
  - `TestFlowPathsKeysEachOrigin`: the graph has no edges, so each origin reaches only itself. `worker` has `stream`
    and `request` inputs only, so it is not a key.
  - `TestFlowPathsWalksDepthFirstInEdgeOrder`: `feed` has an `out-1` edge to `zeta` and an `out-2` edge to `beta`, in
    the order `compareEdges` sorts them (by source port before target). `zeta` continues to `yank`. Depth-first in
    edge order gives `feed, zeta, yank, beta`. Breadth-first would give `feed, zeta, beta, yank`, and a walk by name
    `feed, beta, zeta, yank`, so the case tells all three apart.
  - `TestFlowPathsVisitsEachNodeOnce`: a diamond `a -> b, c -> d` with `d -> a`, plus a second origin `e -> d`; edges
    in sorted order. From `a`: `a, b, d` (whose edge back to `a` ends), then `c` (whose edge to `d` ends), giving
    `a, b, d, c`. From `e`: `e, d, a, b, c`. The second origin shows each walk has its own visited set.
  - `TestFlowPathsOverAnEmptyGraph`: checks non-nil first, then length zero, because a nil map also has length zero.
- Example tests, no generated checks, as design D1 records.
