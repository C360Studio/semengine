## Mutants

the mutant being a copy of the file outside the repository with the one edit shown, and the expected text the test
file's name (`lifecycle_type_test.go:`, `discoverable_reads_test.go:`, `component_test.go:`, `metrics_test.go:`)

expected line and a passing run after; `survivor` is three passing mutant runs with the reach run showing the test

Ten detections, two survivors as the design's table was written; one of the two is now a detection.

- **M4, `TestComponent_Start_BeforeInitialize`.** The test asserted only that `Start` returned an error. With the
  shell's check removed, graph-ingest's own `start` ran and failed on its unconnected NATS client, so the test passed
  for the wrong reason. This task changed its oracle to `assert.ErrorContains(err, "not initialized")`, the shell's
  message, which graph-ingest's code never produces (`grep -n "not initialized" processor/graph-ingest/component.go`
  finds nothing). Rerun: detection at `component_test.go:685`. The design's prediction was wrong for the test as it
  stood; the test, not the design, is what changed.
- **M8, `TestComponent_MetricsAtomic_MessageProcessing`.** Survivor, left as it is: the test counts no input message
  (an in-process create is not one, #302), so `Messages` is zero with or without the mutant and no reading of it can
  tell the two apart. The rule the mutant breaks is proven in the shell's own package (the M8 row above, `:387`);
  graph-ingest's test of counted inputs, `TestIntegration_DataFlowCountsInputMessages`, needs Docker and cannot run
  under `task mutate:check` (#129). The design named the wrong graph-ingest test; nothing in the code is uncovered.

Five rows were first reported `inconclusive: the tree changed during the check` because the writer task edited docs
in the same worktree while they ran; they were rerun on a quiet tree and the verdicts above are the reruns. Lesson:
`task mutate:check` fingerprints the whole tree, so nothing else may edit it while a row runs.
