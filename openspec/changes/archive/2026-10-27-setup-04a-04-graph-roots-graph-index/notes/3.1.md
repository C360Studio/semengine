# Task 3.1: reply envelope, graph-index verbs, ComputeIndexStatus, revision gauges

Choices the design does not spell out (tasks 2.1 and 3.1).

## Reply envelope (`graph/query_response.go`)

- `indexed_revision` has no `omitempty`: a reply states its revision even at 0, so a caller comparing a
  `kv_revision` never reads an absent field as zero by accident. `producer` has none either, since the constructor
  refuses an empty one. `TestQueryResponseCarriesIndexedRevisionAndProducer` checks the zero case on the wire.
- The empty-producer refusal is a plain unexported error (`errQueryResponseProducer`), not a classified one. Its only
  caller is graph-index's own handler (task 4.4), which always passes `graph.ResponderGraphIndex`; the refusal guards a
  programming error, not a request, so no caller branches on a class or code.
- The pin's `UnwrapQueryResponse`, `queryResponseDataKey` and `queryResponseTimestampKey` are not ported (S21).

## Verb table (`graph/query_verbs.go`)

- The eight entries follow graph-ingest's three in the pin's subscription order (`pin:processor/graph-index/query.go:31-80`).
- The existing table test was widened to the full eleven-entry table and renamed
  `TestQueryVerbsDeclareGraphIngestVerbs` -> `TestQueryVerbsDeclareEachRespondersVerbs`; nothing else referenced
  the old name.

## `graph/readiness`

- `ComputeIndexStatus` drops `LastSynced` and the `Revision` string (#110 item 1, S22); the ported tests check
  `IndexedRevision` and `TargetRevision` where the pin checked `Revision`. The stale `revlag.Watermark.Indexed` doc
  (S23) is rewritten as "the watermark's floor".
- One case is added beyond the pin's oracles: a floor above the target reads no lag (the spec's "never below zero").
- `NewRevisionGauges(subsystem)` is the design's proposed name (D10), built on `NewGauges`; no option type (S24).
  `Register` registers the two revision gauges after the shared five through `metric.RegisterOrGet`; `Set` writes
  them only when present, so a backlog set never publishes a revision. Caller: the follower (task 3.2).

## Capture check (#16, design D17)

Adding the eight verbs trips `composition`'s generated check, not `Analyze` itself:
`TestReservedSubjectOverlapMatchesEnumeration` fails with `no concrete subject over the alphabet matches reserved
"graph.index.query.outgoing": widen the alphabet`. Its alphabet (`composition/reserved_test.go:118`) holds only the
tokens of graph-ingest's and the mutation family's subjects. Widening it by nine tokens grows the enumeration from
8^5 concrete subjects to 17^5, so the fix is a design choice (a wider alphabet, a smaller bound, or one token standing
for the verbs) and is left to the orchestrator, as the brief directs. No workaround is applied.
