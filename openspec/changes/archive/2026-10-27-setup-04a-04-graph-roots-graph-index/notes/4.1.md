## Configuration

- Ports follow ruling K (#91 comment 6062681355), applied to graph-index by the owner (PR #414 comment 6431777824):
  a missing `ports` key takes `DefaultConfig()`'s ports, and a present `ports` block is used as written. An empty
  `inputs` or `outputs` list no longer takes the default list for that side, as it did at the pin
  (`pin:processor/graph-index/component.go:132-175`); `Validate` refuses it. `ApplyDefaults` is graph-ingest's shape
  (`processor/graph-ingest/config.go`). The first version of this task kept the pin's merge under Bounded port scope.
  - Tests: `TestConfigWithoutPortsTakesDefaultPorts` (`{}`, `{"workers": 2}`, `{"ports": null}`) and
    `TestConfigPresentPortsUsedAsWritten` (an explicit `"inputs": []`, an explicit `"outputs": []`), both through
    `CreateGraphIndex` from JSON. On 7d4988a the second failed by assertion in both cases ("built with inputs … want
    only the configured ports, refused: at least one input port required", and the output form); the first passed,
    since a missing key already took the defaults. `task mutate:check`, `ApplyDefaults` filling each empty side from
    the defaults again, `-expect-text 'want only the configured ports'`: verdict detection (3 of 3 mutant runs failed
    with the expected line, the after-run passed; logs under `$TMPDIR`, local only).
  - Consumer risk, measured 2026-10-26 by reading each repository's tarball at the stated SHA: no consumer config sets
    an empty `inputs` or `outputs` list for graph-index, so no consumer changes. semconnect (`d0d06e00`):
    `deploy/semstreams.json` and `conformance/compose.semstreams.config.json` give graph-index one input and four
    outputs. semboids (`8c03cc53`): `configs/flock.json` the same. semsource (`e4febc0d`): `cmd/semsource/run.go:800-810`
    sets no `ports` key, so it takes the defaults as before. semteams (`ab480702`): registers graph-index
    (`internal/runtimecatalog/components.go:64`); its configs (`configs/flow-bootstrap.json`,
    `configs/e2e-flow-bootstrap.json`) carry no graph-index entry. Every empty port list in these repositories' JSON
    belongs to another component (`graph-query` outputs; semboids' `sim` inputs).
- Strict-decode and port-resolve errors are classified invalid (`errs.WrapInvalid`); the pin wrapped the unmarshal
  error unclassified. A configuration the factory refuses is invalid configuration whatever the cause.
- `coalesce_ms`, `startup_attempts` and `startup_interval_ms` are not range-checked, as at the pin.
- `maxGraphIndexWorkers` is renamed `maxWorkers` (the package name already says graph-index).

## Metrics

- `key = readiness.KeyGraphIndex` names the registration, the logger, the metric service of every
  `metric.RegisterOrGet` call, and (task 4.3) the follower's `Config.Key`. The subsystem is
  `strings.ReplaceAll(key, "-", "_")`, the same expression `graph/follower/follower.go:161` uses for the readiness
  gauges. That is the derivation written twice; a `readiness` helper would make it one, but it adds an export to
  approved code stop 1, so it is left as an open question rather than done here.
- Seven collectors, the pin's names with namespace `semengine`; the readiness gauges are the follower's (D10). A
  `RegisterOrGet` error fails construction; the pin discarded registration errors.
- Only the two record helpers with logic are ported (`recordReindex`, `recordReconcileOperation`). The pin's other
  five were one-line `Inc` wrappers; task 4.2 writes to the collectors at its call sites or adds a helper as it
  needs one.
- `watch_events_total{event_type}` stays: task 4.2's `Deliver` sees `Entry.Deleted` and can record update or delete.
- The guard named for this task, "the metric-registry guard in `task lint`", is `TestNoProcessGlobalRegistration`
  in `internal/harness/contract/promglobal_test.go`, which `task test:unit` runs; `task lint` has no metric guard.
