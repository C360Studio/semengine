# Task 4.2: the index write path

Choices the design (D2, D3, D7, D8, D12, D13) does not spell out. Tests and dropped pin tests: `notes/2.3.md`.

## Files

`index.go` (bucket acquisition, pool, `deliver`, lane apply, failed set, repair, plan and apply, delete),
`owner_reconcile.go`, `incoming_index.go`, `predicate_index.go`, `predicate_codec.go`, `key_validation.go`,
`revision_coalescer.go`, and the write half of `name_index.go`. The read-side helpers of the pin's files (key decoders,
forward filters, `validateKVPrefix`, `uniqueSortedStrings`) wait for task 4.4, which has their callers.

## What task 4.3 must connect

The write path is methods on `Component`, wired in this order (the test helper `startIndex` in
`index_integration_test.go` does exactly this, and 4.3 moves it into `Start` and `Stop`):

1. `follower.Open` with `Deliver: c.deliver`, `Failed: c.failedTotal`, the config's startup keys and `key`.
2. `c.openIndexBuckets(ctx)`: the five index buckets through `kvcatalog.EnsureCatalogBucket`, and the
   `ENTITY_STATES` reader the lanes read current state from.
3. `c.startIndexPool(poolCtx, f)`: the keyed pool (D7) and, when `coalesce_ms` is above zero, the coalescer.
4. Goroutines joined by `Stop`: `f.Run(runCtx)`, `c.coalescer.run(runCtx)` when non-nil, `c.repairLoop(runCtx)`.
5. `Stop`: end `runCtx` and join the three; then `c.pool.Shutdown(ctx)` with `poolCtx` still live, so accepted work
   is written (`TestStopWritesAcceptedWork`); then end `poolCtx`. graph-ingest orders its pool the same way
   (`processor/graph-ingest/component.go`, `cleanup`).

`poolCtx` must outlive `runCtx`: a lane writing under an ended context fails its writes and marks the entity failed.

## Choices

- The coalescer is in the `Run(ctx)` shape (`background-work` spec): `run(ctx)` holds the ticker on the caller's
  goroutine. The pin started its own goroutine in the constructor and had `Close` (S11 drops it). Keys pending when
  `run` returns are not handed over; their revisions stay incomplete, which nobody reads after `Stop`.
- `OnPanic` marks the entity failed (D7) and also completes the work's revision, as a failed write does at the pin
  (`pin:…/component.go:1373-1381`): the failed set withholds readiness, and a revision left pending would pin the
  watermark after the repair. Repair work carries revision 0 and completes nothing, as at the pin.
- `deliver` counts `DataFlow` (`Lifecycle.CountInput(e.Bytes)`) and `watch_events_total{event_type}` for every
  entry, before coalescing. The pin counted messages and bytes at index writes; the spec counts deliveries.
  Index-write helpers no longer touch `DataFlow`. `Lifecycle.CountError` replaces the pin's `errors` counter, at the
  outcome boundary only (see "Code stop 2 fixes" below; the first version counted each failed operation).
- A failed submit happens only when the context ended or the pool is stopping: logged at Debug then, Warn otherwise.
- The tree's `graph.UnmarshalEntityState(key, …)` already refuses a value naming another entity
  (`noncanonical_entity_id`). The pin's identity branch is kept on that reason: reset latched, entity failed, and the
  revision withheld; any other refusal latches reset and completes, as at the pin.
- Bucket acquisition ensures the five fixed buckets by name. The pin's ownership pre-pass over the output ports
  re-checked a dynamically supplied `Config`; here every `Component` is built through `CreateGraphIndex`, whose
  `Config.Validate` refuses any output that is not one of the four index buckets (`TestConfigValidateOutputs`).
- S5 done (optional): the outgoing plan is `[]graph.OutgoingEntry`, not `[]map[string]interface{}`; the stored JSON is
  the same. The pin's `json.Marshal` checks on values that cannot fail to marshal are dropped.
- `deleteFromIndexes`' always-false `prefix` branch is dropped; `slices.Sort` + `slices.Compact` replace
  `uniqueSortedStrings` there.
- `indexEntity` (the pin's `processEntityUpdateFromData`) and `processWork` are renamed; the six S9 writers and the S11
  surface are not ported.

## Code stop 2 fixes (#424, #425, #426)

Codex's review of `d6bd27e` (PR #414 comment 6439317881). Each test was written first and run against `d6bd27e`'s
production files (the tree's own, or `git show d6bd27e:<file>` copied in with a SHA-256-checked backup and restore);
each failed by assertion as quoted.

- **#424, inputs.** `Config.Validate` resolves each input and requires a `component.KVWatchPort` on `ENTITY_STATES`
  with no `keys` and no `history`, the follower's `WatchAll`; anything else is refused naming the port. `DeclarePorts`
  and `CreateGraphIndex` share `resolveConfig`, so one check covers both. Not added: a limit of one input. Two
  `ENTITY_STATES` watches under two names describe the source correctly, and the review did not ask for it.
  - `TestConfigRefusesInputsTheFollowerDoesNotRead` (unit). On `d6bd27e` all five cases failed: "CreateGraphIndex(…)
    built advertising [{Name:unread_feed … Config:{Bucket:OTHER_STATES …}}], though the follower reads only a full
    watch of ENTITY_STATES", and the same for a key filter, history, a KV read and a NATS subject.
- **#425, ErrorCount.** The nine `CountError` calls in the operation helpers (`reconcileOwnedRows`,
  `writeOutgoingIndex`, `updateAliasIndex`, `deleteFromIndexes`) are gone; those failures stay counted in
  `reconcile_operations_total` and `kv_operations_total`. `markEntityFailed` counts once when an entity enters the
  failed set, beside `write_failures_total`, so retries inside `retryIndexWrites` and repair passes that fail again
  add nothing. A reset that holds its entity (noncanonical key or value) is counted by that mark, not a second time;
  the unreadable-value reset, which holds no entity, counts where it latches. "Each reset" is read as each reset
  graph-index raises, not only the first that latches: a later bad entity is a new event an operator should see.
  - `TestErrorCountCountsOutcomesNotOperations` (integration, three subtests). On `d6bd27e`: "ErrorCount = 3 after one
    entity's writes failed on all 3 attempts, want 1"; "ErrorCount = 0 after one noncanonical value latched reset,
    want 1"; "ErrorCount = 0 after one unreadable value latched reset, want 1".
- **#426, alias skip.** New counter `semengine_graph_index_aliases_skipped_total`, no label: the code has one skip
  reason (not a valid NATS KV key), and the alias value is unbounded, so it is not a label. Registered through
  `metric.RegisterOrGet` with the other seven. The integration harness now hands the component a logger writing to a
  locked buffer (`logBuffer`), so a test can read what it logged; every test's log output goes there instead of stderr.
  - `TestUnsafeAliasSkipIsLoggedAndCounted` (integration). On `d6bd27e`: "semengine_graph_index_aliases_skipped_total
    = 0, want 1". It also asserts the warning names entity and predicate, `alpha-1` is written, and the outgoing and
    predicate rows are stored.
