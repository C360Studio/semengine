# Task 3.1: tests that pass on the base

Base: `08d3fc7`, production code unchanged. None of the tests below sets `consumeStream`, `waitForStreamInput`,
`watchEntityStates` or `subscribeRequests`. Every test below passed on the base, once in the full package run and 3 of
3 in the `-count=3` run (commands at the end).

## The pause

`pause_integration_test.go` adds `pauseOnRecord`, the probe 1.1 handler without its stack and record counters. It is
given as `deps.Logger`. On each record whose message matches, it closes `entered` the first time and blocks until
`Release`; every other record is dropped. Each test registers `defer pause.Release()` after `defer owner.finish`, so
the release runs before Stop (`notes/1.1.md`). Every record waits on the release, not only the first: with eight
lanes, several inputs of a backlog can be held at once, and all of them stay unacknowledged.

## Each test

- `TestConfigAckWaitAndHeartbeatInterval` (moved from `config_fields_test.go` to
  `config_ack_wait_integration_test.go`; `bindEntityStream` is deleted). It proves that the port's ack_wait reaches
  the consumer and that a refused pair creates no consumer. Each accepted case starts graph-ingest on the fixture and
  reads `Config.AckWait` from the server's info for `graph-ingest-entity-wildcard`. The heartbeat interval is still
  read from `ingestDeliveryTiming`, as before. In the refused case, Start fails with "heartbeat interval 1.5s
  exceeds" and the ENTITY stream lists no consumer. The negative-wait case did not change.
  Sensitivity: an overlay that creates the consumer with `AckWait: 0 * ackWait` (`go test -overlay`, tree
  untouched) fails both 2 s cases ("= 30s, want 2s"), the refusal, and the no-consumer check.
- `TestIntegration_ReadinessEnvelope_BacklogIsNotReady` and `_BootstrapCompleteWithBacklog`. They prove that no
  envelope reads caught-up while an input is held, and that `bootstrap_complete` is true with a backlog standing. They
  pause on "Entity ingested". The held inputs are ack-pending, which readiness counts in the lag
  (`readiness.go:306-309`). The barrier wait is now `pause.awaitEntered` with a 30 s bound. Before, it was bounded
  by the test's context.
- `TestIntegration_Settlement_LongApplyIsNotRedelivered`. It proves that a held application past the 2 s ack_wait is
  not redelivered. The test pauses on "Entity ingested". `heldApplyBucket`, `progressCountingMsg` and the in-progress
  count are removed (design D2). The oracle consumer and its three deliveries are as before. Observed:
  `{Deliveries:1 AckFloor:0 AckPending:1 Redelivered:0}`, oracle `[1 2 3]`.
- `TestIntegration_Settlement_ProcessKilledBetweenApplyAndAck`. It proves that an input applied and never
  acknowledged is redelivered and applied once. The first helper's logger handler pauses for good on "Entity
  ingested". `heldWriteBucket` is removed. The helper's name is now `graph-ingest-held-after-apply` (formerly
  `graph-ingest-guard-write-held`). `startSettlementIngest` gains a `handler slog.Handler` argument. Its `wrap`
  argument and the `consumeStream` branch stay for `TestIntegration_Settlement_FailedGuardWriteIsRedelivered`, which
  D3 deletes in 4.2, and go with it.
- `TestRequestBeforeStartCompletesIsRefused` replaces `TestFailedRegistrationRunsNoRequestWork`, and its doc comment
  names "graph-ingest refuses request work until Start completes". Each case pauses Start's goroutine on "query
  handlers registered" or "mutation handlers registered" and sends a real request with `RequestClassified`. The
  request must be refused. Then the test releases the pause, waits for Start to return nil, and sends the same
  request, which must be served (the query case gets the seeded entity; the mutation case's entity is stored).
  - The query case seeds its entity while Start is held. `c.entityBucket` was written before the record, and
    `pause.entered` orders the read after that write.
  - Not in the design's words: `errs.ErrNotStarted` does not survive the wire. `natsclient.classifiedFromHeader`
    rebuilds a new error from the class, code and message. The test therefore asserts a transient class, an empty
    code, and a message that contains `errs.ErrNotStarted.Error()`. These are the facts the requirement's "the
    requester receives the refusal as a transient error with no code" names. The sentinel match on the handler's
    return is not observed directly.
  - M2 sensitivity: dropping the `startCompleted` check in an overlay of `component.go` fails both cases ("request
    before Start completed = {...}, want a refusal").
  - Note for 4.2: `task mutate:check` refuses this test as inconclusive, because the test is integration-tagged
    ("the name selected no test; a test in a file built only with the integration tag is not run by this command").
    M2 was run here with `go test -tags integration -overlay`.
- `newSuiteOwner` / `suiteOwner.Start` (`lifecycle_adapter_test.go`) no longer set `consumeStream`. After a Start
  that returned nil, it wraps each `c.consumers[i].handle` in `countedConsumeContext` and counts one "consumer bind"
  per handle. Only `cleanup` reads `c.consumers` (`component.go:575-585`), and the suite makes one call at a time.
  Binds made by a failed Start, and the drains of its rollback, are no longer counted. The suite reads `Calls` only to
  check that a Stop after a failed Start makes no call (`lifecycletest.go:317`), so that check is unchanged.
  `TestGraphIngestLifecycleSuite/StartedOwnerReportsItsHandles` keeps its counts: binds above 0, one drain per bind,
  no force stop.
