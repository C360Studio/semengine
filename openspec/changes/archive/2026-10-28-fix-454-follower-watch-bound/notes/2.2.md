# Task 2.2 notes

Choices the proposal does not spell out.

- **A `Stop` error when the budget runs out.** The tolerated `Stop` errors (`ErrBadSubscription`,
  `ErrConnectionClosed`, `ErrConsumerNotFound`) are tolerated because a closed delivery shows the watch was already
  gone. When the delivery never closed that reading does not hold, so `stopWatch` returns `errWatchDeliveryOpen`
  joined with any non-nil `Stop` error, as `natsclient`'s `keysByFilter` does (`natsclient/kv.go:716`). With a nil
  `Stop` error it returns `errWatchDeliveryOpen` alone. The unit test covers the nil case only.
- **Names.** `watchDrainBudget` and `errWatchDeliveryOpen` are unexported: `Run`'s one caller,
  `processor/graph-index/component.go:272`, logs any non-nil error and does not branch on it.
- **Library claims in the doc comments** cite nats.go v1.54.0 source lines (`jetstream/kv.go:1356-1368`,
  `nats.go:3830-3834`), checked against the module cache, and say the window has not been reproduced against nats.go;
  the bound is proven only on the scripted watcher.
- **Mutation checks** (`task mutate:check`, test `TestStopWatchGivesUpOnADeliveryThatNeverCloses`), both made in
  copies outside the repository:
  - The bound removed (`context.WithCancel` in place of `context.WithTimeout(..., watchDrainBudget)`):
    detection, `-expect-text "deadlock: all goroutines in bubble are blocked"`.
  - Twice the budget (`2*watchDrainBudget`): detection, `-expect follower_test.go:85` (the elapsed-time assertion).
