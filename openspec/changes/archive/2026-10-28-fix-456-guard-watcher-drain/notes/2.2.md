# Task 2.2: the bounded drain

`stopEntityStateGuardWatcher` now takes the sweep's context and returns an error. It drains under
`context.WithTimeout(context.WithoutCancel(ctx), guardWatchDrainBudget)`, 5 s, the shape of `graph/follower`'s
`stopWatch` (PR #455), and returns `errGuardWatchDeliveryOpen` when the budget runs out.

Choices not spelled out in the proposal:

- On the cancelled path the context's error and the drain's error are joined with `errors.Join`, so a caller can match
  either with `errors.Is`; the test checks both.
- On the marker path the drain error is wrapped as its own step, "stop ENTITY_STATES snapshot watcher", so the log line
  says the snapshot was read in full and only the stop failed.
- `Stop`'s error is still discarded, as on base. The follower reports it because its `Stop` error can say more than
  "already gone"; here the sweep's outcome is decided by the marker and the drain, and base never read it.

`TestEntityStateGuardGivesUpOnADeliveryThatNeverCloses`, `TestEntityStateGuardDeliberateStopDrainsToCloseWithoutMisclassification`
and `TestEntityStateGuardFailureIsReturned` pass under `-race`.
