- `kvwatch.DrainBudget` is exported beside `kvwatch.Stop` and `kvwatch.ErrDeliveryOpen`. The follower's
  `TestStopWatchGivesUpOnADeliveryThatNeverCloses` checks `watchDrainBudget` against the spec's 5 s, so the follower
  keeps `watchDrainBudget` as `kvwatch.DrainBudget`: one spelling of the budget, and the follower test asserts what it
  asserted before.
- The follower keeps `errWatchDeliveryOpen` as the same value as `kvwatch.ErrDeliveryOpen`, and `stopWatch` wraps
  `kvwatch.Stop`'s error with `%w` ("follower: stop the ENTITY_STATES watch: ..."), so `errors.Is(err,
  errWatchDeliveryOpen)` at `follower_test.go:81` still matches.
- `kvwatch.Stop` returns the watch's own `Stop` error unwrapped, and on the timeout path
  `errors.Join(ErrDeliveryOpen, stopErr)`; each caller adds its bucket, so no text is said twice.
- `natsfixture.AwaitNativeDeliveryBlocked` takes its bound as an argument (the follower passes its `waitBound`),
  since the bound was the follower test's own constant.
- The kvwatch bound test is `TestStopGivesUpOnADeliveryThatNeverCloses`. Mutation check: `DrainBudget` set to 6 s,
  `task mutate:check -- -pkg ./internal/kvwatch -test TestStopGivesUpOnADeliveryThatNeverCloses -file
