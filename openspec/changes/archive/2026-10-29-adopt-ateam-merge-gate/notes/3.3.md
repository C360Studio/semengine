# Task 3.3 notes

- The smoke test is `internal/harness/toolcheck/mergewrapper_test.go` (`TestMergeCheckWrapper` and its sensitivity
  test). It runs the wrapper through `ATEAM` and through `ateam` on `PATH`, for exit statuses 0, 1 and 2. In the `ATEAM`
  runs a decoy `ateam` stands first on `PATH`, so a wrapper that ignores `ATEAM` never runs the real binary (which
  would read GitHub) and fails on the decoy's arguments.
- Activity types are checked as an exact set in both files: a missing type and an extra one both fail. The spec
  delta's ci.yml clause ("lists other pull_request types than ...") reads as the exact set; adding `edited` to `ci.yml`
  would rerun Verify on every description edit, which design D1 moved the merge check out to avoid.
- The runner label rule ("Pinned runner image", which names the CI workflow) is applied to `merge-check.yml` too, and
  the old runner-label plants for the `merge-check` job moved there.
- `merge-check.yml` must trigger on `pull_request` alone (a `push` or `pull_request_target` trigger fails), and its
  gate step is found as the step whose `run` calls `scripts/merge-check.sh`; its `ATEAM_REQUIRED_CHECKS` must be
  exactly `Required,Merge check`.
- Not checked: the job's display name (`Merge check` on a non-draft). A rename fails loudly (the ruleset requires a
  check that never reports), so the test does not pin it.
- `TestUnitInvocationsPinned` is unchanged. The `required` step plant "step reads verify alone" was dropped: with
  `verify` the only needed job, `${{ needs.verify.result }}` is no longer a hole by results; the plant "by its source"
  still requires the step to read `needs.*.result`.
