# Task 2.3 notes

`TestSpecTaskWiring` checks both Task entries with one function, `taskWiringViolations(taskfile, task, want)`, the
retired `specCheckWiringViolations` given a task name and its commands. Beyond the spec's four cases (check line
removed, the two swapped, `ignore_error` on the task, `spec:queue` running the retired script), three more are planted:
a third command, a command written as a mapping rather than a plain string, and a missing task. They cover the
checker's other branches, so each one is shown able to fail.

The real-tree subtest was shown able to fail: with `spec:queue`'s command set back to the retired script in a backed-up
`Taskfile.yml` (SHA-256 `05cfbc1a…` before and after), it failed with
`Taskfile.yml: spec:queue: command 1 is "scripts/openspec-queue.sh", want "ateam state spec-queue"`.

The planted case spells `scripts/openspec-queue.sh`, as the spec's scenario does, so a `git grep openspec-queue`
outside the archive also finds `specwiring_test.go`. That is a fixture, not a caller.
