## Choices the design leaves open

- **Absorbed and renamed.** `TestRunRejectsNilContext` became `TestRunRefusesNilContext`, which adds two checks: the
  source is not touched, and the refusal starts nothing (the view's first real `Run` runs). `TestRunLifecycleGuards`
  became `TestRunOnce`, with its checks unchanged as the first subtest and two more subtests: after a lost watch and
  after a watch that could not open. In both, the refused `Run` returns `ErrViewStopped` and opens no watch. The table
  in `notes/2.1.md` still uses the old names; it records what task 2.1 did.
- **"No goroutine left"** is checked by `synctest.Test` itself. It fails with a deadlock if a bubble goroutine is still
  blocked once the test function returns. `TestRunLeavesNothingBehind` attaches its subscriptions with
  `context.Background()`, so the end of `t.Context()` at the end of the bubble cannot end a leaked delivery goroutine
  and hide the leak. Only `Run`'s stop can end them.
- **`TestRunContextEndIsAStop`** runs its 200 views one after another in one bubble. Before releasing the hook, it
  checks that the update channel is closed, so every iteration is the both-ready case the scenario names. Run's
  `select` picks either ready case at random, so a view that counts a close as a loss passes one iteration with
  probability 1/2, and all 200 with probability 2^-200.
- **`TestRunOpenFailure`** calls `Run` on the test goroutine, so its return means nothing of `Run`'s is running. It
  uses its own `refusingSource`, which returns a sentinel error, so the test can check "returns that error" with
  `errors.Is`. A second subtest covers the case design D2 states and the scenario does not: a `WatchAll` that fails
  after the context ended is a stop (`context.Canceled`, then `ErrViewStopped`).
- **`TestDecodeOncePerWrite`** needs its own decode function. `newHarness` now calls `newHarnessDecoding(t, decode)`;
  nothing else in the harness changed.
- **`TestRunLostWatchFailsClosed`**, already in the tree, now also checks that `Get` matches `ErrNotReady`, that a
  `Subscribe` after the loss is refused with `ErrNotReady` and `ErrWatcherLost`, and that the watch was stopped once.
- **Product tests** use their own fake bucket in package `graphview_test` (one watch, closing its channel when the
  watch's context ends, as nats.go's does). They do not use the internal harness, so they call only what a product
  can call. The four sentinels the inventory lists as unread by name (`ErrNotReady`, `ErrViewStopped`,
  `ErrKeyNotFound`, `ErrAlreadyStarted`) are matched there with `errors.Is`, as a product would match them.

set (`view.go`, `removeSub`), and `terminate` overwrites the reason, with only the close of `done` kept once

it failed all three runs at `run_test.go:219` (`expected: "context canceled"`). Each half alone survived three runs,
as design D6 says. Task 3.3 records the D6 mutation checks.
