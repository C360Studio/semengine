# Task 2.2: `pkg/lifecycle` runWatchLoop stops through `kvwatch.Stop`

## Tests

- `TestIntegration_WatchEventsCallbackErrorLeavesNoWatchDelivery` (`pkg/lifecycle/manager_integration_test.go`):
  600 entities matching the fixture workflow, above nats.go's 256-entry updates buffer. The callback holds the first
  event until `natsfixture.AwaitNativeDeliveryBlocked`, then returns an error; `WatchEvents` returns an error that
  `errors.Is` the callback's, and `natsfixture.AwaitNoStacks` over `natsfixture.NativeDeliveryStacks` finds no
  delivery left. One run: the callback's error returns from the loop at once, so every run stops a backlogged watch.
- `TestIntegration_WatchEventsContextEndLeavesNoWatchDelivery` (same file), 10 cycles on one bucket: the callback
  blocks on `<-ctx.Done()` and then returns nil, the test cancels once the delivery is blocked, `WatchEvents` returns
  `context.Canceled` (from the loop's own `ctx.Done` arm), and no delivery is left.
- `TestLifecycleWatchReportsAFailedStop` (`pkg/lifecycle/watch_atomic_bootstrap_test.go`), through both `Watch` and
  `WatchEvents` under `synctest`: the scripted watcher's `Stop` returns a sentinel and closes its updates; the
  returned error `errors.Is` both the callback's error and the sentinel.

## Test watcher

`lifecycleAtomicWatcher` gets `closeUpdates` (a `sync.Once` around `close`) and a `stopErr` field; `Stop` calls
`closeUpdates` and returns `stopErr`. The lost-watch close in `TestLifecycleWatchTransportCloseIsLocalAndLaterSubscriptionWorks`
calls `closeUpdates`. No test sends on a watcher after its `Stop`. Unit run time `go test -count=1 ./pkg/lifecycle/`:
0.461s before, 0.355s after, so no test waits out `kvwatch.DrainBudget`.

## Choices the task left open

- **Join only on a stop error.** `runWatchLoop` uses a named return and a deferred `kvwatch.Stop`, joining
  `fmt.Errorf("lifecycle: stop the watch: %w", err)` only when it is non-nil, as `pkg/graphview`'s `Run` does. The
  primary error is returned unchanged otherwise, so its text and `errors.As` targets are as before.
- **Context passed to `kvwatch.Stop`.** The watch's own `ctx` (the caller's). On a callback or decode error it may still
  be live while the delivery drains; the drain is bounded by `kvwatch.DrainBudget`, counted after the watcher's `Stop`
  returns.
- **Docs.** `Watch` says it returns after nats.go has closed the watch's delivery, for at most 5 s (`internal/kvwatch`'s
  `DrainBudget`) after the watcher's `Stop` returns (corrected after review; first written as "after ctx ends"), that a
  stop failure is joined to the error, and names the two integration tests as the library-claim evidence. `WatchEvents`
  says its error carries a stop failure. No exported alias of `kvwatch.ErrDeliveryOpen`; no exported signature changes.
- **The unit case is the stop-error join only.** That a fake watcher is drained is not separately asserted; the
  integration tests prove the drain against nats.go.

## Uncovered

  deferred stop as the callback error.
- The lost-watch path (updates closed while ctx is live) against nats.go is not driven here.
