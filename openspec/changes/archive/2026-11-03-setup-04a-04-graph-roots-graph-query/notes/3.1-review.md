## The reply walks

`TestRepliesMatchTheirTableEntries` is in `processor/graph-index/query_integration_test.go` and
`processor/graph-ingest/query_verbs_integration_test.go`. Each walks `graph.QueryVerbs()`, sends a real request for each
of its responder's rows, and decodes the reply by the row, refusing unknown fields. A row with no request in the test
fails.

- **Re-encoding, beyond the finding's fix.** Refusing unknown fields does not catch a `Reply` with extra fields:
  `predicate`'s reply decodes cleanly as `CompoundPredicateData`. So the decoded body must re-encode to the same JSON.
- **Optional keys on the wire.** The ingest request asks for one absent ID and a page of one, so `missing` and
  `next_cursor` are present and a type without them fails.
- **`replyMatchesEntry` is in both test packages,** and task 3.x's `TestGraphQueryRepliesDecodeByTheTable` may want a
  third. Two short copies did not earn a harness package.
- **Not proved.** A key a reply omits under `omitempty` cannot be held; the walk sees one reply per verb.
