## Choices the design leaves open

- **The table has no graph-query row until 3.2,** so the production `Start` subscribes nothing. The lifecycle suite and
  the failed-cleanup test run the component's own walk (`subscribeVerbs`) and `cleanup` through the shell, over rows the
  test names. `subscribeVerbs` takes the rows and handlers as arguments, which is no hook on a running component: the
  production `Start` passes `graph.QueryVerbs()` and `queryHandlers()`. `TestStartThroughTheTable` runs the production
  `Start`. When 3.2 adds rows, the suite can start through `Component.Start` for its `factory`.
- **A cleanup begins every drain,** where graph-index stops at the first error. A handler outlasting the context would
  otherwise keep the other verbs answering. The failed-cleanup test proves it with the idle verb.
- **Comparing the input port.** Name, required and everything under `config` must match. `timeout` (but for the resolved
  default `1s`) and `retries` on the input are refused because nothing reads them, stricter than the pin, which checked
  kind, subject and interface. The
  interface stays `graph.query` v1 as at the pin (`pin:processor/graph-query/component.go:84`; `composition` reads it).
  `description` and `external` stay the operator's: they change nothing graph-query serves.
- **`query_timeout_ms: 0` means the default,** as graph-index's optional numbers do; negative is refused, and so is a
  value that does not fit a duration (`notes/3.1-review.md`). No other upper bound: a value above natsclient's handler
  budget ends at that budget, and refusing it would make the operator predict a limit a deployment can change.
- **`query_timeout_ms` has no reader yet.** 3.2 adds it, with `TestQueryTimeoutIsRead`.

## Generated checks

Named examples suffice for the shape refusals: each case is one field off the one accepted port, and the fields do not
interact, since acceptance is exact equality. `FuzzDeclarePorts` covers the bytes: it never panics, and anything accepted
is the one port. Its seeds run with every `go test` of the package. Exploration, apart from that: `go test -run '^$' -fuzz
FuzzDeclarePorts -fuzztime 20s ./processor/graph-query/`, exit 0, 3,421,124 executions, no failure.
