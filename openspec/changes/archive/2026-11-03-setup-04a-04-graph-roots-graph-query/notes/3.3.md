## Choices the design leaves open

- **`data` is `json.RawMessage` in `graph.NewQueryResponse`, through `json.Marshal`.** Orchestrator decision replacing
  this note's earlier choice of a hand splice ("complex where plain would do"). The marshal compacts the entity verb's
  JSON and HTML-escapes it, which replies graph-ingest has already marshalled in Go cannot show, so `data` is "the
  entity verb's JSON as it came, not re-decoded into a struct", not "bytes unchanged". Forwards stay byte for byte.
  The stub row that showed a spaced, escaped reply surviving is gone; `entity JSON is not re-decoded` keeps key order,
  a field `graph.ExactEntity` does not know and a number's spelling. `envelope` replaces `envelopeAround` and
  `envelopeEdges`.
- **An entity reply that is not JSON** fails that marshal and is refused transient `internal`, naming the subject,
  since it cannot sit inside an envelope. An empty reply takes the same path over a real connection (`an empty entity
  reply`): a nil `json.RawMessage` would marshal as `null`, and the row is what holds this at the pinned versions.
  Nothing else about the entity reply is checked, as on a forward: `{}` from the entity verb would be a success. Real
  ingest does not send it.
- **A request that does not decode** is `invalid_request` from `graph-query`, with no downstream request, on both verbs.
  It has to read `alias` or `direction`. Everything else about the request is the index's: an empty alias, a bad
  `entity_id`, a `min_revision` of the wrong type.
- **What counts as an error.** Orchestrator decision replacing this note's earlier choice, which left a broken reply out
  of `ErrorCount` and so hid a broken responder from operators. `CountError` runs whenever `graph-query` itself refuses
  because no usable answer arrived, once per request: no answer (`ask`), and a reply that does not decode, names no
  `producer` or is not JSON (`brokenReply`). A responder's classified refusal and a caller's `invalid_request` count
  none. `TestComposedVerbsCountAsForwardsDo` states the running total as a literal at each step.
- **`forwardRows` keeps the four forwards.** The brief says to extend it, but `TestForwardPassesBytesBothWays`,
  `TestForwardsShareNothingBetweenRequests` and `TestForwardCountsRequestsAndUnansweredOnes` send bytes the two new verbs
  would read and refuse. `declaredRows` is `forwardRows` plus the two, and `TestGraphQueryServesExactlyTheDeclaredVerbs`
  compares the table with a literal list of six. These also run on all six: `TestForwardedRefusalKeepsClassCodeDetail`,
  `TestNoRespondersIsTransient`, `TestQueryTimeoutIsRead`, `TestHandlerBudgetEndsAForward`, and the two lifecycle tests
  that take rows.
- **Keys match case-insensitively**, as `encoding/json` does and as every graph-index request does:
  `{"Direction":"outgoing"}` is read as outgoing. The value is exact.

## `query_timeout_ms` wording

`query_timeout_ms` and the handler budget are now described as deadlines on the wait for a reply, with ADR-112's "Time"
qualification: neither ends a wait for the connection's write lock. Changed: `README.md`, `doc.go`, `config.go`
(comment and schema description), `query.go`, the spec's configuration requirement, design D7,
`processor/graph-query/MIGRATION.md`. No code changed. `TestQueryTimeoutIsRead` and `TestHandlerBudgetEndsAForward`
stay, and prove the reply wait only: a downstream verb that never replies, on a broker that is reading. No test here
holds a write; ADR-112's probes P13, P14 and P17 do.
