## Choices the design leaves open

- **The import.** `composition` already imports `graph` (`composition/analyze.go:12`, for the reserved-subject check),
  and the `component` guard does not cover `composition`. No guard is touched.
- **Non-request ports draw no finding.** D6 says "a NATS-request input port". A core NATS or JetStream input on a table
  subject, and a NATS-request output (a caller), draw none. Named cases prove each.
- **The other party.** With another factory the message names the verb's responder factory, not an instance: graph-ingest
  and graph-index subscribe to their verbs without a port, so often no instance declares the verb. With two instances
  of the responder it names the first instance.
- **Which subject a finding names.** One finding per port, as the spec says, and the first conflicting subject in table
  order, as `reserved_subject_capture` does. So `>` names `graph.ingest.query.entity` and `graph.query.*` from another
  factory names `graph.query.entity`, the spec's scenario.
- **Two instances that share no verb draw no finding.** D6's conflict is on a verb, so `graph.query.entity` beside
  `graph.query.batch` is allowed. graph-query's own configuration refuses both of those ports, so this reaches only a
  factory that declares narrower ports.
- **A refused instance still holds its other verbs.** The port's verbs are all recorded past its conflicts, so a third
  instance is judged against all of them.
- **One instance with two ports on one verb is not a second responder.** D6 counts instances. Another factory with two
  such ports gets one finding per port.
- **A malformed subject stays `malformed_subject` alone.** `flowgraph.SubjectsOverlap` reads a malformed subject as
  overlapping nothing.
- **It runs before `Analyze`'s early returns**, with the other two checks that read only port facts. A separate test
  proves a composition whose graph cannot build still carries it.
- **Beside the brief: `TestGraphQueryIsItsVerbsResponder`** (`processor/graph-query/factory_test.go`) drives the real
  `Register`: the check is only right if the real factory is what the table names. The boot test uses fake factories,
  as the file's other boot tests do.
- **Named examples, not generated checks.** The overlap law is `flowgraph.SubjectsOverlap`'s, already tested. What is new
  is one judgment per port against a fixed table, whose only history is instance-name order, so each outcome has a named
  case and the reversed-input comparison covers order.
