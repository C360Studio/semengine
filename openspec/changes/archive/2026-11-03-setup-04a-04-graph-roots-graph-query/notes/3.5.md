# Task 3.5 notes

The three tests are in `processor/graph-query/revision_integration_test.go`, on real graph-ingest and graph-index
(`startStack`). The code under them already existed, so each is shown able to fail by a wrong change, not by a run
before the code.

## Choices the design leaves open

- **How `TestReadYourWrites` fails on a build that drops the field.** Success with `indexed_revision` at or above W
  looks the same with or without the field once the index has caught up. So after the writes the test asks for the
  index's own revision plus one. Nothing is writing, so no index speed can reach it: only a request that still carries
  the field is refused. Twenty writes before that give the index real chances to lag.
- **Real lag is seen, never required.** Each write is read straight back, in both directions. On
  `revision_not_reached` the test asks again, and it checks that the refusal's revision is below W. Local runs saw 86 to
  98 such refusals in a run, but nothing asserts on that count. The wait is a plain loop on the reply,
  so a build that never catches up runs into `go test -timeout`. It has no deadline of its own (#501).
- **Readiness first.** `awaitIndexed(t, 0)` runs before the first write, so `index_not_ready` cannot reach the loop,
  where the only refusal allowed is `revision_not_reached`.
- **Exact revision in the refusal detail.** Every test here is the only writer on a reset server, so the index stops at
  the last write's own `kv_revision`, and the detail must equal it. The oracle is the revision the write returned, not
  a read of the index.
- **The refusal test has controls.** Each verb first succeeds without the field and at the reached revision, both naming
  the entity written, so the refusal at `min_revision` 2^40 comes from the field and nothing else.
- **The table walk checks the reply names the entity.** An empty reply would match any entry, so `replyMatchesEntry`
  alone could pass on one. `relationships` is read both ways, because the two directions are separate reply paths.
- **Third copy of `replyMatchesEntry`.** The brief accepts it. graph-index and graph-ingest hold the other two.
- **Generated checks: not used.** Design D3 records that examples suffice: the boundaries are 0, R and R+1.
