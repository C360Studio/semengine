# Task 2.1: the four forwards

Choices design D1 leaves open.

- **`TemporalHit` holds only `entity_id`.** D1 lists `similarity` and `lat`, `lon`, `alt` as the other rows' fields and
  drops the constant `type`. The pin's row is `{id, type}` with `type` always `"entity"`
  (`pin:processor/graph-index-temporal/query.go:144`), so nothing else is left.
- **`alt` and `embedder_type` keep the pin's `omitempty`** (`pin:processor/graph-index-spatial/query.go:59`,
  `pin:processor/graph-embedding/query.go:89`). The pin documents `alt` as 0 when an entity has no vertical component.
  `truncated` has no `omitempty`: D1 names it, and a responder that leaves it out would read as not truncated.
  Changes 5 and 7 may edit any of these while nothing has shipped.
- **The composition oracle's premise is restated, not its alphabet widened.** The new rows failed
  `TestReservedSubjectOverlapMatchesEnumeration`, whose comment said to widen the alphabet. Adding the six tokens
  (`embedding`, `search`, `spatial`, `bounds`, `temporal`, `range`) took the test from 6 s to 93 s, without
  the race detector, on a check `test:repeat` runs five times. The test's premise now reads: a left-out subject differs
  from an earlier kept subject of the same length only in tokens not in the alphabet. That still gives the property the
  oracle needs, since a filter over the alphabet reaches such a subject only through wildcards at those positions, and
  those wildcards reach the earlier kept subject first. It drops the "same responder" clause and the check that every
  responder has a kept subject, so `TestValidateRefusesStreamCapturingReservedSubject` gains one named case per new
  family: it reports `graph.embedding.query.search`, `graph.spatial.query.bounds` and `graph.temporal.query.range`.
- **`declaredRows` carries a per-row request**, as the tasks header asks; `everyVerbRequest` is gone. A forward's is
  `{}`, since it reads nothing; `entityByAlias` and `relationships` send only their own keys.
