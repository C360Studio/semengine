# Task 4.2: `hierarchyStats` and the one page read

Choices design D5 and D7 leave open.

- **`readCountPage(ctx, subject, prefix, cursor)`** in `processor/graph-query/counts.go` is the shared read. It returns
  IDs, the listing's total and the cursor, so task 4.3's `summary` can call it with its own prefix. It holds nothing only
  `summary` needs.
- **A page with no `total` key is refused too.** The spec names a missing `entities` key and an unparsable ID. A page
  with no `total` would read as a group of 0 beside real rows, so it fails closed the same way (`AGENTS.md` § 1). Real
  graph-ingest always sends the key since task 4.1.
- **A row outside the prefix is refused too.** The child count must do something with such a row; the pin dropped it from
  the children while counting it. Real graph-ingest does not send one. `underPrefix` reads whole segments, so
  `c360.testing` is not under `c360.test`.
- **An ID is checked by `graph.ValidateDecodedEntityIDs`**, which owns identity-only replies, rather than a new parse.
  Its refusal names the row's index.
- **`decodeStrict`** moved out of `decodePathSearchRequest` to `query.go`, as a second verb now needs it, with no change
  in what it refuses.
- **`prefix` is validated in graph-query as well as graph-ingest**, as the spec asks, so a bad one costs no request. The
  cursor is not read here: only graph-ingest can judge it, and `TestHierarchyStatsPassesABadCursorsRefusal` shows its
  refusal arriving.
- **A real partial page comes from the byte fit**, as in task 4.1: five entities of a fifth of `max_payload` each, of which
  four fit. Seeding over 1,000 to reach the count limit would show nothing more, as graph-query reads only the cursor.
- **The `next_cursor` literal.** The cursor is opaque, so the reply's value is cut to `true` for the literal, and a direct
  read of the prefix verb is the oracle for the value itself.
- **Tests beyond the task's list:** `TestHierarchyStatsOrdersChildren`, because few tied children left the tie-break
  mutation inconclusive (below): twenty; `TestHierarchyStatsRefusesABadRequest` and `TestHierarchyStatsPassesABadCursorsRefusal`,
  for the requirement's refusals. `TestComposedVerbsCountAsForwardsDo` gains the verb's steps, and
  `TestReservedSubjectsDeclaredOnceSensitivity` a case for its subject.

- **D5's "the pin skipped such IDs" does not hold for this verb.** `pin:query.go:514`'s page check refuses a bad ID, so
  only the class and code are new here. MIGRATION says only what changes for `hierarchyStats`.

Generated checks: none. D5 records one law on literal seeds, with no interacting inputs, so examples suffice. Fuzzing:
none. `decodeStrict` and `readCountPage` read only `encoding/json` and the existing ID validator.
