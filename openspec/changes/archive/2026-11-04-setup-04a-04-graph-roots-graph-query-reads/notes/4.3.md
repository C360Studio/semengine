# Task 4.3: `summary`

Choices designs D5, D6 and D7 leave open.

- **`SummaryData` has no `prefix` key.** `hierarchyStats` echoes its prefix; the task's list of keys for `summary` names
  none, and the caller holds the request.
- **`predicateRows` refuses a reply with no list**, `{"data":{},"producer":"graph-index"}` or `predicates` null, as
  `outgoingRows` does with no relationships. D6 names bytes that do not decode and no `producer`. Real graph-index always
  sends `[]` for none (`processor/graph-index/query.go`, `predicateSummaries`), so the empty state is untouched.
- **`predicates` is `null` only when excluded**, by leaving the slice nil. The zero value reads as "asked and none" only
  through the check above, so the two cannot be confused.
- **An empty body is refused**, as `hierarchyStats` refuses one. The pin accepted it (`pin:summary.go:130`). MIGRATION
  says send `{}`.
- **The order of request checks:** strict decode, negative `examples_per_type`, `prefix` without `exclude_predicates`,
  then the prefix validator. A bad prefix without `exclude_predicates` is `invalid_request`, not
  `entity_id_prefix_invalid`. No downstream request either way.
- **`entityTypes` refuses an ID that does not parse**, with `readCountPage`'s page check ahead of it. The branch cannot
  run from the handler. It stays, with a unit test, because a skip there would silently undercount if the check moved.
  `ParseEntityID` runs `ValidateEntityID` first (`pkg/types/entity_id.go:132`), as `ValidateDecodedEntityIDs` does.
- **Examples follow page order**, which graph-ingest sorts. Under concurrent overwrites a repeated row can repeat an
  example; #512 owns the listing, and D5 accepts the page as listed.
- **`min_revision` with a `prefix` or `cursor` and predicates excluded is ignored**, since no index is read (D7).
- **`predicate_total`'s replacement is `len(predicates)`.** `PredicateListData.Total` is not carried, as D6 drops the key.
- **`EntityTypeSummary`'s doc examples were wrong**, naming `agent.agentic-loop.execution` where ADR-102's order, and the
  code at the pin, gives `agentic-loop.agent.execution`. Corrected with the field docs that named removed keys.
- **`doc.go`, `README.md` and `graph/query_response.go`'s doc are task 5.2's.** Only `SummaryData`'s doc warns about
  revision 0 until then.
- **Tests beyond the task's list:** `TestSummaryOrdersTypes`, as `TestSummaryTypeBuckets`' two ties left the tie-break
  mutation inconclusive (below); `TestSummaryFollowsACursor`, `TestSummaryRequestsOneOfEach`, `TestSummaryRefusesABadRequest`,
  `TestSummaryRefusesABrokenPage`, which reuses `brokenPages` from `TestCountsRefuseABrokenPage`, for the requirements
  `hierarchyStats` tests alone covered; `TestEntityTypesRefusesAnIDThatDoesNotParse` for the branch above.
  `spyOnPrefixVerb` is now a call to `spyOnDownstream`, which `predicateList` needs too.

Pin tests not carried, each with what replaces it: `PredicateFailure_StillReturnsEntityFacet`, reversed in
`TestSummaryRefusesWhenPredicatesCannot`; `SkipsMalformedIDs` and the skip half of
`TestGraphSummaryTypeKeyFollowsCanonicalOrder`, reversed in `TestSummaryRefusesABrokenPage` and the unit test;
`TruncationFlag`, `IncludePredicatesFalse`, `HappyPath`, `StableTieBreak` and `Defaults`, in `TestSummaryTypeBuckets`,
`TestSummaryPredicates` and `TestSummaryFollowsACursor`; `PrefixHandlerErrorPropagates` and `PrefixFailure_Propagates`,
in `TestSummaryFollowsACursor`'s bad cursor, real graph-ingest's refusal arriving;
`PoisonedPrefixReplyPropagates`, not carried, as D5 reads IDs only, so a poisoned triple is not read.

**D5's "the pin skipped such IDs" does not hold for this verb either.** `pin:summary.go:166` refuses a bad ID through
`graph.ValidateDecodedEntityStates` in `extractEntityIDsFromPrefixResponse`, called at `pin:summary.go:86` and returned
at `:88-89`, before `aggregateEntityTypes`. That function's skip at `pin:summary.go:193-195` exists, but its parser and
the page check both run `ValidateEntityID` (`pin:graph/entity_predicate_contract.go:140`, `pin:pkg/types/entity_id.go:133`),
so it runs only from the pin's direct unit calls (`TestAggregateEntityTypes_SkipsMalformedIDs`). What is new here is the
class and code, and the refusal of a page with no `entities` or `total` key.

Generated checks: none. D5 and D6 state rules on literal cases: three states of predicates and a page law, with no
interacting inputs. Fuzzing: none. `summary` reads `encoding/json` and the existing validators.
