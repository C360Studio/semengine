## Choices the design leaves open

- The integration test asserts the listed keys (`[]string{"acme.ops.robotics.gcs.drone.001"}`) for `">"` and for
  `"acme.ops.>"`, where the old lines only stopped the listers. The bucket holds one key, so the two patterns return
  the same set; this proves delegation, not filtering, which `FilteredKeys`' own spec scenarios cover.
- `requireKeyListerStopped` had no other caller and is removed with its `nats` import.
- `ListKeys` and `ListKeysFiltered` stay on `CatalogReader` (task 2.2 drops them) but no test calls them through the
  reader from this commit on; the embedded interface delegates them with no code of its own.
