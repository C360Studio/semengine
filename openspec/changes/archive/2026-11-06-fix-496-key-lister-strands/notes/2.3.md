## Choices the design leaves open

- The test-side store `reclaimBacklogStore` embeds `jetstream.KeyValue` and overrides only the listing method; it
  holds `Publish`'s cancel and records a backlog that never formed in `blockedErr`, read after `Publish` returns on
  the same goroutine, so a missing backlog fails the test instead of passing as a listing error.
- `reclaimListingStacks` matches `jetstream.(*kvs).ListKeys.func1` and appends `natsfixture.NativeDeliveryStacks()`,
  the same scan task 2.2 used; the bound is the package's `failureBound` (10s). It uses `t.Context()`, no deadline of
  its own.
- 600 stale rows (`reportBacklogRows`, shared with the consumer's backlog test) are put raw as `STALE_%03d`. The
  collections name no resource, so a complete listing would reclaim all of them. After the ten cycles the test counts
  them in the bucket with `kv.Keys`, an oracle independent of `Publish`'s `Deleted`.
- `fakeReportStore.WatchFiltered` refuses any pattern but `">"`, so a unit test fails if `reclaim` stops listing every
  key. `listClosesEarly` delivers the live keys and closes the watch with no end marker; the existing `listErr`
  stays as the watch's construction error. `fakeWatch` closes `Updates` once, in `Stop`. `fakeKeyLister` is removed.
- `liveKeys` and `WatchFiltered` share `liveKeysLocked`.
- `ReportStore`'s doc names the migration and the test that proves the listing leaves no delivery.
- The empty-bucket case: the removed `ErrNoKeysFound` branch was unreachable (inventory § 1b); an empty bucket now
  arrives as the end marker alone (`TestIntegration_FilteredKeyListingsNoMatch`), so `reclaim` deletes nothing and
  returns no error.
