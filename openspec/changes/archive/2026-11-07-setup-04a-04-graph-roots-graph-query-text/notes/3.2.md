# Task 3.2 notes

## Generated checks

Named examples suffice, decided before the tests were written (`docs/testing.md`, "Decide whether generated checks are
needed"). The change touches a stated law (the group selection: records scoring above 0, best first, ties by key, at
most five) and a score over interacting inputs (terms against one summary and a keyword list), but no input format and
no history of its own: the view's history is `TestViewHistoryMatchesModel`'s and `ListCounted`'s count
`TestListCountedCountsPoison`'s (task 2.1). A reference model of the selection would be the same filter, sort and cut
written again, so a generated check would compare the rule with itself. Each boundary the design names is a named
example instead:

- the score's four cases (a term in the summary, a keyword containing a term, a term containing a keyword, neither),
  each case-insensitive, and a repeated term counted once (`TestTextTierScore`, P2's records);
- score 0 against above 0 (P1's seven records, none selected; `TestTextTierSkipsUnmatchedGroups`);
- exactly five, and seven (two cut) (`TestTextTierReadsAtMostFiveGroups`), with a tie broken by key;
- the revision mark over readable records only, with an unreadable record holding a higher revision
  (`TestTextTierRevisionIgnoresUnreadable`), and every record unreadable (`TestTextTierAllUnreadable`);
- the merged matches against an independent filter written in the test (`TestTextTierMatchesEqualAFilter`), and a
  group past one page (`TestTextTierMarksACutPage`).

## Choices the design leaves open

- **The internal result shape (for task 3.3).** `searchText` returns an unexported `textResult`: the records read
  (`groups`, best first), the merged `matches` (`rankedEntity`: ID, score, the page's bytes), `scanned`, `pageCut` (a
  page had more), `unreadable` (the level's poisoned count) and `revision` (the mark). 3.3 builds
  `graph.TextSearchData` from it and the request (`level`, `unhonoured_hints`); fit, labels, the answer, the poison
  error and Warn, and the truncation counter are 3.3's, so an answer past unreadable records counts no error yet.
- **The handler until 3.3.** `globalText` keeps a `// shortcut:` refusal for a question the search answered,
  transient `internal`, counting no error, naming the group and match counts; every refusal `searchText` returns
  reaches the caller as it will after 3.3. The tests that need an answer read it through `askText`
  (`textsearch_integration_test.go`), which decodes the request with `decodeGlobalSearchRequest` and calls
  `searchText` with the prefix verb's subject; 3.3 changes that one helper to the wire reply. Refusals, the prefix
  requests and `Health` are read through the wire.
- **Where the term limit is checked.** In `searchText`, before the view is read, so only a question routed to the text
  tier is limited and it wins over `index_not_ready`; a 17-word path question is not refused. The check is
  `checkedSearchTerms`, which `decodeLocalSearchRequest` now calls too: one home for the message.
- **`rankEntities` returns `[]rankedEntity`** (ID, score, bytes), sorted by `compareRanked`, which the merge reuses.
  `localSearch` maps the matches to their bytes; its tests' assertions are unchanged, and `rawStrings` in
  `localsearch_test.go` now takes the matches.
- **`levelRecords(view, levelPrefix)`** takes the view as an argument so `TestTextTierRefusesAViewCatchingUp` can hold
  a real `graphview.View` catching up (running on a watch that never ends its replay, in a `synctest` bubble) without
  touching the component's state. It returns `index_not_ready` for no view, `ListCounted`'s readiness errors and an
  empty level; every record unreadable is the caller's, since it counts an error.
- **Refusal wording.** An empty level: `community index not ready: COMMUNITY_INDEX holds no record under "1."`; every
  record unreadable: `internal error: all 2 community records under "1." are unreadable`; a revision not reached:
  `min_revision 6 is above the highest entity_revision 5 under "0."`, detail `indexed_revision`.
- **An empty keyword** would score every term (`strings.Contains(term, "")`), as at the pin. Clustering never writes
  one (`extractWords` keeps words of 3 bytes or more), so it is left as the spec's rule reads.
- **`globalSearch` needs the prefix verb** to be registered, beside the six it already named.
- **`TestMinRevisionRefusalThroughGraphQuery`** gains no text row here: its success half needs the reply (3.3).
- **Ledger.** The `processor/graph-query` row's test list names the step 5 tests; its contract prose is task 5.1's.
