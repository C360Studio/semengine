# Task 3.3 notes

## Generated checks

Named examples suffice, decided before the tests were written (`docs/testing.md`, "Decide whether generated checks are
needed"). The task has no input format of its own (the request decode is 3.1's, fuzzed by
`FuzzDecodeGlobalSearchRequest`) and no history (the view's is task 2.1's). It has two rules over interacting inputs
and one stated law:

- **The label** (design D4): a predicate's priority, a tie by name, triple order, and values that are empty or not
  strings. Each interaction is a named case of `TestMatchLabel`: a title; a more salient registered label beside it;
  two values of one predicate (the first in triple order); an empty first value; a non-string value; a tie of
  priorities broken by name; an agentic predicate not in the set; none. A reference model would be the same sort and
  scan written again.
- **The answer** (design D4): a sentence per condition (no group, a sample, a group with or without a summary,
  unhonoured hints, unreadable records). `TestTextTierAnswer` holds each sentence as a literal, alone and together.
- **The fit** (law: the reply keeps the most of its best matches whose encoding is at most `max_payload`). The bisection
  is `fitLocalSearch`'s, moved to one helper both fits call. `TestTextTierFitKeepsTheBestThatFit` checks every limit
  from the empty reply's length to the whole reply's against a linear scan written in the test, which is exhaustive
  over that range rather than sampled; `TestTextTierFitsMaxPayload` checks the wire reply on a server with a small
  `max_payload`.

## Choices the design leaves open

- **"Most salient label predicate"** is read as the most salient predicate the entity holds a non-empty string value
  for: a preferred label that is empty, or not a string, falls through to the title (`TestMatchLabel`, "a less salient
  label when the more salient is empty"). The label set is held most salient first (`labelOrder`), set in `start`
  before any handler is subscribed.
- **`rankEntities` takes the label set** and labels each match as it decodes it, so no entity is decoded twice;
  `localSearch` passes nil and its reply is unchanged. Its tests gain the `nil` argument, nothing else.
- **One bisection.** `fitLocalSearch`'s search moved to `fitFirst`, which `fitTextSearch` calls too; `fitLocalSearch`'s
  behaviour, error text and tests are unchanged. A cut text reply is longer by the sample sentence, so leaving one match
  out can grow the reply; `fitFirst` tries the whole list first and bisects only below it, where each match left out
  shrinks the reply, so the result holds.
- **Empty lists.** `groups`, `matches` and `unhonoured_hints` are always present, `[]` when empty, so a reader never
  has to tell absent from none. `community_summary`, `keywords` and `label` are omitted when empty, as `localSearch`'s
  record fields are.
- **No group matched.** The answer's first sentence is `No group at level {level} matched the question.` in place of
  the counts sentence (D2: "the answer says no group at that level matched"); the hints and unreadable sentences
  follow it.
- **The Warn's attributes** are `verb`, `level`, `unreadable` and `reason`, whose text is "community records are
  independent, and the answer reads only the readable ones". The error is counted, and the Warn logged, only once the
  reply is encoded, so a request is still at most one error.
- **The verb's name** is the handler's argument (`c.globalSearch("globalSearch", ...)`), for the counter and the Warn;
  task 4.1 registers `searchGraph` with its own name.
- **The step 4 and 3.1 tests that held the text tier by its missing view** (`requireTextTierReached`) now hold the
  reply: `TestGlobalSearchUnknownWordIsSearched` and both halves of `TestGlobalSearchUnknownIDIsSearched` write a
  record keyed by the word and require `strategy` `text` with that record as the one group read (the spec's "its query
  is that word"). `TestComposedVerbsCountAsForwardsDo`'s one-word steps that reach the text tier ("a reference naming no
  entity", "the holder's entity gone") now answer past the unreadable record its `localSearch` steps wrote, one error
  each, so every later total is two higher; it gains five text steps.
- **`TestMinRevisionRefusalThroughGraphQuery`** gains its text row ("alpha drone", two words, so the question is not
  first read as an alias). `TestTextTierRevision`'s at-the-mark question is two words for the same reason: a one-word
  question is an alias read first, at its own index's revision.
- **#31's proving test** (`go list -deps ./processor/graph-query` holds no `vocabulary/agentic`) holds trivially: this
  module has no such package. `TestMatchLabel` holds the behaviour: the pin's agentic display-name predicate is not a
  label.
- **Ledger.** The `processor/graph-query` row's test list names the 3.3 tests; its contract prose is task 5.1's.
