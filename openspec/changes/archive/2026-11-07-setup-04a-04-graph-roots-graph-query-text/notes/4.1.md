# Task 4.1 notes

## Generated checks

Named examples suffice, decided before the tests were written (`docs/testing.md`, "Decide whether generated checks are
needed"). The task adds no input format (the request decode is `globalSearch`'s, fuzzed by
`FuzzDecodeGlobalSearchRequest`), no history and no transformation of its own. Its one stated law is equality: for one
request, `searchGraph`'s `data` equals `globalSearch`'s (design D7). The handler is the same function, so the law
cannot depend on the request's content; what can break it is the wiring (a different handler, a different verb name,
a fallback added after an empty answer). `TestSearchGraphAnswersAsGlobalSearch` holds it over one request per outcome
global search has: each strategy it answers over real ingest, index and community records, an empty text answer (the
pin's fallback trigger), and each refusal kind (a body that is not JSON, SemSource's `summarize_threshold`, a named
start naming no entity, a strategy whose responder is absent). A generated request would reach no wiring the named
ones do not.

## Choices the design leaves open

- **One handler, two names.** `queryHandlers` builds `globalSearchSubjects` once and registers
  `c.globalSearch("globalSearch", subjects)` and `c.globalSearch("searchGraph", subjects)`, as 3.3 left it: the name is
  the counter's label and the poison Warn's `verb`, so a truncated `searchGraph` answer counts under `searchGraph`.
  No new symbol.
- **The oracle.** The spec's law is equality with `globalSearch`, so `globalSearch`'s reply is the comparison. So that
  two equal replies are also right ones, the timestamp-free answers (the path, and the text answer with no group,
  which is where the pin's fallback fired) are held to literal JSON too, the strategy of each answer is a literal, each
  refusal's class and code are literals, and the `summarize_threshold` refusal must name the key.
- **No semantic request**, the spec's second sentence, is held by a spy on both embedding verbs, read after every
  reply: graph-query's handler answers only after any request it sent is answered, and the spy counts before it
  answers.
- **The pin's `searchgraph_test` cases.** The one that is not about the fallback,
  `TestHandleSearchGraph_InvalidRequestPropagates` (a body that is not JSON is refused, not answered), is the row "a
  body that is not JSON". The other four test `searchGraphResponseEmpty` and `adaptSemanticToGlobalSearchResponse`,
  the fallback, which is not carried (design D7).
- **`TestTruncatedSearchIsCounted`**: the task names it in the spec, not in its check list. Its `globalSearch` subtest
  now runs once per verb and requires the other two labels to stay 0; that is what catches the wrong name.
- **`MIGRATION.md`**: this task's entries are SemSource's: the silent decode bullet (in the tree now; what `data` holds
  instead of what `graphSearchBody` reads), a bullet to drop `summarize_threshold`, the use-case and timeout lines no
  longer saying "once step 5 lands", and a `searchGraph` row in "Any caller", which says the semantic fallback is not
  carried. The step table, the "Steps 1 to 4 are in the tree" line and the "silent" entry for the lost tier-1
  fallback are task 5.1's.
- **Ledger**: the `processor/graph-query` row's test list does not yet name `TestSearchGraphAnswersAsGlobalSearch`;
  task 5.1 writes the row's tests.
