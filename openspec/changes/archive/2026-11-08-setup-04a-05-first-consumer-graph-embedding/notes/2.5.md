## What changed

- **ErrorCount counts failures.** At the base nothing in graph-embedding called `Lifecycle.CountError`, so
  `ErrorCount` was always 0, as at the pin, whose `c.errors` has no writer (pin `component.go:309`, read at `:549`
  and `:582` only). ADR-109 Decision 2 asks each port for "a nonzero `ErrorCount` still reads true", which needs a
  count. Hop 1's four marks go through a new unexported `markFailed`, and `onTerminal` handles a Worker failure;
  the counting rule is the one below (changed at stop 3). `Health` is unchanged: `Lifecycle.Health` already ignores
  the count.
- **The counting rule (review M1/L1 at stop 3, orchestrator's decision).** The first form counted every failure
  event, so a repair pass failing the read again every 30 s counted again and `error_rate` grew without bound. Now
  graph-embedding counts as graph-index does (`processor/graph-index/index.go:240-249`, `:425`): once when an entity
  enters the failed set, and once per latched reset. The failed map's `mark` and `failed` (through `worker` and
  `store`) report whether the entity entered: the failure was stored and the entity held no failure before. A failure
  refused as older than the entity's latest outcome, and any failure of an entity already failed (a stranded failure
  replacing one, a newer failure replacing an older), report false and count nothing. The reset is counted in
  `queueEntity` before `Follower.Reset`, on every refused value, as graph-index counts each reset it raises: the
  follower's latch keeps only the first reason and reports nothing back, and a refused value is not re-driven by the
  repair lane, so each count is one refused revision. The Start seed (`seed`, failed records from before the restart)
  counts nothing: those failures are not this process's.
- **No status verb.** Nothing changed in production: graph-embedding subscribes to nothing at the base, and
  `graph.QueryVerbs` declares only `search` and `similar` for it.
- **Import guard.** `processor/graph-embedding` reaches `model` transitively at the base: `component` imports it for
  `component.Dependencies.ModelRegistry` (`component/dependencies.go:7`, `:48`), so every component does. The first
  form of the guard, `providerViolations` over `go list -deps` as the graph/embedding and graph/query guards are
  written, failed on the base tree with `processor/graph-embedding reaches github.com/c360studio/semengine/model`.
  The inventory's "`model` only via the HTTP path" (`inventory.md:51`) is a direct-import statement. The guard now
  holds `model` to graph-embedding's own imports (`go list -f '{{join .Imports " "}}'`) and the OpenAI SDK to
  everything it reaches (`go list -deps`), with its own sensitivity test over planted listings.

## Edge values and what is not covered

- **ErrorCount is asserted exactly** (stop 3): a repair pass that fails the read again, the test's own or the lane's
  every 30 s, counts nothing, so the count is 1 while the read fails and after the repair.
- **Not each hop-1 site.** Only the read failure is asserted; the delete and pending-write marks go through the same
  `markFailed`, which is the check. The failed map's entry rule is checked for every kind of failure by the
  generated histories of `TestFailedMapHistoryMatchesModel`. The reset is asserted once, on a value that is not
  JSON; the other refusal reasons go through the same line.
- **No responders as the oracle.** On nats-server's default configuration a request with no subscriber gets no
  responders at once (`natsclient.IsNoResponders`); the request's one-hour bound is out of reach.
- **Generated checks.** Not used: each test has one input that matters (a failure and its repair, a subject, an
  import list), with no interacting cases.
