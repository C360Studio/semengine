# Task 2.3 notes: handlers, entry checks and ranking

Code: `processor/graph-embedding/query.go` (new), `processor/graph-embedding/component.go` (the cache's Run, the shared
embedder, the subscriptions, drained first in `cleanup`).

## Choices the design leaves open

- **Order of the entry checks.** Both verbs: strict decode, then `min_revision`, then `limit`; then `search` checks
  the query and each scope element, `similar` the entity ID. Every check runs before the embedder, the bucket or the
  cache is reached. A request with two faults is refused for the first.
- **Messages.** `limit 101 is outside 0 to 100`; `min_revision 7: the embedding verbs claim no ENTITY_STATES
  revision; send 0`; `query is blank`; `scope[i]: <validator error>`; `entity_id: <validator error>`; `data after the
  request object`. All are `invalidRequest`, class invalid, code `invalid_request`, as graph-index's (scope's inner
  `entity_id_prefix_invalid` code is replaced, as D3 says `invalid_request`; the pin sent the inner code).
- **Where the score-0 drop is.** After `FindSimilar`'s limit, in `rank`. The cache sorts by similarity descending
  before the limit, and BM25 vectors are not negative, so the zeros are the tail of the cut list and dropping them
  loses no positive hit.
- **Scope matching** uses `graph.MatchesAnyIDPrefix`, the one matcher the prefix query shares; it re-validates the
  (already validated) prefixes and each candidate ID on every call. Not benchmarked here.
- **Cache errors.** An error matching `graphview.ErrNotReady` (before the first snapshot, a lost watch, after Run)
  is transient `index_not_ready`; any other is transient `internal`. This is the minimum a handler needs; task 2.4
  adds the follower's `QueryReady` and the lost-watch Health latch. The cache's Run returning while the run context
  is live is only logged here (error level); 2.4 latches it.
- **Similar's source read errors.** Class invalid (the undecodable record) is passed as it is, no code, as at the pin;
  any other read failure is transient `internal`.
- **`failed_records`** counts the failed map's entries whose reason is not a hop-1 reason (`repaired`), so a hop-1
  failure, which 2.4 withholds on, is never counted as a failed embedding. No change to `failedMap`.
- **`embedder_type`** is `config.EmbedderType`, which `Validate` holds to `bm25`.
- **The embedder.** `start` builds one `BM25Embedder` and gives it to both the Worker and the search handler (D3).

## Tests

Unit (`query_test.go`, a component built and never started, so a request past the entry checks panics on the
missing embedder, bucket or cache; `call` recovers and reports it as `got past the entry checks`):
`TestHandlersDecodeStrictly` (unknown key on each verb, three trailing-data shapes, empty and non-JSON bodies),
`TestMinRevisionAboveZeroRefused`, `TestRefusalsBeforeAnyRead` (limit 101 and -1 on both verbs, blank query, three
bad scope prefixes, three bad entity IDs). This is also the proof that a bad scope leaves the embedder's statistics
unchanged: it is never called.

Integration (`query_integration_test.go`): `TestVerbsServeTableSubjects`, `TestSearchAnswersEnveloped` (empty
search and lone-source similar both `"results":[]`, `min_revision` 0 answered, revision 0), `TestSearchLimitEdges`
(101 entities, both verbs), `TestSearchQueryEdges`, `TestSearchScopeEdges`, `TestSimilarEdges`, `TestTopKAtTie`,
`TestScopedSearch`. `processor/graph-query/embedding_integration_test.go`: `TestSemanticForwardsMinRevision`, a real
graph-embedding behind graph-query's `semantic` forward.

Every read of what the component wrote waits on a reply (`awaitAnswer`, `probe.Await` on the request), since the
cache applies a record after the Worker's write lands in the bucket (D4). The one-word titles make each vector the
same unit vector, so ties are exact (cosine of two equal one-hot float32 vectors is exactly 1 in float64).

graph-query's canned embedding replies (`revision_integration_test.go:212-213`) now carry `indexed_revision` 0 (D4).

Failing first: the tests were written before `query.go` and the component fields, and were not run before the
implementation (they could not build: `queryHandlers` and `subscriptions` did not exist). That each can fail is shown
by the mutants below.
