# Task 2.4 notes: fusionvocab

Choices the design leaves open:

- **The parents function's type is `func(iri string) []string`**, the shape of semvocab's `cco.Parents`
  (`semvocab:catalog/cco/hierarchy.go:64`), so SemSource passes it unwrapped: `fusionvocab.New(cco.Parents)`.
- **An empty class never asks.** `ClassSpecificity("")` returns 0 without calling `parents`, as the pin did; a nil
  `parents` returns 0 for every class. An unknown class scores whatever `parents` returns for it (semvocab returns
  none, so 0).
- **`Signals` holds the function by value.** It is safe to share as long as the function is; semvocab's is a pure
  lookup.
- **Pin tests.** The pin's `TestClassSpecificity` used real BFO/CCO IRIs and depths from `vocabulary/cco`, which this
  tree does not have and must not import. `TestClassSpecificityCountsParents` uses a hand-built ancestor table, so the
  expected scores are the lengths written in the test; it keeps the pin's monotonic check (a subclass outranks its
  ancestor). `TestPredicateSalience` is the pin's, plus a negative weight.
- **Dependencies.** `go list -deps ./pkg/fusion/...` lists no `semvocab`, no `vocabulary/cco`, no `vocabulary/bfo`,
  and no NATS package (a `grep -E 'semvocab|vocabulary/cco|vocabulary/bfo|nats'` over it matched nothing, rc=1, on the
  commit that wrote this note).
