# Task 3.4 notes: spec sync

The requirement "A fatal seed read or an ended context fails the call" was narrowed and split when it was synced
into `openspec/specs/fusion/spec.md`. The delta in this change said `Fuse` returns the context's error "when the
request's context has ended during any read". That overclaimed, and so did the spec it modified.

What the code does: `Fuse` checks the context only after a failed read, or when every resolved seed is unhydrated;
a read that completed is kept (`pkg/fusion/engine_lens.go:118-212`, the all-unhydrated check at `:147-151`, and
`seedReadFailure` at `:207-218`, `miss` at `:291-297`). The test is `engine_lens_readiness_test.go:227`
(`TestEndedContextReturnsError`).

The synced spec therefore has two requirements: "A fatal seed read fails the call" and "A failed read under an ended
context returns the context's error". Every clause and scenario test name is kept. The MODIFIED block in this
change's `specs/fusion/spec.md` was rewritten to that two-requirement form so the archive records what was synced.
