# Task 2.1 notes: follower `Entry.Value` and the plug-in-neutral `Stuck`

## Choices the design leaves open

- **Sentence shape.** `Stuck` says `N unresolved failures` and, when `Failed` returns reasons, appends
  `: <reason> <count>, <reason> <count>` with the reasons in name order, so the sentence is the same on every call
  (a map's order is not). `1 unresolved failures` keeps the plural, as the design's "N unresolved failures" does; the
  old sentence (`1 index writes unresolved`) did the same.
- **Updated assertions.** graph-index reports no reasons, so its two assertions match `1 unresolved failures`.
  graph-embedding reports reasons, so its two assertions name them: `1 unresolved failures: entity_read_failed 1`
  (`health_integration_test.go:41`) and `1 unresolved failures: content_error 1` (`withhold_integration_test.go:191`).
  `follower_test.go`'s `TestWithholdNarrowsQueryReady` names `content_error 1` the same way.
- **`Entry.Bytes` stays.** graph-index and graph-embedding count it (`index.go:123`, `hop1.go:33`); it is now
  `len(Value)`, set from the same read.
- **`Value` is nats.go's slice, not a copy.** The doc's "valid only for the duration of `Deliver`" is a restriction
  on plug-ins, not a statement about nats.go: it leaves the follower free to reuse the buffer. No plug-in keeps it
  today; graph-clustering (task 2.2) decodes it inside `Deliver`.
- **Delete marker.** `Value` is left nil on a delete or purge marker (set only in the put branch), not nats.go's
  marker value, which is an empty non-nil slice at the pinned nats.go (the mutant below shows it).

- **Named examples, no generated checks.** The sentence has two inputs (a count, a reason map) and no stated law beyond
  the format; the four cases (one reason, two reasons, none, a zero count) are every branch `unresolved` and `Stuck`
  take.
