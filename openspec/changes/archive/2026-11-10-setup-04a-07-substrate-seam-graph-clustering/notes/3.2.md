# Task 3.2 notes: the tree-wide provider guard

## What the tree holds

- **Neither `graph/llm` nor `model/wire` exists in this tree**, and `go.mod` names no
  `github.com/sashabaranov/go-openai` (`ls graph/llm model/wire` fails; `model/` holds `breaker`, `health`,
  `httpclient`, `registry`, `watch`). `go list -deps ./... | grep -E "graph/llm|model/wire|go-openai"` prints nothing.
  `TestTreeImportsNoProviderPlumbing` therefore passes today and guards against their return: the ledger keeps
  `graph/llm` and `model/wire` as rows a later change could port (task 4.1 rewrites their exit condition).

## Choices the design leaves open

- **The rule each violation names.** No spec requirement covers the tree-wide guard or graph-clustering's provider
  imports, and the change's spec deltas add none, so both tests name the owner's ruling 2 on #32 (PR #582 comment
  6768832111): `(#32 › tier 0 builds without the LLM plumbing)`, one constant, `llmPlumbingRule`. They carry no
  `// Requirement:` line for the same reason.
- **The listing is `go list -deps ./...` without `-test` or tags.** It is the build the ruling names (tier 0
  builds); test-only imports and `integration`-tagged files are outside it.
- **"Reusing the provider reader".** The tree-wide reader cannot call `providerPathsFor`, which forbids `model`;
  both now share `under(path, root)`, the one root-or-below match (a name-prefixed sibling such as `modelregistry`
  or `graph/llmx` is not under the root). `graphEmbeddingProviderPaths` became
  `directModelProviderPaths(module, pkg, rule, direct, deps)`, called by both direct-`model` guards through
  `requireNoDirectModelProvider`; its sensitivity test runs per package (`graph-embedding`, `graph-clustering`).
