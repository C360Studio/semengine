# Task 2.1 notes: `graph.query.predicate`

## Choices the design leaves open

- **Where `graph.PredicateRequest` lives.** In `graph/query_index_types.go`, beside the `PredicateData` it asks for,
  with the field names, JSON keys and `*string` value of the inline struct it replaces in
  `processor/graph-index/query.go`, so the wire does not change. `TestPredicateRequestWireNames` holds the keys and
  that an empty `value` still arrives as a value (a nil `Value` means no value filter).
- **Table order.** The `graph.query.predicate` row follows `graph.query.byName`, the other graph-index forward.
- **Tests that walk graph-query's verbs gained a `predicate` case**, since each refuses a declared verb it has no
  request for: `forwardRows` (so `TestForwardPassesBytesBothWays`, `TestForwardsShareNothingBetweenRequests` and the
  lifecycle tests over the forwards cover it), the declared list in `TestGraphQueryServesExactlyTheDeclaredVerbs`,
  `TestGraphQueryRepliesDecodeByTheTable` (with and without `value`, real graph-index reply decoded strictly as
  `graph.PredicateData`) and `TestMinRevisionRefusalThroughGraphQuery` (graph-index's `revision_not_reached` passes
  through). The graph-index predicate tests are unchanged.
- **Docs.** `graph/README.md` and `processor/graph-query/README.md` name the new verb. The query-pattern skill,
  `docs/repository-map.md` and `MIGRATION.md` are task 2.6's contract text.
- Generated checks: not used. A forward passes bytes; the cases are named examples already shared by every forward.
