# Task 2.5 notes: composed smoke

## Choices the task leaves open

- **Where the gateway is asked.** `checkGateway` (`internal/smoke/smoke_integration_test.go`) runs in
  `TestSmoke_OneConfigAnswers` only, after each `checkAnswers`: once on the fixed entities, once after the edit and
  the delete. The restart tests keep their NATS-only `checkAnswers`; they list and check the six components' health
  through `fullStack`, which now includes graph-gateway.
- **Ordering.** The gateway's reads go through graph-query to graph-ingest's `ENTITY_STATES` reads (`entity`,
  `entitiesByPrefix`) and to graph-index (`entitiesByPredicate`, `pathSearch`). `checkGateway` runs after the
  caller's `awaitIndexed`, which returned once graph-index reported the `ENTITY_STATES` revision read after the last
  write, so the same wait that orders `checkAnswers` orders these reads. No new wait.
- **Oracle.** Expected answers are written from the fixed inputs, never from a reply: each live entity's triples
  from `statementStrings`, the four bases by literal ID for the `c360.<platform>.fleet.ops.base` prefix (total 4,
  no cursor), drones 5 to 8 (5 to 7 after the delete of drone 8) for `fleet.link.home` = base 2, and `leadPath` for
  `pathSearch` from drone 1, `OUTGOING`, `maxDepth` 10, with `paths[k]` the first `k` edges of the chain and
  `truncated` false. Each POST must answer HTTP 200 with no `errors`.
- **HTTP.** `send` (`internal/smoke/stack_integration_test.go`) is `get` generalised to a method and a body, dialled
  at the IPv6 loopback as `get` already was (#390); `get` calls it.
- **Config.** `"graph-gateway": {"type": "gateway", ..., "config": {}}`: its defaults (the one `graph_queries`
  output, 60 s timeout). The service manager mounts it at `/graph-gateway`.
