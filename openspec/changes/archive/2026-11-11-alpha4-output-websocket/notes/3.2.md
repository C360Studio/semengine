# Task 3.2 notes: TLS and metrics

Choices the design leaves open, and what task 3.2 did not do.

## TLS

- 3.1's factory refusal (`errTLSNotBuilt`, `TestTLSNotBuiltYet`) is gone. `Start` calls
  `tlsutil.LoadServerTLSConfig(deps.Security.TLS.Server)` before it binds. A refusal from tlsutil (an `acme` mode,
  `acme.enabled`, mTLS without server TLS, an unreadable certificate) fails `Start` with nothing bound or held.
- The server is served over `tls.NewListener(listener, config)` rather than `ServeTLS`. net/http documents that
  `ServeTLS` turns on HTTP/2, and the upgrade is an HTTP/1.1 request; over this listener the server speaks HTTP/1.1
  only. The whole config tlsutil returns is used, so mTLS applies. `TestTLSServesWSS` proves it by refusing a client
  that presents no certificate.
- `TestACMEModeRefusedAtStart` is a unit test. Its NATS client never connected, so a `Start` that did not load TLS
  first would fail at the subscribe with another error.

## Metrics

They live in `metrics.go` (`outputMetrics`), and `drops.go`'s counter moved there. Every metric is registered through
`metric.RegisterOrGet`, and the collector it returns is the one used. With a nil registry nothing is registered, as
in graph-clustering. Each metric is labelled `listener`. A metric with only that label is resolved for the
instance's listener at construction, so its sample exists, at 0, from the start.

| Metric | Counted where |
| --- | --- |
| `messages_received_total` | each subject message the handler gets, JSON or not |
| `messages_sent_total`, `bytes_sent_total`, `message_size_bytes` | each data frame written to a client, once per client; ping and close frames are not counted. Buckets are the pin's |
| `clients_connected` | set to the number of attached clients, under the clients lock, on attach and detach |
| `client_connections_total` | each request upgraded |
| `client_disconnections_total{reason}` | each upgraded client, once both its reader and writer have returned |
| `errors_total{type}` | `upgrade`: a request to the path that could not be upgraded (answered 400). `serve`: `Serve` returned before `Stop` |

Disconnection reasons, a closed set: `read_timeout` (the read deadline passed: a `net.Error` with `Timeout()`),
`client_closed` (any other read failure: close frame, closed socket, protocol error), `write_failed` (a frame or ping
write failed) and `stopped` (`Stop` sent close 1001). The first reason recorded wins (`client.end`, a `sync.Once`).
Each side records its reason before it closes the connection, so the side that saw the failure first is the one
recorded. The side that only saw the closed connection afterwards is not. A client the fence refused because `Stop`
had begun is still counted as a connection and a `stopped` disconnection.

`errors_total` has two types only. A write failure to a client is a disconnection, not a server error, so it is not
counted twice. The pin's `client_send`, `client_timeout`, `buffer_creation`, `json_marshal`, `envelope_marshal`, ack
and pending types belong to paths this port does not carry.

`changes_coalesced_total` is not registered here. graphview's fan-out hook feeds it, so it belongs to the
applied-state input (task 3.3), which has the hook.

## Test ordering

- `clients_connected` is set under the lock `awaitClients` reads the clients under, so a read after `awaitClients`
  sees it.
- `detach` counts the disconnection before it takes the lock and removes the client, so after `awaitClients(n)`
  sees the client gone, its disconnection has been counted (`TestSilentClientIsClosed`, the `client_closed` check in
  `TestMetricsCountTraffic`).
- Every other count in `TestMetricsCountTraffic` is read after `Stop`. `Stop` drains the subscription and joins every
  handler and writer.
- The byte oracle is the length of each frame the test's clients read, not the server's own arithmetic.

## Generated checks and fuzzing

No generated checks. Each metric counts one event at one site, and nothing interacts across messages, so named
examples with the test's own traffic as the oracle are enough. No fuzz target either: no new exported surface, and
nothing new parses external bytes. The TLS configuration is tlsutil's to parse and test.
