## Choices the design leaves open

1. **A scope element `""` matches every entity**, as `graph.SemanticRequest`'s and `lexical.Options`' do; any other
   element must pass `ValidateEntityIDPrefix`. A scope of only `""` is the same as no scope.
2. **The limit reuses `graph.DefaultSimilarityLimit` and `graph.MaxSimilarityLimit`** (D4: "the existing similarity
   bounds"); no new constants. Their doc comments now name the word search too.
3. **The query is checked before readiness.** The spec lists the query among the request checks, so a malformed
   query is refused `invalid_request` during the build, not `index_not_ready`.
4. **`bodies_not_indexed` is read after the search, under the applier's lock, not in one snapshot with the hits.**
   Both are read while the reply is built; holding the applier's lock across the search would stop deliveries and
   serialize searches for no reader that needs the two to agree.
5. **No handler timeout.** The search is in memory; the request's context bounds the readiness check, as on
   graph-embedding's verbs.
6. **The request and reply are typed by the verb (`QueryVerb.Reply`), not polymorphic payloads**, so no
   `BaseMessage` and no `RegisterPayloads`, as for every other verb in the table. Their wire names are held by
   `TestLexicalSearchTypesWire`.
7. **The strict decoder is a copy of graph-embedding's** (unexported, ten lines). A shared one would be a new
   exported surface across packages, which this task does not need.
8. **`Score` is the index's BM25F score**, documented as comparable only within one reply; D4 rejected sharing
   `Similarity` for this reason.
9. **The tests are integration tests** through a real follower and the NATS request path. The withheld test holds
   the build open with an offloaded body on a store whose read waits until the test releases it (D5's "queued: floor
   waits"), rather than racing a large replay. The store ignores its context and answers only on release, so the
   read's 10 s deadline cannot end the build early; a cleanup releases it so `Stop` can join after a failure.
10. **Added beyond the Accept list:** `TestSearchRefusesMalformedRequests` (unknown key, data after the object, three
    malformed scope prefixes, a negative `min_revision`), `TestLexicalSearchTypesWire`, the reserved-subject
    sensitivity case, and "query subscriptions" in the lifecycle suite's adapter.
11. **`graph/README.md`'s verb-table paragraph** now lists the new row, since it claims to list every row. The
    component's own README and the `graph/lexical` README are task 3.1's.

## Generated checks

Not used; named examples suffice. The request's inputs are checked one at a time, each against its own rule, and
every boundary is named: limits 0, 1, 100, 101 and -1. The one law, scope before the limit, is a single ordering:
the witness is built so that the better matches lie outside the scope, which the unscoped search shows first. The
index's own scope and limit law over generated documents and scopes is `TestPropIndexMatchesModel`
(`graph/lexical/index_prop_test.go`), which this task does not change.

No new exported parser: the request is decoded by `encoding/json`, and the query and the prefixes go to
`lexical.ParseQuery` and `ValidateEntityIDPrefix`, which `FuzzParseQuery` and `pkg/types`' own tests already cover.
