`TestPrefixIDsCursorWalkMatchesSortedKeys` (rapid) and `TestPrefixIDsCursorWalkNamedCases` (the boundaries, every
run). The reference model is `prefixIDsModel` and `modelLimit`, which restate the spec; maximality is checked by
`json.Marshal` of every longer run within the limit.

## Choices the design leaves open

- **No table row in 2.1.** `setupQueryHandlers` subscribes only to the table's rows, so `prefixIDs` sits in
  `queryHandlers` unserved until task 2.2 adds the row. No graph-ingest row was needed.
- **Every run length is measured.** Only a page with keys after it carries a cursor, so the last run (no cursor) can
  be smaller than a shorter one with a cursor. The fit takes the longest run that fits, not the first that fails.
  `TestPrefixIDsCursorWalkNamedCases/a_longer_run_fits_where_a_shorter_one_does_not` pins it.
- **When `response_too_large` is refused.** Only when no run holding the first key fits. Its `response_bytes` names
  the one-key reply, as the prefix verb names its one-entity reply. `TestPrefixIDsFirstKeyTooLarge` uses a maximum
  below both the one-key and the two-key reply for that reason. An empty listing whose `{"ids":[],"total":0}` does
  not fit is refused the same way, as the prefix verb does.
- **A separate fit function.** `marshalFittingPrefixIDsPage` is new; the prefix verb's `marshalFittingPrefixPage` is
  untouched. The shared part is `listPrefixKeys` (decode, checks, limit, listing, exact-key check, sort, repeats,
  total, cursor), moved out of the prefix handler with its order of checks unchanged.
- **Sizes.** Each ID is measured with `json.Marshal`; the cursor as its length plus two quotes, since base64url needs
  no JSON escaping. The encoded reply is checked against the maximum before it is returned.
- **The named cases are their own test.** rapid refuses to start in a test that has already failed, so a failing
  witness in the same function would hide the generated result.
- **The test spells the cursor encoding out** (`cursorOf`) to size candidate replies and to check `next_cursor`.
- **The limit clamp at 1000** needs 1001 keys, so it is the named `TestPrefixIDsLimitClamp`; the generated draws stay
  at 25 keys or fewer, where the model still applies the clamp.
- **Keys under an exact ID** are drawn as seven-part `.child` keys in the mock bucket, so the exact-key rule meets both
  "nothing listed under it" and "something listed under it".
