## Choices

- **The real-responder test has its own lens.** The integration file is the external `fusionnats_test` package, so
  it cannot use the unit tests' `prefixLens`. `idPrefixLens` is a copy that names each node by its entity ID.
- **Nodes are compared as a sorted set.** The engine's node order is not what this test is about.
- **The ordering check lists IDs out of key order.** `TestResolve_Prefix`'s fake lists
  `a.b.c.d.e.2` before `a.b.c.d.e.1`, so a client that sorted or reordered the IDs would fail.
- **`Entities` is unchanged.** Hydration still reads through batch, and falls back to one read per ID when batch
  refuses.
- **Docs are task 2.4.** `fusionnats/doc.go` and the fusion README still name `prefix`.
