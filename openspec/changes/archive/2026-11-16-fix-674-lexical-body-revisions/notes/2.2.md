# Task 2.2 notes: implementation

## Choices the design leaves open

- **No new field for "a read is out".** The `queued` body state already means a read was asked for the held reference
  and has not been taken; `deliver` only sets it when it returns a read, which `Component.deliver` always enqueues.
  So "a read of that reference is queued or in flight" is `body == bodyQueued`: a read `deliver` asked for, never a
  repair pass's read, which the spec delta now says. The same-text path defers the revision's completion to that read
  exactly then.
- **One predicate for `wanted` and `bodyDone`:** `serves(read)`: the key's latest revision names `read.ref` (whole
  `==`) and its body is `queued`, `unread` or `no_store`. A read that serves completes the latest revision (and with
  it every earlier waiting one); a read that does not is dropped and completes its own revision, as before.
- **`held.waiting` is renamed `held.offloaded`**: it is no longer "what still waits to be read" but the latest
  revision's inline document and reference, kept in every body state (`missing` and indexed included) and cleared
  only by a revision with no reference or a delete (`remove` resets the whole entry).
- **A revision waiting on a read that a reference change then drops** completes with the next revision's outcome, not
  when the dropped read returns: the dropped read completes only the revision that asked for it, as the spec says. The
  floor is late for that revision, never early. Witness: "a revision waiting on a read that a reference change drops".
- **A repair read in flight is not "a read out".** While a body is `unread` or `no_store`, the applier does not know a
  repair read is in flight. A same-text revision then completes at once (the body is in a state below, so the floor
  may pass it) and asks for nothing; a text change under the same reference asks for a read, so two reads of one
  reference can be out. The second finds the body indexed and is dropped. Cost: one extra read per such
  coincidence, at most once per 30-second repair pass.
- **Comment on `bodyPath.read`** (`bodies.go`) was corrected: a read is skipped when the key no longer names its
  reference or its body is already indexed, not when the key passed its revision.
- **`bodies_test.go`'s missing-body message** now says "until its reference or inline text changes".
