## Choices the design leaves open

- **Nil context.** `Generate` and `GenerateQuery` refuse a nil context with an error and send nothing, even for no
  texts (developer contract: exported context-taking boundaries reject nil). Proof: `TestNilContextRefused`, not in
  D3's table.
- **Empty result.** No texts returns `nil, nil`; the test asserts `len == 0` and no request.
- **Endpoint.** `url.JoinPath(base, "embeddings")`, so a base URL with or without a trailing slash posts to the same
  path. `TestNewRefusesConfig` accepts `https://api.example.com/v1/`.
- **Non-2xx with no `error.message`.** The error names the status alone (`status_503_no_body` case).
- **Reply with no `model`.** Accepted; only a non-empty name that differs is refused (owner ruling, question 1).
  `TestVectorsPlacedByIndex`'s reply carries no model.
- **Error wording.** Only width refusals contain "dimension", so graph-embedding's `classifyEmbedErr` files them
  `dimension_mismatch`; no other refusal contains "dimension", "timeout" or "connection refused".
- **A refused reply teaches no width.** The learned width is set only after a reply is accepted whole; every
  `TestRefusesUntrustedReply` case asserts `Dimensions()` is unchanged.
- **Fuzz target.** `FuzzReplyIsWholeOrRefused` (`fuzz_test.go`): the reply body is external bytes, so the developer
  contract's fuzz rule applies. Invariant: never panics; an error comes with no vectors and no learned width; an
  accepted reply is two vectors of the width `Dimensions()` reports, each the numbers the reply carries at that
  vector's index, read by a test-owned decoder that requires a numeric index and numeric coordinates. 18 seeds,
  one per reply class accepted or refused. Seed replay runs in `task verify`. Exploration, run by hand once
  (below), found nothing.
- **Generated checks.** Beyond the fuzz target, named examples suffice: each refusal is one independent check on a
  whole reply, the checks do not interact beyond "any one refuses", and the table has a case per check.

## Not covered

- A deadline (rather than a cancel) ending the request before the reply's headers: `TestContextEndsRequest`
  cancels; that deadline path is D5's real-provider probe (task 2.3). A deadline during an error body read is
  `TestContextEndsErrorBodyRead`.
- A reply body too large to hold: the client reads the whole reply, with no size bound; none is in the design.

## Review fixes

The review at de4cc16f found three defects. Each test below was written first and run on that commit's client.

- **Context during a non-2xx body read.** A cancel or a passed deadline while the error body was being read returned
  only the status, so the error did not match `ctx.Err()`. Now the status stays in the message and `ctx.Err()` is
  wrapped when the body read failed with the context done. Test: `TestContextEndsErrorBodyRead`, cases `cancel` and
  `deadline`. The handler writes 503 headers, flushes, and blocks until the test releases it; the test swaps
  `http.DefaultClient` for a transport that signals the first body read, and ends the context only after that
  signal. The deadline case uses a test context whose `Err` is `DeadlineExceeded` once cancelled, so no clock is
  waited on. The swap is safe because the package's parallel tests start only after its sequential tests end.
- **Null coordinates and an absent or null index.** These decoded to zero and were accepted. The wire fields are now
  `[]*float32` and `*int`, and `accept` refuses a nil. Tests: `TestRefusesUntrustedReply` cases `null_coordinate`,
  `absent_index`, `null_index` (each asserts no vectors and `Dimensions()` unchanged). The fuzz oracle now compares
  each accepted vector with the reply's numbers at its index, read by its own decoder; three seeds hold these replies.
- **A base URL with no host.** `New` accepted `http:` and `http:///v1`. It now refuses an empty hostname. Test:
  `TestNewRefusesConfig` cases `scheme only` and `no host`.
