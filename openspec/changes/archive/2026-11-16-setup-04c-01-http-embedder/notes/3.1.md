## Choices the design leaves open (task 3.2)

- "Text has no matches" is read as the reply's `text.matches` being empty, so a word hit that was deleted before it
  was read back (`missing` above 0, no matches) also falls back.
- The embedding search is sent `{"query": ..., "limit": ...}` (`graph.SemanticRequest`) with no `min_revision`: the
  embedding verbs refuse one above 0, so forwarding it would make every fallback with a revision fail.
- On the `index_not_ready` path the reply still lists the hints and verifies an entity or path reference as
  globalSearch does; only `text` is null. Its `indexed_revision` is 0: no word index was read, and the embedding
  verbs claim no entity revision.
- A fallback whose reply is broken (not an envelope, no producer) is not honoured with code `internal`, and counts
  one error, as every broken reply does.
- `TestSearchGraphAnswersAsGlobalSearch` now runs with `embedding_enabled` false: the spec's "same question" scenario
  is the tier 0 one, and at tier 1 an empty answer now carries `fallback`.
- No metric is added for a failed fallback. It is declared in the reply itself (`fallback.honoured` false with code
  and reason); a timeout or missing responder also counts one Health error through `ask`. A counter of fallbacks by
  outcome would be new surface with no named reader.
