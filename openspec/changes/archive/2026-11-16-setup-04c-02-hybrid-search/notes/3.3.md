# Task 3.3: `internal/harness/scorecard` and `task scorecard:tier1`

## Choices the design leaves open

1. **The semantic verb's own copy.** graph-embedding answers from an in-memory copy of `EMBEDDING_INDEX` kept by its
   own watch, which can trail the watch the program reads. After every section has a generated record, the
   program also waits until the semantic verb answers each section: a hundred at a time, by one plain question
   ("section") scoped to their IDs, and, since the verb leaves out a vector scoring 0 or less, any section missing
   from that answer by its own body scoped to it alone. The output prints how many needed the second ask.
2. **A run that would not measure what a row names ends with exit 2**: a searchGraph reply whose merge was not
   honoured or has no text, a semantic reply counting failed or unreadable records, a failed embedding record.
3. **Words are awaited twice**, as `TestSearchScorecard` does: graph-index's `alias` verb and globalSearch, each
   with `min_revision` set to the last write's revision.
4. **Composition** mirrors the integration tests: each component through its `Create...` function, graph-embedding
   through `RegisterWithEmbedder` and a registry, graph-ingest under `c360.semengine` (the corpus IDs' authority),
   graph-query `{"embedding_enabled": true}`, graph-embedding `{"text_suffixes": [".content"]}`. Cleanups stop the
   components in reverse order, each under a one-minute budget, then close the client and remove the container.
5. **Output**: the results go to standard output, component and Docker logs to standard error, so
   `2>/dev/null` gives the record. The rows reuse the word scorecard's format.
6. **`task scorecard:tier1` is not in `task verify`**, CI or `test:tools`; only its unit tests are.

## Review round 1

Codex's review at `05c5651e` (PR #687, REQUEST CHANGES, issue #688), two findings.

1. **Exit statuses through Task.** `go run` reports every failing status as 1, and Task without `-x` reports any
   failure as 201, so `task scorecard:tier1` could not tell a floor miss from a broken run. Task now builds the
   program to `${TMPDIR:-/tmp}/semengine-scorecard` and runs it; the documented entrypoint is
   `task -x scorecard:tier1`, which passes 0, 1 or 2 through. No Taskfile setting gives `-x`'s pass-through, so the
   spec states both: the program's statuses, `-x` passing them on, 201 without it.
2. **Waits that cannot end.** The semantic verb's catch-up wait (and the word waits) retried every error until the
   process was interrupted. `awaitAnswer` (`await.go`) asks again only on `index_not_ready` or
   `revision_not_reached` refusals, or an answer still missing what is awaited, for at most five minutes
   (`readyBudget`), then names the last answer; any other error, such as graph-embedding's `internal` refusal when
   the provider fails to embed the question, ends the run with exit 2 at once.
