## Outside the task text

`TestDamagedEntityUnderPrefixOverRealResponders` is not named in task 2.2. It breaks once graph-ingest names a damaged
entity `damaged`, because `unhydratedReason` would map that reason to `unknown`. The `damaged` mapping fixes it, and
the test itself is unchanged.

## Generated check

`reconcile_prop_test.go` now draws `damaged` among the reasons. Its model maps `damaged` to `error`, and a named
witness, `damaged is error`, runs before the generated run. The `-rapid.seed=1` run above failed on main after 16
tests, so the drawn reason reaches the assertion.

## Choices the design left open

- The fake wire was renamed from `poisonWire` to `damageWire` and now answers every `entity` request with an error.
  Every test asserts that the wire saw no entity request.
- Kept beside the spec's tests: `TestDamagedDuplicateListedOnce`, which replaces `TestPoisonedDuplicateReadOnce`, and
  `TestAllSeedsDamagedDefer`, which proves `deferred` `all_seeds_unhydrated` and replaces
  `TestAllSeedsPoisonedDefer`.
- Deleted along with the per-ID read: `TestPoisonFallbackNotFound`, `TestPoisonFallbackReturnsOtherError`,
  `TestPoisonFallbackEndedContext`, `TestPoisonFallbackEmptyID`, `TestPoisonFallbackOneSeedCancelled` and
  `TestPoisonFallbackFinalSeedCancelled`. The empty-ID and duplicate cases are already covered for the batch path by
  `TestReconcileTotal`.
