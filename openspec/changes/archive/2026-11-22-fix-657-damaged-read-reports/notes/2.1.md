# Task 2.1 notes: refusal detail

Choices the design left open.

- **The key `entity_ids` is spelled at four sites.** `graph/state_contract.go` holds it as the unexported
  `detailEntityIDs`; `graph/follower/damaged.go`, `processor/graph-index/index.go` (`noncanonicalRefusal`) and
  `processor/graph-ingest/query.go` (`aggregateEntityPoisonError`) write the literal. An exported constant or an exported
  refusal constructor would remove the repeats, but the proposal names one new export, `StateRefusalEntityIDs`. Each
  site's test reads the detail back through the helper, so a misspelling fails a test. Widening to a shared constructor
  is a reviewer or architect call.
- **A refusal with no key carries no detail** (`ValidateDecodedEntityStates`' refusals): no `Detail` map at all, so
  the helper returns nil, as the spec delta says.
- **Each once.** `aggregateEntityPoisonError` compacts the sorted list. Its one caller, the prefix verb, passes keys
  from a sorted, unique listing, so the message text is unchanged in every reachable case.
- **The helper returns the caller's own copy** of an in-process list (`slices.Clone`), so a caller cannot change a
  follower's recorded refusal, which later replies reuse. A JSON list holding any non-string returns nil rather than a
  partial list.
- **Two more tests than the task names**, for the two refusal sites a wire read does not reach:
  `TestReportWithNoRefusalNamesTheEntity` (`graph/follower`) and `TestNoncanonicalRefusalNamesTheKey`
  (`processor/graph-index`, a key that is not a literal ID, which no query can name).
- **Generated checks are not used.** The helper has two input shapes and one code check; the named cases in
  `TestStateRefusalEntityIDs` are the whole space.
