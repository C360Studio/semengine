# Task 2.2 notes: value filter

Choices the design left open.

- **The filter stops at the first damaged value it reads.** The refusal is `graph.UnmarshalEntityState`'s own, so
  `entity_ids` holds that one entity, which is every damaged entity the filter read: "each damaged entity it read,
  sorted" is met with a list of one. Reading on to name every damaged entity would mean more ENTITY_STATES reads for a
  request that is refused anyway, and a second refusal builder beside `stateRefusal`. A caller that repairs B and asks
  again learns of the next one. Widening to name all of them is a reviewer or owner call.
- **The handler tells the two failures apart with `graph.IsStateContractError`**
  (`processor/graph-index/query.go`, `handleQueryPredicate`), returning the refusal unwrapped and wrapping every other
  error in `internalError` as before. `entitiesWithValue` already returned the decode refusal bare and wrapped the
  `Get` error, so it needed only its doc comment.
- **The test stores the membership row by hand**, as `TestMalformedIndexRowsAreSkippedLoggedAndCounted` does: no
  graph-index writer stores a row for an entity it recorded damaged. It sends the refused request with `query`, not
  `settled`, because on the old code the answer is transient and `settled` retries transient answers.
- **Generated checks are not used.** One input shape (a stored value that does not decode) decides the outcome;
  the one named case is the whole space.
- **Not covered by a test: an ENTITY_STATES read that fails for another reason** still answers transient `internal`.
  The arm is unchanged, and reaching it needs a fault the code does not choose (the bucket failing between the
  membership listing and the value read).
