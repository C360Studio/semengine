# Task 2.3 notes: skipped-row counts

## A predicate named twice in a compound query

`predicateCompound` lists each predicate it is given and adds up the rows each listing skipped. A predicate named
twice is listed twice, so its malformed rows are counted twice. This matches the
`semengine_graph_index_query_rows_skipped_total` metric, which counts each listing's skips the same way, so the reply
and the metric agree for every request. Counting each row once would need the compound handler to remember row keys
across listings for a case no caller has: a caller that names a predicate twice gets the same rows either way.

## Why named examples suffice

The count depends on one input per index: whether a row has that index's layout. The test stores one malformed row
per index layout (incoming, alias, predicate, name key, name value) and asserts every one of the seven verbs, plus a
clean request per verb that must carry 0. There are no interacting inputs or order-dependent history to generate.
