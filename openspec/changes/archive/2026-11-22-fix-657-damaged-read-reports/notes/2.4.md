# Task 2.4 notes: embedding scope

Choices the design left open.

- **`ListCounted` takes `keep` in place of its prefix.** Its one caller passed `""`, so the prefix was dead surface; a
  filter is the shape the caller already has (`FindSimilar`'s `keep`). A nil `keep` accepts every key. The filter
  applies to the listing and to the count alike, so "every key is listed or counted, never both" still holds, and
  `FindSimilar` no longer checks `keep` itself.
- **`keep` runs after the view's lock is released.** The entries and the poisoned keys are copied under one hold (the
  one-moment read), then filtered. Calling caller code under the lock would stall every write while it runs, and
  `TestFindSimilarReadsOneMoment` and `TestVectorCacheInvalidationLinearizesWithActiveRead` block or write from inside
  `keep`; under the lock they deadlock. Copying the poisoned keys costs one string slice per call, sized by the
  poisoned count.
- **A `graph-view-subscription` delta is added.** Its requirement "An enumeration counts what it cannot serve" named
  `ListCounted(prefix)`, which no longer exists. The proposal lists five capabilities; this is a sixth, and task 3.1's
  wording now says six. The proposal itself is unchanged.
- **The search-level proof is one assertion in `TestSimilarEdges`**, which already holds an undecodable record: a
  `search` whose `scope` is another entity's ID answers `unreadable_records` 0. It shows `query.go` hands the scope
  to the count.
- **`TestVectorCachePoisonCountedAndHeals`'s scoped check now expects 0**: its `keep` accepts only b, and both
  unreadable keys are a and c.
- **Generated checks are not used.** The count is a filter over a set of keys: accepted or not is the only input that
  matters, and the named cases cover both, with nil `keep`.
