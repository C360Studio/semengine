# 2.2: choices the design leaves open

- **Where the check sits.** In `NewComponentManager`, right after the one configuration snapshot is read
  (`bootConfig := currentConfig.Get()`) and before the `ComponentManager` value is built, so it precedes
  `cm.initialize()` and every factory. It compares against that same snapshot, so the pair checked is the pair the
  components would be built under.
- **One unexported helper, `checkPlatform`.** It takes the given `types.PlatformMeta` and the snapshot's
  `config.PlatformConfig`. No exported surface changes.
- **Error shape.** `errs.WrapInvalid(..., "ComponentManager", "NewComponentManager", "platform check")` around
  `deps.Platform (org %q, platform %q) is not the configured platform (org %q, id %q); build it from the
  configuration manager's GetConfig().Get().Platform after Start`. Quoting with `%q` makes an empty field visible
  as `""`. The test pins the two parenthesised pairs, nothing else of the wording.
- **Fixtures.** Each of the three reads `GetConfig().Get().Platform` from the started manager it already holds and
  copies `Org` and `ID`; no fixture helper was added. The boot-only fixture still derives its bucket name from the
  declared stem (`config.BucketName("test", "boot-only")`), which is correct: the bucket is named from the stem.

## Mutation checks

`task mutate:check` takes no build tag, and this test is integration-tagged, so each wrong change ran through the
same mechanism by hand: a copy of `service/component_manager.go` outside the repository, swapped in with
`go test -tags integration -overlay <json> -count=1 -run TestComponentManagerRefusesAPlatformOtherThanTheEstablishedOne
./service/`. Nothing in the tree was edited. The unchanged code passed after the runs.

| Wrong change | Observed |
| --- | --- |
| compare only `Platform`, not `Org` | detected: `org empty, platform equal` and `org different, platform equal` fail at `:97` (no error) |
| accept a pair with either field empty | detected: the four half-empty cases fail at `:97` |
| `errs.Wrap` in place of `errs.WrapInvalid` | detected: the seven refused cases fail at `:98` (`errs.IsInvalid` false) |
| run the check after `cm.initialize()` | detected: refused cases fail at `:103` (factory count 1, want 0) |

## Not anticipated by the design

- `task mutate:check` cannot run an integration-tagged test (no `-tags` flag). Worked around with a manual overlay
  as above; not filed, since the tool's scope is a separate question.
