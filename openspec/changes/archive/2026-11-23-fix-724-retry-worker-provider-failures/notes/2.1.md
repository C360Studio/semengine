## TLS probe at go1.26.11

`untrusted_certificate_is_not_transient` drives `net/http`'s default client against `httptest`'s TLS server,
whose certificate the client does not trust. At go1.26.11 the error `Client.Do` returns matches
`*tls.CertificateVerificationError` with `errors.As` (the subtest asserts it, and it passed both before and after
the change). The embedder checks that type before marking a no-reply error transient, so a certificate failure
stays unmarked and is filed `embedder_error`.

## Choices the design left open

- Error text. A transient error reads `httpembedder.embed: embeddings request failed: <cause>`, the shape
  `errs.WrapTransient` gives; the cause drops its own `httpembedder:` prefix so the name is not said twice. A 429
  reads `httpembedder: provider answered 429 ...: <provider message>: rate limited`, the sentinel joined with
  `%w`, not wrapped by `WrapTransient`: matching `errs.ErrRateLimited` already makes it `errs.IsTransient`. The
  action word `embeddings request` holds none of "timeout", "connection refused" or "dimension".
- A 504 reply. Its status text is "Gateway Timeout", so the Worker's text check files it `timeout` before
  `errs.IsTransient` is reached, as D2 (A)'s order says. Both reasons are retryable; the README says so.
- Which no-reply errors are transient. Every `Client.Do` error but a certificate failure: refused, reset, DNS
  and the caller's own context ending. The last is filed `timeout` (deadline) or caught as shutdown
  (`context.Canceled` with the Worker's context ended) before any reason is read.
- The TLS server in the test is `httptest.NewUnstartedServer` plus `StartTLS`, which is what
  `httptest.NewTLSServer` does, so the server's log of the abandoned handshake can go to `io.Discard`.
- `TestScanFailed_KeepsProviderReasons` puts the failed records directly, as the neighbouring scan tests do,
  rather than through `SaveFailed`; `SaveFailed` stores the reason it is given unchanged.
- `RetryableReason` sits in `storage.go` beside the closed set and `normalizeFailureReason`.

## Residual

- `errs.IsTransient` reports `context.Canceled`. A canceled error the Worker sees while its own context is still
  live (an embedder canceling something of its own) was `embedder_error` and is now `provider_unavailable`, and so
  retryable. No path in this repository produces one.
- A product embedder that marks nothing keeps today's filing: its 5xx-shaped outages are `embedder_error`, not
  retried. The README tells it how to mark them.
- Nothing retries yet: the retry lane is task 3. This task only names the reasons and says which are retryable.
