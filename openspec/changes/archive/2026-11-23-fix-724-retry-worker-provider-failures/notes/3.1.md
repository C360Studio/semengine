## Not covered

- The re-check of "waiting" under `hop1Mu` in `retryEntity`: a delivery must write its pending record between
  `retryTargets` and the lane taking `hop1Mu`. No test can order that without a hook in production code; it is
  review only. Without the check the cost is one extra pending write for an entity already queued.
- `queueing` running before the pending write rather than after it: the Worker would have to report the record's
  outcome before `SavePendingGuarded` returns. Not reachable by a test without fault injection; review only. Moved
  after the write, an entity whose outcome arrived first would wait forever.
- D5's limit (a NATS fault during a retry) is declared in the README, not tested, as the design says.

## Generated checks

`TestFailedMapHistoryMatchesModel` keeps its generated histories; they now draw a success's kind (generated,
skipped, deleted) and the new `queueing` step, and show neither moves the count, the reasons or hop 1's repair
targets. Retry targets are proven by named examples in `TestRetryTargets`, not a generated model: each rule (retryable
and not waiting; a wait ended only at or above its revision; one then all; skipped and deleted are not vectors; a
refused vector and a vector for an entity not failed are not either; seeded waits; the cursor and its wrap) is one
named step with an exact set, and each wrong change above fails at its own step. A model of the cursor and the wait
would restate `retryTargets` line for line rather than check it against an independent rule.

## Choices the design left open

- **Where the wait is set.** `failedMap.queueing`, called by `queueEntity` under `hop1Mu` just before
  `SavePendingGuarded`, marks a Worker failure waiting for that record's revision. Before, not after, because the
  Worker can report the record before the write call returns. A failed write (`mark`) or a generated record found
  standing (`ended`) replaces the entry, ending the wait. `queued` is unchanged.
- **The wait is a revision, not a flag.** It ends on a Worker outcome at or above the queued record's revision; an
  outcome below it (an older record's) leaves it standing. A seeded failure waits for its own record's revision.
- **The cursor after "all".** A pass that returns every target sets the cursor to the last of them, so the next pass
  that returns one wraps to the first.
- **What counts as a stored vector.** `OutcomeGenerated` that actually clears a failure the map holds. A vector
  below the failure's revision (refused) or for an entity not failed does not switch the next pass to all.
- **The re-check.** `retryEntity` takes `hop1Mu`, asks `failedMap.retryable`, and only then runs the same
  `reconcileLocked` as `reconcileEntity`; `reconcileEntity` now locks and calls it.
- **Docs outside the task list.** `docs/admission-ledger.yaml`'s httpembedder row said an outage's failures wait for a
  new revision or a restart; that is no longer true, so its sentence now says the repair lane retries them. The
  README's diagram label "retries hop 1's failures" became "retries failures".

## Review fix

The cross-agent review of PR #733 at `04fe488d` found one blocking defect, filed as #735; this PR closes it. In
`failed.go`, `worker` kept a newer pending record's wait but stored an older record's outcome. A slow retry overtaken
by a new write of the entity fails, its failed record is superseded by the new pending record, and the Worker reports
it `OutcomeSkipped`. That cleared the failure while the new record still waited, so the entity read not failed and a
later failure counted in `ErrorCount` again. The spec delta says the entity stays counted failed until the waiting
record reports.

The fix adds `workerOutcome`, used by `failed` and `succeeded`, the two calls the Worker's callback makes. While the
entity waits, an outcome below the waiting revision changes nothing, failure or success: the held failure keeps its
reason and its wait. `worker` keeps only the revision fence and is still what hop 1's `ended` and the Start seed call,
so hop 1's own outcomes end a wait as before.
