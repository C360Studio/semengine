# 2.3: a restart keeps stored vectors when the width is declared

## Choice: a sibling test, not the `same-provider` case

`TestDeclaredWidthRestartKeepsVectors` in `processor/graph-embedding/provider_switch_integration_test.go`.
`TestProviderSwitchRestart` drives an in-test `switchEmbedder` and checks search and similar across a provider
switch. The task wants the real `httpembedder` against a fake HTTP provider, with a count of the requests that
provider receives. Putting that into the `same-provider` case would give one case of the table its own embedder
kind and its own assertions. A sibling test keeps the table as it is and states this one behaviour directly.

The test builds graph-embedding with `httpembedder.New(Config{..., Dimensions: 2})` against an `httptest` provider
that counts requests. It stores one entity's vector, stops, and starts a second component on the same NATS state.
Each start builds a new embedder, so the restarted one has learned no width. After the restarted follower's
indexed floor passes the entity's revision, the test asserts:

- the provider saw no request since the restart;
- the stored record is unchanged (same `GeneratedAt`).

The Worker's terminal write for the replayed revision comes after any request it would send for the entity, and
the floor moves only after that write. So the request count read after the floor is ordered after any such request.

## Failing with the width removed

`Dimensions: 2` removed from the test's config (the file backed up first, then restored; SHA-256 `c02404c1...c838`
before and after):

```text
--- FAIL: TestDeclaredWidthRestartKeepsVectors (0.27s)
    provider_switch_integration_test.go:237: provider saw 1 requests after the restart, want none: the stored vector is unchanged
FAIL
FAIL    github.com/c360studio/semengine/processor/graph-embedding    0.726s
```

With the width declared it passes:
`go test -tags integration -race -count=1 -run TestDeclaredWidthRestartKeepsVectors ./processor/graph-embedding/`
gives `ok`.
