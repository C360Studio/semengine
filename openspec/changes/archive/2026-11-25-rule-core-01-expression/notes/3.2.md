`transition`'s three limits (owner ruling, PR #753 comment 7163777239):

1. Entity rules only: `evaluator.go:275-284` (nil entity: false, or an error when required). Checked further: a
   `transition` on a `$state.`, `$prev.`, `$entity.lifecycle.` or `$message.` field never reaches
   `evaluateTransition`; it falls to `applyOperator`, which has no `transition` entry, so it is an unsupported-operator
   error. `TestTransitionOnStateOrMessageFieldIsRefused` was added for it.
2. Batching: not checked. The entity watcher is not ported; the guide says so in plain words ("This is not yet
   checked"). PR 10's design confirms or corrects it.
3. Equality only: the previous value is recorded as text at the pin's `processor/rule/stateful_evaluator.go:514-518`
   (`values[triple.Predicate] = fmt.Sprintf("%v", triple.Object)`, read at `8b99efe9`); here `evaluator.go:293`,
   `:309`, `:319` compare with `compareValues`, equality only. The guide says the recording is the rule engine's,
   not yet in this repository.

Choices: examples use three-part predicates (`fleet.drone.type` for the pin's `entity.type`); the "Next Steps" links
to guides not yet in this repository are dropped; the "Type Coercion" and "Field Types" tables, which described
behaviour the code does not have, are replaced by "Comparing values".
