## Survivors

- **0, strict rule decode off** (`DisallowUnknownFields` removed from `DecodeDefinition`), and **9, strict `when`
  decode off**. Both are equivalent mutants. After the step-C ruling (`notes/2.5.md`), the exact-key check compares
  every key of the rule, its entity config, each condition and each `when` condition with the declared set. It
  refuses every key `DisallowUnknownFields` refuses, with the same message (`json: unknown field "<key>"`). No test
  can tell the two apart. `DisallowUnknownFields` stays because design D4 names it.

## Tests strengthened

- **37.** `TestLoadRefuses/a_condition_with_no_operator` expected the cause `operator`, which the `unknown operator ""`
  refusal also contains. It now expects `no operator`.
- **41, 42.** `TestActionBody`'s "Load refuses" cases checked only "build the action by decoding", which all three
  refusals (no body, a body that does not decode, fields that differ from the body) say. Each case now also names its
  own cause: `no body`, `cannot unmarshal string` and `differs from its body`.

## The three invalid mutants

38, 43 and 48 left a variable unused (`known`, `same`, `i`), so they did not build. Each was rewritten to keep the
variable (`&& false`, `i*0`) and run again.
