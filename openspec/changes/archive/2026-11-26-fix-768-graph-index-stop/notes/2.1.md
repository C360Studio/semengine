# 2.1 notes: the failing-first test

Test: `TestStopDropsQueuedWork` in `processor/graph-index/lifecycle_integration_test.go` (integration tag; it needs
the package's NATS server, which is what stands up the pool and the follower).

## How the lane is held

graph-index has no hook into its lane, and none was added. The lane logs `indexed entity` (Debug) after an entity's
writes and before its revision completes (`processor/graph-index/index.go`, `indexEntity`). The test's log handler
(`holdFirstIndexed`) blocks that first record on a channel, so the one lane holds one entity in flight and the other 49
of the 50 stored entities queue behind it. The handler is the component's real logger dependency, given through
`component.Dependencies.Logger`.

## Order of events

1. 50 entities stored before `Start`; `{}` config, so one lane and no coalescer.
2. The handler reports the entity in flight; the test then waits until all 50 entries are counted (the last counted
   entry means every earlier submit returned).
3. `Stop` under an already-ended context returns `context.DeadlineExceeded`. `cleanup` never returns early on an
   earlier context error, so it has reached `pool.Shutdown`, after which the flag (task 2.2) is set.
4. The lane is let go, and a second `Stop` under a 5 s context must return nil. That deadline is the behaviour under
   test, not a wait for work that must finish.

## Oracle

Independent of the implementation: what the test stored and what it observes on the server and the follower.

- `OUTGOING_INDEX` holds exactly one key, the entity in flight (written before the hold).
- No entity is in the failed set (`failedTotal() == 0`), and `ErrorCount` is unchanged.
- The follower's floor (`Indexed()`) stays below the lowest revision of the queued entities: none completed.
- No `readiness withheld` text, and no WARN or ERROR line, in the component's log.
