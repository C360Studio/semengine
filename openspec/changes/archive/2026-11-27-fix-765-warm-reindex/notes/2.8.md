## Choices

- **One lane in every phase, the cold build included.** Step 2 built cold on 16 lanes; this run's cold build (666 s)
  is therefore not comparable with step 2's 93 s.
- **The live-change breakdown applies a changed value by the calls `runApply` makes**, without writing ENTITY_STATES,
  so the follower stays idle while the steps are timed; the real `reconcileEntity` then takes the index back to the
  stored value, a change of the same size. The end-to-end figure comes from 1,000 real ENTITY_STATES writes.
- **Each change moves the title and one relationship target**, so 5 row writes. A change of a plain property value
  alone plans the same rows and is skipped, so it would measure the unchanged path.

## Not measured

- Repeat runs; other sizes and lane counts.
- A listing pass over full indexes, which a record-format change or a reset causes. The README's "about 38 minutes at
  40,000 on one lane" for it is step 2's inferred figure, which this run does not replace: the cold build lists over
  indexes that start empty.
