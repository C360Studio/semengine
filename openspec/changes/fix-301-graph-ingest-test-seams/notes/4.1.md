# Task 4.1: unit tests and `inputLane`

Base: `22421cb`. The four test-only fields and their nil-checks stay until 4.2. The `consumeStream` override still
wraps the same call, which now passes `func(_ context.Context, m jetstream.Msg) { lane.deliver(submitCtx, m) }`.

## Choices the design does not spell out

- `inputLane` and `deliver` sit at the end of `consume.go`. `deliver` is the closure body moved as it was: the same
  statements, log text and comments, with `c.` read as `l.c.` and each captured value read from the lane.
- `startStreamLane` builds the lane itself and no longer runs `setupSubscriptions`. It uses the values the default
  `entity_stream` port gave before: subject `entity.>`, no import, generation `time.Unix(1, 0)`, and the shared
  `testConsumer` and `testHeartbeat` from `keyed_ingest_test.go`, which hold graph-ingest's default 30 s wait and a
  quarter of it. `deliverStreamLane` takes the lane and calls `deliver`. The callers in `derived_time_test.go`,
  `fact_lane_fence_test.go`, `write_modes_test.go` and `statement_metadata_test.go` changed only the variable's name
  and type (`handler` became `lane`) and the comments that named the consume closure.
- With that, no unit test reads a port's values through `setupJetStreamConsumer`. The integration tests still do:
  `TestConfigAckWaitAndHeartbeatInterval` for the timing, the authority gate test for the `entity.>` label, and the
  guard generation integration test for the generation.
- The straddle test is `TestInputLaneNaksAfterFailedStartRollback`, in a new file, `input_lane_test.go`. Its failing
  start derives the pool and submit contexts from Start's context and records their cancels on the component, as
  `start` does, so the rollback's `release` ends them. It then builds the pool and the lane and fails. After Start
  returns, the test checks that the submit context is canceled, calls `deliver` with it and a valid Graphable input,
  and checks for exactly one disposition, a Nak, and no stored entity. `deliver` settles a refused submit before it
  returns, on the test's goroutine, so the reads need no other wait. A panic in `deliver` fails the test.

## M1: `deliver` acks a refused submit

The mutant replaces `msg.Nak()` with `msg.Ack()` in the submit-failure branch of `deliver` (`consume.go:312`). It ran
through `task mutate:check`, which builds it with an overlay and leaves the tree as it was (`consume.go` sha256
`5eb276b2…` before and after):

```bash
task mutate:check -- -pkg ./processor/graph-ingest -test TestInputLaneNaksAfterFailedStartRollback \
  -file processor/graph-ingest/consume.go -mutant "$M" -expect input_lane_test.go:67
```

Verdict: detection. All three baseline runs passed. Each of the three mutant runs failed with
`input_lane_test.go:67: disposition = ack, want nak`, and the run after passed.
