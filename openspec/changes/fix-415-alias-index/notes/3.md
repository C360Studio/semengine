## Choices the design leaves open

- **Key helpers.** `aliasIndexKey` is `nameCompositeKey(nameIndexKey(alias), …)`, so the alias is trimmed and
  case-folded by NAME's own hash (ADR-114 §1). The read therefore already folds case and space; task 5 adds the
  tests that pin it. `aliasIndexEntityFilter` returns NAME's `*.<entity6>.*`.
- **Two or more holders, before task 4.** The read collects the distinct entity IDs of the listed rows and refuses
  when there are two or more: class invalid, code `invalid_request`, message `alias "<alias>" is held by <n>
  entities`. Task 4 changes only that code (one `errs.ClassifiedCode` call, marked `// shortcut:` in `query.go`).
  No test drives it yet; `TestSharedAliasIsRefusedAsAmbiguous` (4.1) does.
- **Malformed alias row, before task 6.** The read refuses the whole request as `internal` naming the key (fail
  closed). Task 6 replaces that one return with `skipMalformedRow("alias", …)`; marked `// shortcut:`.
- **Kept until task 5.** The plan's KV-unsafe skip, `aliasesSkipped`, and the read's `ValidateKVLiteralKey` refusal
  stay. `TestUnsafeAliasSkipIsLoggedAndCounted` changed one line only: its `ALIAS_INDEX` key assertion now names
  the owner-keyed key for `alpha-1`.
- **3.3 fixture.** The alias predicate is `f…64.b…64.e…64` (194 bytes), outside the `a…` namespace the
  test's `predicateList` checks count, so those expectations stand. The test now restores the registry with
  `defer vocabulary.SnapshotRegistry()()`, which also covers the label predicate it already registered.
