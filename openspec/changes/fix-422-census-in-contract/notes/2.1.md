# Task 2.1 notes: the allowlist guards and their failing-first evidence

The guards are in `internal/harness/contract/consumerpolicy_test.go`. Every test that
`natsclient/consumer_policy_callsite_test.go` held keeps its name there, except
`TestParseProductionGoFilesIgnoresClaudeWorktrees`, whose walker is gone.

## Choices the proposal does not spell out

- **Two allowlists, one per guard.** `policyEntryPointAllowlist` holds
  `processor/graph-ingest/consume.go`; `directConsumerCreationAllowlist` holds `natsclient/stream.go`. Their union
  is the spec's allowlist. One shared list would let `consume.go` create a consumer directly, or `stream.go` call
  an entry point, without a guard noticing; the census before this change refused both.
- **The port-backed rule stays.** The old census also failed when one file both read `GetConsumerConfig` and
  consumed through `ConsumeInternalStreamWithConfig`. It is kept, so `consume.go` cannot move to the internal path
  even though it is on the entry-point allowlist. Sensitivity subtest: "port-backed file on the internal path".
- **References, not only calls.** Both guards match a selector of one of the seven names, so a method value
  (`consume := c.ConsumeStreamWithConfig`, the form `consume.go:152` uses) counts. The old direct-creation census
  matched only call expressions and keyed them by argument count (`/args=2`); with a file allowlist the argument
  count no longer decides anything, so it is dropped. Violations name `file:line` and the method.
- **Fail closed on reading nothing.** `productionGoFiles` fails the test on a parse error and when the listing
  holds no production Go file; `natsclientFiles` fails when nothing is under `natsclient/`.
- **The three natsclient surface guards** (`TestConsumerPolicyExportedClientAPICensus`,
  `TestNoDeliveryDispositionExportedSurface`, `TestClientHasNoChildLifecycleSurfaceOrCatalog`) had no sensitivity
  test in natsclient. `contract/doc.go` says every check in the package has one, so each check now returns its
  violations and `TestNatsclientSurfaceGuardsRejectPlantedSurface` plants one of each under `natsclient/`. They
  read the files under `natsclient/` (including `natsclient/storagereport/`), the tree their old `"."` walk read.
- **Generated checks are not used.** The input is a fixed set of seven method names and a file list; the
  planted subtests name one case per method plus the method-value and port-backed shapes.
