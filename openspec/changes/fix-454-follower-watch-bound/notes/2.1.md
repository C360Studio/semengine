# Task 2.1 notes

Choices the proposal does not spell out.

- **Names.** The test names the budget `watchDrainBudget` and the error `errWatchDeliveryOpen`, both unexported in
  `graph/follower/follower.go` (task 2.2). The test checks `watchDrainBudget` against the spec's 5 s before it uses
  it, so the expected wait comes from the spec, not from the code under test.
- **The scripted watcher** (`openWatcher` in `follower_test.go`) returns nil from `Stop` and never closes its
  channel. A nil `Stop` keeps the test on the bound alone; the tolerated `Stop` errors are unchanged by this change.
- **Failing on base.** The test cannot compile on base (41a111c): `stopWatch` takes no context and neither name
  exists (`go vet`: `follower_test.go:73:5: undefined: watchDrainBudget`). It was run with `go test -overlay`,
  replacing `follower.go` with the base file plus only a compile shim: the two names declared, `stopWatch` given an
  ignored `_ context.Context` first parameter and `follow` passing `ctx`; the drain loop is base's, unbounded. Result:

  ```text
  --- FAIL: TestStopWatchGivesUpOnADeliveryThatNeverCloses (0.00s)
  panic: deadlock: all goroutines in bubble are blocked [recovered, repanicked]
  ...
  github.com/c360studio/semengine/graph/follower.stopWatch(...)
  FAIL github.com/c360studio/semengine/graph/follower 0.233s
  ```

  The deadlocked bubble goroutine is blocked in `stopWatch`'s drain.
- **The 2.1 commit does not build** the test package on its own: it holds the test ahead of the code it calls, and
  the 2.2 commit makes it compile. The PR squash-merges, so main never carries it.
