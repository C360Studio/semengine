# Task 2.1: the test fails on the base commit

The test names `guardWatchDrainBudget` and `errGuardWatchDeliveryOpen`, which task 2.2 adds, so on the base commit it
was run with `go test -overlay`, adding one file that declares only those two names (a 5 s constant and a placeholder
error) and changes no behaviour:

```text
go test -overlay overlay.json -run TestEntityStateGuardGivesUpOnADeliveryThatNeverCloses -count=1 ./processor/graph-ingest
--- FAIL: TestEntityStateGuardGivesUpOnADeliveryThatNeverCloses (0.00s)
    --- FAIL: TestEntityStateGuardGivesUpOnADeliveryThatNeverCloses/after_the_end-of-snapshot_marker (0.00s)
panic: deadlock: all goroutines in bubble are blocked [recovered, repanicked]
```

On base the sweep reads the marker, stops the watch, and blocks for good in `for range updates`; with no timer pending,
synctest reports the deadlock. The panic ends the package's run, so the cancelled-context case did not run on base; it
blocks in the same loop.

The scripted watcher's channels are made inside the bubble (inventory review on PR #459): a read of a channel made
outside does not count as durably blocked, so the bubble's clock would never advance and the test would hang instead of
failing. `ingestGuardWatcher` cannot be reused, because its `Stop` closes the channel.
