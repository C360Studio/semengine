## Choices the design leaves open

- `listingStacks` matches `jetstream.(*kvs).ListKeys.func1` and appends `natsfixture.NativeDeliveryStacks()`, so
  one `AwaitNoStacks` covers both stacks D3 test 1 names. The bound is the file's `watchBound` (10s).
- The test writes the 600 raw values with `jetstream.KeyValue.Put` on the bucket graph-ingest created
  (`ingestClient`, `startGraphIngest`), workflow `gate-fixture`. It uses `t.Context()`, no deadline of its own.
- `fakeBucket.WatchFiltered` refuses any pattern but `">"`, so a unit test fails if `List` stops listing every key.
  Without `fakeBucket.listing` it delivers `listKeys` and the nil marker; with it the test feeds an unbuffered
  `fakeListing`, whose send returns once `List` has taken the key, which orders the cut after one key.
- `fakeListing` closes `Updates` once, in `Stop` or in the 2(ii) script's `end`.
- `fakeBucket.ListKeys` now panics like the other methods `Manager` does not call; `fakeKeyLister` is removed.
- `List`'s doc also states that a read error other than a missing or non-lifecycle entity returns no participants
  (already the behaviour at `:70`), since the error contract is now stated there.
- `ListKeys` callers left after this task (`git grep -n ListKeys -- '*.go'`): `natsclient/storagereport` (task 2.3),
  `jetstream.KeyValue` in tests (`graph/kvcatalog/storage_report_integration_test.go`,
  `natsclient/kv_key_contract_integration_test.go`), and test doubles in `graph/embedding`, `processor/graph-ingest`
  and `pkg/lifecycle`. None goes through `CatalogReader`; all compile.
