# Task 2.1: the test fails on the base commit

Command, with `processor/graph-index/component.go` at the base commit:

```text
go test -tags integration -race -count=1 -timeout 90s -run TestStopWithAStuckHandlerStopsEveryOtherVerb ./processor/graph-index/
```

Result: the wait for the verbs to go quiet never ends, at `lifecycle_integration_test.go:298`, because they keep
answering. The test sets no deadline of its own, so `go test -timeout` ends the run. The 90 seconds here only shorten
the run; `task test:integration` allows ten minutes.

```text
panic: test timed out after 1m30s
  running tests:
    TestStopWithAStuckHandlerStopsEveryOtherVerb (1m30s)
```

With the change restored, the test passes in about 2.5 seconds.

The test ends `Stop`'s context while `Stop` is running. The lifecycle refuses a context that has already ended without
running `cleanup`, so a context cancelled before the call would fail this test with or without the fix.

## Generated checks

Not used; one fixed example covers this. The change is a loop over a fixed list of subscriptions, and each drain's
result does not depend on another's, so the only order that matters is where the stuck handler sits. The test puts it
first, the worst position, where all eight verbs follow it. A later position leaves fewer verbs behind it through the
same loop. The retry after the handler returns is the same example's last step, and repeating a drain is
`Subscription.Drain`'s own contract, which this change does not touch. A drain that fails with an error other than the
context's takes the same path through the loop and is not run separately.
