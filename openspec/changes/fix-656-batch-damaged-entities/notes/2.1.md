## Generated check

`TestBatchAccountingMatchesModel` (rapid). Each case draws one to six IDs, each good, cached, damaged, absent or
empty, and a request of one to ten of them with repeats. `batchAccountingModel` maps each requested occurrence to an
outcome from its drawn state alone. The law: the reply's entities and `missing` match the model's multisets exactly,
the reply is not a refusal, and exactly the requested damaged IDs are recorded. Every assertion runs in every case.
The named cases (`TestBatchAccountingNamedCases`) run the boundaries first: all damaged, a damaged ID twice, a cached
entity beside damage, the empty ID beside damage.

- Run: `go test ./processor/graph-ingest -run '^TestBatchAccountingMatchesModel$' -count=1 -race -v
  -rapid.checks=1000 -rapid.seed=6561` gave `[rapid] OK, passed 1000 tests`.
- Mutation check: `task mutate:check -- -pkg ./processor/graph-ingest -test TestBatchAccountingMatchesModel -file

## Choices the design left open

- How the shared fetch tells the batch from the prefix page apart: `fetchEntitiesConcurrent` now returns an
  `entityFetch` (entities, `missing` with reasons, and the damaged entities' refusals) and treats damage as no error.
  Each caller decides: the batch returns `missing` as is; the prefix page refuses with the same aggregate error as
  before whenever anything is damaged, checked before any other read fault, so damage still outranks a fault there,
  as it did.
- The empty ID's `error` reason is now set where the ID is skipped, inside the fetch, and `batchMissingReason` is gone;
  the counter and the wire both read the reply's own entries.
- The debug log gives the counts as a `by_reason` group (`by_reason.not_found=1 by_reason.damaged=1`), naming only
  reasons that occurred.
- Order inside `missing`: empty IDs first, then KV misses in request order, damaged and not-found interleaved. The
  reply has never promised an order.
- `TestEveryEntityReadRefusesTheSameStoredPoison`: the batch entry left the refusing-sites table and became its own
  subtest beside it, with the same recorded/not cached/not deleted assertions, so the other three sites' loop body is
  unchanged.
