## Choices the design leaves open

- **The per-call record is `skipLog`.** Every read site already takes the one call's `*skipLog`, so the largest count
  is kept there (`sawDamaged`) rather than in a second per-call value threaded through the same functions. Its doc
  comment now says it records what the call's reads left out: skipped reads and the largest damaged count.
- **Which reads count.** Every read that answered: `Resolve` (any mode), each relations read (`collectEdges`), each
  impact, paths and graph walk read (`neighbors`), and the miss's `Names` read. A failed read returns no count, so it
  adds nothing; a failed `Names` read is treated as an empty `Names`. `Entity` and `Entities` read graph-ingest's
  bare `entity` and `batch` replies, which carry no envelope and so no count; they are unchanged.
- **Every resolve mode.** Unlike `bodies_not_indexed`, which only a word search sets, the count is copied after a
  symbol or prefix resolve too, since a relations or walk read can report it in any mode. `prefixIDs` is a bare row,
  so a prefix resolve itself reports 0.
- **A deferral after the resolve answered carries the count** (all seeds unhydrated, or a relations read not ready),
  as it carries `bodies_not_indexed`. A deferral from `Resolve` itself read nothing and carries none.
- **`decodeReply` returns `(T, int, error)`**: the data and the envelope's count; a bare row returns 0. Two non-error
  returns, so no struct.
