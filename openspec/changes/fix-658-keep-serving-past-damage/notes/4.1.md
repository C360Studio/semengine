## Generated checks: used

The record is an order-dependent history (reports, completions, deletes per key), so the rule is checked by
`TestPropDamagedSetFollowsLatestEvent` against a reference model. The model keeps only the history; it reads the
requirement off it: a key is recorded exactly when some report of it has no later completion or delete above that
report's revision. That is the requirement ("one entry per key at the highest reported revision, dropped by a
completion or delete above it") stated over the history rather than as the implementation's running maximum, so a
plausible bug in the running state disagrees with it.

Each completion or delete of a key that has a report is drawn at the last report's revision minus 1, at it, or above
it by 1 or 2, so every boundary the requirement names is reached by construction. Reports draw revisions 2 to 9 (so
"below" is never 0) and can go down as well as up. After every step the check compares each key's `DamagedRefusal`,
`DamagedCount` with no filter and with a prefix filter, the envelope's `failed_count` and
`failed_reasons["damaged_entity"]`, and Stuck's damage sentence; a report's return value is checked inside the step.
Deletes go through `observe`, as the watch delivers one; a drawn delete below a revision already delivered declares
the feed lost, which the check leaves out of Stuck on purpose.

Named witnesses run first through the same checks: a completion at the report, a lower report after a higher one, a
clear then a lower report, a delete at the report, and keys apart.

## Spec wording

The delta's "Any history" scenario says a key is recorded "exactly when its last report is above every later
completion and delete". Read literally, a completion at the reported revision would clear the key, against "Report,
then repair" and "A completion below the report" in the same requirement, and a lower last report would decide
against the highest. The test follows the requirement and those scenarios (at or below changes nothing; the highest
report holds). The scenario's sentence should read "some report of it is at or above every later completion and
delete of it", and now does.
