its callers change together"). This commit is additive: the plug-ins build and behave as before, and the new methods
have only test callers until task 5 gives them their production callers (`ReportDamaged` in place of each `Reset`
above, `DamagedCount` in each query, `DamagedRefusal` in graph-index `outgoing` and graph-embedding `similar`).

## Choices the design leaves open

- Names: `ReportDamaged(key, revision, refusal error) bool`, `DamagedCount(keep func(id string) bool) int` (nil keeps
  every entity), `DamagedRefusal(id) error`. The filter is a function so each plug-in passes its own scope rule (an ID
  prefix for graph-embedding and graph-lexical, none for graph-index) without the follower knowing scope grammar.
- A report at the recorded revision replaces the stored refusal; one below it changes nothing. Either is invisible to
  the counts; replacing keeps the latest read's reason in Stuck.
- A report with a nil refusal is recorded with a fatal `graph_state_reset_required` refusal naming the key, reason
  `unreadable_entity_state`, so a recorded key never reads back nil from `DamagedRefusal`. No caller passes nil.
- Stuck's sentence: `N damaged entities: <id> (<reason>), ..., and M more; write a valid value for each key or delete
  it`, singular for one, `and M more` only past 10. It comes after a latched reset and before unresolved failures.
- The envelope adds the damaged count to `failed_count` and `damaged_entity` to the map `Failed` returned when the
  plug-in has failures (the follower owns that map), or to a new map when it has none, so stray reasons beside a zero
  count stay unpublished. Damage reads degraded, but the build latch still reads the floor, so damage stored at start
  does not hold the first build.
- One mutex over a map, taken on every `Complete`. No fast path: a lock nobody else holds is cheap beside an index
  write, and a second counter would be a second spelling of the map's length.
- A delete clears the record in `observe`, before the entry is delivered, so the plug-in's own delete path sees the
  key already cleared.
