# Task 2.1 notes

Choices the proposal leaves open.

- **Optional interface, not a wider `Embedder`.** Adding a return to `Embedder.Generate` would break every product's
  embedder and every test fake (`graph/embedding`, `processor/graph-embedding`, `processor/graph-query`) for a fact
  only one implementer has. `TruncationMarker` is asserted in `generateOne` only; `Generate` and `GenerateQuery` are
  unchanged, and `httpembedder.Generate` is `GenerateMarked` with the marks dropped.
- **`MarkedVector`, not a parallel `[]bool`.** A vector and its mark travel together; two index-matched slices would
  be the drift the developer contract's exported-surface rule names.
- **`IncTruncated(by string)`, not a second method.** It mirrors `IncDedupSkipped(reason)` and
  `IncFailedReason(reason)`. The values are the exported constants `TruncatedByTextCap` and `TruncatedByProvider`,
  so graph-embedding names the same two label values when it creates the series.
- **Where a cut is counted: after the save** (review of a00fe4bf, HIGH: counting before generation counted failed
  embeds, and a failed record replayed after a restart counted the cap again). `getSourceText` and
  `fetchTextFromStorage` only report a cut; `getOrGenerateEmbedding` returns the provider's mark with the vector
  (`MarkedVector`); `handleKVEntry` picks the label and `saveAndNotify` counts it once `SaveGenerated` succeeds,
  beside the dedup hit. A failed embed or save counts nothing; a failed record embedded on a later try counts once,
  for the one stored vector. No count is kept in storage. Each singleflight peer saves and counts its own entity. A
  dedup hit reuses a vector without the mark, so it counts no provider cut (a cap cut on it still counts); the dedup
  record is not widened to keep the mark (proposal, non-goals).
- **Each cut entity is counted once** (owner ruling, 2026-11-23, after the SemSource run showed the series overlap).
  The label is `text_cap` when `getSourceText` reports a cap cut, else `provider` when the vector came back marked.
  On the offloaded lane the cap cut is reported when either the body or the joined identity and body was cut.
- **Both series start at 0** (`WithLabelValues` at construction), so a scrape of a deployment with no cuts reads 0
  rather than an absent series.
- **A non-boolean `truncated` is refused.** The reply decoder already refuses a malformed reply whole; the fuzz target
  now asserts each accepted mark equals the entry's boolean, read by its own decoder.
- **Generated checks.** The mark is one boolean per reply entry, already covered by the reply fuzz target (extended
  with marked, unmarked, null, string and number seeds); the counting is two named examples.

## Not covered

- The offloaded lane's cut is checked as reported (`TestGetSourceTextReportsCapCut`, `offloaded_identity_test.go`,
  `review_followups_test.go`); only the inline lane's label is checked end to end.
- A save that fails after generation (other than the provider refusing) is not tested on its own; it takes the same
  path as the refused embed, returning before the count.
- Query-side cuts (`GenerateQuery`) are not counted.
