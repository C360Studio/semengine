# Task 2.1 notes

Choices the proposal leaves open.

- **Optional interface, not a wider `Embedder`.** Adding a return to `Embedder.Generate` would break every product's
  embedder and every test fake (`graph/embedding`, `processor/graph-embedding`, `processor/graph-query`) for a fact
  only one implementer has. `TruncationMarker` is asserted in `generateOne` only; `Generate` and `GenerateQuery` are
  unchanged, and `httpembedder.Generate` is `GenerateMarked` with the marks dropped.
- **`MarkedVector`, not a parallel `[]bool`.** A vector and its mark travel together; two index-matched slices would
  be the drift the developer contract's exported-surface rule names.
- **`IncTruncated(by string)`, not a second method.** It mirrors `IncDedupSkipped(reason)` and
  `IncFailedReason(reason)`. The values are the exported constants `TruncatedByTextCap` and `TruncatedByProvider`,
  so graph-embedding names the same two label values when it creates the series.
- **Where a provider cut is counted.** In `getOrGenerateEmbedding`, after `generateShared` returns, once per caller:
  singleflight peers each embedded their own entity from the cut text, so each counts. It is counted before the save,
  as the cap cut is counted before the save in `getSourceText`. A dedup hit reuses a vector without the mark, so it
  is not counted; the dedup record is not widened to keep the mark (proposal, non-goals).
- **Both series start at 0** (`WithLabelValues` at construction), so a scrape of a deployment with no cuts reads 0
  rather than an absent series.
- **A non-boolean `truncated` is refused.** The reply decoder already refuses a malformed reply whole; the fuzz target
  now asserts each accepted mark equals the entry's boolean, read by its own decoder.
- **Generated checks.** The mark is one boolean per reply entry, already covered by the reply fuzz target (extended
  with marked, unmarked, null, string and number seeds); the counting is two named examples.
