# 3.2 Choices the design left open

- **One site in the engine.** `Fuse` sets the response's provenance once after `fuseSeeds`
  (`pkg/fusion/engine_lens.go`), so an answer, a miss and a deferral from a later read all carry the resolve's
  provenance; a failed resolve keeps the mode's, as before. `fuseSeeds` and `miss` still stamp the mode's value,
  which that line overwrites.
- **Provenance for any mode.** The engine takes `Resolution.Provenance` whatever the mode; only fusionnats' NL
  resolve sets it. Symbol and prefix resolves leave it empty.
- **Request type.** The merged search takes `graph.LexicalSearchRequest`, so the request bytes are as before; only
  the subject changed.
- **No-responders wrap kept.** A request nothing answers is still wrapped transient `internal` naming the subject,
  now `graph.query.mergedSearch` (graph-query not composed).
- **Comments beyond the task's list.** `pkg/fusion/lens.go`'s `ResolveMode`, `ResolveModeNL` and
  `ProvenanceForMode` comments said NL provenance is always `lexical`; each now says a resolve may report its own.
  The README, MIGRATION and `doc.go` are task 4.1's.
