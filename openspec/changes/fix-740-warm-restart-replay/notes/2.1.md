## Choices the design leaves open

- Own server or shared: the shared server. It runs with nats-server's defaults (the fixture sets no
  `max_pending`), and the count is read before and after the restart, never against zero, so earlier
  tests' counts do not matter. No `// Own server:` marker is needed.
- The count is read with the observer's connection through natsclient's `RequestWithHeaders` (the
  server's reply is not a classified handler's). An absent `slow_consumers` field fails the test rather
  than reading as zero on both sides.
- When the second read happens: after `awaitIndexed` (graph-ingest's envelope from the new process, then
  a websocket client reading the snapshot through the revision, then the output's health) and, for each
  follower key, an envelope whose entry revision is above the one read before the child started, with
  `bootstrap_complete` true and `indexed_revision` at the seeded revision. A follower's old envelope keeps
  `bootstrap_complete` true from the earlier process, so the entry revision is what makes it the new
  process's.
- Seeding: the ENTITY stream keeps 64 MiB and discards its oldest, so inputs go in batches of 1,000,
  each acknowledged by graph-ingest's consumer before the next; inside a batch the test publishes
  asynchronously and waits on every acknowledgement (`publishBatch`). `publish`'s encoding moved into
  `encodeInput` so both share it.
- The manifest predicate, `fleet.cargo.manifest`, ends in no suffix `graph/entitytext` reads as text,
  so graph-lexical builds no word index of the filler.
