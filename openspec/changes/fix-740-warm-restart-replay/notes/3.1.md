## Choices the design leaves open

- **How settings are copied.** `NewSibling` builds a new `Client` literal and names each copied
  field, under the parent's read lock, rather than copying the struct and clearing fields. A struct
  copy would also copy the locks, the lifecycle state, the connection and the claim maps, which
  `go vet` refuses for the locks and which would make the sibling share the parent's connection
  handle; naming the fields means a setting added later is left out until someone adds it, which
  `TestSiblingCopiesEverySetting` makes visible for every field today.
- **Fields copied:** `urls`, `logger`, `maxReconnects`, `reconnectWait`, `pingInterval`,
  `writeTimeout`, `timeout`, `drainTimeout`, `netDial`, `requestHandlerTimeout`, `username`,
  `password`, `clientName`. The logger is copied so a sibling's lines go where the parent's go,
  which is also how a refusal on a sibling is logged. `netDial` is how every Client dials
  (`(*net.Dialer).Dial` in production); a sibling built without it could not dial.
  `requestHandlerTimeout` and `drainTimeout` have no option, but they are settings the parent
  runs with (the first from the environment), so the sibling matches.
- **Fields left out:** `jsMetrics`, `metricsInterval` (no metrics, so no poller); `onConnectionLost`,
  `connectionLossTimeout` (the parent keeps the one exit policy); everything else is per-Client
  state (connection, JetStream handle, claims, consumer releases, lifecycle fields, timers,
  closed-signal map), which a new Client starts empty.
- **Refusal after Close.** `NewSibling` reads `closing` under the same lock `Close` sets it under,
  before `Close` clears the credentials, so a sibling made while `closing` is false carries them.
  The error is `errs.Wrap(nats.ErrConnectionClosed, "Client", "NewSibling", "client closed")`, the
  same wrap `Connect` returns once `Close` has begun. Only "after `Close` returned" is tested:
  "after it began and before it returned" needs a `Close` held partway, and the lock makes the two
  the same read.
- **Credentials on the wire.** The shared fixture server is password-protected with a token
  carried in its URL, so `TestSiblingCarriesTheClientSettings` proves the URL's credential reaches
  the server; nats-server with a token refuses a user and password, so `WithCredentials` is proved
  by `TestSiblingCopiesEverySetting`'s field read instead. No harness option for a user/password
  server was added: the field read covers it without new harness code. No own server is needed, so
  no `// Own server:` marker.
- **The no-poller check.** The stack scan counts goroutines in `startBackground`'s closure as well
  as `join`, `awaitClosedHandler` and `runPoller`, against the count read before the sibling was
  made. A goroutine started through `startBackground` has the closure on its stack from its
  creation, before it reaches `runPoller`, so the scan is ordered after `Connect`'s start; the
  copied-poller mutant fails it.
- **The permission refusal.** No fixture server has permissions, so the refusal is a scripted
  server's `-ERR` line on a `net.Pipe`, as `TestServerRefusalCountedBeforeLog` does for the
  parent's counted case; this test reuses its log handler, which reads the registry when the record
  is written.
- **Close contexts.** No production code closes a sibling yet (task 4). The tests close a sibling
  in the body under `t.Context()`, since that Close must finish and `go test -timeout` is the one
  deadline, and in `t.Cleanup` under `context.WithTimeout(context.Background(), closeBudget)`, the
  bounded cleanup root the harness rules ask for.
- **An extra test.** `TestSiblingCopiesEverySetting` is not named in the spec. Timeouts and
  reconnect settings have no observation short of a fault, so it reads the fields in-package
  against the values the test passed.

## Observed, not changed

`Client.Connect` logs its URLs at Info (`Connecting to NATS urls=nats://<token>@localhost:...`), so
a credential carried in a URL reaches the log. A sibling logs the same line. This predates the
change and is outside tasks 3.1 and 3.2; no open issue names it, and it is handed to the claimer
to file.
