# Task 2.2: the dialer, and Connect honours its context

Choices the design and the prototype (`fix-prototype.diff`, PR #177 comment 6110634660) do not spell out, or that
depart from the prototype.

- **`netDial` is a field on each client** (design review r2-2, MEDIUM), not the prototype's package variable.
  `NewClient` sets it to `(*net.Dialer).Dial`, and `connectWith` passes it to `newSocketDialer`, which keeps it as
  `dial`. A test sets its own on its client before `Connect`, so no other client in the test binary reads it. No test
  sets it in this task; T8 (task 3.3) will.
- **One record of the cut.** The prototype kept a `closed` flag beside the `done` channel, two spellings of one fact
  (developer contract, "Before adding anything new", question 1). Here `done` is the only record: `isCut` reports
  whether it is closed. `cut` still closes `done` at most once, under `mu`, and a second `cut` returns at once. In
  this task `Connect`'s `AfterFunc` is the only caller, once per dialer; `Close` becomes the second in task 3.x.
- **`Dial` refuses before dialling once cut** (design review r2-2, NIT), so a listening server never sees a connection
  after the cut. The check after the dial stays: a dial that was already in progress when the cut came is closed and
  refused. `TestSocketDialerRefusesADialAfterTheCut` (new file `natsclient/socket_test.go`) holds it. It failed before
  the check was added:

  ```text
  socket_test.go:16: the dial reached the network after the cut
  socket_test.go:22: Target error should be in err chain:
      expected: "use of closed network connection"
      in chain: "unexpected dial"
  --- FAIL: TestSocketDialerRefusesADialAfterTheCut (0.00s)
  ```

- **The ended-context check comes straight after the nil check**, before the closed and already-connected checks, as
  the task says ("before anything else"). So a closed client given an ended context returns the context's error, not
  `nats.ErrConnectionClosed`. No dial was attempted, so it records no failure and changes no status; the check after
  the dial still calls `connectFailed`, as before.
- **The dialer is added in `connectWith`**, not in `buildConnectionOptions`, because each `Connect` gets its own.
- **Doc comments.** `Connect`'s comment now names the ended context and the cut (T3, T4). The sentence that the context
  does not bound later reconnects waits for T5 (task 2.3). `socketDialer`'s comment cites T4 and P18, P25 (design
  review r2-2, L1). The comment on `Dial` says the net package still honours `net.Dialer.Cancel`; that is a fact about
  Go, not nats.go, cited to design D1. No test in this task reaches a dial in progress; T8 (task 3.3) will.

## Review stop 1: the ended-context check moves after the Close check

Implementation review of 925afa3 (MEDIUM): the check came before the Close-begun check, so a closed client given an
ended context returned `context.Canceled`, where "Close refuses new work" (`openspec/specs/transport-client/spec.md`)
says `Connect` returns `nats.ErrConnectionClosed` once Close has begun, and the delta settles the same order for
`Subscribe` ("whether or not the call's context has ended"). The task's "before anything else" and the prototype had
put it first.

- The check now follows the `closing` and `started` checks. Those only read state, so the check still comes before
  any write and any dial.
- The delta's "Connect is bounded by its context" now says "unless Close has begun (Close refuses new work)".
- `Connect`'s doc comment says Close's error wins whether or not the context has ended (T3).
- T3 is now two subtests. `after Close` closes a client, then calls `Connect` with an ended context and expects
  `nats.ErrConnectionClosed`. On 925afa3 it failed:

  ```text
  client_connect_test.go:167: Target error should be in err chain:
      expected: "nats: connection closed"
      in chain: "Client.Connect: connection cancelled failed: context canceled"
  --- FAIL: TestConnectRefusesAnEndedContext/after_Close (0.00s)
  ```

  With the move it passes, and `go test -race ./natsclient/` passes.

This replaces the earlier bullet above that put the check "straight after the nil check": a closed client given an
ended context now returns `nats.ErrConnectionClosed`.

## Review stop 1, Codex F1: the host lookup

Codex's stop-1 review (PR #177 comment 6111641674, BLOCKING F1): nats.go v1.54.0's `createConn` calls
`net.LookupHost` before the dialer unless `SkipHostLookup` is set (`nats.go:2484-2485`), and nothing ends that
lookup when Connect's context does. The orchestrator reproduced it 3 of 3 on 2813fd0 (comment 6111684071).

- **The fix** passes `nats.SkipHostLookup()` beside `nats.SetCustomDialer(socket)` in `connectWith`. The name reaches
  the dialer, and `net.Dialer` resolves it under the dial's `Timeout` and `Cancel` (`net/dial.go:526-540`, `:560`).
- **The cost.** A hostname that resolves to several addresses is now dialled in the resolver's order: nats.go's shuffle
  of those addresses (`nats.go:2509-2511`) is gone. Its shuffle of the server list across separate URLs
  (`nats.go:2158-2159`) remains. The lookup and every address now share one `WithTimeout`; design D1, "Costs", and
  ADR-112 §1 are corrected to say so.
- **The test** is a new T4 subtest, "host name resolved inside the dial". The client's URL is `localhost` on an
  ephemeral port, and its `netDial` stand-in records the address it is asked to dial, then waits for `Cancel`. The
  test cancels once the dial is entered, requires `context.Canceled`, and requires the stand-in to have received
  `localhost:<port>`. Without the option, nats.go resolves the name first and the stand-in receives an IP. The probe's
  shape, replacing `net.DefaultResolver`, is not used: that is a package global every test in the binary reads.
- **The fixed-address guard.** `TestNoFixedAddressesInTests` refuses the literal text `nats://localhost:` in a test
  file, because it stands for a fixed broker address. The test builds its URL with `net.JoinHostPort("localhost",
  port)` from a port bound with `127.0.0.1:0` and released (`refusedNATSURL`), so the URL names no fixed address, as
  the guard's rule asks; the guard and `scripts/lint-test-ports.sh` pass. A name that does not resolve (`.invalid`)
  cannot replace `localhost`: nats.go falls back to the name when its lookup finds nothing, so the test could not fail
  without the option, and the lookup would send a real DNS query.
- **No test stalls a real lookup.** As for `Cancel` (design D1), the test shows only that the name reaches the dialer
  natsclient cuts; that Go's resolver honours the dial's context is Go's code, read.
