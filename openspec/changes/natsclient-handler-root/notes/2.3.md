## M3 survives: equivalent at nats.go v1.54.0

M3 is reported as a survivor, not a detection. It is equivalent for `SubscribeForRequests` at the pinned nats.go
v1.54.0, as read from its source (not promised across nats.go versions, ADR-112). A core subscription records its
delivery's end (`ownedDelivery.end`) only from nats.go's closed handler (`natsclient/client.go:935`, `:948-949`,
`:1131`). nats.go's `waitForMsgs` runs the callback, `mcb(m)`, inside its loop (`nats.go:3807`) and the closed handler,
`done(s.Subject)`, only after the loop exits (`nats.go:3829-3835`), on the same per-subscription goroutine. So the
closed handler cannot run while a callback runs: after `Unsubscribe`, while T3's handler is held, `d.ended` is still
false when Close begins, and M3 cancels exactly as the code does. The reach run agrees: line 1187, inside the
`closing` case, ran, and the test passed.

The code still cancels when Close begins after delivery has ended because the subscription's watcher has the shape of
`ownConsumer`'s, where JetStream consumers do reach that state (`ownConsumer` calls `d.end()` itself,
`natsclient/owned_delivery.go:155`). Disposition (coordinator, task 2.3): no test or code change; the result is recorded
on the M3 line of `design.md` § Mutants.
