# 2.4 Sensitivity: mutants M1-M8

Each mutant (design, "Mutants") was run with `task mutate:check` at `d5b2b36`, against each expected detector the
design names. The command runs the test three times on the unchanged code, three times with the wrong change, and once
more on the unchanged code; the wrong change is compiled in with Go's `-overlay` option, so no file in the repository is
edited. Every report shows the tree fingerprint `c4ddc609816d` before the first run and after the last, and the
target's SHA-256 unchanged. The mutant copies and the run logs are on this machine only (`/tmp/mut378.k1X4/`).

`task mutate:check` does not build `integration`-tagged files by itself. For the logger tests that live in such files
(T5 and the two `message_logger_subscription_integration_test.go` tests), the caller's `GOFLAGS=-tags=integration` is
carried into every run (`mutation-check` spec, "The environment is the same in every run"), as in
`archive/2026-10-13-remove-natsclient-test-seams/notes/2.1.md`. Each such report shows `GOFLAGS: -tags=integration`
on every run.

## Choices the design does not spell out

- M1 against `TestMessageLoggerKeepsCapturingAfterStartContextEnds` (row 2) targets `natsclient/client.go` while the
  test is in `./service`: the overlay reaches the `natsclient` package the `service` test binary builds.
- M5 names no detector in the design. It was run against T5 and against
  `TestMessageLoggerKeepsCapturingAfterStartContextEnds`, the two logger tests whose Start path it changes. Both report
  a survivor, and the reach run shows each test reached the wrong change. This is the design's declared survivor
  (Mutants; Residual risk, "M5 is undetected"): telling Start's context from the run context apart at the subscribe
  needs a server that withholds its PONG. It stays reviewed only.
- M6, row 9, is inconclusive and is not counted as a detection. The design (D5) says M6 loses message 2, the
  assertion at `:219`, and that was the only location named. In mutant run 3 the test failed one assertion earlier, at
  `:213` ("Stop returned while message 1's callback was held: \<nil\>"): with `Unsubscribe` in place of `Drain`, Stop
  does not wait for the held callback, and whether the test sees that at `:213` or the missing message at `:219`
  depends on when Stop returns. Both assertions are the drain contract the test states in its comment. Row 10 names
  both and is a separate check, run after row 9's result was seen; it reports detection, with all three mutant runs
  failing at `:219`. The test was not changed.
- Expectations are named by message text where the assertion carries one, and by `file.go:N` otherwise (T6's
  `assert.Equal` at `:325` and `require.Len` at `:337`, M6's `:213` and `:219`).
