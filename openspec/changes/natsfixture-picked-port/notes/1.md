# Notes: section 1 (developer)

Choices the design (#209 comment 6151740502) does not spell out, and the test record.

## Choices

- **The port is picked inside the start phase.** `freePort` runs in the `PhaseStart` closure of `attempt`, so a
  failure to take a port is a start-phase `*Error` with the usual rollback, and Start's replacement attempt picks a
  port of its own. No new phase and no new `deps` entry: the pick is not a Docker or NATS call.
- **`net.Listen`, not `net.ListenConfig.Listen(ctx, ...)`.** The brief names `net.Listen("tcp", ":0")`; with `:0`
  there is no name to resolve, so a context would bound nothing.
- **No `HostIP` in the binding.** Docker publishes on all addresses, as before (the probe's
  `{"HostIp":"0.0.0.0",...},{"HostIp":"::",...}`); loopback publishing is unchanged, as the brief says.
- **`HostConfigModifier` replaces testcontainers' default modifier.** At v0.44.0 the default is installed only when
  the request has none (`lifecycle.go:513-516`), and it copies only deprecated request fields (`AutoRemove`, `Binds`,
  `CapAdd` and the like, `lifecycle.go:662-675`) that the fixture does not set. `mergePortBindings`
  (`lifecycle.go:546`, `:626-649`) then keeps a binding the modifier set for an exposed port, and puts `"0"` only where
  `HostPort` is empty. The key is `network.MustParsePort(clientPort)` from `github.com/moby/moby/api v1.55.0`, the type
  testcontainers keys the map by.
- **The test's held ports.** `heldPorts = 4`: one for each of Start's two containers and two for other runs' containers
  in between. On `main`'s code the first fixture's port is Docker's latest pick, so the held ports are Docker's next.
  On the fix the first fixture's port came from the kernel, so the held ports are the Mac's next, and the second
  fixture's port shows the kernel stepping past them (fix run 1: held 52733-52736, second fixture at 52737). A port the
  test cannot hold is logged, not fatal: then another process holds it, which is #209's condition anyway.
- **The oracle is Start returning nil.** Start returns only once JetStream answers on the URL it reports; a held port
  would give either an empty port list (no URL) or a listener that never answers the NATS handshake.
- **`TestRestartPastAHeldPort` is removed, not rewritten.** It held the port after the fixture's own and restarted.
  With the port kept, that held port plays no part, and what remains (Restart's URL dials) is `TestRestartURLDials`,
  which now also asserts the URL is unchanged. Its file held only that test, so the new test goes in
  `start_port_integration_test.go` and the old file is gone.
- **The retries' comments.** Start's replacement container and Restart's one more stop and start stay (brief). The
  `maxAttempts` comment now says the #180 case they were also kept for no longer arises, and that #205 decides whether
  they stay; `restart.go` and `restart_test.go` point at it instead of citing the removed test.
- **`scripts/lint-test-ports.sh`.** Its header already used `gh#209` for a SemStreams issue, so the new text says
  "SemEngine #209". The failure message is unchanged: it is addressed to test files, which can hand over a listener.
- **The Restart requirement is removed and re-added.** `task spec:check` refused a MODIFIED block without the
  scenario "Binding changes across a restart", so the delta removes "Restart keeps the container and re-reads its
  binding" and adds "Restart keeps the container and its host port", as `remove-setconnection` did. On archive the
  requirement moves to the end of `openspec/specs/nats-fixture/spec.md`.
- **The spec states no Docker refusal.** That Docker refuses a held explicit port is measured only by the probe, so
  the requirement says only that a failure to take a port fails the start phase; `freePort`'s comment cites the probe.
- **Generated checks are not needed.** One input case (held ports before a start), no stated law, no order-dependent
  history.
