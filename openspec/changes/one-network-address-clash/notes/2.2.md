## Choices

- Within one holder, `checkResourceConflictsLocked` visits the holder's claims, then the candidate's claims. The
  design fixes only the holder order; no test row has a candidate or holder with two network claims.
- `exclusiveResources` checks each claim against the earlier ones in input-then-output order, then sorts the resource
  texts it returns. `Declaration.ExclusiveResources` is still sorted text.
- `TestRegistryAdmitsNetworkClaimsThatCanBothBind` paths (a) and (b) also check that `Snapshots` reports both
  resource texts unchanged (`ResourceID` unchanged, design "Behaviour").
- The tests compare with `strings.Contains`, as the existing ones do: the registry wraps the refusal in its
  operation prefixes (`Registry.CreateComponent: ...`), which the design does not fix.
