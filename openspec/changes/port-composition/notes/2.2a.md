## Choices the design does not spell out

- Test files: `composition/lanes_test.go` (#346), `composition/offline_test.go` (#347, #348 through
  `composition.Validate`), `config/validate_document_test.go`; the model test is in `model/registry_test.go`.
- Standard error is captured by pointing `os.Stderr` at a temporary file for the duration of the call. Neither
  `composition` nor `config` has a `t.Parallel` test, so nothing else writes there meanwhile.
- `TestRegistryValidateNamesFirstInvalidEndpointByName` also checks capabilities (`a-cap`, `b-cap`, `c-cap`), since
  the design sorts both loops and only the endpoint loop had a named test.
- `TestValidateDocumentReadsNoFile` also checks that a missing `tls.server.key_file` is still refused by
  `ValidateDocument`, so the required-field checks did not move to the host half.
- The security checks split into `validateSecurity` (required fields and TLS versions, called by
  `ValidateDocument`) and `validateSecurityFiles` (the three `os.Stat` checks and the warning, called by `Validate`).
  Both errors keep the `security configuration:` prefix.
- `ComponentPortRef.Direction` takes the direction `portsByConnection` was called with, the one construction site.
  The request-edge deduplication key (`connectRequestPorts`) is the pair of refs, so it now includes the direction:
  edges to a request input and a request output of the same name on one component are no longer merged into one.
  No test drives that case (UNVERIFIED beyond reading the code). The orphan check's map is keyed by the whole
  `ComponentPortRef`.
- The flowgraph test literals in `declarations_test.go` now carry the direction.
- Doc lines changed with the code: `config/README.md` (a paragraph on `Validate` and `ValidateDocument`) and the
  `TypeConfigInvalid` comment in `composition/findings.go`.
