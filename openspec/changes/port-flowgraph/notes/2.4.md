# Task 2.4 notes

Choices task 2.4 made that the design does not spell out.

- `TestUnconnectedOptionalInterfacePortReportsNoPublishers` is one test, built through `BuildFromDeclarations`,
  asserting the whole `OrphanedPorts` list. Beside a plain control port (`write`) it holds the pin's
  `write-graphable` on `storage.objectstore.graphable` and `input-typed` on `processor.input.typed` (both of the
  pin heuristic's marks), plus two ports that each carry one mark only: `data` on `processor.data.validated` (the
  subject mark) and `event-raw` on `processor.events` (the name mark). The pin's second subtest checked its ports
  only if it found them, so it could pass on an empty list; this one cannot. It was red on 250b933's code
  (four ports reported `optional_interface_unused`) and green after the heuristic and its constant went.
- `TestRefusalsNameNoInternalFunction` asserts each refusal's full text as well as `errors.Is` and the absence of
  internal names. The forbidden names are the design's four plus R12's lower-case `addComponentNode` and
  `connectComponentsByPatterns`. It was red on adf9d52's code (all five subtests: each text carried
  `FlowGraph.<method>: ... failed`; `errors.Is` already held) and green at 47c50d0.
- The five message bodies are the pin's, with one change: the connect refusal lists its conflicts joined by `"; "`
  instead of `"validation warnings: [...]"`, since these are refusals, not warnings, and the brackets were Go's
  slice formatting. The conflict texts themselves still print component/port pairs with Go's struct formatting
  (`[{first listen} {second listen}]`); they are built in `validateNetworkPorts` and `validateKVWriters`, not at
  the five refusal sites, and are left as the pin wrote them.
- The ledger `contract` clause (7) names the four refusal kinds that wrap `errs.ErrInvalidConfig`; the port/fact
  count and connection-identity refusals in `extractPortInfo` never did (plain `fmt.Errorf` at the pin) and still do
  not. The graph-mutation clause is written as the code checks it: only once a graph-mutation port is declared,
  every such port must have the required shape, and exactly one of them must be an input.
- README.md and doc.go needed no change: neither named the heuristic, its issue value, or the refusals' wrapping.
