## Choices the design leaves open

- **Fifteen cases, not seventeen.** D4 says "a plain `switch` of 17 cases"; `SearchOptions` has 15 JSON names, and
  the switch has one case per name. `TestEveryHintNameIsTyped` walks the struct, so the count is checked, not
  asserted.
- **One name at a time.** Each option is marshalled as `{name: value}` and unmarshalled into a fresh `SearchOptions`,
  so a refusal names the one option that failed. The JSON decoding is `SearchOptions`' own, so a field's type and
  the hint's type cannot drift apart.
- **Null hints are refused.** A JSON `null` under any known name is refused with the error "null value" (review
  finding 6 at `34af95b`, fixed in `47d1622`). `"time_range": null` and `"geo_bounds": null` would decode to a nil
  pointer, which tiers 0 and 3 never give and a reader that type-asserts and dereferences would panic on; under the
  other names `null` would decode silently to the zero value. An empty `strategy` is refused, because the empty
  string is not one of the eight values.
- **A fractional `limit` is refused** (`2.5` does not decode into `int`). A whole number in an example file
  (`5`, read by `encoding/json` as `float64`) decodes to `int`.
- **Unknown names whose value JSON cannot encode** (only possible for an example built in code, such as a channel)
  still pass through unchanged: the encoding error is reported only under a known name.
- **The refusal error** is `errs.WrapInvalid` around `domain "<domain>", example "<query>": option "<name>": <reason>`.
- **East and West are not checked**, as D4 and D6 say: a box crossing the antimeridian keeps East above 180 or West
  below -180. The test "pole and antimeridian boxes are accepted" holds that.
- `NewEmbeddingClassifier` copies each example and builds a new `Options` map. Values under unknown names are still
  shared with the caller; known values are freshly decoded and the classifier's own.
