## Choices the design leaves open

- **Oracles.** `TestTimeRangesFromOneInstant` writes each start and end as a UTC literal worked out by hand: New York
  on 2026-03-08 (the day is 23 hours, EST to EDT), a UTC+14 fixed zone (today is already the 31st at 11:00Z), a
  Sunday and a Saturday for "this week", February 2026 and 2028 for "this month". `time/tzdata` is imported by the
  test so `America/New_York` loads the same everywhere. The box rows are hand values (5 km is 5/111 degrees).
- **Tests that asserted `NotNil` only** now assert exact values through the production entry points
  (`KeywordClassifier.ClassifyQuery`, `ClassifierChain.ClassifyQuery`), which read the real clock: the call is
  bracketed by two clock readings and the range must be the calendar day of either reading
  (`assertCalendarDay`, a day can turn between them) or end between them and start the span before its end
  (`assertSpanEndingNow`). Those are `TestKeywordClassifier_AggregationWithTemporal`,
  `TestKeywordClassifier_ExistingPatternsUnaffected` (yesterday, last 7 days), `TestClassifierChain_T0_KeywordMatch`
  (yesterday, today, last week) and `TestClassifierChain_TierPriority`. The spatial `NotNil` rows are not temporal
  and stay as they were.
- **Generated checks.** Not used: the bounds are three comparisons per phrase, and each is shown both ways at its
  edge by named rows (2562047 and 2562048 hours, 106751 and 106752 days, 0 and 1, -90.5, -180.01, 90, 180).

### Finding 1: a chain with no keyword tier skipped the refusal

What `b37aaa6` answered: with `NewClassifierChain(nil, nil)` the default result and a nil error for "events in the
last 3000000 hours", "sensors within 5km of 95,10" and "events in the last -1 hours"; with an example tier holding
each question word for word, tier 1 `temporal_filter` at 1.0 and a nil error; with an LLM tier, tier 3
`entity_lookup` at 0.9 and the LLM client called 3 times (`Should be zero, but was 3`). The control subtest "in range
control" passed: "events in the last 3 hours" reaches the LLM tier when no keyword tier is composed.

- **Fix.** The bound check is its own function, `numbersOutOfRange(query) error`, the one place that reads every
  "last N hours", "last N days" and "within" phrase. `ClassifierChain.ClassifyQuery` calls it first, after the
  nil-chain and ended-context return (unchanged) and before any tier, so the refusal holds whichever tiers are
  composed. `KeywordClassifier.classify` no longer returns an error (no production caller read it once the chain
  checks first); `extractTemporal` and `extractSpatialBounds` return only the hint, and a phrase past its bound
  still gives none. `notes/6.2.md`'s seam bullet is updated to match.
- **Test.** `TestOutOfRangeRefusedWithoutKeywordTier` (`graph/query/classifier_clock_test.go`): three nil-keyword
  compositions (no tier; an example tier shown by `FindBestMatch` to answer each question at or above 0.7; a counting
  fake LLM), each requiring no result, `errs.IsInvalid`, the phrase and the bound in the error, and no LLM call.
- The mutation row "chain ignores the keyword tier's error" above was run before this change; the chain now reads
  `numbersOutOfRange` instead, checked by the first row below.

### Finding 2: a negative N never reached the lower bound

What `b37aaa6` answered: "events in the last -1 hours" and "events in the last -3 days" the default result and a nil
error, as Codex found; "events from yesterday and the last -2 hours" and "events in the last 3 hours and the last -1
days" tier 0 with a `time_range` and a nil error. The patterns read only unsigned digits, so `lastSpan`'s `n < 1`
check never saw a negative N.

- **Fix.** `lastNHoursPattern` and `lastNDaysPattern` read N as `-?\d+`. `lastSpan` checks `n < 1` before the upper
  bound: for a number past int64, `strconv.ParseInt` returns `math.MinInt64` or `math.MaxInt64` by its sign, so
  "last -99999999999999999999 hours" is named as below 1, not as past the span.
- **Rows.** `TestOutOfRangeNumbersAreRefused` "refused": `last -1 hours`, `last -3 days`, `last
  -99999999999999999999 hours` (each "at least 1"); "a later impossible phrase": "events from yesterday and the last
  -2 hours" and "events in the last 3 hours and the last -1 days", each refused by the chain while the keyword tier
  keeps the valid phrase's `time_range`.
