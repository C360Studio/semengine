# Tasks 4.1 and 4.2 notes: graph-ingest on `damage.Record`

## The gauge (the choice the design leaves to the developer)

The gauge is set by `setEntityPoisonGauge` (`processor/graph-ingest/poison_inventory.go`), called only after a
`Report` that recorded a new key or a `Clear` that dropped one. It takes a graph-ingest mutex, `poisonGaugeMu`, reads
`entityPoison.Len()` and sets the gauge under it. Why this is enough: every change to the size is followed by its own
gauge write, so the last write in lock order comes after every change and reads the final size. Without the mutex, a
goroutine could read an older size, be overtaken by a newer write, and write its older size last.

Rejected: `Inc` on a new report and `Dec` on a drop. It needs no lock, but the gauge is shared through
`metric.RegisterOrGet`, so a gauge already holding a value from an earlier component on the same registry would stay
off by that value for good. A `Set` from the current size corrects itself on the next change.

## Other choices

- `dropEntityPoisonRecord(id, proofRev)` calls `Clear(id, proofRev+1)`: a proof at a revision covers that revision.
  A `proofRev` of the largest `uint64` would wrap to 0 and drop nothing, which keeps the entry (fails closed); KV
  revisions do not reach it.
- Health's message reads `Len` and `Sorted(10)`, as design D4 says. `DebugStatus` reads `Sorted(0)`. The reason
  comes from `errors.As` on the stored refusal (`poisonContractError`), which is always the stamped
  `*graph.StateContractError` `recordEntityPoison` reported.
- The fast paths (Health, `writeFailed`, the three clear paths) check `entityPoison.Len()`, one atomic load.
- `component.go`'s `entityPoisonMu`, map and `entityPoisonSize` are gone; the boot sweep keeps `entityPoisonRecord`.
