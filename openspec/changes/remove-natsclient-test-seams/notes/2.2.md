## Row 28 gains two status checks, not one

The task asks for one check: after the late disconnect, `Status()` is still Disconnected
(`client_lifecycle_test.go:402`). The test also checks, before the late disconnect, that Close's cleanup has already
written Disconnected (`:396`). Without that check the test does not show the "still": if Close's cleanup ran after the
disconnect, it would write Disconnected over a wrong Reconnecting, and the check at `:402` would pass on code that
writes the status once Close has begun. `synctest.Wait()` returns once Close is blocked on its join, and `cleanup`
writes Disconnected before it starts the joiner (`client.go:999`), so the check at `:396` holds on this code.

The test's doc comment adds one sentence naming the spec requirement, "Only Close changes the status once Close begins"
(`openspec/specs/transport-client/spec.md:123`-`:127`).
