# Notes: task 2.2 (developer)

Choices the design (D3) does not spell out, and the check record. Line numbers are after the edit.

## What changed

- `processor/graph-ingest/README.md:27-38`, "At-least-once delivery": the generation is read by `Start` before it
  binds the stream's consumer, and every input that consumer delivers carries it. "Never dropped" is gone: an input
  from another generation is not dropped because of the stored sequence, and the cases where an input from a recreated
  or restored stream still carries the stored generation are left to the spec requirement.
- `docs/contract.md:79-82`: re-sending applies the current data after the ingest component has started again; the
  exceptions are named only by the pointer.
- `processor/graph-ingest/keyed_ingest.go:34-35` (`ingestWork.generation`): "read when the consumer was bound" becomes
  "read once before Start binds the consumer".
- `processor/graph-ingest/keyed_ingest.go:80-85` (`guardRecord.covers`): "a recreated stream ... is never suppressed"
  becomes "not covered, whatever its sequence", plus the pointer to the declared limitations.

## Choices the design does not spell out

- **Which correction goes where in `keyed_ingest.go`.** The field comment at `:34-35` made no "never" claim, so it
  takes only the read-before-the-bind correction. The pointer goes on `covers`, which held the "never" claim. The
  window itself is already named at the read (`component.go:1475-1479`, task 2.1), so the field comment does not
  repeat it.
- **"Sequences restart at 1" is dropped** from the README and from `covers`. It states how nats-server numbers a new
  stream, and these edits make no claim about nats-server or nats.go. Each sentence now states what graph-ingest does
  with the generation it read.
- **The README and `docs/contract.md` link to the spec file** (`openspec/specs/graph-ingest-recovery/spec.md`). The
  README had no links before; a link is how `docs/contract.md` already sends readers to other records (`:11`). Until
  the archive (task 3.2) that file still holds the old requirement, "Replay protection is generation-aware"; the name
  the pointer uses is in this change's spec delta and lands there at the archive.
- **The README names "deleted and created again, or restored"** to say which inputs the pointer is about. That is the
  spec requirement's own summary sentence, not its list of cases; the list stays in the spec.
- **"The ingest component"** in `docs/contract.md` is the name that page already uses (`:86`).
- **`covers` was rewrapped through `:85`.** The last sentence ("Generations are compared ...") is unchanged in
  wording; it moved because the lines above it changed length.
