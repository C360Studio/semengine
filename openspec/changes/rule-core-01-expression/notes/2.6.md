## Generated checks: decision and record

The design's invariants are laws over interacting inputs (any number of conditions, three logic values, list
membership, range bounds in any order, arbitrary patterns), so they get one rapid property test. Each law has a
test-owned oracle: integer comparison for the six comparison operators, `slices.Contains` for `in`,
`lo <= v && v <= hi` for `between`, `regexp.MatchString` and `regexp.Compile` for regex. Boundaries are named
witnesses run through the same checks before `rapid.Check`: an empty condition list under each logic value, all
false and all true pairs, an empty list for `in`, `lo == v == hi`, `lo > hi`, `v < lo`, the empty pattern, an
end-anchored pattern, an invalid pattern. Every check runs on every generated case.

Run: `go test ./processor/rule/expression -count=1 -race -run '^TestPropConditions$' -v -rapid.checks=1000
-rapid.seed=20261125` printed `[rapid] OK, passed 1000 tests`. Seed 1 with 100 checks: `[rapid] OK, passed 100
tests`. No failure was found, so no failing input is kept.
