# Notes: tasks 2.2 and 2.3 (step A)

Step A carries `Definition`, `EntityConfig`, `DecodeDefinition`, `Action`, the nine type names, `ActionHandler`,
`Handlers`, `NewHandlers` and the cap key. Built-in `Check`s accept every body until task 2.4; `Load` is task 2.5.
These are the choices the design leaves open.

## Decode

- **Core action keys match exactly; definition keys do not.** `decodeAction` reads `type`, `when`, `id` and
  `max_iterations` from a `map[string]json.RawMessage`, so `"Type"` is a body key, not the type: the action has an
  empty type, which `Load` will refuse as unknown. The `Definition` decode is `encoding/json`'s struct decode, which
  matches keys without regard to case, so `"ID"` or `"Enabled"` is accepted as `id` or `enabled` and not refused by
  `DisallowUnknownFields`. Open question for the reviewer: refuse case variants at definition level too (a key list
  check before the struct decode), or accept them as harmless.
- **Positions at decode.** A misspelt `when` key names `when[<i>]`. The decode does not name the action list position
  (`on_enter[1]`): `encoding/json` reports neither the path of an unknown field nor of an `UnmarshalJSON` error.
  Every decode error names the rule ID and the source, and an undeclared key by name; `Load` names positions.
- **The rule ID in a decode error** comes from a first, lenient decode of `id` alone, so a refusal names the rule
  even when the strict decode fails part way.
- **An empty action list or `metadata` object decodes as nil.** The pin's fields carry `omitempty`, so a stored
  definition drops them; without this, a rule file holding `"on_exit": []` would not round-trip to an equal
  definition, which the spec requires. `FuzzDecodeDefinition` found nothing else of this kind.
- **`null`** for a definition key leaves its absent meaning (`"enabled": null` is enabled); `"logic": ""` means
  `and`.
- **An action must be a JSON object.** `null`, a string or an array is refused naming `action`.

## Action

- `Action`'s fields carry no JSON tags; `UnmarshalJSON` (pointer receiver) and `MarshalJSON` (value receiver, so a
  `[]Action` marshals) are the only codec. `actionCore` holds the four tagged keys for `decodeAction`.
- **`decodeAction(body)` is the one reading of a body**, shaped for `Load`'s check: decode the four keys from `Body`
  with it and compare them with the action's fields in marshalled form.
- **`MarshalJSON` refuses an empty `Body`**, saying to build the action by decoding, so marshalling a definition that
  holds a Go-literal action fails rather than writing `null`.

## Handler set

- `Handlers` is a struct with one unexported map; a zero `Handlers` (nil map) is the set `NewHandlers` did not build,
  which `Load` will refuse. A copy of a built set is the same set: the map is never written after `NewHandlers`.
- `NewHandlers` copies the product map, so a later change to it does not reach the set.
- Product names are checked in sorted order and the first refusal is returned, so the error is the same every run.
- A nil handler is refused only as a nil interface. A typed nil pointer inside the interface is not detected; doing so
  needs `reflect`, and the design asks only for nil.
- `Handlers` has no exported method. `TestNewHandlers` reads the map from inside the package; `Load` will be its
  reader.

## Cap key

- The hash input is the rule ID, the type and the canonical body, each length-prefixed (`<len>:<part>`), so no rule ID
  or type can make two different inputs hash the same. The key is the first 16 hex characters of the SHA-256, the
  pin's length.
- An `id` is used as written; it could equal another action's hashed key only by an author choosing a 16-hex string.
- `capKey` returns an error for a body that is not JSON. A decoded body always is; the error keeps a Go-literal body
  from panicking.
- `defaultActionMaxIterations` (3) is carried with no reader yet. The pin's `effectiveMaxIterations` and
  `isUnlimited` (`action_id.go:108-133`) are not carried: nothing in this PR resolves a cap, and the fire path that
  does (PR 7) can carry them with their reader. Task 2.9 counts `action_id.go:1-133` as carried; if these stay out,
  that range is `:1-106` and the production total drops by 27 lines. Open for the reviewer.
