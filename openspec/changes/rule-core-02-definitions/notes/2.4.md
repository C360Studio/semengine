## The predicate check, run beside it

The same run also ran each built-in's whole `Check`, after declaring every action's literal three-part predicate with
`vocabulary.Register` in place of semteams' own vocabulary. It refused 21 `add_triple` actions in 7 semteams rules,
all for a predicate that is not three lower-kebab segments, not for a key:

- `configs/rules/dev-from-task/` (`01a`, `01b`, `02`): two-part predicates such as `dev_from_task.requested`;

The pin refused the same predicates (`config_validation.go:376`, `vocabulary.RequireDeclaredPredicate` parses the
predicate with the same three-part grammar). Neither flow's `rules_files` list (`configs/flow-bootstrap.json`,
`configs/e2e-flow-bootstrap.json`) names a file in the three directories; whether another path loads them was not
measured. Recorded only: it is semteams' to fix, and nothing is filed outside this repository.

## Choices the design leaves open

- **Keys match exactly as written.** The key check reads the body as a map, so `"Subject"` is refused as a key
  `publish` does not read, rather than taken as `subject` by `encoding/json`'s case-blind struct decode.
- **The first refused key is named**, in sorted order, so the error is the same on every run.
- **Values are type-checked.** After the key check the body decodes into one struct holding every built-in key with
  the pin's Go type (`object` and `ttl` strings, `merge` a bool, `properties`, `payload` and `set` objects), so a
  value of the wrong JSON type is refused at load, as the pin's decode refused it.
- **The predicate check covers `add_triple`, `remove_triple` and `update_triple` only**, the pin's three triple
  types. `reconcile_predicates`' predicate is checked against its projection target in PR 5.
- **The reserved-subject check reads the subject as written**, `$` tokens included; the after-substitution half is PR
  4's.
