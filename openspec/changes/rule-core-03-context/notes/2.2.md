# Task 2.2: choices the design leaves open

Scope: `ExecutionContext`, the one scan and every token it reads (`execution_context.go`, `entity_substitution.go`,
`message_substitution.go`, `lifecycle_substitution.go`), `SubstituteVariablesWith`, `SubstituteVariablesTyped`
(`typed_substitution.go`), `LifecycleManager`, and the consumer-corpus run below.

## Lifecycle tokens

- The four names are fixed names on the one scan, so `workflow_def` is never read as `workflow`: the pin's sorted
  table, its `init` sort (F24) and its placeholder swap go. The participant snapshot type goes too; the kept lookup
  holds the `lifecycle.Participant` itself.
- The manager is asked only when a template holds one of the four names, a manager is set and `EntityID` is not
  empty; `$entity.lifecycle.x` asks nothing. The result, found or failed, is kept on the context (one lookup per
  context, pin `lifecycle_substitution.go:221-236`).
- A failed workflow definition lookup or encode logs its own warning with the workflow and the error, as at the pin,
  and the token is then reported in the substitution warning: two warnings for that case
  (`TestLifecycleWorkflowDefinition`). A failed participant lookup logs nothing of its own, as at the pin; the token
  is reported.
- The lookup runs under the context `SubstituteVariables` was given (`TestLifecycleLookupGetsTheCallersContext`), so
  `ctx` is threaded through `substitute`, `resolve` and `resolveEntity`. `SubstituteVariables` returns no error and
  does not refuse a nil context; a nil context reaches the manager, whose store refuses it, and the token stays and is
  reported.
- `var _ LifecycleManager = (*lifecycle.Manager)(nil)` in `lifecycle_substitution.go` keeps the interface's two
  methods in step with the one production implementer.
- `populateLifecycleStateFields` is the pin's error-returning function, unexported (D1); the pin's tolerant
  `PopulateLifecycleStateFields` wrapper is not carried. Nothing in this PR calls it outside tests: its callers are
  the condition paths of PRs 6 and 7, which decide what to do with the error.

## Typed substitution

- `SubstituteVariablesTyped(template) (any, bool)` keeps the pin's signature: no typed token needs a lookup, so it
  takes no context.
- It reads the template with the scan's own grammar (`parseTriple`, `dottedRun`), so a triple token is typed only in
  its bare form. `.value` after a valid 3-part predicate is the suffix form and returns false; the caller's text path
  then gives the first object as text. The pin looked the whole `<p>.value` up as a predicate, found none and also
  returned false, so the caller's result is the same.
- The triple path is the scan's `[a-z0-9_-]`, where the pin's typed regex took `[\w.-]` (upper case too). A path
  with upper case is not a predicate the vocabulary accepts.

## Handler names (D7)

- `$<name>` is the whole run of letters, digits and underscores after the dollar sign, looked up as is: the
  fixed-name end rule, so `$subtopic.` and `$subtopic-x` hold `$subtopic`, and `$subtopics` is not it. With two
  names where one extends the other (`subtopic`, `subtopic_1`) each matches only itself.
- Names are tried only where no framework prefix starts. The refusal makes the two disjoint: a name whose `$<name>`
  starts with `$now`, or whose `$<name>.` is a prefix, is refused; any other name either differs from each prefix's
  word or ends inside it at a word byte, where the end rule does not match.
- A `$<name>` not in the map is ordinary text and is not reported, since it starts no framework prefix. An empty or
  nil map is allowed and behaves as `SubstituteVariables`.
- A nil context is refused, classified invalid: an exported boundary that returns an error refuses nil (`AGENTS.md`
  § 1).
- Generated checks are not added for names. The name grammar is one byte class with one boundary (the end of the
  word run), and the refusal set derives from the five-element `SubstitutionPrefixes()` list. Each boundary (dot,
  hyphen, a word byte extending the name, a name extending another) and each list member is a named example in
  `TestSubstituteWithNames`; the existing generated check covers the scan the names ride on.

## Where a token ends

- An unresolved token is `$` plus the longest run of dot-joined `[A-Za-z0-9_-]` segments, a final dot excluded, so
  `$entity.` before a space is reported as `$entity`, and `$state.iteration.` (no state) as `$state.iteration`.
- The triple path is taken longest first, then split: `.length` and `.triples` are always the suffix form, as at the
  pin; `.value` only after a valid 3-part predicate. A path holding the suffix twice therefore splits at the last
  one: `$entity.triple.a.length.b.length` counts `a.length.b` (the pin's lazy regex counted `a`). No rule writes
  either form.
- The same holds for the whole class of a suffix followed by more path text: a `.length`, `.triples` or `.value`
  with path text after it is part of the predicate, and only a suffix at the end of the run is the suffix form.
  `$entity.triple.a.b.c.length.x` reads the predicate `a.b.c.length.x`; with no such triple it stays and is reported
  (the pin gave `1.x` for `a.b.c` holding the list `["q"]`: its `.length` pass replaced
  `$entity.triple.a.b.c.length` and left `.x`). Likewise `.triples.x` and `.value.x`; probed on the pin copy with
  `a.b.c` = `["q"]` and then `"scalar"`, the pin gave `["q"].x` and `["scalar"].x` for `.triples.x`, `[q].x` and
  `scalar.x` for `.value.x`, and `[ERROR_LENGTH_NOT_LIST:a.b.c].x` for the scalar's `.length.x`.
  No consumer template writes this form: the corpus run below found 0
  matches of `\$entity\.triple\.[A-Za-z0-9_.-]*?\.(length|triples|value)\.[A-Za-z0-9_-]` in its 375 strings.
- The token grammar takes `_` in a triple path although the predicate grammar does not (`TestTokenEnds` writes the
  spec's `agent.run.entity_id` triple directly). A path that is no stored predicate is unresolved either way.

## Carried as at the pin

- `$entity.id` gives `EntityID` even when it is empty, and is never reported; the six parts resolve only from a valid
  six-part ID.
- A bare triple token on a list-valued object writes it with `%v` (`[a b c]`); `.triples` is the JSON form.
- The warning goes to `slog.Default()` (F23 is optional), now through `WarnContext` with the caller's context.
