# Task 2.2: choices the design leaves open

Scope so far: `ExecutionContext`, the one scan and the `$entity.*`, `$state.*`, `$message.*` and `$now` tokens
(`execution_context.go`, `entity_substitution.go`, `message_substitution.go`). Not yet here: `typed_substitution.go`,
`lifecycle_substitution.go`, `LifecycleManager`, `SubstituteVariablesWith`, and the consumer-corpus run this task asks
for.

## Lifecycle tokens wait for the lifecycle unit

`ExecutionContext` has no `Lifecycle` field yet, and the scan has no `$entity.lifecycle.*` branch, so today such a
token is an unresolved `$entity.` token: it stays and is reported. The unit that carries `lifecycle_substitution.go`
and `LifecycleManager` adds the field and the four fixed names; `TestTokenEnds`' `$entity.lifecycle.x` case then
gains the lifecycle manager knowing the entity that the spec scenario names.

## Where a token ends

- An unresolved token is `$` plus the longest run of dot-joined `[A-Za-z0-9_-]` segments, a final dot excluded, so
  `$entity.` before a space is reported as `$entity`, and `$state.iteration.` (no state) as `$state.iteration`.
- The triple path is taken longest first, then split: `.length` and `.triples` are always the suffix form, as at the
  pin; `.value` only after a valid 3-part predicate. A path holding the suffix twice therefore splits at the last
  one: `$entity.triple.a.length.b.length` counts `a.length.b` (the pin's lazy regex counted `a`). No rule writes
  either form.
- The token grammar takes `_` in a triple path although the predicate grammar does not (`TestTokenEnds` writes the
  spec's `agent.run.entity_id` triple directly). A path that is no stored predicate is unresolved either way.

## Carried as at the pin

- `$entity.id` gives `EntityID` even when it is empty, and is never reported; the six parts resolve only from a valid
  six-part ID.
- A bare triple token on a list-valued object writes it with `%v` (`[a b c]`); `.triples` is the JSON form.
- The warning goes to `slog.Default()` (F23 is optional), now through `WarnContext` with the caller's context.
