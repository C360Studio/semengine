# Task 2.4: choices the design leaves open

- **The entity key is checked as part of the whole key.** `stateKey` checks the rule ID with
  `natsclient.ValidateKVLiteralToken`, then `<rule ID>.<entity key>` with `ValidateKVLiteralKey`. The entity key is
  not checked as a 6-part entity ID, since the message path keys by message ID (D9).
- **No separate nil-context check.** `KVStore.Get`, `Put` and `KeysByFilter` refuse a nil context, classified
  invalid; the tracker adds no check of its own. `DeleteAllForEntity` checks the entity ID before the listing, so a
  nil context with a bad ID reports the ID.
- **A key missing during the delete loop is a failure.** A record deleted between the listing and its delete
  returns `ErrKVKeyNotFound` from `KVStore.Delete`, and it is joined into the error like any other failure. There is
  one writer per bucket (ADR-111), so this is not a case the tracker expects; it is reported, not hidden.
- **The integration tests use the bucket name `RULE_STATE`.**
- **`storedKeys` ignores the error from `lister.Stop()`.** Once the key channel has closed, nats.go has been seen to
  return `nats: invalid subscription` for it. That is observed, not promised; the test reads the keys from the
  channel either way.
- **The coverage target becomes `processor/rule merged`** (`scripts/cover-check.sh`, with the row in
  `internal/harness/toolcheck/cover_test.go`). The package now has an integration test, so "in-memory only" is false,
  and the record store is exercised only by the integration lane. The unit lane alone measured 84.4%, above the
  80% floor, so the change is about measuring the right code, not about passing the gate.
- **Not done here:** unexporting `substituteConditionValues` and `populateLifecycleStateFields`. Both live in the
  `ExecutionContext` and lifecycle files, which come with task 2.2's unit.

## Not covered

- The error for a record that failed to delete, naming its key, has no test. Reaching it needs a delete to fail
  after a successful listing, which needs an injected fault; there is no real-world trigger with one writer.
- F28's port-history lines: none fall in `state_tracker.go`, since the two pin lines carrying them were not carried.
