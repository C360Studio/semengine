# Task 2.4: choices the design leaves open

Scope: unit B of the port, the message match and the payload projection (2.4), with the tests in 2.1 that prove them:
`TestMessageMatch`, `TestUnreadableReportedOnce`, and the message side of `TestRequiredFieldMissing`. Three items from
unit A's review ride with it: the stateless refusal classified invalid (L3), `TestMatchesConcurrent` (L4), and two
comments rewrapped. The generated check and its two mutants (rest of 2.1), the carried test sweep and comments (2.6,
2.7), ledger, PR body and docs are not here.

## Choices

- The message match is `(*Rule).matchMessage(ctx, msg message.Message)` in `processor/rule/message_match.go`, with
  `ruleFields`, `payloadTypeLabel` and `(*Rule).reportUnreadable`. It takes one message, not the pin's slice of which
  it read the last: the rule processor's caller (PR 9) has the one message it received.
- It does not check `entity.pattern`, as the entity match does not: the caller picks the rules a message reaches, and
  `Load` already refuses a `$message.` condition in a rule with a pattern (D6).
- Order: a disabled rule or one with no conditions is `false, nil` before the payload is read, so neither reports an
  unreadable payload (the pin's order). Then projection; an unreadable payload is reported and is `false, nil`. Then
  the values are filled through `substituteConditionValues`, as the entity match does, with an `ExecutionContext`
  holding only `MessageData`; then the evaluator, an absent required field read with `errors.Is` as no match.
- The report set is a `sync.Map` field of `Rule` (`unreadableReported`), keyed by payload type, so it dies with the
  loaded rule and a second `Load` reports again. `Rule` is only ever handled by pointer; `go vet`'s copy check passes.
- The report is `slog.Default().WarnContext`, as the package's other warnings are, with `rule_id`, `payload_type` and
  `remedy`. The pin's `rule` (the rule name) is not logged: D7 names rule ID, payload type and remedy.
- `payloadTypeLabel` answers `"none"` for a nil message; at the pin a nil message reached `msg.Type()` and panicked.
- `ruleFields` has one caller here, the message match. PR 9's action message data is its second.
- The test-side log reader (`substitutionWarning` in `execution_context_test.go`) gained `level`, `payload_type` and
  `remedy`, so the report is checked through the same JSON reader as the substitution warnings.
- The empty-payload case is tested on `{}` against a payload holding another field, with `ne`, `eq` and `not_in`
  literal conditions: no operator answers true on an absent field, so both give false. A `$message.` value template on
  `{}` is an error naming rule, field and token.
- Generated checks: not used for the message match. Its inputs are a payload's readability (unreadable, readable and
  empty, readable with fields) and the condition, and the evaluator it calls is the entity path's, which the 2.1
  generated check exercises; the named examples cover each readability class and each answer (true, false, absent
  required field, error).

## Seen to fail

- All the new tests: build failure first (`r.matchMessage undefined`). Then, against a stub `matchMessage` returning
  `false, nil` and a stub `ruleFields` returning `nil, false`, with the L3 change not yet made: `TestMessageMatch` (five
  subtests), `TestUnreadableReportedOnce` (and its reload subtest), `TestRequiredFieldMissing`'s message operator
  failure, and `TestMatches/a_condition_needing_state_is_refused` (L3) failed. The tests that passed against the stub
  (an absent required field on a message, the legitimate false, the empty payload, `TestMatchesConcurrent`) were then

## Uncovered case

"Exactly one Warn" is not proved against a check-then-store report set. Every gate runs at `-cpu 1`, where the 16
goroutines are never switched between a `Load` and a `Store`, so that mutant survives (five runs); the race detector
does not see it, as each `sync.Map` call is race-free. A direct probe at `-cpu 8` failed it 19 of 50 runs with `-race`
and 8 of 50 without. The guarantee rests on `LoadOrStore` in `reportUnreadable`. No hook forces the interleaving, as
that would be a test-only door into production code.
