# Task 2.1: the product-shaped test

`TestProductServesTLSFromDependenciesSecurity` (`pkg/security/product_test.go`, commit `9d7f118`) tests behaviour
that already exists, so it passes on the base commit `3aab575`. Its proof that it can fail is the two mutation checks
below.

## Mutation checks

Both were run with `task mutate:check` on commit `9d7f118c3341facc97850c7900935f252e22ccbc`, clean tree, each
wrong change in a copy outside the repository. Each runs the test three times on the unchanged code, three times on
the wrong change and once more on the unchanged code.

| Mutant | Wrong change | Expected failure | Verdict |
| --- | --- | --- | --- |
| A | `internal/tlsutil/tlsutil.go:122` `if mtlsCfg.ClientCertOptional {` to `if !mtlsCfg.ClientCertOptional {` | `product_test.go:184`, the no-certificate client is refused | detection: each of the 3 mutant runs failed at `:184`, and the after-run passed |
| B | `metric/handler.go:149` `if s.security.TLS.Server.Enabled {` to `if false {` | `product_test.go:187`, the signed client is served | detection: each of the 3 mutant runs failed at `:187`, and the after-run passed |

Mutant A also fails `:197` (with `client_cert_optional` the no-certificate client is refused). Mutant B also fails
`:197` and `:204` (`Start` no longer loads the TLS configuration, so it neither serves TLS nor refuses `"1.4"`).
The full reports were local only, under `$TMPDIR/semengine-mutcheck-*`.

The arrival case ("every setting arrives unchanged") has no mutant: no code SemEngine owns sits between the decoded
document and the `deps.Security` the factory receives, so only the decode can change what arrives, and
`TestConfigDecodesEveryKey` covers the decode.

## Choices the design leaves open

- The product type carries all six `component.Discoverable` methods `main` has at `3aab575`, `Meta()` and
  `ConfigSchema()` included (design, Merge order). If #273 lands first, its removal of those two methods reaches this
  file when this branch merges `origin/main`.
- The test reaches the server through the `*product` the factory returns (a type assertion in the test), and starts
  it with `StartWithListener` on `127.0.0.1:0`. The product adds no start method of its own.
- The operator document for the server cases is built by `operatorDocument`, which quotes the `t.TempDir()` paths
  with `encoding/json`; the variants add `client_cert_optional` or `min_version` to it as text.
- The test writes its own self-signed identity; `metric/tls_test.go`'s helper is unexported in another package.

## After merging main (PR #273)

PR #273 landed first. It removed `component.Metadata`, `Meta()` and `ConfigSchema()`, so after this branch merged
`origin/main` (`71f042e`) the test no longer compiled (`product_test.go:41:34: undefined: component.Metadata`). The
product type now carries the four `component.Discoverable` methods `main` has: `InputPorts`, `OutputPorts`, `Health`
and `DataFlow`, and nothing else. No test assertion changed.
