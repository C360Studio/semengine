### Tests added

`internal/graphmutation/client_test.go`:

- `TestClientAppendRefusesMalformedResponse` (D11: "the client refuses a malformed append response",
  `validateAppendResponse`). An append reply is handed on only when it answers the request subject for subject. Two
  valid replies pass unchanged; thirteen malformed ones (no results, fewer results than subjects, one per statement, a
  subject not asked, a subject twice, a failure without an error, class or code, a failure with a revision, applied or
  unchanged without a revision, not-found with one, an outcome append does not report) each return no response and an
  append `commit_unknown` after one request.
- `TestClientReconcileAndDeleteSendOneRequestAndReadTheReply` (D11: "`Reconcile` and `Delete` send their requests and
  read their replies"). Each sends the request it was given, unchanged (decoded from the payload and compared whole),
  as one request on its own subject, and returns the reply when it answers that request (reconcile: applied or
  unchanged, same entity, a revision; delete: applied, same entity, same fence). A reply for another entity, outcome,
  fence, or with no entity or revision is `commit_unknown`, never a success.

`pkg/projection/mutation_client_requests_test.go` (new):

- `TestCreateSendsItsCanonicalRequestAndReadsTheReply`: one request on the create subject with the entity, its
  statements with source, context and time filled from the metadata, the contract's indexing profile, the trace and
  request IDs; the receipt carries the reply's entity and revision, verified.
- `TestAppendSendsItsCanonicalRequestAndReadsTheReply`: one request on the append subject with the filled statements
  and the trace and request IDs; applied and unchanged are verified at the reply's revision; entity-not-found is a
  not-committed `MutationNotFound` with code `entity_not_found`, class invalid.
- `TestDeleteSendsItsCanonicalRequestAndReadsTheReply`: one request on the delete subject with the entity, the
  caller's fence and the trace and request IDs, no read before it; verified at the fence the reply confirms.
- `TestMutationErrorKeepsTheReplysClassCodeAndDetail` (`newMutationError`, `cloneDetail`, `MutationError.Unwrap`): on
  all four writes, the error keeps the reply's class, code and detail, unwraps to the reply itself, and keeps its own
  copy of the detail when the reply's map changes afterwards.
- `TestGroupAndStatementCanonicalizationRefusedBeforeRequest`: on Create, Reconcile and Append, an unknown contract,
  an entity outside the contract's pattern, a statement on another subject, a predicate the operation may not write,
  a statement source or context that differs from the metadata, and (Reconcile, Append) an undeclared group or a
  group of the other mode are each refused as invalid, not committed, with no request.
- `TestCreateRefusesAnEntityItCannotBuildFrom`: a nil entity, or one carrying statements (the mutation's own list is
  the sole fact source), is refused as invalid, not committed, with no request.

### Generated checks

Not used. The append reply rules are one predicate per result (count, membership, duplicate, outcome against error and
revision); each case changes one rule from a valid two-subject reply, and the two cases where the count and the subject
set interact (one result per statement; a subject twice at the right count) are named. The refusal table changes one
input from a write the same subtest shows accepted, so each refusal has one cause; no rule depends on the order or
combination of inputs.
