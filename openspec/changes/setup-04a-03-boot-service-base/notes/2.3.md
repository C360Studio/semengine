## Outcome

Nine unit runs and one integration check, eight design mutants (D6's fifth row run as two, m5a and m5b, since it
names two wrong changes). Every one is a detection; no survivor, invalid or inconclusive run.

## Choices the design does not spell out

- **m2 and m7 sit in front of the guard.** The guard returns an ended Stop context's error before it runs any cleanup
  (`internal/lifecycleguard/guard.go:109-111`), so neither wrong change can be made in `stop`. Both are written in
  `BaseService.Stop`, the one place a port could reintroduce them.
- **m3's shape.** "A later Stop returns at once" is written as the first Stop forgetting its handles when its context
  ends: the guard then runs `stop` again, finds no cancel, and returns nil without waiting. That is how the pin's
  one-shot Stop behaved.
- **m4's shape.** Probe H3 says `Serve` returns as soon as Shutdown begins, so a Shutdown that waits on the serving
  goroutine alone returns nil with the request still in its handler; the test's first assertion catches it.
- Every wrong change edits a line the named test reaches, and none leaves an import or variable unused, so all built.
