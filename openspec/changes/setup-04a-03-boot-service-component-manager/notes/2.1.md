# Notes: task 2.1 (tests first)

Status: not started. One section per unit of `tasks.md` 2.1. Each section names its files, the pin lines it carries
(SemStreams `8b99efe9`, `service/` unless another path is given), the design sections its brief cites, and the names
its tests call in the port. The developer fills "Choices the design leaves open" and "How the tests fail on the base".

Rules for every unit (design D7): a manager is built through `NewComponentManager` with a test `component.Registry`
and a `config.Manager` holding the test components, never as a struct literal; no test writes or reads a lifecycle
field the guard replaced (`initialized`, `lifecycleUsed`, `cleanupPending`, `lifecycleTerminal`, `stopping`,
`startDone`, `cancel`, `componentRuntime.cancel`/`startDone`/`terminal`), and none touches a record's state value or
the pin's `components`, `mu`, `storeProvided` or `updateComponentState`, which the state shape replaces (design D2);
assert outcomes instead (what `Start` and
`Stop` return, `GetComponentStatus()[name].State`, what a component recorded). No `time.Sleep`, `Skip`, fixed port, or
`t.Parallel` in an integration file. Measured for building without a broker: `config.NewConfigManager` over an
unconnected `natsclient.NewClient` returns a manager whose `GetConfig()` is non-nil (go1.26.10, a probe outside the
repository; the test names an address the fixed-port guard accepts).
