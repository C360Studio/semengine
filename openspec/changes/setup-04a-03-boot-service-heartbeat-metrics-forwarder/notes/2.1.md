Stub contract additions for 2.2 (the tests call none of these by name; they read the wire and the registry):

- Config keys `push_interval`, `include_go_metrics`, `include_proc_metrics`; `{"push_interval":"1h"}` and `"1s"` are

  every later round reach a stream over `metrics.>`; the first round runs at once after `Start`.
- Each sample is one JSON object with exactly the keys `timestamp` (Unix milliseconds), `name`, `component`, `type`,
  `value`, `labels`, on `metrics.<component>.<name>`; `component` is the `component` label, else `system`; `labels` is
  `{}`, never `null`, for a sample with no labels; a counter's `type` is `counter`, a gauge's `gauge`.

- An unencodable sample increments `semengine_errors_total{service="metrics-forwarder",type="metrics_publish"}` on the
  injected registry's `CoreMetrics()` and is not published.
- The stub's mapping is `func metricSamples(families []*dto.MetricFamily, includeGo, includeProc bool, now time.Time)
  []metricSample` with `metricSample{Timestamp, Name, Component, Type, Value, Labels}` and `subject()`; U-e does not
  call it, so U-d's signature governs if the two differ.

Choices the design left open: the stream is `METRICS` in memory storage (the design names no storage); samples are
read through an ordered consumer filtered to one subject from the stream's start, decoded into a test-local
