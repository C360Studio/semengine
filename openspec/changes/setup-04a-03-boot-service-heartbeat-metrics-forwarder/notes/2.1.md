Stub contract for 2.2:

- `func NewHeartbeatService(rawConfig json.RawMessage, deps *Dependencies) (Service, error)` returns
  `*HeartbeatService`; registered by name `heartbeat` and built through `Manager.CreateService`, so `deps.ServiceManager`
  is the manager; `{}` is accepted (default interval) and the constructor does no lookup and no I/O.
- `func NewMetricsForwarderService(rawConfig json.RawMessage, deps *Dependencies) (Service, error)` returns
  `*MetricsForwarder`; accepts `{}` over `newUnconnectedClient(t)` with a fresh `metric.NewMetricsRegistry()`, and does
  no I/O.
- Both structs embed `*BaseService` (the suite reads `Status()`); `Start(ctx) error`, `Stop(ctx) error`; a `Start`
  after `Stop` returns `errs.ErrAlreadyStarted` (`lifecycleguard`).
- The heartbeat's `Start` finds `component-manager` through its `ServiceManager` and needs it to be a
  `*ComponentManager`; the suite's manager holds `newTestComponentManager(t)`, not started.
- `hb.loopDone` and `mf.loopDone`, each `chan struct{}`, read by `Observe` without a lock: nil before `Start`, closed
  once the service's one loop has returned; the channel `Stop`'s join waits on. Assigned once inside `start` before
  `Start` returns, never reassigned (the pin's field name, `hb:73`, `mf:139`; PR 5's `loopsDone` precedent).

Choices the design left open: the join field keeps the pin's name `loopDone`; `Observe` labels `base-status=<status>`
(neither stopped nor starting) and `loop` (non-nil and open), `Calls` nil, shared by both adapters through
`observeOneLoop`; both owners share `runOneLoopSuite`, which adds `StartedOwnerReportsItsHandles` and
`StartAfterStopIsRefused` (PR 5 precedent); the must-fail owner is a service stopped before `Start`; both services log
to the package's `discardLogger` (`graph_triples_http_test.go`), since the suite reads no record; `newTestHeartbeat`
registers the component manager under `componentManagerName`, not a literal; no generated checks in this unit (design
"Harness rules").
