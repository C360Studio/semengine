  as `TestMaybeStartPProfLogsABindFailure` does (probe H1 on #343).

- **`TestTypeNameFromReflectNamesEachShapeApart`** sits in `schema_test.go`, beside `TestTypeNameFromReflect`,
  whose assertion that `[]int` is named `"[]int"` is removed: it pinned the behaviour #349 fixes, and `[]int` does
  not match `^[A-Za-z0-9._-]+$`.
- **`TestScanGraphTriplesMatchesSortedOracle`** (Generated checks) has a named example first, keys listed in
  reverse with limits 1 and 3, so the unsorted-scan mutant fails on every run, not only on a lucky draw. The
  generated part: zero to six entities from a six-ID pool, zero to three triples each from two predicates and
  objects `"x"`, `"y"`, `2.0`, listed in a drawn permutation; each filter absent or one pool value; the limit drawn
  from 1, matches-1, matches, matches+1. The oracle sorts the IDs itself and matches each filter on its own; results

- **`TestGraphTriplesSkipsOnlyADeletedKey`** also covers an entity `graph.UnmarshalEntityState` refuses (500), the

- **`registry_race_test.go`.** `TestServiceManager_ConcurrentOperations` checks each registered name through

### Choices the design leaves open

- **Runtime-stop tests (pin `:352-545`).** They drove private runtimes and flags. Their outcomes: a cancelled
  `StopAll` stops nothing (`TestStopAllWithAnEndedContextStopsNothing`); `StopAll` waits for an in-flight request
  on the main and the health listener (`TestStopAllWaitsForInFlightRequests`, new: a service whose `Health` blocks
  holds `/health` open on either listener, since the health routes take no middleware); the deadline cut
  (`TestStopAllCutsOpenConnectionsAtItsDeadline`); nil contexts and stop-before-start (the suite). The publisher
  and HTTP failed-start retention tests (`:475-545`) go to the suite's `FailedStartHoldsNothing` and the
  rollback-retry leg of `TestStartAllRollsBackFailedChildStartWithDetachedBoundedContext`.
- **`TestStartAllRollsBackFailedChildStartWithDetachedBoundedContext`** keeps the pin's `context.WithValue` pass token
  as an observation that the rollback context derives from the `StartAll` context. The main listener's address is
  read while `earlier`'s rollback Stop blocks (listeners stop after services), and a dial to it is refused after
  `StartAll` returns, in both cases: the rollback goes on past a service that fails to stop, as `StopAll` does. The
  retry after a failed rollback expects `errs.ErrAlreadyStarted` from a second `StartAll`.
- **`TestStartAllRollsBackMainAndPublisherAfterPublisherStartFailure`.** The pin started the publisher through a
  private call first. Here the last service's `Start` ends the `StartAll` context and returns nil, so the publisher,
  started under that context after every service, is refused: `StartAll` returns an error wrapping
  `context.Canceled`. This assumes `StartAll` refuses an ended context at the publisher start or at commit, which D2's
  "bounds StartAll" implies; the test reads `httpListener == nil` and the publisher not running instead of the pin's
  `httpTerminal` and `healthPublisherTerminal`.
- **`TestStopAllRetainsServiceAuthorityAfterFailure`** goes through `StartAll` and `GetService` (the pin wrote the
  service map), and asserts the spec's second `StopAll` calls the failing `Stop` again.
- **Negative windows.** Three tests assert that a call has not yet returned while something it must wait for is held
  (`negativeWindow`, 100 ms, a `time.After` in a `select`). The window can only miss an early return, never fail a
  correct wait. `TestStartAllRollbackWaitsForAnInFlightRequest` also checks, deterministically, that the handler
  had returned when `StartAll` returned.
- **`TestHealthPublishFailureIsCounted`** reads the counter after `StopAll`, which joins the publisher, so the first
  publish has run whether `StartAll` made it or the goroutine did. The unconnected client is
  `natsclient.NewClient("nats://unconnected.invalid")`, never connected; `PublishToStream` refuses with
  `ErrNotConnected` (`natsclient/client.go:1296`).
- **`TestHealthListenerRequestContextOutlivesStartContext`** reads `healthServer.BaseContext` if set, else the
  server's default background context, as D2 says (the health routes take no middleware).
- **`TestManagerPassesTheLifecycleSuite`.** The adapter lists `main-listener`, `health-publisher`, `metrics-server`
  and `child-health-loop`; the publisher runs with no NATS client (pin `:695-720` starts the goroutine either way;
  `publishServiceHealth` returns at once). `mustFail` composes the stand-in, a failing second service, then
  `metrics` and the child, so the rollback must release the claimed metrics server. Calls is empty.
- **D4's manager-driven half.** The service registered first scrapes the metrics listener in its `Start` (the
  server serves before any service starts) and in its `Stop`, which runs last, after `Metrics.Stop` (the server
  stops after every service). That the claimed server binds after the main listener is
  `TestMetricsBindFailureClosesSharedAndStartsNoLaterService`'s (part 5). "Healthy only while it serves" is read
