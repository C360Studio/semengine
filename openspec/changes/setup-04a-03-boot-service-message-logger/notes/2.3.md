## Uncovered (design D7)

- **The mid-start cancel (D2).** `Start` checks its context before each subscribe (`<ml>:284-287`); a context that ends
  between two subscribes returns the transient error and the guard rolls back through `cleanup`. No test ends the
  context between two subscribes without a hook (#186), so the check and its rollback are review only; the suite's
  `FailedStartHoldsNothing` covers a failed `Start`'s rollback in general.
- **The two KV `Get` branches (D4).** In `queryKVBucket`, a key whose `Get` answers `jetstream.ErrKeyNotFound` is left
  out, and any other `Get` error answers 500 naming the key (`<http>:410-416`). Both need the bucket to change, or
  the server to fail, between the `Keys` listing and the `Get`; no test makes that happen, so both are review only.
- **The source naming of a malformed subject a component declares (D3).** `collectDeclaredSubjects` refuses it naming
  the component and port (`<ml>:370-373`). It is the same `ValidSubject` call as the `monitor_subjects` loop, which
  row 10 tests; the naming text itself has no test.

## Review only, from `notes/2.2.md`

- **nats.go's Updates channel.** nats.go waits for room when it puts a watch entry on its 256-entry Updates channel
  (`jetstream/kv.go:1319` at v1.54.0). If more than 256 entries arrive between the reader's last receive and its
  `watcher.Stop` after a fall-behind, a nats.go goroutine could stay blocked until `Stop`. Not probed; no real-world
  trigger named, so MEDIUM at most (#185). No mutant applies: the window is in nats.go, not in the logger.

## Tests that could be stronger

- Row 6: `TestMessageLoggerRetriesSubscribeUntilConnected` cannot detect an unjoined retry, because the retry has
  always ended before `Stop` runs. A test that stops the logger while the retry still runs (a client that never
  connects) and then checks `Observe` for `subscribe-retry` would reach the join; under an unjoined retry it would
  detect only when the retry goroutine has not yet returned, so it would be probabilistic, not certain. Not written;
  recorded for the reviewer.
- Row 1b: the suite's `StartContextEndStopsNothing` is listed in the design as catching a run context derived from
  `Start`'s, but cannot on this owner (the `Observe` adapter has nothing that changes when the run context ends).
  Row 1's other test detects it, so the row is covered; the design's cell overstates the suite.
