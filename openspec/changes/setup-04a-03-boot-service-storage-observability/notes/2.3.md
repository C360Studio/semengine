## Uncovered (design, Sensitivity)

- **A collection in progress when `Stop` begins (D2).** `Stop` ends the run context and waits for both loops
  (`<so>:310-320`). How soon a collection already inside the JetStream account listing sees that context end depends
  on whether nats.go's listing honours its context, which nats.go does not promise (`Stop`'s doc comment,
  `<so>:298-303`). `Stop` stays bounded by its own context either way, and `TestStorageObservabilityFailedStopIsRetried`
  covers a loop that cannot return; no test holds a loop inside the listing itself, so the listing's own cancellation
  is not tested.
- **The bucket lock held across acquisition (O12, retained).** `lazyReportBucket.resolve` holds `b.mu` while
  `kvcatalog.EnsureCatalogBucket` runs (`<so>:358-371`), so a slow server holds the second caller behind the first.
  Retained as the design and `sweep.md` O12 record (no named trigger beyond a slow server); no mutant applies.
- **P-1's `clear(m.accountTiers)` survivor.** m18, `<met>:492`: the line removed. `task mutate:check -- -pkg
  ./service -test TestStorageAccountMetrics_ForgetAccountRetractsEveryTierSeries -file <met> -mutant
  /tmp/pr5mut/m18/storage_observability_metrics.go -expect <met_t>:387 -expect <met_t>:398`: **survivor** (exit 201;
  the reach run shows the test reached the change). Deleting a series that is already gone does nothing, and the next
  `ObserveAccount` replaces the record, so no read through the metrics surface can see the stale record. The line is
  kept so the published-tier record stays true, as `notes/2.2.md` (P-1) states.
