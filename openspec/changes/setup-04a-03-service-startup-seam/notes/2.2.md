## Choices the design does not spell out

- The gauge's description is a package-level `startupUnitsDesc` built with `prometheus.NewDesc` and the full name
  `semengine_startup_units`, so the name is spelled once in production code, which is what
  `TestStartupGaugeVecHasOnlyPrivateServicePackageOwner` now looks for (the old check matched a `GaugeVec` field that
  no longer exists).
- `registerStartupCollector` keeps the writer's two refusals (nil registry, nil snapshot function) and its error text
  `register fresh startup metric collector`, which `TestStartupMetricRegistrationConflictFailsBeforeListenersOrChildren`
  matches.
- `recordStartInvoked` and `recordStartCompleted` now hold `m.mu` with `defer`, since nothing runs after the unlock.
- `TestComponentManagerOnItsOwnPublishesNoStartupGauge` builds the manager inline (not `newTestComponentManager`) to
  reach the `Dependencies` whose `MetricsRegistry` it gathers, and starts one lifecycle component to completion first.
- `TestStartupGaugeReadsZeroComponentsForAStandInComponentManager` also checks the nine-series count and that the
  service series count the stand-in (one admitted, one completed), so a collector that reads zero everywhere fails.
- Stale comments naming the writer were reworded in `component_startup_test.go`, `service_manager_test.go`
  (`newStandInComponentManager`) and `foreignStartupGauge`.
- The ledger text at `docs/admission-ledger.yaml:2932` and `:2964` still names `startup_metrics.go (publishComponents)`;
  left for task 3.1 (`task ledger:check` passed with it).
