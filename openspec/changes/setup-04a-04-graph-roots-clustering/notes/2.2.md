# Task 2.2: the unit tests of design D5, shown able to fail

This note covers the D5 tests that belong to `types.go`, `storage.go` and `terms.go` (tasks 3.1, 3.2). The
maintainer's D5 tests (`TestObsoleteDeliveryIgnored`, `TestRefusedEntityMakesTickIncomplete`,
`TestTickBeforeBootstrap`, `TestFailedWriteRetried`, `TestFirstTickFailedPublicationKeepsOldRecords`,
`TestUpsertDuringBlockedWrite`, `TestRepresentativesWithoutScan`, `TestTickReportsCancel`) came with task 3.3; their
wrong changes are under "The maintainer's tests" below.

`TestKeywordsIgnoreIDAndPredicates` is written here against `entityWords` and `newCommunity`; the maintainer unit
extends it through `Upsert` and `Tick` rather than adding a second test of that name.

## Generated checks or examples

Named examples suffice for these files: word extraction is a single-pass scan whose interacting cases are the length
bounds (3, 32, 33) and the separators, each a named case; the record bound is one worst case built at every field's
maximum. The order-dependent history is the maintainer's, covered by `TestMaintainerMatchesModel` (task 2.3).
