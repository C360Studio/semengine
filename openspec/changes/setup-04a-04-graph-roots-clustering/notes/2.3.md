# Task 2.3: the generated checks of design D5

`TestMaintainerMatchesModel` and `TestHistoryOrderIrrelevant` (`graph/clustering/maintainer_prop_test.go`), Rapid
`v1.3.0`. The reference model is written in the test from the spec and design D2: it splits IDs on `.` itself, takes
each entity's words from the generated word list (the value's text is that list joined by spaces, every word valid by
construction), applies the `MaxEntityTerms` cap with lexical ties, builds the summary from the template text, and
never calls `terms.go` or `maintainer.go`.

## What makes each assertion run

- `TestMaintainerMatchesModel` compares every record and `Tick`'s result with the model after every tick past
  `BootstrapDone`, and checks `Upsert`'s and `Delete`'s errors at every step. A fixed prefix in every history upserts
  an entity with 40 distinct words (the cap applies) and five members with words in one source (its level-1 and
  level-2 records hold `MaxRepEntities` representatives). A fixed suffix upserts an entity no generated delivery names,
  ticks, deletes it and ticks, so three groups become empty and their removal is compared in every check. Generated
  operations: upserts (valid, nil state, mismatched state ID, unparseable ID), deletes of any ID and of held IDs,
  obsolete upserts and deletes at a revision drawn from 1 to the held one, ticks, `BootstrapDone`.
- `TestHistoryOrderIrrelevant` draws one to ten entities (unparseable IDs included), one to four deliveries each at
  revisions 1..n, and after any upsert, an obsolete upsert or delete at a revision drawn from 1 to that upsert's. It
  runs two independently drawn interleavings with ticks at drawn points and compares the final buckets byte for byte
  and the final `Tick` results.

## Wrong changes (`task mutate:check`, seed 1)

| Test | Wrong change | Outcome |
| --- | --- | --- |
| `TestMaintainerMatchesModel` | a newer upsert adds without subtracting the old contribution | detection |
| `TestMaintainerMatchesModel` | a refused newer upsert keeps the old contribution | detection |
| `TestMaintainerMatchesModel` | a group that becomes empty is not marked changed | detection |
| `TestHistoryOrderIrrelevant` | a group that becomes empty is not marked changed | detection |
| `TestHistoryOrderIrrelevant` | a newer upsert adds without subtracting | survivor: both histories apply the same per-entity deliveries, and sums commute, so the wrong records are equal; `TestMaintainerMatchesModel` owns this law |

## Not covered

The model is sequential: concurrent `Upsert` and `Tick` are covered by `TestUpsertDuringBlockedWrite` and the `-race`
runs, not here. Ten or more types in a group (the `MaxKeywords` type bound) is not generated (two types); it is
`TestRecordIsBounded`'s.
