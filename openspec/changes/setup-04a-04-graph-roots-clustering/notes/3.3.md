# Task 3.3: choices `maintainer.go` makes that design D2 leaves open

- **Locks.** `mu` guards the maintainer's state and is never held across storage I/O; `tickMu` makes one `Tick` run
  at a time and is held across I/O. `Upsert` and `Delete` take only `mu`, so they never wait on a write
  (`TestUpsertDuringBlockedWrite`). An entity's words are extracted before `mu` is taken.
- **Refusal and revision.** A refused upsert above the held revision removes the old contribution and holds the new
  revision with no contribution, so the records equal those of the final (refused) value. A refused upsert at or below
  the held revision still returns its error and changes nothing.
- **`Delete` errors.** `Delete` refuses only an ID it does not hold that the canonical parser refuses; a held refused
  ID, even an unparseable one, deletes, so it leaves the refused set.
- **Failed tick.** Writes run in key order and stop at the first failure; every group the tick took goes back to
  pending, written ones too, and the next tick skips those because they equal what was published. Stale keys stay
  pending until their own removal succeeds.
- **Stale keys.** The first tick's listing records every key; a key whose group exists is dropped from it (the
  group's own write replaces it), the others are removed after the writes. A group that becomes empty is removed only
  if a record of it was published, so a group created and emptied between ticks writes nothing.
- **Equality.** The last published record of each group is kept in memory (at most `MaxRecordBytes` encoded each) and
  compared with `reflect.DeepEqual`.
- **Ordered set.** Members with words are kept as sorted chunks of 256 to 512 IDs: an insert or removal moves one
  chunk, and representatives are read from the front. A sorted slice would make a replay of n members O(n²) moves.
- **`IncompleteError`.** `Refused` holds every refused ID, sorted; `Error()` names the first ten and counts the rest.
- **Cost not bounded by the design.** Recomputing a changed group sorts its distinct words (`topCounted`), so a tick
  costs O(w log w) per changed group with w distinct words; a level-2 group can hold many. No member scan.
