# Task 3.3: choices `maintainer.go` makes that design D2 leaves open

- **Locks.** `mu` guards the maintainer's state and is never held across storage I/O; `tickMu` makes one `Tick` run
  at a time and is held across I/O. `Upsert` and `Delete` take only `mu`, so they never wait on a write
  (`TestUpsertDuringBlockedWrite`). An entity's words are extracted before `mu` is taken.
- **Refusal and revision.** A refused upsert above the held revision removes the old contribution and holds the new
  revision with no contribution, so the records equal those of the final (refused) value. A refused upsert at or below
  the held revision still returns its error and changes nothing.
- **Revision 0 and `Delete`.** `Upsert` and `Delete` refuse revision 0 and change nothing: a KV entry's revision is
  its stream sequence, which starts at 1 on the pinned nats.go and nats-server (`TestKVRevisionStartsAtOne`; not
  promised beyond that). A delete for an ID the maintainer does not hold, parseable or not, returns nil (review of
  `42ad8eb`, LOW 1); a held refused ID deletes, so it leaves the refused set.
- **Failed tick.** Writes run in key order and stop at the first failure; every group the tick took goes back to
  pending, written ones too, and the next tick skips those because they equal what was published. Stale keys stay
  pending until their own removal succeeds.
- **Stale keys.** The first tick's listing records every key. A key leaves that set when its group's record is
  written or when it is removed; while its group exists it is not removed (the group's write replaces it), the others
  are removed after the writes. A group that becomes empty is removed only
  if a record of it was published, so a group created and emptied between ticks writes nothing.
- **Equality.** The last published record of each group is kept in memory (at most `MaxRecordBytes` encoded each) and
  compared with `reflect.DeepEqual`.
- **Ordered set.** Members with words are kept as sorted chunks of 1 to 512 IDs: a split makes chunks of 256 and 257,
  and removals never merge, so a chunk can shrink to one ID. An insert or removal moves one chunk, and representatives
  are read from the front. A sorted slice would make a replay of n members O(n²) moves.
- **`IncompleteError`.** `Refused` holds every refused ID, sorted; `Error()` names the first ten and counts the rest.
- **Cost per changed group.** `topCounted` keeps only the best n while it reads the counts (O(w log n) comparisons for
  w distinct words, same tie rule), under `mu`. Measured on this machine with `MaxKeywords`: 0.22 ms at 10,000 words,
  4.3 ms at 200,000 (`go test -bench`, a throwaway benchmark not kept). Design D2 states the cost.
