# Task 2.1: a refused index plan marks the entity failed

Developer notes on choices design D6 leaves open, and the evidence behind the task's checks. Base `34a4e23`.

## Premises

Checked on the tree before coding, all true. `processor/graph-index/index.go:207-213`: when `indexEntity` returns an
error other than `errAuthoritativeIdentityMismatch`, the revision completes and only a log line is written.
`:243-250`: `markEntityFailed` is what counts `ErrorCount` and `semengine_graph_index_write_failures_total` and puts
the entity in the failed set that withholds readiness. `:429-432` (before this task): a refused plan returned its
error with no mark, so the revision completed and the entity's old rows kept answering (#428).

## The change

One line before the plan's error is returned, `c.markEntityFailed(entityID)`, mirroring the write-failure path just
below it (`retryIndexWrites` failing). The `indexEntity` doc comment now names both. The caller, the repair loop and
the counters are unchanged: the repair loop re-drives the entity, and a rewrite or delete clears it.

## Not covered, and the departures D6 records

- **The mark has no test.** D6's reachability reading, read and not probed: every check in `buildEntityIndexPlan`
  is implied by what `graph.UnmarshalEntityState` accepts (six-part IDs of at most 256 bytes, three-part predicates of
  at most 194 bytes in the lower-kebab alphabet, which sits inside the KV key alphabet) and by the byte budgets (the
  longest planned key, the incoming key, is 902 of the KV limit's 1,024 bytes). No stored value drives the branch, so
  no test can reach it without a hook, and production code carries none (#186). The mark is shown by reading.
- **Departure from #428's test sentence.** #428 asks for a test that drives a refused plan without a hook; that is
  not possible for the reason above. `TestContractValidStateAlwaysPlans` proves the premise instead.
- **Departure from failing-first.** The property holds on the tree before the change, and the mark cannot be driven,
  so nothing failed first. The test is shown able to fail by D6's mutant (below).

## Generated check

`processor/graph-index/plan_prop_test.go`, `TestContractValidStateAlwaysPlans`. The law (D6, spec delta "An entity
that cannot be planned is held as failed"): every state `UnmarshalEntityState` accepts gets a plan. Each generated
state is written through `graph.MarshalEntityState` and read back through `graph.UnmarshalEntityState`, the
production codec, before `buildEntityIndexPlan` runs on the decoded value.

- **Oracle.** The generator counts, as it draws each statement and from the requirement alone, the rows the plan must
  hold: one outgoing row per entity-reference object, one alias row per alias-predicate value non-empty after
  trimming (ADR-114 §5), one name row per non-empty label-predicate value. The plan's row counts must match. The
  oracle never calls the ID or predicate validators: a literal string carries a space, which the ID alphabet excludes,
  so it is never a reference.
- **Bounds, by construction.** A drawn flag pads each entity ID (entity, foreign subject, target, ID-shaped literal)
  to exactly 256 bytes and each predicate's three segments to exactly 64 (194 bytes); otherwise each is padded to a
  drawn length up to the bound. Alias and name values are any string (`rapid.String`), blank ones (`""`, `" "`,
  `"\t\n"`), KV-unsafe ones, and 4,096-byte ones. Two alias and two label predicates are registered, one of each at
  194 bytes, and the component reads them as `startIndexPool` does (`vocabulary.Discover*Predicates`).
- **The 902-byte key.** The named witness (`witness at every bound`) runs first, through the same assertions: a
  256-byte entity, a 194-byte predicate to a 256-byte target, a 194-byte alias predicate and a 194-byte label
  predicate. It asserts the longest incoming key the plan writes is 902 bytes. The generated run reaches the same key
  by construction (both IDs and the predicate at their flags); the count is logged after the run, never asserted
  (`TestNoReachCheckAfterGeneratedRun`).
- **Choices.** The component is built through `CreateGraphIndex` (`createFromJSON`) and never started; the two
  predicate maps are assigned in the test the way `startIndexPool` assigns them. Up to eight statements per entity;
  timestamps up to `1<<37` seconds, since `time.Time` refuses to marshal a year past 9999. The registry is restored by
  `vocabulary.SnapshotRegistry`.
