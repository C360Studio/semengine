# Task 2.1 notes

## Generated checks

Named examples suffice, decided before the tests were written (`docs/testing.md`, "Decide whether generated checks are
needed"). `LevelPrefix` takes one integer with one range: the examples are both bounds inside (0, 2), the middle (1)
and the first value past each bound (-1, 3), and `FuzzGroupKey` already drives it with any integer through
`GroupKey`. `ListCounted` adds no history of its own: it reads, under the lock `List` takes, the two maps every apply
already keeps (`entries` and `poisoned`); the order-dependent history of those maps is
`TestViewHistoryMatchesModel`'s. `TestListCountedCountsPoison` walks the four transitions the spec names (poison,
heal by a valid write, delete, the three readiness errors) as named steps, with a poisoned key outside the prefix.

## Choices the design leaves open

- **`levelPrefix`, unchecked, beside `LevelPrefix` (the reviewer's NIT, applied).** `communityKey` and `exists` use a
  level that is always 0 to 2 (a record's checked level, or an index into the `[levels]` array), so they call the
  unexported `levelPrefix`, which `LevelPrefix` calls after its one range check; no dead error branch. `GroupKey` and
  `DecodeCommunity` call `LevelPrefix` and return or wrap its refusal: the range check is spelled once, at
  `graph/clustering/storage.go` `LevelPrefix`.
- **Refusal wording.** `GroupKey`'s refusal of a level now names `clustering.LevelPrefix` as its source, and
  `DecodeCommunity`'s reads `record at <key>: clustering.LevelPrefix: check level failed: level 5 is not 0, 1 or 2`;
  both stay invalid errors naming the key where they did, which `TestGroupKey`, `TestDecodeCommunity` and both fuzz
  targets check unchanged.
- **One listing loop.** `List` and `ListCounted` share the unexported `listLocked`, so the listing beside the count is
  `List`'s by construction. `listLocked` drops `List`'s `prefix != ""` test: `strings.HasPrefix(k, "")` is true.
- **No fuzz target for `LevelPrefix`.** It parses no bytes or string; its integer input is covered by the bounds
  above and by `FuzzGroupKey`.
- **Docs.** One row in `pkg/graphview/README.md`'s table and one sentence in `graph/clustering/README.md` name the new
  exports; the ledger rows for both packages name them, `ListCounted` with its one reader (the text tier, task 3.2).
