## Choices the design leaves open

- **The marks' source.** The test's literals come from what each handler replies with:
  `processor/graph-ingest/query.go:100,148,431` and `processor/graph-index/query.go:149,188,270,305,428,457,507,650`.
- **Generated checks.** Examples suffice: the table is a fixed list, with no interacting inputs or stated law.
- **`MinRevision` is the field inside `MinRevisionField`, tagged `omitempty`.** D3 says zero means none, and optional
  request keys here already use `omitempty` (`graph/query_predicate_types.go:23`). `TestQueryWireNames` holds both.
- **`TestQueryWireNames` is added beside the task's named check.** Without it nothing in this task holds the three new
  spellings. `TestRelationshipsRowKeys` and `TestMinRevisionBoundary` hold them on the wire in later tasks.
- **Homes.** `RelationshipEdge` is in `graph/query_index_types.go`, beside the entries it joins; `MinRevisionField` is
  in `graph/query_response.go`, beside `IndexedRevision`, which it compares with; the code is a plain string with the
  other codes in `graph/mutation_responses.go`, not in `errs`, since graph-index and graph-query both import `graph`.
- **`QueryVerbs`' doc comment** no longer lists reply types, since the table now declares them.
