## Choices the design leaves open

- **Every failure that is not a refusal gets one answer.** D2 names no responders and a plain timeout. `forward` asks
  one question instead: did a classified refusal arrive? If not, no answer arrived, and it refuses transient
  `internal`, naming the subject. That also covers `natsclient.ErrNotConnected` and a context the client ended. It
  needs no statement about which raw errors `errs.Classify` calls transient, and no-responders' class stays unpromised
  (ADR-112). A timeout therefore carries code `internal`; the spec asks only that it stay transient.
- **The handler's row comes from the table.** `queryHandlers` reads each forward's downstream subject from the row of
  that name and responder. A row that goes missing leaves its verb with no handler, so `Start` names it.
- **What a test cannot reach.** With the seam gone, `Start` failing on a declared verb with no handler is reached only
  through `handlerFor` and `subscribeQueries`' one call to it: no test makes the real table lack a handler.
  `TestEveryDeclaredVerbHasAHandler` holds the other half, that today's table has none missing. This is the reviewer's
  stated fix, not a gap added here.
- **Serving.** One `SubscribeForRequests` per verb, nothing added on top; no worker pool.
- **Task 3.3 changes `forwardRows`' reader.** `TestGraphQueryServesExactlyTheDeclaredVerbs` compares the table's
  graph-query rows with the four forwards, so 3.3's rows must extend that literal.

## Do requests and replies copy their payload?

`natsclient` does not copy. `RequestWithHeaders` sets `msg.Data = data` (`natsclient/request.go`), and the reply's
`Data` goes back as received; the handler's `data` is the delivered `msg.Data`. At the pinned nats.go v1.55.0 each
delivered message gets its own payload: `processMsg` copies unless the parser has already copied it
(`nats.go:3928-3932`). That is a reading of this version's source, and `TestForwardsShareNothingBetweenRequests` is
the probe: stubs and callers keep their slices uncopied through later requests on a real broker, longest first, and
all still match at the end. Across versions it is not promised. `forward`'s closure holds only the subject and the
timeout, so graph-query retains nothing after the reply.
