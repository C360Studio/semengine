# Task 3.2 notes: the order of a loss

Codex's review of `7aa3a21` (PR #476 comment 6524178123) found `OnWatcherLost` firing before the subscriptions'
`Deltas` had closed: `failClosed` closed each subscription's `done` channel and called the hook straight away, while
`Deltas` closes later on the delivery goroutine. Design D2 and the spec scenario "The update channel closes" require
the channels closed first.

## Failing first

`TestRunLostWatchFailsClosed` (`pkg/graphview/degraded_test.go`) attaches two subscriptions that never read; one has a
delivery blocked on its full channel. Inside `OnWatcherLost` it drains what is buffered and requires each `Deltas`
closed and each `Err` matching `ErrWatcherLost`. At `7aa3a21` it failed on three of three runs:
`subscription 0's Deltas still open when OnWatcherLost fired`. `task mutate:check` with the wait below removed from
a copy of `view.go`: `verdict: detection` (3 mutant runs failed with the expected text, the after-run passed).

## The fix and the ordering it relies on

- Each subscription has a `closed` channel, closed by the delivery goroutine's deferred `close(s.closed)`, which runs
  after its deferred `close(s.deltas)` (`subscription.go`, `run`; deferred calls run last-in first-out).
- `failClosed` calls `terminate` on every subscription, then waits on each `closed`, then calls `OnSubscribers(0)`
  and `OnWatcherLost` (`view.go:692-704`). It holds no lock while it waits.
- The wait ends promptly. `terminate` sets `err` and then closes `done` (`subscription.go:64-72`). Every wait in
  `run` also selects on `done`: the idle wait and the send of a batch. So once `done` has closed, `run` returns
  without waiting on a reader. A consumer that never reads cannot hold the loss report. The subscription's own
  `ctx.Done` branch calls `detach`, which takes the view lock briefly and returns.
- Every subscription in the set has a delivery goroutine: the attach starts `go s.run(ctx)` right after it releases
  the lock (`view.go`, `SnapshotAndSubscribe` and `Subscribe`).

## The stop path

No hook waits for the channels there, and none needs to. `stop` calls `terminate(ErrViewStopped)` for each
still-attached subscription (`view.go:306`). `terminate` sets `err` under the subscription's lock before it closes
`done` (`subscription.go:66-70`), and `Deltas` closes only after `done` has closed. So `Err` is `ErrViewStopped`
before `Deltas` closes, as the spec says. `Run` waits for the goroutines through `wg.Wait` before it returns.
