## How the rows run

- **One file, no build tag:** `task mutate:check -- -pkg ./pkg/graphview -test <T> -file pkg/graphview/<file> -mutant
  /tmp/gv33mut/<m>.go -expect <file_test.go:N>` (or `-expect-text <text>`). The tool's defaults: three baseline runs on
  the unchanged code, three mutant runs, one after-run on the unchanged code, `go test -json -count=1 -cpu 1 -race
  -timeout 2m0s`, `RAPID_SEED=1`. Its logs are under `$TMPDIR/semengine-mutcheck-*` (this machine only).
- **Integration rows:** `task mutate:check` has no build-tag flag (`internal/harness/mutcheck/runs.go`, `testArgs`), so
  `go test -tags integration -race -count=1 -v -overlay /tmp/gv33mut/<m>.json -run '^<T>$' ./pkg/graphview`: one clean
  run before, three mutant runs, one clean run after.
- **The two-file row:** `task mutate:check` takes one file, so `go test -count=1 -cpu 1 -race -v -overlay
  /tmp/gv33mut/<m>.json -run '^TestDetachedReasonSurvivesStop$' ./pkg/graphview`: three clean runs before, three runs of
  each overlay, one clean run after.

### The two halves of D6-6 against the whole package

Design D6 states either half alone survives the named test, and it does. Each half was also run against the whole unit
package once (`go test -count=1 -cpu 1 -race -timeout 60s -overlay <half>.json ./pkg/graphview`), to see whether any
other test catches it:

- **D6-6a alone** fails `TestOnSubscribersFiresOnAttachAndDetach` at `hooks_test.go:34` (`expected: []int{2}, actual:
  []int(nil)`: a detach that leaves the set reports no new count), and the package run then hit the 60 s timeout. So
  the package catches this half, through another test.
- **D6-6b alone** passes the whole unit package: a **survivor** at package level. It is observable. A probe test,
  added only through an overlay (`/tmp/gv33mut/probe_reason_test.go`, never in the tree), cancels a subscription's
  context, waits for `Deltas` to close, calls `Unsubscribe`, then requires `Err` to be `context.Canceled`. The probe
  passes on the unchanged code and fails on D6-6b at its `Err` assertion: the later `Unsubscribe` overwrites the
  reason with nil. `Err`'s doc comment promises "the context error for a context detach". A real trigger is a consumer
  that does `defer sub.Unsubscribe()` and reads `Err` after its context ended. That was the survivor, kept here as
  history.

### Closing the survivor

The coordinator ruled it a test gap to close in this task (2026-10-30). `TestDetachReasonIsTheFirst`, next to
`TestDetachedReasonSurvivesStop` in `run_test.go`, is the probe promoted, with the mirror case:

- *context end, then Unsubscribe*: `Err` is still `context.Canceled` (`run_test.go:243`);
- *Unsubscribe, then context end*: `Err` stays nil (`run_test.go:258`), read after `synctest.Wait` so anything the
  context's end runs in the bubble has run.

The mirror case does not fail on D6-6b: once `Unsubscribe` has closed `done` the delivery goroutine has returned, so
nothing calls `terminate` again when the context ends. It guards the other order of the same promise.

D6-6b against the new test is `detection` (the row in the table above). Against the whole unit package with
`d6b_only.json` it now fails `TestDetachReasonIsTheFirst/context_end,_then_Unsubscribe`, so no half of D6-6 survives the
package. Production files unchanged: `view.go` and `subscription.go` hash as above after the runs.

Gates after the test was added (not committed): `go test -race -count=1 ./pkg/graphview` ok, `go test -count=5 -cpu 1
-shuffle=on ./pkg/graphview` ok, `task lint` rc 0, `task vet` rc 0, `task docs:check` rc 0.
