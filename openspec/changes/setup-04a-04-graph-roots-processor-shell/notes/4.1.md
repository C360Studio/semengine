## Lifecycle methods as they are now

- `Initialize`: `c.shell.Initialize()`.
- `Start`: nil `natsClient` refused (`errs.ErrNoConnection`, fatal), then `c.shell.Start(ctx, c.start, c.release)`. The
  order of the two refusals flipped (nil client is checked before initialized); both still refuse before the guard is
  consulted, as the doc comment says. No test depends on the order.
- `Stop`: `c.shell.Stop(ctx)`.
- `Health`: poison message when `entityPoisonSize > 0`, backlog fault when one is held, each empty otherwise, passed to
  `c.shell.Health`. Both are now computed whether running or not; the shell ignores them when not running. `Health` no
  longer takes `c.mu`.
- `DataFlow`: `c.shell.DataFlow()`.

## The three declared behaviour changes, as implemented

1. `Initialize` no longer re-validates: it is the one-line delegation; `Config.Validate` runs only in the factory
   (`resolveConfig`).
2. `LastActivity` before the first input is the zero time: the construction-time store is gone and the shell returns
   its zero `lastActivity` until `CountInput`.
3. The "component initialized" log line is gone with `Initialize`'s body.

Plus `DataFlow` now carries `Messages` and `Bytes` (the shell's totals).

`TestComponent_Initialize_InvalidConfig`: D6 says it "becomes a test that the factory refuses that configuration".
The old test reached `Initialize`'s check by setting `Ports = nil` after construction, and the factory never refuses a
missing ports block (ruling K: `ApplyDefaults` fills it in). So the test uses the nearest configuration `Validate`
refuses that the factory can see: `DefaultConfig()` with its input ports removed. It asserts the factory returns
`errs.ErrInvalidConfig` and no component, then that `Initialize` on a validly constructed component returns nil. This
reading of "that configuration" is mine; the reviewer should confirm it.

Not changed: the in-test comment `discoverable_reads_test.go:41` ("release has cleared running") and `readBound`'s
comment ("wait on nothing but c.mu") are outside D6's line list and now describe the shell's state and lock loosely;
they make no false claim a reviewer could hold an assertion to, so they stay.
