`task mutate:check -- -pkg ./graph/query -test <subtest> -file graph/query/classifier_embedding.go -mutant <copy>`:

No survivor, no inconclusive run. The chain holds no copy of its own: the tier-1 result's `Options` is the map
`FindBestMatch` already cloned, so a second clone in the chain could be removed with no visible effect, a
survivor by construction. The chain row therefore removes the one copy the chain's result relies on and shows the
`chain` subtest, which edits only the chain's results, detects it.

## Choices the design leaves open

- `FindBestMatch` returns `copyExample(c.examples[best])`: the struct, its `Options` map (`maps.Clone`) and its
  `Vector` (`slices.Clone`). Nested values stay shared (D4).
- With `UpgradeVectors` gone the examples are never written after construction, so the classifier's `sync.RWMutex`
  is removed; the BM25 embedder locks its own statistics. `go test -race` covers the pin's concurrent chain test.
- `NewEmbeddingClassifier` checks the context before collecting examples, so an ended context is refused even with
  no examples (spec: "when that context is nil or has ended").
- Nil contexts are refused with `errs.WrapInvalid`, the same spelling `BM25Embedder` uses.
- The chain's LLM failure stays a documented degrade with no log or metric (design D4 row, S8b): the package has no
  logger or metrics registry today.
- The query guard reuses the embedding guard's listing: `providerPaths` became `providerPathsFor(module, pkg, rule,
  deps)` so each violation names its own package and requirement; the embedding test's calls are unchanged.
- The examples tests drop `TestDomainExamples_DuplicateDomains` (see `2.1.md`).
