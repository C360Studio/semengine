## Choices the design leaves open

- **Readers at 2.1.** D4 asks for a test per kept key that fails when it is ignored. The live readers (the
  follower's startup wait, the coalescer, text extraction, the Worker) enter with 2.2 and 2.3, so at 2.1 each test
  proves the value the factory resolves through the production JSON path, as graph-index's config tests do. The
  2.2/2.3 tests that drive those readers are where the live reading is proved.
- **Defaults resolved at construction.** `max_text_len` 0 becomes 4,000 and an empty `text_suffixes` the pin's nine
  in `ApplyDefaults`, instead of the pin's read-time fallbacks (`maxSourceTextLen`, `extractTextForEmbedding`). At
  tier 0 the embedder is always BM25, so the pin's per-embedder switch has one arm; resolving once means the Worker
  (whose own 0 default is 8,000, the pin's neural cap) and the dedup key always see the same cap.
- **Inputs.** The pin only required one input. Following graph-index (#424), an input other than a full
  ENTITY_STATES watch or a store read is refused naming the port, and one such watch is required: D1's follower
  reads only that watch, and D5 reads offloaded bodies through the store registry a store-read input admits.
- **Ports present are used as written** (ruling K, #91 comment 6062681355), as graph-index; the pin filled an empty
  input list with the entity watch.
- **Embedder type.** One refusal for every value but `bm25`, naming the value and tier 0; empty means `bm25`, as
  at the pin. The registration drops `Dependencies: DepModelRegistry`, so boot builds no model registry for it.
- **`cache_ttl`.** The pin's targeted probe is gone; strict decoding refuses the key by name.
- **Stub component.** The factory returns a `*Component` that holds config, ports, client, logger and store
  registry, and implements `component.Discoverable` through `component.Lifecycle` (Health, DataFlow). It has no
  Initialize, Start or Stop yet; it is marked `// shortcut:` in `component.go`. No metrics are registered yet.
