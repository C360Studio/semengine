## Choices the design leaves open

- **The Worker is not run yet (2.3).** `onTerminal` has the `embedding.TerminalCallback` signature, so 2.3 hands
  it to `WithOnTerminal`; until then the tests call it in the Worker's place. It is marked `// shortcut:`.
- **Hop 1 reads the current value.** `follower.Entry` carries no value, so every update, coalesced or not, goes
  through `reconcileEntity`: read the entity now, write its pending record at the revision read. Completing that
  revision drains every lower delivered one (revlag). graph-index reads current state the same way.
- **One mutex for hop 1.** Deliveries run on the follower's goroutine and coalesced batches on the coalescer's;
  `hop1Mu` serialises them per the pin (#629), so a tombstone and a batch never interleave.
- **Coalescer.** `internal/cache.CoalescingSet`, the pin's choice (pin `component.go:749`), under the run
  context; `cleanup` joins the follower's `Run` first, then `Shutdown`s the coalescer, which waits for a batch
  in progress.
- **`TestGraphIndexHeldRevisionNotDegraded` is a follower test.** The rule lives in the follower and graph-index
  has no option of its own, so the test runs the held-revision history under graph-index's status key. Driving
  graph-index's own lanes to hold one revision past 30 s would need a test-only hook in graph-index (#186), so it
  is not done.
- **`content_unresolved_total`.** The excluded offloaded body is a declared skip, so the one counter it needs is
  registered now (`metrics.go`), on the injected registry. The other pin collectors wait for the tasks that use
  them.

## Stubbed for later tasks

- `failedTotal` returns 0 (2.4). A failed pending write logs and leaves its revision pending; a failed entity read

- No Worker, so no lost-watch state in `Health` (2.3); `Health` names only the follower's stuck states.
