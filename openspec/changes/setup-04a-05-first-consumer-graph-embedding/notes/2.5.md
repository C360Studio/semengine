## What changed

- **ErrorCount counts failures.** At the base nothing in graph-embedding called `Lifecycle.CountError`, so
  `ErrorCount` was always 0, as at the pin, whose `c.errors` has no writer (pin `component.go:309`, read at `:549`
  and `:582` only). ADR-109 Decision 2 asks each port for "a nonzero `ErrorCount` still reads true", which needs a
  count. Each failure the failed map records is now counted once: hop 1's four marks go through a new unexported
  `markFailed` (mark, then count), and `onTerminal` counts a Worker failure. Counting is per failure event, as
  graph-ingest does (`consume.go:248`), not once per entity entering the set, as graph-index does (`index.go:244`):
  a repair pass that fails the read again counts again. A latched reset is not counted: it is not in the failed
  map, and Health names it as a stuck state. `Health` is unchanged: `Lifecycle.Health` already ignores the count.
- **No status verb.** Nothing changed in production: graph-embedding subscribes to nothing at the base, and
  `graph.QueryVerbs` declares only `search` and `similar` for it.
- **Import guard.** `processor/graph-embedding` reaches `model` transitively at the base: `component` imports it for
  `component.Dependencies.ModelRegistry` (`component/dependencies.go:7`, `:48`), so every component does. The first
  form of the guard, `providerViolations` over `go list -deps` as the graph/embedding and graph/query guards are
  written, failed on the base tree with `processor/graph-embedding reaches github.com/c360studio/semengine/model`.
  The inventory's "`model` only via the HTTP path" (`inventory.md:51`) is a direct-import statement. The guard now
  holds `model` to graph-embedding's own imports (`go list -f '{{join .Imports " "}}'`) and the OpenAI SDK to
  everything it reaches (`go list -deps`), with its own sensitivity test over planted listings.

## Edge values and what is not covered

- **ErrorCount is asserted as at least one** while the read fails: the repair lane's own pass, every 30 s, may fail
  the read again in between and count again. After the repair it must not have lowered.
- **Not each hop-1 site.** Only the read failure is asserted; the delete and pending-write marks go through the same
  `markFailed`, which is the check. A latched reset is not counted, by choice (above).
- **No responders as the oracle.** On nats-server's default configuration a request with no subscriber gets no
  responders at once (`natsclient.IsNoResponders`); the request's one-hour bound is out of reach.
- **Generated checks.** Not used: each test has one input that matters (a failure and its repair, a subject, an
  import list), with no interacting cases.
