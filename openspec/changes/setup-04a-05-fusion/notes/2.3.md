# Task 2.3 notes: construction, metrics, logging, hydration

Choices the design leaves open:

- **Options set fields; registration runs once.** `Option` is `func(*Engine)`; `NewEngine` applies the options, then
  registers both counters through `metric.RegisterOrGet` under the service name `fusion` (keys
  `fusion.body_hydration_failures_total`, `fusion.skipped_reads_total`) and keeps the collectors it returns. Families:
  `semengine_fusion_body_hydration_failures_total{reason}`, `semengine_fusion_skipped_reads_total{facet}` (namespace
  `semengine`, as `graph/readiness` uses). Without `WithMetrics` both are nil and nothing is registered anywhere.
- **Refusals are plain errors.** Nil client, nil logger, nil context (`Fuse`, `ResolveBody`) return `errors.New`
  messages, as `graph/readiness` does; a registration refusal is wrapped (`fusion: register counters: %w`) so its fatal
  class survives. A typed-nil client is not caught (only an untyped nil).
- **Per-call skip log.** Each `Fuse` call owns a `skipLog` (count and first error per facet), so concurrent calls never
  share it; a deferred `report` writes at most one Warn per facet in the order relations, paths, impact, graph, and adds
  the count to the counter. It runs on every return, including a deferral or an ended context, because the skips it
  holds happened. A skipped read is a walk read that returned an error (D1's "skipped and declared"); a read that found
  nothing is not one, though it still sets the facet's label.
- **Body failures log one Warn each** (handle, reason, error). They are bounded by the node budget (20 by default), and
  a body failure is per node, unlike a skipped read; D5 says only "a body failure also logs".
- **Evidence caps sort too** (the 2.2 carry). `appendFactEvidence` and `graphEdgeAcc.add` now collect every
  contribution; `capEvidence` sorts by `evidenceKey` (source, timestamp, confidence, context), drops repeats and keeps
  the first 8, for facts in `graphNodeFor` and for edges in `result`. No concrete reason against sorting was found: the
  pin's doc called the survivors "a prefix of the discovered contributions", which is discovery order, not a meaning a
  reader relies on. Evidence now lists in that key order; the `GraphFact.Truncated` and `GraphEdge` docs say so.
- **Test helpers.** `mustEngine` (engine_lens_test.go) builds every test engine with a discarding logger. `fakeStore`
  gained `Open` (so it is a `storage.StreamableStore` the store registry accepts), a `getHook` and a `gets` count.
  `TestEngine_NilBodyResolver` has its counter assertions back. The pin's `metrics_internal_test.go` is not carried: it
  tested the default-registerer fallback and hand-rolled register-or-get that D5 removed; the spec's three tests replace
  it.
