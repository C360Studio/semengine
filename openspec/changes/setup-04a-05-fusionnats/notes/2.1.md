# Task 2.1 notes: client and wire

Choices the design leaves open, and what the task carried or dropped.

## Code

- **Decoding by row.** One generic helper, `decodeReply[T](verb, raw)` in `pkg/fusion/fusionnats/client.go`, reads
  `verb.Enveloped`: true decodes `graph.QueryResponse[T]` and refuses an empty `producer`; false decodes `T`. The
  entity reply goes through it too, as a local `entityReply` type that leaves `entity` raw for
  `graph.UnmarshalEntityState` (the shadowing shape of `graph.ExactEntityReader`, `graph/exact_entity.go`).
- **Verb lookup.** `lookupVerbs` takes the six rows whose `Responder` is `graph-query`; a `Name` is unique only within
  its responder (`graph/query_verbs.go`), so the responder filter is what keeps graph-ingest's `entity` row out.
  Its error names the verb with `%q`.
- **Requests.** `graph.EntityRequest`, `EntityBatchRequest`, `PrefixQueryRequest`, `SemanticRequest`; byName and
  relationships keep local structs (`byNameRequest`, `relationshipsRequest`). The byName `limit` keeps the pin's
  always-sent key (no `omitempty`).
- **Entity refusals.** "No entity" and "zero KV revision" stay plain errors, as at the pin. The wrong entity and a
  refused stored value now come from `graph.UnmarshalEntityState` (fatal `graph_state_reset_required`,
  `noncanonical_entity_id`, `EntityID` the requested ID), replacing the pin's separate ID-mismatch check.
- **Nil context.** Not checked in the client: every call goes through `RequestClassified`, and natsclient's
  `RequestWithHeaders` refuses a nil context (`natsclient/request.go:177-178`). Zero IDs short-circuit before it, as
  at the pin.
- **Zero timeout.** Passed through as zero (the `graph.NewExactEntityReader` rule); the pin's `defaultTimeout`
  constant is gone with `TestNew_DefaultsTimeout`.

## Tests

- Carried from the pin, on the tree's wire: the resolve, entity, batch, neighbors, names tests
  (`client_test.go`), the poison-before-projection table, the exact-entity tests (`exact_entity_test.go`,
  from `slice_e_contract_test.go:16-53`) and `TestReconcileHydration` (`reconcile_test.go`). Changes: replies on
  enveloped rows are built with `graph.NewQueryResponse`; entity triples carry `Source` and `Timestamp`, which the
  stored-value rule requires; relationship replies use `predicate` and three-part predicates; the unscoped
  byte-parity test compares with a literal through `JSONEq` (the pin compared with a marshalled map, whose keys
  sort, which a struct request does not match byte for byte); the exact-entity ID-mismatch and poisoned cases assert
  the `StateContractError` reason, not text.
- Not carried: `TestStatus_*` and the status fakes (D4), `slice_e_contract_test.go:55-105` (replaced by
  `TestEnvelopedRowNeedsProducer`), `TestNew_DefaultsTimeout` (replaced by `TestNewZeroTimeoutUsesDefault`), and
  `TestUnhydratedReasonsMirrorGraph`: the tree has no `graph.MissingUnknown`, and `unhydratedReason` maps by switch,
  so value parity is no contract; the mapping is covered by `TestReconcileHydration`'s reason subtests and by
  `TestReconcileTotal`.
- Added beyond the task's list: `TestEntities_BatchIgnoresUnknownKeys` (the bare-row "unknown keys ignored" clause of
  D2).
- `TestSubjectsComeFromVerbTable`'s oracle is the six `graph.query.*` subjects spelled in the test file (test files
  are outside the reserved-subject guard), not the table the client reads.
- Generated check: `TestReconcileTotal` (`reconcile_prop_test.go`) uses Rapid. IDs come from a pool of four, so
  duplicates and unrequested entities occur; each pool ID is in the entities, the missing list (reason in or out of
  the set), both or neither; entity order is permuted. The reference model `reconcileModel` is written from the
  requirement, with reason strings spelled literally. Named witnesses (duplicate, both lists, neither list, reversed
  order) run first through the same `checkReconcile`. Run:
  `go test ./pkg/fusion/fusionnats -run '^TestReconcileTotal$' -count=1 -race -v -rapid.checks=100 -rapid.seed=1`:
  `[rapid] OK, passed 100 tests`.

## Review stop 1 (task 2.2)

- `missing` listing one ID twice with different reasons: `reconcileHydration` keeps the last entry, and the model
  kept the last reason in the set, so the two differed (for example `not_found` then `later`) on a case the
  generator never drew. The model now reads the last entry, the generator draws an ID listed missing twice, and the
  witness `missing twice, last wins` runs it every time. A first-wins mutant of `reconcileHydration` is detected by
  that witness (`task mutate:check`, `-expect-text "unhydrated = "`, three mutant runs). Run:
  `go test ./pkg/fusion/fusionnats -run '^TestReconcileTotal$' -count=1 -race -v -rapid.checks=100 -rapid.seed=1`:
  `[rapid] OK, passed 100 tests`.
