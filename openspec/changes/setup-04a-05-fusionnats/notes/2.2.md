## Code

- **Trigger.** Only the error the batch's `RequestClassified` returns, matched by `graph.IsStateContractError`
  (`client.go:266`). The decode and `ValidateDecodedEntityStates` refusals after it are returned as before, so the
  client's own refusal is told apart by where it arises, as D3 says.
- **Per-ID read.** `entitiesAlone` reads sequentially, in request order, one `entity` request per distinct non-empty
  ID; D3 names no concurrency, and at most 40 seeds reach it. No goroutine, no stored context.
- **Shared decode.** `Entity`'s reply checks moved into `decodeEntity` (`client.go:223`), which `Entity` and
  `entitiesAlone` both call, so the per-ID path decodes exactly as `Entity` does and its refusals are returned. In the
  per-ID switch, the `IsStateContractError` check sees only the requester's error, never `decodeEntity`'s.
- **Ended context.** `entitiesAlone` checks `ctx.Err()` before each request, so it stops once the caller gives up even
  if a requester still answers. natsclient's own refusal of an ended context reaches the `default` arm and is returned
  either way.
- **Empty ID.** Listed unhydrated `error` with no request; deduplicated with the rest, so it is listed once.
- **Result shape.** `Entities` is a non-nil empty slice, `Unhydrated` nil when nothing is listed, as
  `reconcileHydration` builds them. A returned error carries an empty `Hydration`.
- **Declared degrade.** The client holds no logger or metrics registry. The degrade is declared in the answer:
  each poisoned seed is an `Unhydrated` entry with reason `error`, which `Fuse` carries to `Response.Unhydrated`. The
  design names no log line or metric; that is left to review.
- **`UnhydratedError`'s doc** (`pkg/fusion/retrieval.go:109`): "Reserved while the handler's first-error contract
  stands" is gone; it now names a refused stored entity and an empty ID. This is the one line outside
  `pkg/fusion/fusionnats` the task names; `retrieval.go:37` stays for task 3.3.

## Tests

All in `pkg/fusion/fusionnats/poison_test.go`, on a fake wire (`poisonWire`) that routes by subject, records each
`entity` request's ID in send order, refuses an empty ID `invalid_request` as graph-ingest does, and builds the reset
refusal as `ClassifyReply` does (class fatal, code `graph_state_reset_required`, text naming no ID). Expected values are
literal IDs, reasons and `"all_seeds_unhydrated"`, never the client's own output or constants it reads.

- `TestAllSeedsPoisonedDefer` runs `fusion.Engine.Fuse` over the client with a test lens that resolves by prefix and
  walks no edges.
- Added beyond the task's list: `TestPoisonFallbackNotFound` (the requirement's not-found clause).
- Generated checks: not used. Each per-ID outcome (hydrated, reset, not found, empty, other error, ended context) is
  one branch on one ID's own reply; they do not interact except through deduplication and order, which named
  examples hold (`TestPoisonedDuplicateReadOnce`, `TestPoisonedSeedUnhydrated`). The accounting law over interacting
  replies is the batch path's `TestReconcileTotal` (task 2.1).

Failing-first: the new tests run against the pre-task `client.go` (an overlay of `git show HEAD:...` at `ac0ebb6f`):
`TestPoisonedSeedUnhydrated`, `TestPoisonFallbackNotFound`, `TestAllSeedsPoisonedDefer`,
`TestPoisonedDuplicateReadOnce`, `TestPoisonFallbackReturnsOtherError`, `TestPoisonFallbackEndedContext`,
`TestPoisonFallbackEmptyID` and `TestOwnValidationNotRetried` (its per-ID case) failed. Its batch case passed there,
as expected: the old code already returned the batch refusal.
