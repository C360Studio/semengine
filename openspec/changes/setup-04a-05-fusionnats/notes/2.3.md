## Ordering

- Writes go through `graphmutation.Client.Create`, which returns after the commit; graph-ingest's reads (`entity`,
  `batch`, `prefix`) read the bucket, so they are ordered by that return.
- graph-index: `fusionnats` sends no `min_revision`, so the test first asks graph-index's `alias` verb with
  `min_revision` set to the last write's revision until it answers (`probe.Await`); every index read after it reflects
  every earlier write. Same wait as the composed test's `awaitIndexed`.
- graph-embedding claims no revision; the wait is a direct `search` for "widget" until it answers both widget
  entities (`index_not_ready` asked again, any other refusal fails). The scoped NL read after it is then expected to
  answer `alpha` only.
- Poison: `kv.Put` returns after the value is stored, after every component's `Start` returned. A direct
  `graph.query.batch` request first checks the precondition (refused `graph_state_reset_required`), so the test is
  known to take the per-ID path.
