## Second composition

- `internal/smoke` had one configuration, one registration list and one list of readiness keys, all with
  graph-embedding. They are now one `composition` value each: `fullStack` (the four-component stack, unchanged) and
  `graphOnlyStack` (`graphOnlyConfig`, no graph-embedding entry). The test passes the name to the child in
  `SMOKE_COMPOSITION`; the child registers exactly the composition's factories (`componentFactories`), and
  `awaitIndexed` waits on the composition's `indexKeys` after graph-ingest's (graph-index only, for graph-only).
- `requireComponentsListed` and `requireComponentsHealthy` now take the stack and read its health themselves, so
  the expected list is the composition's. Every existing call was `requireX(t, readHealth(t, s))`; 16 call sites
  became `requireX(t, s)`. The four-component tests boot, wait and check as before; the only change in their child
  is the order the four factories register in (sorted by name), which the registry does not read.
- graph-index's name lookup indexes only label predicates registered before it starts (notes/2.3.md). The graph-only
  composition registers `fleet.identity.name` as a label in the child (`composition.labels`) before `StartAll`. The
  full stack registers none, as before, so its graph-index indexes what it did.

## What the test checks

All expectations are literals written from `fixedEntities`, compared as the JSON a consumer reads.

- After the acknowledgement and `awaitIndexed`: the three components listed and healthy; `GRAPH_STATUS` keys are
  exactly `graph-index`, `graph-ingest` (the reset emptied the server; `awaitIndexed` read both entries this child
  wrote).
- Symbol `Kestrel`: one node with `next` Osprey, `previous` Falcon, and one path to North Field.
- Prefix `c360.<platform>.fleet.ops.drone`: the eight drones in ID order with their relations, and eight paths;
  drone1's is four hops, the walk's depth cap, so it is marked truncated (`maxPathDepth`).
- Symbol `Condor`: a miss with no near-match.
- NL `falcon`: `Fuse` returns a `*errs.ClassifiedError`, class transient, code `internal`, its message naming
  `graph.embedding.query.search` (read from the verb table and checked against the literal), and a zero `Response`.
  Health is read before this question, since graph-query counts the failed request as an error.

## Ordering

`awaitAcknowledged` (graph-ingest acknowledged every input), then `awaitIndexed` (the `ENTITY_STATES` revision,
graph-ingest's envelope from this child, graph-index's envelope at or above that revision). Every fusion read is
after both; the comment above the symbol read names them. graph-embedding claims nothing here, so it has no wait.
