# Task 2.1: tokenizer

Code: `graph/lexical/doc.go`, `graph/lexical/tokens.go`, `graph/lexical/tokens_test.go`. The only exported symbol is
`Tokens`; the stopword list, `fold` and the identifier split are unexported. Expected values in the tests are worked
by hand from the spec's rules (`specs/lexical-search/spec.md`, the three tokenizer requirements), never produced by
the code.

## Generated checks: decision

The tokenizer has two stated laws: tokenizing twice equals tokenizing once, and folding twice equals folding once.
Both get generated checks: `FuzzTokens` (any string) and `TestPropFoldIsIdempotent` (Rapid). The rules' boundaries
(each rule's length bound, each excluded ending, the 32-byte cap) are named examples in `TestTokens`,
`TestPluralRules` and the witness list of `TestPropFoldIsIdempotent`, so they run every time rather than when a
random draw lands on them.

## What makes each assertion run

- `TestPropFoldIsIdempotent`: 32 named witnesses (every rule's ending at and past its length bound, and the endings a
  fold leaves for a later rule) go through the same `check` before `rapid.Check`. The generator draws a stem of 0 to 6
  runes over `acehiosuxy` and one of 21 endings that bring each rule and each exclusion into play.
- `FuzzTokens`: 14 seeds, among them the spec witnesses, non-ASCII capitals (`İstanbul`, `ǅemal`, `Xϒ`, `ΣΑΣ`), a
  ligature, a combining mark, a 33-byte run, invalid UTF-8 and the empty string. `Xϒ` is the shape that broke the law
  when a capital meant `unicode.IsUpper` (U+03D2 has no lower-case form).

## Runs (go1.26.11 darwin/arm64, commit 3c20d3e2 plus this task's files)

- `go test ./graph/lexical -run '^TestPropFoldIsIdempotent$' -count=1 -race -v -rapid.checks=10000 -rapid.seed=20261112`:
  `[rapid] OK, passed 10000 tests`.
- `go test ./graph/lexical -count=1 -race -v -rapid.seed=20261112`: every test passes; `[rapid] OK, passed 100 tests`;
  14 `FuzzTokens` seeds replayed.
- Exploration, separate from the seed replay: `go test ./graph/lexical -run '^$' -fuzz '^FuzzTokens$' -fuzztime 60s`:
  7,613,217 executions, 170 new interesting inputs, PASS. No failure, so no input to keep.

## Choices the design leaves open

1. `TestSingularFindsPlural` and `TestJoinedIdentifierIsNotHeld` are written against `Tokens`: an entity's words come
   from `Tokens` of its text, and a query "returns the entity" when one of its words is held. The spec scenarios say
   the query returns the entity, which needs the index of task 2.2. When the index exists these two tests should go
   through `Put` and `Search` instead; that is left to task 2.2.
2. The second split after lower-casing (spec: "split it again at any non-letter, non-digit") never fires on Go's
   tables. The probe source's comment says U+0130 lower-cases to `i` plus U+0307; in Go it does not:
   `strings.ToLower` maps rune by rune with simple case mapping, so `İstanbul` gives `istanbul`. A scan of every
   letter and digit rune found none whose lower-case form holds anything else (0 at go1.26.4 and go1.26.11). The
   split is kept, as the spec states it, as a guard for a later Unicode table; the code comment says so. No rule
   changes.
3. Lower-casing is Go's simple per-rune mapping: no final sigma (`ΣΑΣ` gives `σασ`) and `ß` stays `ß`. `TestTokens`
   pins the first; the design's non-goals already exclude Unicode normalisation.
