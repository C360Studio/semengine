## Choices the design leaves open

1. **No store-read input port.** The body path reads `deps.StoreRegistry` directly (`component.go:111`); a nil
   registry means every body has no store. graph-embedding admits its registry only through a declared `store-read`
   input (ADR-063's declaration, `processor/graph-embedding/component.go:166-176`), and 2.3's note 8 left the port to
   this task. The spec reads every offloaded body unconditionally and its configuration requirement names one input,
   so a port would either be required (a config change the spec does not state) or optional (an absent port silently
   turning every body into `no store`). The cost of no port: the flowgraph does not show graph-lexical reading
   stores. This is for the architect to confirm or overturn.
2. **A pass is a batch.** Each wake or repair tick takes the whole queue as it stands and reads it; reads queued
   during the batch are the next batch, straight after. A repair tick only re-queues `unread` and `no store` bodies
   and clears the skipped stores; it shares the goroutine with delivery reads, so passes never overlap. The ticker
   runs start to start: a pass longer than 30 s is followed at once by the next.
3. **A read whose key has moved on is not made** (`wanted`, `apply.go:158`); its revision completes as a dropped
   read's does. It saves the I/O for every superseded revision of a hot key.
4. **`no store` does not skip a store.** It is a registry lookup, not a read on a store; skipping its instance would
   report later bodies on it as `unread`, the wrong state. `missing` does not skip either, as the design says.
5. **A read cut short by `Stop`** is discarded: no outcome applied, no store skipped, no warning (`bodies.go:92`).
   Its revision stays pending; nothing reads the floor after `Stop`.
6. **Unread keeps the waiting state** for the repair pass (2.3's note 5); `missing` drops it.
7. **Logging.** Each skip of a store logs one warning naming the instance, entity and error: at most one per store
   per pass. The first cut, first missing body and first unregistered store since start are logged once each.
8. **The cut gauge counts held entities whose body text is cut**, the body being the inline non-name text plus the
   offloaded body (D3's `Document.Body`), so an entity whose inline text alone passes the cap is counted too.
9. **Gauge names**: `semengine_graph_lexical_bodies_not_indexed{state}` with `queued`, `unread`, `missing`,
   `no_store`, and `semengine_graph_lexical_bodies_cut`. The verb's `BodiesNotIndexed` (task 2.5) is their sum; no
   reader for it is added here.
10. **Integration tests use the objectstore package's `Store`**, opened as the objectstore component opens it, under
    the instance `objectstore`, and registered in a `storeregistry.Registry` by hand, not the component through a
    component manager. The unread case deletes the store's bucket before graph-lexical starts, then recreates it with
    the body; the registered handle reads it at the next pass. The integration tests are named
    `TestUnreadBodyCountedThenRepairedOnObjectStore` and `TestMissingAndUnresolvedBodiesOnObjectStore`, since the
    unit tests hold the plain names in the same package. The repair test waits for a real pass: about 37 s of wall
    clock (local run, 36.66 s).
11. **`Failed` goes through `Component.failed`**, since the applier is built after `follower.Open`; the follower is
    published to `Health` and runs only after it is built.

  the follower's and the shell's, not tested here.

  A2-shaped fake (blocks until its context ends, then `nats: timeout`, wrapping no context error).

  which a bubble's clock does not advance past.
