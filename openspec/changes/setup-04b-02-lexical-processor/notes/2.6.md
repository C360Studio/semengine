# Task 2.6 notes: first-build cost

Implemented by claude (opus, medium). Measured at `734e61631906ce98eec5d1e9fac0860189f6d9bb`; no production code
changed.

## Verdict

The owner's budget (#10 comment 6852149945): the first build of 32,000 entities with offloaded bodies finishes
within 60 seconds on one machine. Measured on this host it finishes in about 16 seconds (15.7 s and 16.3 s in two
runs), a quarter of the budget. The budget holds, so the per-entity word record (design D6) is not needed now.

The time grows in a straight line with the number of offloaded bodies, about 0.41 to 0.47 ms each, which is the
healthy read the object-store probe measured (0.42 to 0.46 ms mean). At that rate the 60-second budget is reached at
roughly 120,000 offloaded entities on this host; 100,000 took 50.5 s and 54.2 s.

## Measured

Probe: [`probes/first-build-probe.go.txt`](probes/first-build-probe.go.txt). Output, both runs:
[`probes/first-build-probe.log`](probes/first-build-probe.log).

- Host: Apple M3 Pro, 12 cores, 36 GB, darwin/arm64; Docker Desktop 29.9.3; go1.26.11; 2026-11-13. Load average
  2.5 to 5.4 from other sessions during the runs (logged per case).
- Server: one NATS server in Docker, the repository's pinned image
  `nats:2.15.0-alpine@sha256:ac8f88a6494bffc2c2a5289a0ca61cb28a9145c11ba5677cf24265d07f46d8d4`, through the
  package's shared `natsfixture` server, a fresh container per case.
- Corpus: the scorecard's 2,000 sections, repeated under new entity IDs to the count, each body cut at the last
  space before 800 bytes: mean body 606 bytes, SemSource's code-body size (`probes/body-size-probe.log`).
- Inline: the name and the body are both in the entity state. Offloaded: the name is in the entity state, the body is
  an object in a NATS object store registered under the entity's storage instance.
- Timed: from the call to `Start` to the first reply of `graph.lexical.query.search` that is not an
  `index_not_ready` refusal, asked every 10 ms. Seeding the bucket and the store happens before `Start` and is not
  timed. Each first answer was checked: `indexed_revision` equal to the bucket's last revision and
  `bodies_not_indexed` 0, so every body was read before the verb answered.

Command, with the probe copied to `processor/graph-lexical/first_build_probe_integration_test.go`:

```bash
PROBE_ENTITIES=32000 PROBE_MODE=offloaded go test -tags integration -run '^TestFirstBuildProbe$' \
  -count=1 -timeout 60m -v ./processor/graph-lexical/
```

Time from `Start` to the first answer (`Start` itself returned in 2 to 4 ms every time):

| Entities | Inline, run 1 | Inline, run 2 | Offloaded, run 1 | Offloaded, run 2 |
| --- | --- | --- | --- | --- |
| 20,000 | 1.40 s | 1.34 s | 9.68 s | 9.90 s |
| 32,000 | 2.18 s | 2.15 s | 15.74 s | 16.35 s |
| 100,000 | 6.77 s | 6.83 s | 54.21 s | 50.51 s |

Body reads are the cost: offloaded minus inline, divided by the count, is 0.41 to 0.44 ms per body at 20,000 and
32,000 and 0.44 to 0.47 ms at 100,000. The design's arithmetic (about 15 s of reads for 32,000) was right.

## Choices the task leaves open

1. **32,000 was run directly**, not interpolated, alongside the two sizes the task names.
2. **The inline case puts the body in the entity state** under a `.description` predicate, so both cases index the
   same words and differ only in where the body is read from.
3. **The probe lives outside every gate**: a `.go.txt` file under the change's notes, copied into the package only to
   run. It has a polling ticker and its own corpus loader, which the repository's test rules would not take as a
   committed test; it asserts only that the first answer is complete.

## Not covered

- One host only. A slower disk, a remote NATS server or a loaded object store would read slower; nothing here measures
  them.
- Bodies of SemSource's mean size only; the 16,000-character cap's worst case is not timed.
- A body store that fails or blocks during the build: design D5 bounds that by one read deadline per store, which
  task 2.4's tests prove, not this probe.
