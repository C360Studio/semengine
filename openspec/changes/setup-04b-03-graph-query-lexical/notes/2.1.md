# Task 2.1 notes: what search accepts (PR A)

Base commit `6199a05f`. Owner question 2 is ruled option (b) (#624 comment 6877352345): a final `~` separates words,
so `HEAD~` searches `head`.

## Choices the design leaves open

- **The refusal's wording.** `ErrReservedSyntax`'s message is now `...: "<term>"; put it in double quotes to search it
  as text`. The term is quoted with `%q`, as before, so a caller sees exactly what was refused. graph-lexical passes it
  on inside its `invalid_request` message unchanged.
- **Which term is named.** For an excluded reserved term (`-name:retry`, `retry -retr*`) the message names the term
  after the `-` (`name:retry`, `retr*`), since that is the part a caller quotes: `-"name:retry"` is accepted.
- **Emphasis means the term's first character is `*`.** The spec says "unless the term also starts with `*`". A term
  read after a `-` that is not an exclusion (`-*bold*`, where `-*` does not start an exclusion) still starts with `-`,
  so it stays reserved. Nobody types that; it is left as the spec words it rather than widened.
- **`Query.Excluded` returns copies**, nil when the query excludes nothing, so a caller cannot change what the query
  removes. `TestParseQueryExcluded` checks both.
- **The reply's `excluded`** is built in graph-lexical's handler by joining each term's words with a space, as the
  graph-lexical delta states; `graph.LexicalSearchData.Excluded` is `omitempty`, so a query excluding nothing sends no
  key (`TestSearchDeclaresExcluded` checks the raw reply).
- **graph-query until PR B.** `graph.MaxSearchTerms` is shared, so graph-query's own white-space count (deleted in
  PR B, task 2.2) now also allows 32. Two of its tests built their over-limit query from a fixed list of 17 words;
  they now generate `MaxSearchTerms+1` words, and the expected numbers are 33 and 32. graph-query's README, MIGRATION
  and the `query-pattern` skill say 32.
- **graph-lexical's over-limit test** made its words as `word` plus one letter, which past 26 gives punctuation that
  tokenizing drops, so the words stopped being distinct. It now uses two letters.
- **The oracle stays literal.** `FuzzParseQuery` and `checkParsed` compare against the literal 32, not
  `graph.MaxSearchTerms`, so a later change to the constant shows in this package's tests rather than passing through.

## Generated checks or examples

`FuzzParseQuery` already holds the parse laws (typed errors only; a parsed query writes back to itself; quoting makes
any text one phrase of its words); its bound moved from 16 to 32 and it gained the seeds `*bold* text`,
`git reset HEAD~`, `*retr*` and `retr*x*`. The new forms are a short list of cases the spec names one by one
(emphasis, a final `~`, a final `*` after a word rune), so named examples in `TestParseQueryReservesForms` cover each;
the fuzz target's quoting law covers every refused form's advice ("quote it") for arbitrary text.
