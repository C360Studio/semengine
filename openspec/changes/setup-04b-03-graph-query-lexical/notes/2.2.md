# Task 2.2 notes: local search on the word index (PR B)

Base commit `5a3882f2`.

## Not done in this task: the substring scorer's deletion

The task says the substring scorer and `checkedSearchTerms` are deleted. Local search no longer uses either, but
today's text tier of global search still does (`searchText` calls `checkedSearchTerms` and `rankEntities`), and its
replacement is task 2.3 ("today's text tier and its group score are deleted"). Deleting them here would break the
text tier, or need a stopgap rewrite of it that 2.3 throws away. So they moved, unchanged, from `localsearch.go` to
`textsearch.go` (their only caller), with their tests in `textscore_test.go` (renamed `TestTextTier...`), and go
with the text tier in 2.3. The 2.2 checkbox is left unticked for that one clause; every Accept test is in place.

## Choices the design leaves open

- **One shared hit reader, `processor/graph-query/matches.go`.** `wordSearch` asks graph-lexical and `readMatches`
  reads the hits back with one batch request. Both are written for global search (2.3) to call too. The match type
  is the existing `graph.TextSearchMatch` (`id`, `label`, `score`, `entity`), whose doc now names both verbs; no new
  match type.
- **A hit the batch neither returns nor names missing** is graph-query's own `internal` refusal, counted, naming the
  ID: answering would drop a match without saying so. A word reply with no `results` list is refused the same way.
- **New exported surface in `graph`** (design's list): `LocalSearchRequest.Limit`; `LocalSearchData` as the design
  lists; `RecordState` with `RecordRead`, `RecordNone`, `RecordNotReady`, `RecordUnreadable` (2.3 puts it on each
  `TextSearchGroup`); `LocalSearchRecord` for the `record` object (`member_count`, `community_summary`, `keywords`).
  `record` is omitted unless `record_state` is `read`; `excluded` is omitted when empty, as in `LexicalSearchData`.
- **What graph-query checks before any request**: strict decode, a literal `entity_id`, `level` 0 to 2, a query that
  is not blank, `limit` 0 to `graph.MaxSimilarityLimit`. Anything else about the query is the word index's to refuse.
- **The scope** is the group's ID: `clustering.GroupKey` minus `clustering.LevelPrefix`.
- **Answer**: `Found {matched} matching entities in {community_id}.`, then `Showing the first {n}.` after a space when truncated,
  then the record's summary when one was read and it is not empty.
- **An unreadable record** answers, then counts one error and logs one Warn (`localPastUnreadable`, with verb, level,
  `unreadable` 1, community ID and reason), after the reply is encoded, as the text tier does.
- **The community supervisor's log line** now says local search answers without records.

## Tests outside the Accept list that changed

- `awaitCommunityView` waited on localSearch's `revision_not_reached`, which no longer exists. It now reads the
  component's own view (`c.communities.Load().Get(key)`), the read every search makes. Its callers pass the component.
- `startCommunityStack` also starts a real graph-lexical, so `TestMinRevisionRefusalThroughGraphQuery` and
  `TestGraphQueryRepliesDecodeByTheTable` get a real localSearch answer (their query is now `alpha`, a word the
  index holds; `drone` is the type, which is not text).
- The verb-table tests' localSearch row goes to the word search first, so they no longer set up a community record.
- `TestComposedVerbsCountAsForwardsDo`: the localSearch steps now cover the word reply and the batch reply paths;
  the global steps that follow count six more errors.
- `TestTruncatedSearchIsCounted`'s localSearch cases are now "more matched than returned".
- The community view tests (`...BeforeCommunityIndexExists`, `...AfterCommunityIndexAppears`, `...DuringBlockedTick`,
  `TestLocalSearchRefusesAfterWatchLoss` renamed `TestLocalSearchAfterWatchLoss`) assert `record_state` and the
  record instead of refusals. The watch-loss rounds publish 2 and then 3 members, so an old record would show.
- Smoke (task 2.6 owns the rest): `checkCommunities` awaits localSearch until it attaches the record of every
  member, compares its matches with graph-lexical's hits, and awaits global search past `revision_not_reached`,
  since local search no longer orders the community view's read.

## Generated checks or examples

`FuzzDecodeLocalSearchRequest` holds the request laws (an accepted request has a literal ID, level 0 to 2, limit 0
to 100, a query that is not blank, and a scope that is the ID's whole-part prefix with 4 - level parts named by the
key); seeds cover each class it accepts and refuses. Seed replay passes in `task test:unit`; one exploratory run,
`-fuzztime 20s`, 363,826 execs, no failure. The reply is a fixed path over named inputs (hit order, missing, the
fit, the record states), so named examples cover each case the spec names.
