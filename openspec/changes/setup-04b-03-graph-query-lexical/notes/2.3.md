# Task 2.3 notes: global search and its groups (PR B)

Base commit `9f9ac44d`.

## What changed

The text strategy of `globalSearch` and `searchGraph` (`processor/graph-query/textsearch.go`, `globalText`) is one
unscoped word search, passing `query`, `limit` and `min_revision` unchanged, then one batch read of its hits
through 2.2's `wordSearch` and `readMatches`. The groups are the matches' groups at `level`, listed by their best
match. The old text tier (`searchText`, `levelRecords`, `textGroups`'s group score, `maxTextGroups`) is deleted
with the substring scorer (`checkedSearchTerms`, `searchTerms`, `score`, `rankEntities`, `minTextScore`,
`rankedEntity`, `compareRanked`), `communityNotReady` and their tests (`textscore_test.go`, the `TestTextTier...`
tests). The router (`routeGlobalSearch`, `chooseRoute`) is untouched; it still sends the same questions to text.

## Choices the design leaves open

- **A group's record goes under `record`**, as `graph.LocalSearchRecord`, as it does in local search, and is
  present exactly when `record_state` is `read`. The spec delta's sentence ("when read, its record's
  `member_count`, `community_summary` and `keywords`") can be read as flat fields; `record` gives one shape for both
  verbs and one field to check. `TextSearchGroup` is `community_id`, `matches` (its count), `record_state`,
  `record`. The spec delta now names `record`, in local search's words; the requirement's wording is cut to stay
under the validator's 500-character limit, so the record's fields are named once, under local search.
- **The groups follow the matches sent.** When the payload fit leaves matches out, the groups and
  `unreadable_groups` are recomputed from the matches kept, so the counts always sum to the reply's matches and a
  group whose only match was cut is not listed. `fitFirst` now returns the count it kept (it returned a bool), so
  `fitTextSearch` can return the data it encoded; the error count and Warn read `unreadable_groups` from that.
- **`unreadable_groups` counts `unreadable` only.** `not_ready` and `none` are not errors, as in local search.
- **One community view read per request**: `groupRecord` now takes the view, loaded once, so the groups of one reply
  never mix two views. Local search calls it the same way.
- **A hit whose ID names no group** (the word index sent an ID `clustering.GroupKey` refuses) is the word index's
  broken reply: transient `internal`, one error, naming the subject, before any batch request.
- **`GlobalSearchRequest` gains `limit`** (design D4), checked as local search's by one shared `checkSearchLimit`.
  `decodeGlobalSearchRequest` no longer returns the level's key prefix, which nothing reads now.
- **Answer**: `Found {matched} matching entities in {groups} groups.`, then `Showing the first {n}.` after a space when
  truncated. The old answer's sentences for hints and unreadable records are gone; the fields still carry both.
- **`unhonoured_hints` stays** until the router (2.4) replaces it with `hints`.
- **The Warn**: message `global search answered past unreadable community records`, with verb, level, count and
  reason. The community supervisor's log line now says searches answer without group records.
- **Smoke** (2.6 owns the rest): `checkCommunities` reads a group's member count from `record`, and compares global
  search's matches with graph-lexical's unscoped hits instead of the substring rule, whose helper `matching` is
  deleted.

## The four tests named for both verbs

`TestSearchRevisionIsTheWordIndexs`, `TestSearchDeclaresWhatItLeftOut`, `TestSearchWithoutWordIndex` and
`TestSearchRequestsAreBounded` are now written, each over both verbs, in `textsearch_integration_test.go`;
`TestSearchRequestsDecodeStrictly` gains its global half and `TestGlobalSearchPassesWordIndexRefusals` is added.

- `TestSearchDeclaresWhatItLeftOut` excludes `valve`, not the spec scenario's `test`: every test entity's ID holds
  `test`, and the scenario is about the declaration, not the word.
- `TestSearchRequestsAreBounded` covers a local search, a text question and a one-word question that names no
  entity. A path question makes no word search until the router (2.4) gives every question one, so its bound is
  2.4's to add.
- `TestGlobalSearchPassesWordIndexRefusals` asks a two-word question: a one-word question reads the alias verb
  first until 2.4, so "no other request" holds only for text questions today.

## Tests outside the Accept list that changed

- `TestGlobalSearchRoutesByHints`: a text question on a component that was never started is now refused by the word
  search it cannot send (`internal`, one error), not by the community view.
- `TestGlobalSearchUnknownWordIsSearched`, `TestGlobalSearchUnknownIDIsSearched`: a stub word search stands in for
  the seeded record; "searched as text" is now one word search of the question.
- `TestComposedVerbsCountAsForwardsDo`: the global text steps cover a word refusal, a word reply that does not
  decode, a hit that names no group, a batch refusal and a batch reply that leaves a hit out unnamed.
- `TestSearchGraphAnswersAsGlobalSearch`, `TestMinRevisionRefusalThroughGraphQuery`: the new no-match literal, and
  the text strategy passes the word index's `revision_not_reached`.
- `TestTextTierRefusesAViewCatchingUp` became `TestRecordNotReadyWhileTheViewCannotServe` (no view, catching up,
  stopped are each `not_ready`); `TestTextTierPoisonIsDeclared` became `TestUnreadableRecordIsDeclared`;
  `TestMatchLabel` reads the label through `decodeSearchEntity`; `TestTextTierAnswer` moved into `TestSearchAnswer`.

## Count order

`TestTextSearchGroups` now lists the matches `c1, b1, a1, b2, a2, b3`, so the best-match order c(1), b(3), a(2) is
neither ID order nor count order. `TestGlobalSearchGroupsHits` now also asserts the `pump` reply's groups, where third
(1 match) comes before system (2). The wrong change, a stable sort of the groups by match count, most first, added in
`textGroups` before the unreadable count:

```go
slices.SortStableFunc(groups, func(a, b graph.TextSearchGroup) int { return cmp.Compare(b.Matches, a.Matches) })
```

- Unit: `task mutate:check -- -pkg ./processor/graph-query -test TestTextSearchGroups -file
  processor/graph-query/textsearch.go -mutant <copy> -expect-text 'groups = '`, verdict detection (3 of 3 mutant runs
  failed, the after-run passed).
- Integration: `go test -tags integration -count=1 -overlay <overlay> -run '^TestGlobalSearchGroupsHits$'

  {CommunityID:c360.test.query.system Matches:2 ...}, want "c360.test.query.third" with 1 matches`. Without the
