## Fixed LLM parameter (review fix at 44383a0c)

Codex's review of 44383a0c found that with `NewClassifierChain(keyword *KeywordClassifier, llmClassifiers
...*LLMClassifier)` an unchanged old call `NewClassifierChain(keyword, nil, llm)` still compiles, and the chain reads
the `nil` as its LLM tier and drops the real one. The owner ruled a fixed parameter (epic #10 comment 6881770203):
`NewClassifierChain(keyword *KeywordClassifier, llm *LLMClassifier)`, `nil` meaning no LLM tier; design D1 was
re-approved with it. Keyword-only test calls now pass `nil` as the second argument.

`TestChainSignatureHasNoListOfTiers` (`graph/query/classifier_chain_test.go`) is the regression. Its oracle is
`reflect.TypeOf(NewClassifierChain)`, independent of the chain's code: not variadic, exactly two parameters,
`*KeywordClassifier` then `*LLMClassifier`, one `*ClassifierChain` result. A three-argument call cannot be written in a
test that must compile, so the signature is the checkable fact. Failing first, on the variadic signature, command
`go test ./graph/query -run TestChainSignatureHasNoListOfTiers -count=1` (the `Error Trace` and `Test` lines cut):

```text

        Error:      Should be true

FAIL    github.com/c360studio/semengine/graph/query 0.246s
```

It passes on the fixed signature. The zero- and one-LLM tests (`TestNewClassifierChain_Constructor`,

## Choices the design leaves open

- `processor/graph-query/globalsearch.go:326` is not edited. It calls `NewClassifierChain(query.NewKeywordClassifier(),
  nil)`; with the middle parameter gone, that `nil` is the fixed `llm` parameter, which the chain reads as no LLM tier.
  It is the right call for a keyword-only chain and stays, so PR A leaves #660's file alone.
- `TestChainKeepsExclusions` with the LLM tier only: the fake LLM answers `{"aggregation_type":"count",
  "use_embeddings":true}`. The LLM tier parses no `aggregation_type`, so "would answer an aggregation" is shown as
  "answers at tier 3" with an LLM-only chain (no keyword tier), and `use_embeddings` true for the similarity. Step (1)
  of the test is that witness; without it the chain step proves nothing.
- `TestChainAnswersFromFirstTier` takes over the product shape of the deleted `TestEmbeddingClassifierAsAProduct`: an
  example file on disk read with `LoadDomainExamples` and handed to `NewLLMClassifier`, so `LoadDomainExamples` keeps a
  test that calls it the way a product does.
- Deleted beside the two test files: `TestClassifierChain_T1T2_EmbeddingMatch`, the tier 1 cases of
  `TestClassifierChain_ResultStructure` and `TestClassifierChain_OptionsPopulation`, the example-tier subtest of
  `TestOutOfRangeRefusedWithoutKeywordTier`, `TestNewEmbeddingClassifierRefusesEndedContext`,
  `TestFindBestMatchEndedContext`, `TestResultEditsDoNotReachClassifier` (its chain half is
  `TestChainOptionsAreCopies` now), `TestEmbeddingClassifierAsAProduct` and `TestExample_VectorField`. The rest of the
  chain tests run on the keyword tier alone, as they did whenever the example tier did not match.
- `TestClassifierChain_NoEmbedding_KeywordOnly` is renamed `TestClassifierChain_KeywordOnly`.
- Generated checks: none added. The chain's routing is three named branches (keyword hint, LLM, default) plus the
  exclusion and ended-context branches, each a named example above; `FuzzKeywordClassify` still covers the keyword
  tier's input space.
- `docs/repository-map.md:76` is rewritten here for the two-tier chain (keywords, then the optional LLM tier).
  `openspec/specs/query-classification` is synced at archive.
