## Choices the design leaves open

- **Which failures become transient `internal`.** Only an NL resolve wraps a failure that is not a responder's
  refusal (no responders, a timeout, an ended context), as graph-gateway's `ask` does. The wrapped error keeps its
  cause (`errors.Is`, `natsclient.IsNoResponders` still match; the integration test checks the latter). The other rows
  return such failures unchanged, as before: changing them is outside D2.
- **`semantic` row dropped from the client.** Nothing in fusionnats asks graph-query's `semantic` row now, so the
  lookup no longer requires it (an unused row would refuse construction on a table that lacks it for no reason).
- **`TestResolve_Semantic_ScopeInBody` folded into `TestNLResolveAsksTheWordIndex`**, which checks the request's
  bytes with a scope; the unscoped byte check, the invalid-scope and empty-scope tests stay, renamed `NL`.
- **Integration stack.** `startStack` no longer composes graph-embedding; `startWordIndex` adds graph-lexical, and
  `seed` waits on a word search with `min_revision` when it runs. `TestRealRespondersAnswer` also asks `name:widget`
  and expects graph-lexical's own invalid `invalid_request`, the live half of `TestNLWordIndexRefusalReturned`.
- **No-embedder smoke.** `TestSmoke_NoEmbedderAnswers` composes no graph-lexical, so its word question now fails
  transient `internal` naming the word search instead of graph-query's `not_enabled`. The test asserts that; task 2.3
  composes graph-lexical there and makes the question answer (composed-stack delta).
- **Docs kept true.** `fusionnats/doc.go`, the `pkg/fusion/README.md` verb table and no-embedder paragraph, the
  `Seed.Similarity` comment and `internal/smoke/doc.go` say what the code does now.
