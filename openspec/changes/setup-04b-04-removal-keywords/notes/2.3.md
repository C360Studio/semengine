## Choices the task leaves open

- **The main stack's word question moved from `checkSearch` to the end of `checkLexical`.** Its old place ordered it
  after a graph-embedding wait, which orders nothing for graph-lexical. fusion's word search request carries no
  `min_revision`, so the question now runs right after `checkLexical` asked graph-lexical for the same word
  (`field`) until its reply reached the revision; nothing is written in between. The expected nodes are the same
  live bases `checkLexical` already computes from the fixture.
- **No-embedder stack.** graph-lexical is added to `graphOnlyConfig` with its defaults, to the composition's
  components and to its `indexKeys`, so `awaitIndexed` waits on the `graph-lexical` key and the `GRAPH_STATUS` key
  list holds three keys. Before the word question the test asks graph-lexical directly for `falcon` at the revision
  `awaitIndexed` returned, for the same ordering reason. The answer is checked whole, on the wire, like the symbol
  and prefix answers: drone1 with its relation and its truncated path, provenance `lexical`.
- **`ProvenanceLexical`** sits between `deterministic` and `embedding` in the constant block, which says the tiers
  run in increasing order of uncertainty.
- **`TestNLMissCarriesSearchCounts` folded into `TestNLAnswerCarriesWordIndexCounts`** as its `miss` subtest, with a
  `nothing left out` subtest that proves both keys are omitted when the reply reports none.
- **`TestWordIndexCountsReachResolution`'s symbol and prefix halves** send replies carrying keys named
  `bodies_not_indexed` and `excluded`, so a client that read them from any reply would fail; the replies are
  hand-written JSON because the wire types have no such fields.
- **Docs.** `pkg/fusion/README.md` (the labels list and the no-embedder paragraph), `MIGRATION.md` (the `Resolution`
  bullet, two new silent-change bullets for the word index and the provenance, the labels bullet, and the
  no-embedder paragraph, which still said a word question was refused `not_enabled`), `lens.go`'s mode comments,
  `internal/smoke/doc.go`, ADR-062's and ADR-071's port notes and both ledger rows. The fusionnats row also takes
  what task 2.2 changed (rows read, the word search request, its proving tests), which 2.2 left to this task.
