## Choices the design leaves open

- **`NewMaintainer(storage, textSuffixes []string)`, not an `entitytext.Rule` argument.** This changes an exported
  signature (callers: `processor/graph-clustering/component.go`, and the tests in `graph/clustering` and
  `processor/graph-query/localsearch_integration_test.go`). A suffix list mirrors the config key a product already
  holds for graph-lexical, nil means the default list as everywhere else, and it cannot be got wrong: the zero
  `entitytext.Rule` selects nothing, so a `Rule` argument would let a product that forgot `entitytext.New` publish
  groups with no keywords and no representatives, silently. `maxLen` is 0: `Values` never cuts.
- **No validation of the suffix list**, as graph-lexical and graph-embedding have none.
- **`TestKeywordsIgnoreIDAndPredicates` moved its text value** from `robotics.flight.status` to
  `robotics.flight.description`: `.status` is not a default suffix, so the old fixture would now hold no text and
  the test would prove nothing. Its claim (IDs, predicates and relationships add no words) is unchanged.
- **The oracle for `TestKeywordTextMatchesLexical`** is `entitytext.New(suffixes, 16000).Values` (graph-lexical's
  construction, with its default cap), not the code under test: each text value is one distinct word held once, so
  the published keywords must equal those values sorted. It runs three suffix lists (default, SemSource's, a custom
  one) and adds a smaller-ID member holding only an unselected string, which must not be a representative.
- **`TestTextSuffixesIsRead` is integration-tagged**: the maintainer is built in `Start`, so proving that the key
  reaches it needs the real component on a NATS fixture. `TestConfigTextSuffixes` (unit) checks the resolved default
  against graph-lexical's own `ApplyDefaults`.
- **Generated checks are not added.** The change is which values feed an unchanged counter; the rule's own selection
  is `entitytext`'s and is tested there. The maintainer's property test runs on with the default list (its
  fixture's text sits under `.body`).
