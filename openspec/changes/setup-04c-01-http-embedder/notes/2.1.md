## Choices the design leaves open

- **Nil context.** `Generate` and `GenerateQuery` refuse a nil context with an error and send nothing, even for no
  texts (developer contract: exported context-taking boundaries reject nil). Proof: `TestNilContextRefused`, not in
  D3's table.
- **Empty result.** No texts returns `nil, nil`; the test asserts `len == 0` and no request.
- **Endpoint.** `url.JoinPath(base, "embeddings")`, so a base URL with or without a trailing slash posts to the same
  path. `TestNewRefusesConfig` accepts `https://api.example.com/v1/`.
- **Non-2xx with no `error.message`.** The error names the status alone (`status_503_no_body` case).
- **Reply with no `model`.** Accepted; only a non-empty name that differs is refused (owner ruling, question 1).
  `TestVectorsPlacedByIndex`'s reply carries no model.
- **Error wording.** Only width refusals contain "dimension", so graph-embedding's `classifyEmbedErr` files them
  `dimension_mismatch`; no other refusal contains "dimension", "timeout" or "connection refused".
- **A refused reply teaches no width.** The learned width is set only after a reply is accepted whole; every
  `TestRefusesUntrustedReply` case asserts `Dimensions()` is unchanged.
- **Fuzz target.** `FuzzReplyIsWholeOrRefused` (`fuzz_test.go`): the reply body is external bytes, so the developer
  contract's fuzz rule applies. Invariant: never panics; an error comes with no vectors and no learned width; an
  accepted reply is two vectors of the width `Dimensions()` reports. 15 seeds, one per reply class accepted or
  refused. Seed replay runs in `task verify`. Exploration, run by hand once (below), found nothing.
- **Generated checks.** Beyond the fuzz target, named examples suffice: each refusal is one independent check on a
  whole reply, the checks do not interact beyond "any one refuses", and the table has a case per check.

## Fail-first evidence: a pin-shaped stub

Method: a copy of `httpembedder.go` whose `accept` behaves as the pin's `http_embedder.go:179-198` does (count
checked; vectors placed in reply order; no empty, width or model check; width latched from the first non-empty
vector), applied with `go test -overlay`, so the tree was not edited. The stub's `accept`, which replaced the real one
(everything above it in the file unchanged):

```go
func (e *Embedder) accept(r reply, n int) ([][]float32, error) {
    if len(r.Data) != n {
        return nil, fmt.Errorf("httpembedder: reply has %d vectors for %d texts", len(r.Data), n)
    }
    vectors := make([][]float32, n)
    for i, d := range r.Data {
        vectors[i] = d.Embedding
        if len(d.Embedding) > 0 {
            e.dimensions.CompareAndSwap(0, int64(len(d.Embedding)))
        }
    }
    return vectors, nil
}
```

## The real client

```bash
go test -race -count=1 -cpu 1 -v ./graph/embedding/httpembedder/   # every test PASS
go test -count=5 -cpu 1 -shuffle=on ./graph/embedding/httpembedder/ # ok 6.209s
go test -run '^$' -fuzz FuzzReplyIsWholeOrRefused -fuzztime 30s ./graph/embedding/httpembedder/
# fuzz: elapsed: 31s, execs: 7196 (0/sec), new interesting: 5 (total: 20) ... PASS
```

The three carried `Dimensions` tests each take about 1.2 s under `-race -cpu 1`, as they did on the pin (about
1 s); they run in parallel with the race test's eight reader goroutines spinning on one CPU. The cause was not
measured further.

## Not covered

- A deadline (rather than a cancel) ending the request: `TestContextEndsRequest` cancels; the deadline path is D5's
  real-provider probe (task 2.3).
- A reply body too large to hold: the client reads the whole reply, with no size bound; none is in the design.
