# Task 3.2: the scorecard program's flag refusals and tally arithmetic

Tests: `internal/harness/scorecard/flags_test.go` (`TestOptionsAccepted`, `TestOptionsRefused`, `TestProgramTB`)
and `tally_test.go` (`TestTallyCountsHandWorkedRanks`, `TestEmptyTallyReadsZero`, `TestMatchRank`, `TestVerdict`).
The package joins the tool packages in `scripts/test-pkgs.sh`; `TestTestPkgsLists` and docs/testing.md say four.

## Choices the design leaves open

1. **The merge-gate spec named the three tool packages**, so the change gains a `specs/merge-gate` delta naming four.
2. **`-commit` and `-tree` are flags Task sets** (`git rev-parse HEAD`; `clean` when `git status --porcelain` prints
   nothing). The program refuses to run without them, so a bare `go run` cannot print a commit it did not read.
3. **The URL is checked by `httpembedder.New`**, the constructor graph-embedding calls, rather than a second check.
4. **`-api-key-env` naming an empty or unset variable is refused**; a key is never a flag value, so it stays out of
   the shell history and the printed command.
5. **No flag sets the floor.** The owner ruled it constants; the verdict function takes the floor as arguments only
   so the test can hold it at the boundary.
6. **`TestVerdict` holds the boundary in answers**: 300 of 500 is exactly 60% and holds; 299 does not.
