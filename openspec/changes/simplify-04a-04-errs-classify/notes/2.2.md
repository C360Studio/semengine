## Choices the design does not spell out

- **Code where no reply came back.** The `deadline` and `malformed response` faults (lifecycle) and `nats.ErrTimeout`
  (projection) have no reply, so there is no reply code. D2 builds the fatal wrapper "the way `errs.Classified` builds
  one: it keeps the text and inherits the inner `Code` and `Detail`" (`errs.go:251-260`, `:282-287`); with no inner
  `*errs.ClassifiedError` there is nothing to inherit, so the tests expect `Code` `""` on both the `MutationError`
  and the `*errs.ClassifiedError` that `errors.As` finds. Lifecycle never sets `MutationError.Code` today
  (`graph_emit.go:108-111`), so "`Code` unchanged" there means empty.
- **Detail only with a code.** The projection replies carry a `Detail` only when the row has a code, because
  `inheritMachineContract` (`errs.go:251-260`) copies `Detail` only with a non-empty inner `Code`. Expecting a detail
  on a code-less reply would demand more than D2's construction gives.
- **`TestAppendSubjectFailureAfterPossibleWriteIsCommitUnknown`** (same projection file, not named by D2) returns a
  commit-unknown error built from an append response body (`classifiedAppendFailure`, `mutation_client.go:238`). The
  spec requirement covers every commit-unknown `MutationError` projection returns, so the test now expects fatal with
  code `internal` and the three `errs` predicates. The integration test at `:383` covers the same path over a broker.
- **`fatal without code`** (projection) is commit-unknown and its reply is already fatal, so its new assertions pass
  on the base commit; it shows no failure and guards against a fix that would read the reply's class back.
