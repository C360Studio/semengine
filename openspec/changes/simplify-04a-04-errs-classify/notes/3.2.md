# Task 3.2 notes: commit-unknown is fatal; the rest stays transient

Base commit: `2602177` (task 3.1). Codex checkpoint review: PR #255 comment 6193499709.

## What changed

- `pkg/projection/mutation_client.go` `unknownMutation`: sets `Class` to `errs.ErrorFatal` and replaces `Err` with
  `errs.Classified(errs.ErrorFatal, err)`. `unknownMutation` is the only caller of `newMutationError` with
  `CommitUnknown`, so every commit-unknown error the typed client returns passes through it. `Code` and `Detail` are
  still copied from the reply by `newMutationError`; the wrapper inherits the reply's `Code`, and its `Detail` only
  when the code is not empty (`errs.go` `inheritMachineContract`).
- `pkg/projection/mutation_client.go` `newMutationError`: an unclassified error that is no responders gets
  `Class` `errs.ErrorTransient`. Without it 3.1's default made the field fatal (`commit_ambiguity_test.go:180`).
- `pkg/lifecycle/graph_emit.go` `classifyEmitError`: the commit-unknown error has `Class` `errs.ErrorFatal` and
  `Err: errs.Classified(errs.ErrorFatal, err)`. The no-responders branch and the classified-reply branches,
  `ErrEmitFailed` included (#257), are unchanged.
- `pkg/lifecycle/errors.go` `ErrUpdateRetriesExhausted`: the sentinel itself is
  `errs.Classified(errs.ErrorTransient, errors.New(<same text>))`, declared with static type `error`. Its text is
  unchanged (`Classified` keeps the inner text as `Message`); `errors.Is` still matches it by identity. All three
  return paths (`manager.go:453-454`, `:656-657`, `:768-769`) wrap it with the first `%w` and format the mismatch
  with `%v`, so the first `*errs.ClassifiedError` `errors.As` finds is the sentinel's.

No exported symbol and no method on `MutationError` were added.

## Choices the design does not spell out

- **Classify the sentinel, not the three call sites.** D3 says "every error matching
  `lifecycle.ErrUpdateRetriesExhausted` is transient". Carrying the class on the sentinel makes that true for every
  path that wraps it, now and later, with one change instead of three `errs.Classified` wraps.
- **No-responders class set in `newMutationError`'s unclassified branch.** That covers every write and
  `ReadAuthoritative` (`mutation_client.go:279`), mirroring the literal lifecycle sets (`graph_emit.go:102-107`).
  Other definite-not-committed transport outcomes (`TransportDeadline`, a context already done) wrap
  `context.DeadlineExceeded` or `context.Canceled`, which `errs.IsTransient` lists, so 3.1 did not change them.
- **New lifecycle test `TestNoRespondersIsTransientAndNotCommitted`** (`graph_emit_contract_test.go`), for the
  lifecycle half of the spec requirement "A request no responder took keeps the transient class" (Codex: no lifecycle
  test named it). It is a guard: the class was a literal before this change. To share the three write calls with
  `TestMutationAmbiguousReplyReturnsCommitUnknownAfterOneAttempt`, the operations table moved to
  `emitWriteOperations()`; that test's assertions are unchanged.
- **Create path `errs.IsTransient` check** (`manager_test.go:1748-1750`, after the `Classify` check at `:1745-1747`),
  Codex's gap. Since 3.1, for a non-nil error `errs.Classify` returns transient exactly when `errs.IsTransient` is
  true (`Classify` checks `IsTransient` first and no longer defaults to transient), so the new line cannot fail
  unless the `Classify` line before it fails first. It was cheap and states the promise; it is not separately
  mutation-checkable. The same equivalence holds for `TestUpdateRetriesExhaustedIsTransient`'s two subtests; its doc
  comment, which said the `classify` subtest read "the unclassified default", now says both read the sentinel's class.
- **Stale comment corrected**: `mutation_client_requests_test.go:15-18` said every mutation error keeps the reply's
  class; it now says so only for a reply that proves nothing was written.
