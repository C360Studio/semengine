# 3.1 `ClassifyMutationError`

`pkg/projection/mutation_client.go`. `ClassifyMutationError` asks `isDefiniteFailure` once and builds the error
through one of two constructors, `notCommittedError` and `commitUnknownError`; `Kind` is set once in each
(`notCommittedKind` for the first, `MutationCommitUnknown` for the second). `newMutationError`, which set `Kind` and
patched it later, is gone. Every write's failure goes through `mutationFailure`, which calls the mapping and
returns the receipt that still carries `Commit` (task 3.2 removes that).

Choices the design does not spell out:

- The two dead-layer sites (`Create`'s response-entity check, `Append`'s `default:`) call `mutationFailure` with
  their unclassified error, which the mapping reads as commit-unknown, the same answer as before. `unknownMutation`
  is gone. Task 3.4 removes both sites.
- The detail is still copied with `cloneDetail`; task 3.4 replaces it with `maps.Clone`.
- `notCommittedKind` keeps today's fallback by class when a code names no kind (invalid -> invalid, fatal ->
  internal, otherwise unavailable).
- `MutationUnavailable`'s doc: "a request that was not delivered: no responder took it, or the caller's context
  ended before it was sent".
