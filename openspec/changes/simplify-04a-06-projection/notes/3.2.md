# 3.2 `MutationReceipt` without `Commit`

`pkg/projection/mutation_types.go`, `mutation_client.go`. The receipt keeps `Entity` and `KVRevision`. Every failing
return is `MutationReceipt{}` (the `notCommitted()` helper is gone; `mutationFailure` returns a zero receipt beside
`ClassifyMutationError`'s error). The receipt's doc says a failing method returns a zero receipt and the error's
`Commit` reports what is proven.

Tests, changed first:

- `pkg/projection`: every failing-path `receipt.Commit != X` became `receipt != (MutationReceipt{})`, with the
  error's `Commit` asserted where it was not already (`assertProjectionRejectedBeforeRequest`,
  `TestAppendAmbiguousTransportFailureIsNotRetried`, `TestRevisionMismatchRemainsDefinite`). Success-path
  `receipt.Commit != CommitVerified` checks are dropped: each already checks `err == nil`, which is now the proof.
- `processor/graph-ingest/commit_ambiguity_integration_test.go`: the six failing-path reads became
  `assert.Equal(t, projection.MutationReceipt{}, receipt)`, beside the error-`Commit` assertions each already had;
  the three `created.Commit` checks after `require.NoError` are dropped; the `t.Logf` prints the error's `Commit`.

Failing at `0e49711` (the receipt still carried `Commit`), with the tests above and the old implementation: 83
`--- FAIL` lines in `go test ./pkg/projection/`, for example

```text
--- FAIL: TestTransportOutcomesKeepTheirCommitState/no_responders (0.00s)
    commit_ambiguity_test.go:198: reconcile: receipt = projection.MutationReceipt{Entity:(*graph.EntityState)(nil),
    KVRevision:0x0, Commit:"not-committed"}, error = &projection.MutationError{...}; want a zero receipt,
    commit "not-committed", kind "unavailable"
```

After: `go test ./pkg/projection/...` passes, and
`go test -count=1 -tags integration -race -run 'CommitAmbiguity|CommitUnknown' ./processor/graph-ingest/` passes
(three tests). The first run of that command, before `-count=1`, failed `TestIntegration_TypedClientPreservesCommitAmbiguity`
after 143.78s; its output was not kept, and three later runs passed in about 0.3s each. Unexplained; filed as
issue #270 (Codex review of `b1549f0`), with ten further `-count=1` reruns at `b1549f0`, all passing.

Choices the design does not spell out:

- `CommitVerified` stays: removing an exported constant is outside D2. Nothing in the tree reads it now (a
  `*MutationError` is never verified); left for review.
- Generated checks: not used. The change is one field's removal; each method's failing paths are already named
  rows in the existing tables.
