# 2.3 Validate runs the shape check: the test and the fuzz law

Test: `message/generic_json_shape_test.go`, `TestGenericJSONValidateRefusesWhatTheShapeCheckRefuses`. Four rows
built from the shape-test fixtures: a `time.Time` at `data.a[1].b`, a map that contains itself (`data.m.self`), and
invalid UTF-8 in a value and in a key at depth (the rows of `TestGenericJSONRefusesInvalidUTF8AtDepth`). `Validate`
must return an invalid-data error (`errs.IsInvalid`) whose text names the same path and reason encoding names, and
each row also goes through `requireRefused`, so the path is checked against encoding's error too. Two more rows, NaN
and positive infinity in a list, require `Validate` to return nil and `MarshalJSON` to return an error (owner
question 5, option 1). Those two pass on the base commit as well; they pin that the change does not move them.

The cycle row runs in process, not under the child-process stack cap `TestGenericJSONRefusesCycles` uses: `Validate`
runs the same `shapeCheck` that test already proves terminates on cycles.

`FuzzGenericJSONShapes` (`message/generic_json_fuzz_test.go`): before encoding, `Validate` is called on every
generated payload. The oracle is the generator's own flags: an invalid-data error exactly when it marked `foreign` or
`badUTF8`, nil otherwise, which covers `nonJSON` (the NaN seed) and valid values. The doc comment states the law.

Both fail on the base commit `b840587b27a07e8cbc346cca4e15bdb94ec13799` (tests changed, `message/generic_json.go`
unchanged), go1.26.9 darwin/arm64.
