# 2.6 FuzzParsePredicateAgreesWithGrammar

Test: `vocabulary/predicate_parse_test.go`. Generated checks are used (design, "Generated checks").

- Rule 1, oracle the test owns: `grammarAccepts` splits on `.` and requires three segments, each at most 64 bytes and
  matching `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`, and at most 194 bytes in total. `ParsePredicate` must accept exactly
  then, with the same parts.
- Rule 2: a refusal is a `*PredicateValidationError` equal, in `Predicate`, `Reason` and `Segment`, to the one from
  `parsePredicateBySplit`, the base parse copied into the test without its memo.

Choices the design leaves open:

- `parsePredicateBySplit` copies the base parse's top level (empty, length, `strings.Split`, arity, segment loop) and
  calls the production `validatePredicateSegment`, which D7 leaves unchanged and which the namespace and entity-type
  parsers share. Rule 1 checks each segment independently of it.
- The seeds are a table, `predicateGrammarSeeds`, with the reason each should give. A unit test,
  `TestPredicateGrammarSeedsCoverEveryReason`, checks each seed's reason against the base parse and that the seeds
  reach acceptance and all eight reasons, so rule 2's comparison runs on every reason under plain `go test`.
- Seeds (12): one valid predicate; one per reason (`""`; a 195-byte total `64.64.65`; `a.b`; `a..b`; `a.b.` + 65 bytes;
  `a.B.c`; `a.b_c.d`; `a.b-.c`); the multi-fault `a..b.c` (arity before the empty segment); a 64-byte segment and a
  194-byte total, both accepted.
- `FuzzParsePredicateNeverPanics` stays as it is; the new target adds the two rules rather than rewriting it.
- `BenchmarkParsePredicate` (one fixed predicate) is in the same file, for task 3.7's before/after numbers.

Passes on the base commit `314a01228126c5aa51de6bfc6f2304164d1f24e8`, as the gate says (on the base, rule 2's oracle is
the code itself), exit 0, seeds #0 to #11 pass:

```bash
go test ./vocabulary -count=1 -v \
  -run 'FuzzParsePredicateAgreesWithGrammar|TestPredicateGrammarSeedsCoverEveryReason'
```

Its ability to fail is shown in task 3.7 (`notes/3.7.md`).
