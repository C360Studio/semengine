# 3.7 ParsePredicate with strings.Cut, no memo

`vocabulary/predicate_contract.go`: `ParsePredicate` checks empty and length, then splits with two `strings.Cut` calls
and checks arity (`!ok || !ok2 || strings.IndexByte(property, '.') >= 0`) before validating the three segments in
order with the unchanged `validatePredicateSegment`. The memo (`validParsedPredicates`, `validParsedPredicateCount`,
`maxMemoizedPredicates`, `memoizeParsedPredicate`), the `sync` and `sync/atomic` imports and
`vocabulary/predicate_memo_test.go` go. `ParsePredicateNamespace` is not touched.

Choice the design leaves open: the segment loop ranges over a `[3]string` array value, which stays on the stack
(`TestParsePredicateDoesNotAllocate` passes under `-race` and without it).

## Gate

- 2.5 and 2.6 pass: `go test ./vocabulary -count=1 -race`, exit 0.
- Mutation check, verdict **detection**. Mutant: the arity check moved after the segment loop (segments before
  arity), in a copy outside the repository; target sha256 `f0695b0a05eca24f6bdfdc0b3efbad85ff83869029cad454f429c4d03805aac9`
  before and after, the committed implementation. Run on the implementation, uncommitted on top of `ac02766`:

  ```bash
  task mutate:check -- -pkg ./vocabulary -test 'FuzzParsePredicateAgreesWithGrammar/seed#9' \
    -file vocabulary/predicate_contract.go -mutant "${TMPDIR:-/tmp}/mutant.go" \
    -expect-text 'ParsePredicate("a..b.c") refused with'
  ```

  Seed #9 is `a..b.c`. All three mutant runs failed with
  `predicate_parse_test.go:162: ParsePredicate("a..b.c") refused with {Predicate:a..b.c Reason:segment_empty Segment:1},
  the pre-change parse with {Predicate:a..b.c Reason:arity Segment:-1}`; three baseline runs and the after-run passed;
  exit 0. Logs are local only.
