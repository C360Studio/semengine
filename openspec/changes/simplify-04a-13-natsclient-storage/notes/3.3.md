# Task 3.3 notes

- `replaceWith` copies the held account row before clearing it, under the lock, and calls `ForgetAccount` after the
  unlock, last of its observer calls (after `ForgetResource`, `ObserveResource` and `ObserveAccount`). Because the
  branch that retracts is the one where the new initial values have no account, `ObserveAccount` and `ForgetAccount`
  never both run for one marker.
- `removeAccount` reads the row and `hasAcct` together under the lock; with no observer nothing is called, as for the
  other observer calls.
- The `remove` doc comment now says a held account's delete reaches the observer through `ForgetAccount`. The
  `Observer` doc says `ForgetAccount` carries the last row, like `ForgetResource`.
