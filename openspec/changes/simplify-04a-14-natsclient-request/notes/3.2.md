# Task 3.2 notes

`RequestWithRetryClassified` (`natsclient/errors.go`) now holds the attempt itself; `requestMsgWithRetry`,
`RetryConfig` and `DefaultRetryConfig` are gone from `natsclient/request.go`.

## Choices the design does not spell out

- Errors are returned as `retry.Do` returns them, with no natsclient wrap. A caller's cancellation is
  `retry.Do`'s `fmt.Errorf(... %w)` of `ctx.Err()`; it matches `context.Canceled` and `errs.IsTransient` reports it
  transient through that sentinel. Before, natsclient wrapped it with `errs.WrapTransient`, so it was also a
  `*errs.ClassifiedError`; it no longer is. The spec delta promises only the match and the transient answer.
- `resetCircuit` runs inside the attempt on a reply, as the old loop did.
- The nil-context refusal stays natsclient's (invalid-data), ahead of `retry.Do`'s own nil check, so the spec's
  "nil context refused before it acts" requirement keeps its class.
- A config `retry.Do` refuses is returned after the connected and circuit checks (`ErrNotConnected` /
  `ErrCircuitOpen` win on a disconnected client); still before anything is sent.
