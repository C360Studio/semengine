# Task 2.3: the two replacement oracles

## `TestIntegration_RequestWithRetryClassified_NoResponder` (`request_integration_test.go`)

The test reads `client.GetConnection().Stats().OutMsgs` before the call and asserts a delta of 4 after it, with
`MaxAttempts` 4 and no responder. **Probe outcome: holds** at the pinned nats.go (`go.mod`, v1.54.0): each
attempt that gets no-responders counts as one sent message, so the design's primary oracle is used and the
never-replying-subscriber fallback is not. The existing `Failures()` assertion stays until step B.

## `TestIntegration_RequestWithRetryClassified_RetriesThenSucceeds` (`errors_integration_test.go`)

Rewritten as the design says: a core subscription on the client's own connection, made and flushed before the
call, leaves its first request unanswered and answers the second. Per-attempt timeout 1 s, `MaxAttempts` 3; the
call returns the reply and the handler count is 2. The late-subscribe wait on `Failures()` is gone with the old
responder, so `probe` is no longer imported by that file.

Choices: `MaxAttempts` 3, not 2, so a call that stopped retrying early fails rather than passing by luck; the 1 s
timeout is what the first attempt waits, chosen so a slow `-race` host does not let the second attempt time out too
and reach a third request.
