## Choices the design does not spell out

- `TestKVStoreFilteredNoWatcherPrecedence/live_direct_no_keys` expected nil and no error from the removed
  `ErrNoKeysFound` branch. It now expects an error matching `jetstream.ErrNoKeysFound`, like `wrapped_no_keys`: a
  reader that returns that error with no watcher is reporting a failure the listing passes on. No row is left that
  succeeds, so the table's `wantOK` field went with it.
- `ownershipBucket.ListKeysFiltered` and `ownershipLister` in `kv_watcher_ownership_test.go` modelled nats.go's
  `ListKeysFiltered` forwarder, which only base `FilteredKeys` reached. Nothing calls them now, so they went.
- `keysByFilter` takes a small unexported interface, `filteredWatchReader`. `FilteredKeys` keeps the design's inline
  interface in its signature so its documentation shows the one method a caller must offer.
- The rewritten `TestFilteredKeysAcceptsMinimalReader` reuses the scripted watcher from
  `kv_watcher_ownership_test.go` (`closedOnStopWatcher`) and checks that `Stop` ran once.
