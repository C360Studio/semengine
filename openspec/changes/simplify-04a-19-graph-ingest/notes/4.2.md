## Open: `TestHandleMessage_RejectionsLandOnPoisonAccounting` cannot drive `processIngest`

Design D7 says `handleMessage`'s two tests "drive `processIngest` instead". One of them,
`TestHandleMessage_RejectionsLandOnPoisonAccounting` (`fact_lane_fence_test.go:227`), checks five payloads that fail
in `decodeEntity` (invalid, and four panics) and one that decodes. `processIngest` takes an `ingestWork` whose entity
is already decoded: the consume closure runs `decodeEntity`, counts and terminates a failure, and submits only a
decoded entity to the pool. So the five rejection rows never reach `processIngest`, and the test cannot be rewritten
as written. `TestStreamLane_FailingPayloadIsTerminated` (`fact_lane_fence_test.go:261`) already drives the same five
payloads through the consume closure Start wires, asserting the error count rises by one, nothing is stored, and the
next (conforming) message is applied. Proposed: delete the test as covered by that one, then remove `handleMessage`
and the comments that name it. Waiting for the orchestrator.

## Choices the design does not spell out

1. **The stale-repopulation test** (`cache_stale_repopulation_integration_test.go`). The test-side wrapper is
   `pausingGetBucket`, a `jetstream.KeyValue` that pauses the first `Get` of the entity after the server has answered
   it, until the test releases it; every other `Get` (the concurrent append's included) passes through, chosen by a
   compare-and-swap rather than `sync.Once`, whose `Do` would hold the append's `Get` until the first returned. The
   reader captures the key's generation before its `Get` (`query.go`), so the pause holds it in the same window the
   hook did. The component is not started: as `TestIntegration_TypedClientPreservesCommitAmbiguity` does, the test
   gives an unstarted component the fixture's `ENTITY_STATES` (through the wrapper) and the cache Start would build
   (`cache.NewSimple`), so no running goroutine reads the store it replaces.
2. **The failed-start test** (`TestFailedRegistrationRunsNoRequestWork/query`). The hook and its `hookEntered`
   check go; the seeded entity stays, so a query that ran would succeed and only the refusal gives the error the test
   asserts (`errs.ErrNotStarted`, transient).
3. **`handleMessage`'s integration test** is renamed `TestIntegration_StreamIngest_DoesNotClobber`: it decodes with
   `decodeEntity` and applies with `processIngest` on a `keyedIngestTestMsg`, the two steps the consume closure runs,
   and also asserts the input is acknowledged.
4. **D6.** The help text is the design's sentence, with `internal` in single quotes inside the Go string; the
   constructor's doc comment no longer names `MutationResponse ErrorCode`.
