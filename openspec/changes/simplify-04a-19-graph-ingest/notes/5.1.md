# Task 5.1 notes

Ruling K (#91 comment 6062681355): a missing `ports` key takes `DefaultConfig()`'s ports, a present block is used as
written, the lane clamp moves to `ApplyDefaults`, and `Validate` only checks.

For the PR body: **behaviour change** — a graph-ingest configuration with no `ports` key (`{}`,
`{"enable_hierarchy":true}`, `{"ports":null}`) used to fail construction ("at least one input port required") and now
builds with the default ports; a `ports` block that is present is still used exactly as written.

## Choices the design does not spell out

1. `Validate` gains no lane check: after `ApplyDefaults` the count is always at least 1, and the factory is the only
   way to build the component, so a check there could not fail on any configuration a caller gives.
2. The default ports come from a fresh `DefaultConfig()` on each call, so no two configurations share a port slice.
3. The factory's `config = DefaultConfig()` branch for an empty raw configuration stays; it now builds the same
   configuration `{}` does.
4. `README.md` § Configuration options: `ports` defaults to the default ports, and a present block is the whole set.
