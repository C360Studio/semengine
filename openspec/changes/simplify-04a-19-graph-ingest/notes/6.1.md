## Counter deltas

- `TestComponent_MetricsUpdate_EntityOperations` checks `entities_updated_total` moves by one on a create and not on a
  refused second create of the same key. The old test also appended a fact and said the counter "should be
  incremented again", but asserted nothing; it is not incremented: the append lane (`addTriplesLane`,
  `component.go:2434`) counts errors but never `entitiesUpdated`, `messagesProcessed` or `bytesProcessed`. The test
  asserts only what holds today; the gap is a defect for the orchestrator to file (it is the same family as #302,
  "status counters measure something other than their names", but a different counter and lane).
- `TestComponent_MetricsAtomic_MessageProcessing` checks the deltas of `messagesProcessed` (+1), `bytesProcessed`
  (grows) and `errors` (0) after one create, then `errors` +1 and `messagesProcessed` unchanged after a create whose
  KV write fails (the mock bucket's `createFunc`). Its old `DataFlow` lines go: `TestComponent_DataFlow_ReturnsMetrics`
  owns those.
- `TestComponent_MetricsRegistry_CreateComponent` replaces `assert.NotNil(comp.entitiesUpdated)`, which the factory
  makes always true, with a create that moves the counter by one with and without a metrics registry.

## DataFlow rates

`DataFlow` computes rates over uptime, which is zero unless the component is running, so the unit test sets
`running` and a `startTime` one second back, as `poison_scoping_test.go` already does. It asserts zero rates before
any write, a `MessagesPerSecond` and `BytesPerSecond` above zero after one create, an `ErrorRate` of zero then, and an
`ErrorRate` above zero after a failed create. It never asserts a rate's value or a per-message count (#302).
