# Task 2.1 notes: the sensitivity double (D4)

## Choices the design leaves open

- The clean double's run context is `context.WithCancel(context.WithoutCancel(ctx))`: one line, and it keeps the
  Start context's values. Under `workDiesWithStartContext` the parent is `ctx` itself, as the double did before.
- `startFailsButHolds` keeps `context.WithCancel(ctx)`; only its comment changed (D4 says comment only).
- `TestAbortStopThenFinishJoinsWorker`, branch where `finished` wins: D4 says to end the worker with the double's
  cancel and then join it. That alone deadlocks the bubble: the worker then enters `probe.Callback.Block`, which does
  not return when its context ends (`internal/harness/probe/callback.go:28-31`). The branch therefore cancels,
  calls `o.workerExit.Release()`, joins, and fails. For the same reason the worker is always still listed by
  `Observe` when `finished` wins, so the branch fails without testing that condition.
- The exclusion in `TestAbortStopThenFinishJoinsWorker` filters on the check name, as D4 says, so it also drops
  `workDiesWithStartContext` (mapped to the same check). That row would pass the test; it is excluded only because
  it shares the check name.
- `checks` (the list in `refowner_test.go`) is unchanged: it still names `ControlledStopUnderLiveStartAuthority` and
  `AbortStopPreservesCause` and calls their functions, which task 2.2 renames in `lifecycletest.go`.
- The `refowner` type comment and the `TestAbortStopThenFinishJoinsWorker` doc comment were also reworded: both
  described the worker as ending with Start authority, which is no longer true.
