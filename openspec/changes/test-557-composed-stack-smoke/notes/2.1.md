# Task 2.1 notes: the composition root, the oracle and `TestSmoke_OneConfigAnswers`

Developer notes on the choices design D1 to D5 leave open, and the two "shown to fail" runs design D7 asks for.

## Choices the design leaves open

- **The platform ID is minted, so the fixed IDs carry it.** The configuration declares `platform.id` `smoke`;
  `config.Manager` treats a declared ID as a stem and, at the first boot on a fresh configuration bucket, mints the
  effective ID (`smoke-<six hex digits>`, ADR-104, `config/manager.go`, `establishPlatformIdentity`). graph-ingest
  refuses every entity whose position 2 is not that ID (the first run here failed with `authority_foreign` on every
  input). The child writes the effective ID, `configManager.GetConfig().Get().Platform.ID`, into its ready file, and
  the fixed entities are `c360.<that ID>.fleet.ops.<kind>.<n>`: positions 3 to 6 are fixed, positions 1 and 2 are
  the deployment's. A later boot on the same bucket adopts the same ID, which tasks 2.2 to 2.5 will read again from
  the ready file. A producer outside the process has to learn the minted ID: a seventh fact for the adopter gap
  (task 3.3).
- **The indexing profile is part of the oracle.** graph-ingest stamps `entity.indexing.profile` on every entity it
  creates, from the payload type's registration. The composition root registers the test type with
  `IndexingProfile: content` (`smokeIndexingProfile`), so the expected statements and the summary's predicate counts
  include that stamp, written from the registration, not read from a reply.
- **Embedding records are checked by revision, not text.** A generated BM25 record stores no `source_text` here, so
  each record is checked for status `generated`, its entity ID, and `source_revision` equal to the entity's
  `kv_revision` as the entity verb read it in the same `checkAnswers` call. The edit then shows as drone 3's record
  regenerated at the edit's revision, and the delete as its record gone (the key set equals the live entities).
  Vectors and rank are not checked (inventory section 2: BM25 statistics are process-local).
- **Health is read twice.** Right after the child reports `StartAll` returned, `/components/health` must list exactly
  the four components (total 4): the composition is fixed by then. After the ordered waits it must list them again,
  each `healthy: true`. A missing component fails at once instead of at the test timeout (mutant a, below).
- **The delete goes through graph-ingest's mutation verb**, `internal/graphmutation`'s `Delete` with the
  `kv_revision` the entity verb returned, since the `entity.>` stream lane has no delete. Its reply comes after its
  write, so the `ENTITY_STATES` revision `awaitIndexed` reads next covers it; the edit before it is on the stream and
  waits on the ack floor first.
- **graph-ingest's readiness key is awaited, not read once** (corrected at task 2.2's review): graph-ingest writes its
  first record from a goroutine `Start` launches, so the key can be absent on a first boot and hold the earlier
  process's record after a restart. `startStackOn` reads the key's revision before the child starts (0 if absent),
  and `awaitIndexed` waits, after the ack floor, for an entry above it, which must not be `degraded` and carry no
  latched state or code. graph-index's and graph-embedding's keys are polled until `indexed_revision` reaches
  the `ENTITY_STATES` revision; a `reset_required` state or a code on either fails at once, naming it.
- **Files.** `stack_integration_test.go` holds `TestMain`, the configuration constant, the composition root
  (`runStack`), the child helper and the observer (waits, health). `smoke_integration_test.go` holds the fixed
  inputs, `checkAnswers` and the test, where tasks 2.2 to 2.5 add theirs.
- **Timeouts.** Every wait is `probe.Await` under `t.Context()`: `go test -timeout` is the one deadline. Each request
  passes natsclient's required reply timeout, and the child's three stops each get a budget, as terminal work; both
  are an hour (corrected at task 2.2's review), unreachable fallbacks, so a hang ends at `go test -timeout`
  (`docs/testing.md`, #500). A clean stop is SIGTERM, `Wait` under `t.Context()`, and exit
  code 0, which the child returns only when every stop returned nil.
- **Not checked:** `semantic` and `similar` (PR #558 is open; task 3.2), and `byName`, `batch`, `prefix`,
  `hierarchyStats`, which design D5 does not list.
- **Examples, not generated checks**, as design D6 states for the whole change.
