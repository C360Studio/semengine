## Choices the design leaves open

- **Its own NATS server**, as in case 3 (`// Own server:` on the line above `natsfixture.New`; `brokerBudget`, an
  hour, bounds `Start` and `Restart` as an unreachable fallback).
- **The URL is required unchanged** (`restartBrokerKeepingURL`, shared with case 3).
- **Nothing is stopped before the restart.** `Restart`'s doc says a caller stops what it built on the URL first;
  this case deliberately does not, for the stack: that is the case. The observer does not either. It keeps its one
  connection, and natsclient's defaults (unlimited reconnect attempts, `natsclient/client.go:317`) reconnect it in
  place: the client's connection and JetStream context are the same objects after the reconnect, so the observer's
  handles stay valid. Before its first publish after the restart the observer waits on its own reconnection: the
  connection's `Reconnects` count, which nats.go increments once the connection is re-established, above the count
  read before the restart, and the client reading connected. So the first publish goes to the restarted server, not
  into nats.go's reconnect buffer. The wait runs through `await`, so it fails at once if the stack exits.
- **The stack is required to be the same process**: alive after the restart (checked before the writes and by every
  `await` and HTTP read after), and stopped by SIGTERM with exit 0 at the end, so every stop returned nil.
- **The writes after the restart**: `checkWritesAfterRestart` (the new entity and the edit, as cases 1 and 3), then a
  delete of drone 8 through graph-ingest's mutation verb, which the spec scenario adds and which also shows
  graph-ingest's request subscription outlived the restart. The delete moved from `TestSmoke_OneConfigAnswers` into
  `observer.deleteEntity`, shared by both tests, unchanged. After each write: the waits of design D5 (a latched
  `GRAPH_STATUS` envelope fails at once), the four components listed by name and each healthy, and the answers.
  The final check is the first batch plus the new entity and the edit, with drone 8 deleted, and an embedding record
  at its current revision for each live entity.
- **No answers are checked between the restart and the new writes**, for the reason in `notes/2.2.md`.
