# Step notes: tasks 2.1, 2.2, 2.4 and 2.5

One file for the step (the brief named it `2.2.md`). These are the choices the design does not spell out.

## The task and the coverage gate (2.1, 2.2)

- `test:integration` is three commands: `rm -f coverage/integration.tree && mkdir -p coverage`, the `go test` line,
  then `scripts/tree-state.sh > coverage/integration.tree`. Task runs a task's commands in order and stops at the
  first that fails, so the fingerprint exists only after `go test` passed. `go test -coverprofile` does not create
  the directory, so `mkdir -p` comes first. `TestUnitInvocationsPinned` pins all three lines in order.
- The fingerprint is taken after `go test`, not before it as the runner did. A file edited while the run is in
  progress is fingerprinted with the run. A tracked edit already fails `task verify` (tracked-file check), and a
  step starts on a clean tree. An untracked file edited during a run is the gap that remains.
- `cover-check.sh` has one check with one message for both refusals ("no passing integration run measured this
  tree"). It still runs the unit `go test` first, so the two existing no-argument tests keep their shape. A failing
  `tree-state.sh` ends the script under `set -e`, so an empty fingerprint never matches an empty file.
- `TestCoverCheckRefusesAnUnmeasuredTree` covers each refusal (no file; another tree's fingerprint) and has a
  passing control (this tree's fingerprint gets past the check).
- Failing first: `TestUnitInvocationsPinned` failed on the old Taskfile naming `test:integration` and the three
  required lines; the refusal test failed on the old script with "no integration run recorded in this worktree".
- Probe of the stop-at-first-failure claim (Task 3.51.1, this Mac, uncommitted tree of this step):
  `task test:integration -- ./internal/harness/probe/` exited 0 and left `coverage/integration.coverprofile` and
  `coverage/integration.tree`. `task test:integration -- ./does/not/exist/` exited 201 (`FAIL ./does/not/exist
  [setup failed]`) and left only the profile. `task cover:check` then exited 201 with "cover: no passing integration
  run measured this tree; run task test:integration" (spec scenario "A failed run's profile is refused").

## The image pin (2.4)

- The pin file keeps its `#` comment lines. `pinnedImage` skips blank and `#` lines and requires exactly one image
  line. Its pattern, `digestImage`, accepts a reference with no tag; `TestOneImagePin` still requires the tag. The
  spec asks natsfixture only to refuse a reference without a digest.
- The check stays where it was: the image phase of each attempt, before `deps.start`. `TestImagePin` swaps the
  embedded `imagePin` for one subtest to prove that Start refuses before any dependency call. The package's tests
  do not run in parallel.
- Fuzzing does not apply to `pinnedImage`: its input is a file compiled into the test binary, not bytes from
  outside. Four named cases cover the shapes: a tag only, another repository, two images, comments only.
- `doctor.sh` reads the new path and says "testcontainers pulls it on first use", since nothing pre-pulls now.

## Admission and evidence (2.5)

- The fixture gains `logf` (`t.Logf`) beside `errorf`. A failed attempt's container log, capped at `maxLogBytes`,
  goes to the test log. A log that cannot be read is still a test error (`report`), now worded for the test log.
- The evidence record went with its writers, as did Stop's per-step timings and the message count read before a
  stream's delete. `own` lost its label argument, which only fed the record.
- Integration tests that read the record now read something independent of the fixture:
  - S1-1 and S1-2 read the per-attempt `*Error` values (`fixtureErrors`) for the phase, container, parent state
    and cleanup.
  - The container logs come from a `logTB` that records `Logf`.
  - The mapped-port replacement wraps `deps.start` to collect container IDs.
  - `sessionContainersLike` reads the session label from `testcontainers.GenericLabels()`, as `recordSession` did.
  - S1-4 checks that every `PublishAsync` future is acknowledged when Stop returns.
- Dropped, now review only:
  - S1-3's stop-order assertion (publish-complete, consumer, stream, connection, container); the order was read only
    from the record, and pull request 2 (task 3.1) removes the ordered teardown.
  - `TestFixtureRoundTrip`'s proof that the runner's leak-check label selects the container: the leak check is gone,
    and 2.3's sweep tests prove the new label.
- prochost writes to `t.TempDir()` directly (no `prochost/` subdirectory). The cleanup reads the files after the
  reap; `t.TempDir`'s own cleanup was registered earlier, so it runs later.
