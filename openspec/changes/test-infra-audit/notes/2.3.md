## Ryuk, the label and the sweep (2.3)

- **Where the once-per-process step runs.** `prepareDocker` (`sweep.go:34`) is called by the real `start` in
  `defaultDeps` (`deps.go:52`), just before `testcontainers.GenericContainer`. It is not called in `attempt`: unit tests
  replace `deps.start` with fakes and must not reach Docker. `defaultDeps` now takes the test's log function so
  the step can write to the test output. Pull request 2 removes the seams (L10); the call then moves into `attempt`.
  The first test to start a container in a process runs the step under its own `Start` context.
- **What reads testcontainers' configuration.** `config.Read` runs at the first `GenericContainer`,
  `NewDockerClientWithOpts`, `GenericLabels` or `SessionID` call (`tc:docker_client.go:132`, `tc:generic.go:104`,
  `tc:testcontainers.go:54`); the `wait` package reads none. The sweep builds its Docker client after the `Setenv`.
  Each new test calls `prepareDocker` before its first testcontainers call, so a shuffled order cannot read the
  configuration before Ryuk is off.
- **The label value** is `<import path> pid <pid>`, for example
  `github.com/c360studio/semengine/natsclient pid 4242`. The package comes from `debug.ReadBuildInfo().Path`:
  go test names a test binary's main package `<import path>.test` (probed with go1.26.4; asserted by
  `TestFixtureContainerIsLabelled`).
- **The sweep's filter** is Docker's `label` filter. The production call passes the key alone (any value). The test
  passes `key=value` with a value of its own (`<test name> pid <pid>`), so its age-zero sweep cannot reach another
  process's containers.
- **Age** is `time.Since(time.Unix(Created, 0)) > age`, with `Created` in Docker's clock (P4). Clock skew was
  measured on this Mac on 2026-10-12 (Docker 29.8.2, API 1.56). Three reads put `docker info`'s `SystemTime`
  between two host readings that were at most 202 ms apart, so no skew showed at that resolution. If the daemon's
  clock is ahead, the test's age-zero sweep keeps the container. The test then fails with Docker's creation time
  and the host's time.
- **Errors.** The design names removal errors. Failures to set the environment variable, to build the client or to
  list containers take the same path: they are written to the test output and fail nothing. A container that is
  already gone is recognised by `cerrdefs.IsNotFound`. The client returns the daemon's 404 as
  `errdefs.ErrNotFound` (moby client v0.5.0 `errors.go:94-99`).
- **`go.mod`.** `github.com/moby/moby/client` and `github.com/containerd/errdefs` change from indirect to direct
  requirements, at the same versions. Listing containers by label needs the client's types, and testcontainers
  exports no list call. The #200 note said that `go.mod` stayed unchanged; that was a choice for that task, not a
  rule. The `containerAbsent` comments said these modules stayed indirect, so they were corrected.
  `containerAbsent` keeps its text match, and L11 removes it in pull request 2.
- **Test containers** are started with the docker CLI, which does not go through natsfixture. They use the pinned
  image through `pinnedImage(imagePin)`, so no image literal appears, and they publish no port. Their cleanup is
  `docker rm -f` under `stopBound`.
- **"A removal error never fails a test"** is tested through `removeContainer`. A name that does not exist writes
  nothing, and a cancelled context writes one line naming the container.
- **`processContainers`** replaces `sessionLabel` and `sessionContainersLike` in `TestRestartFaultMatrix`. The old
  helper matched the container's name up to its random suffix, and the container now has no name of ours. The new
  one lists this process's label, which holds only the running test's containers because tests in a package run
  one at a time.
- **Generated checks are not used.** The input space is two facts per container: the label matches or it does not,
  and the container is older than the age or it is not. The named cases (young under one hour, the same container
  under zero, an unlabelled one) cover each combination the requirement names.

## Names (2.7)

- natsfixture gives its container no name, and Docker names it (harness-boundaries ADDED, "Docker names this
  repository assigns").
- `Consume` names its consumer with the name the caller passes; its parameter `base` is now `name`. `Consume` is
  removed in task 3.2.
- natsfixture's integration tests, `natsclient/integration_test.go:112` and the graph-ingest helper use literal
  names. The helper (`processor/graph-ingest/query_verbs_integration_test.go:81-82` after the change) now creates the default
  configuration's stream `ENTITY` and drops its port override. That override existed only to carry the generated
  name, and the helper's doc already says "default configuration".
- `TestS1_8Isolation` drops its name assertions; the requirement they proved is removed.
- The prefix and character rule is now `checkDockerName` in `internal/harness/contract/docker_test.go`. The
  destroyer cases are gone. Every other lane case now fails on the prefix or on a character, and "compose network
  name" is the character case (`semengine-net_1`). `FuzzCheckName` went with `names_test.go`.
- `fixture_test.go`'s bounds comment cited the removed requirement. It now cites "Bounded test streams".

## Evidence

- Failing first, on 0091fd7 with only the new tests added: `TestRyukIsOff` failed with
  "org.testcontainers.reap=true: Ryuk is on". `TestFixtureContainerIsLabelled` failed with "containers labelled …:
  [], want only the fixture's …".
- Mutation checks (`GOFLAGS=-tags=integration task mutate:check`), each with 3 baseline and 3 mutant runs. All six
  verdicts were detection:
  - `Setenv` removed: `TestRyukIsOff` failed at `sweep_integration_test.go:61`.
  - Label removed (`fixture.go`): `TestFixtureContainerIsLabelled` failed at `:69`.
  - Age check removed: `TestOnlyOldLabelledContainersAreSwept` failed at `:83`.
  - Removal call removed: the same test failed at `:89`.
  - Not-found no longer ignored: `TestSweepRemovalErrorsGoToTheLog` failed at `:112`.
  - The log call removed: the same test failed at `:118`.
- Two mutants were not run, because a mutant that ignores the label filter, or one that sweeps by key alone at age
  zero, would remove other processes' containers.
- `checkDockerName` lives in a test file, which `task mutate:check` refuses. A hand mutation was run under a
  `cp` backup and restored with matching SHA-256 sums. With the prefix check off, 10 sensitivity cases failed; with
  the character check off, "uppercase" and "compose network name" failed.
