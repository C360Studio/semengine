## Choices

- **Consumer joins stay in Stop until 3.2.** Task 3.2 removes `Consume` and the consumer joins together. Until then,
  Stop still stops each consumer's delivery, waits for its running handlers and cancels their context before it
  closes the connection (`stop.go:36-43`); removing the joins without `Consume` would leave a handler running with a
  live context after Stop returned. The server-side `DeleteConsumer` is gone: the consumer goes with the container.
  The operation slot and the refusal of creations once Stop begins also stay for 3.2.
- **Stop closes the connection; it does not drain it.** Draining waits for the server, which Stop no longer needs.
  Restart still drains (`restart.go`), as its requirement says.
- **Stop no longer waits for in-flight async publishes.** That wait belonged to the removed "Checked cleanup"
  requirement; only the fixture's own test (S1-4) published asynchronously on the fixture's connection, and it is
  removed. `JetStream()`'s doc comment says Stop does not wait.
- **The final "still owns" check is removed.** Stop's fields are cleared by its own steps; checking them again
  repeated what the code had just done.
- **Restart's consumer joins** call the same `stopConsumer`, which now drops a joined consumer from the fixture's list.
  Before, Restart left it listed so Stop could delete it on the server; nothing deletes it now.
