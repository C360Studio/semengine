## Choices

- **No serialisation replaces the slot.** The slot let Start, Stop, Restart and creations run from different
  goroutines. `nats-fixture` › "Own server per test" says the fixture's methods are called from the test's own
  goroutine, so nothing needs serialising; the mutex still guards the fields `URL()` and `JetStream()` read.
- **"Once Stop has begun" needs no flag.** Stop clears the connection and JetStream context before it removes the
  container (`stop.go:32`), and Restart refuses without a connection (`restart.go:60`), so a Stop whose removal fails
  still leaves Restart refusing. The `stopping` flag, `stopBegun` channel and `errStopping` are removed; Restart's
  refusal says "needs a fixture whose Start succeeded and whose Stop has not begun". `CreateStream` and
  `CreateMemoryStream` refuse the same way (`started`, `fixture.go:405`, "fixture not started, or stopped").
- **`PhaseCreateKV` and `PhaseConsume` are removed** with the only methods that produced them. The `Phase` type and
  `Error` stay for task 3.3.
- **Callers migrated.** None outside natsfixture (P11 re-measured with `git grep`). In natsfixture's own tests,
  `TestFixtureRoundTrip` and `TestFaultKVOverARealBucket` call `f.JetStream().CreateKeyValue` with a plain
  `jetstream.KeyValueConfig`; their assertions are unchanged.
- **natsclient's consumer-creation census** (`natsclient/consumer_policy_callsite_test.go`,
  `directConsumerCreationCensusViolations`) counted `Consume`'s `CreateConsumer` call in `fixture.go`; that entry is
  removed, and the ledger's `natsclient` row says so.
- **Tests removed with what they proved:** `TestS1_3BlockedCallbackDelaysFinalisation`, `TestS1_5DeadlineIsNotAJoin`,
  `TestStopJoinsHandlersOnAClosedConnection`, `TestRestartEndsConsumers` (consumer joins);
  `TestNoCreationOnceStopBegins`, `TestQueuedCreationRefusedWhenStopBegins`,
  `TestStopHonoursItsContextWhileStartHoldsTheFixture` (the slot); `TestCreateKeyValueDeclaresBounds`. Task 3.1's
  survivor note names `TestS1_3`; that survivor now stands on `TestStopNeedsNoAnswerFromTheServer` alone.

## Tests and how each was shown able to fail

- `TestRestartRefusedOnceStopHasBegun` (new, `fixture_integration_test.go:649`, scenario "Restart before Start", its
  "once Stop has begun" half). It replaces a unit subtest that called the removed `beginStop`. A Stop whose container
  removal is refused (the terminate dependency returns an error without calling Docker) has begun; Restart must then
  return an error, make no dependency call, and leave Docker's `State.StartedAt` for the container unchanged (Docker
  CLI, independent of the fixture); a second Stop with the real terminate removes the container. Wrong change, made in
  the tree with a `cp` backup and restored with matching SHA-256 sums (`task mutate:check` runs only unit tests):
  "Stop clears the connection only after the removal succeeds". Detected: `fixture_integration_test.go:670: Restart
  after Stop began returned nil` (Restart drained the closed connection and restarted the container).
- Not covered: the "before Start" half stays the unit subtest it was (`TestRestartRefusesWithoutDockerCall`).
