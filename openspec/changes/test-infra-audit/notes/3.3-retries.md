architect check, PR #230 comment 6173216821) that the ruling and design rows L10 and L13 do not spell out. This is

## Choices

- `attempt` and `rollbackAttempt` keep their names: each still runs, or rolls back, one go at Start's phases, and
  renaming them would widen the diff into code task 3.3 rewrites anyway. They lose the attempt number. The container
  log line in the test output reads `natsfixture: failed Start, container <id> log:` instead of "attempt N".
- Restart's phases are inlined in `restart` rather than kept in a `bounce` closure: with one pass there is nothing to
  call twice.
- `TestMappedPortFailureCarriesTheInspect` relied on the retry to see both inspect outcomes (shown, then failed) in one
  call. It now runs four cases, Start and Restart, each with an inspect that shows and one that fails, and checks one
  `*Error`, one port read, one inspect and no second container start. Two mutation checks with `task mutate:check`,
  both detections: dropping the inspect text from `mappedPort` (fails at `restart_test.go:85`), and a second port read
  after a failed one in `restart` (fails at `restart_test.go:89`).
- `restartOnFakes` lost its `fails` count: the one remaining caller that needs a failing read sets `mappedPort` itself.
  `fixtureErrors` is gone: no path joins errors any more, so tests use `errors.As`.
- `TestS1_2CancellationDuringIO` loses its "connect after mapped-port failure" case: it existed to show a replacement
  earned before cancellation is counted. The two remaining cases check one `*Error` with the cancelled parent and a
  clean rollback, and that no container starts after cancellation.
- `TestS1_1PartialStartupCleanup` drops the per-row attempt count: every row now expects one start, one terminate,
  one container log.
- Spec: "Phased start with typed failure" lost a scenario, so it is REMOVED and re-ADDED as "Phased start in one
  container" (design § Specs). Its new scenario "A missing mapped port fails Start" states the no-retry outcome and is
  proven by the S1-1 mapped-port row and `TestMappedPortFailureCarriesTheInspect`. It also states the inspect rule,
  which the owner ruling on #180 kept and the same test proves. "Restart keeps the container" is ADDED in this change,
  so it is edited in place: its scenario is renamed "A missing mapped port fails Restart" and states the no-retry
  outcome, and the requirement says Docker does not promise the kept binding (one macOS probe).
- Left as is: `design.md` § Options (c) still says the shared-server option was "exposed to #180 and its replacement
  container"; it records the reasoning when the option was chosen. `notes/3.2.md` cites the removed
  `TestRestartTriesOnceMoreAfterAMappedPortFailure`; it records 3.2's state at its commit.
- The draft's "Retiring harness code" asks for such a removal in its own pull request; this one rides PR #230 because
  the owner ruled it there.
