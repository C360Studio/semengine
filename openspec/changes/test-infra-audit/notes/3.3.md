# Task notes: 3.3

Choices made keeping the mapped-port read as the one test seam, removing the others, and making the error type
unexported (design row L10, premise P11; `specs/nats-fixture/spec.md` "Phased start in one container" and "Restart
keeps the container") that the design does not spell out. The retry removal, the first part of this task, is in
`notes/3.3-retries.md`.

## Rulings and where they are implemented

| Ruling | Where |
| --- | --- |
| Keep one test seam, the mapped-port read (owner ruling on #180) | `internal/harness/natsfixture/fixture.go`: `Fixture.readPort`, set to `readMappedPort` (`deps.go`) by `New`; read in `mappedPort` |

## Choices

- The count. The task says "the other 12"; at this commit `deps` had 12 entries counting the kept one, because
  `createKV` and `absent` went in tasks 3.1 and 3.2. Eleven replaceable calls went (`start`, `host`, `inspect`,
  `connect`, `jsReady`, `createStream`, `terminate`, `stopContainer`, `startContainer`, `drain`, `logs`), and with
  them the per-call counter (`calls`, `count`, `callCounts`, `totalCalls`): it existed so tests could count calls
  through the seams, and reading it was reading private state.
- The phases are string literals at each `run` call; the list and order are in `phaseError`'s doc comment. No
  constants: nothing outside the package names a phase (P11), and tests read the text.
- `inspect` is called directly, not through a seam. The "inspect failed" branch is reached through the real Docker
  inspect: the test's port read cancels the caller's context before it fails, and the inspect runs under that context.
- The kept seam also drives other phases' failures: returning a port nothing listens on makes the real connect fail
  (S1-1 `connect`), and holding the read after a real successful read is S1-2's cancellation point. No other seam is
  needed for either.
- "No call" proofs. Where a test used the counter to show a path made no Docker call, it now uses an outcome: Stop
  under an already-ended context returns nil only when the fixture holds nothing (Stop's documented order), and a
  refused Start leaves `used` false.
- `TestRestartRefusedOnceStopHasBegun` reaches a begun-but-failed Stop by removing the container with `docker rm -f`
  first, so Stop's own removal fails. A cleanup registered after New's clears the fixture's container handle, so New's
  Stop does not fail on the container the test removed.
- The lifecycle-floor test (task 3.4 removes it) is adapted, not removed: `mustFailFixture` fails the mapped-port read
  instead of the start hook, and `owner.Observe` reports no call counts, so the floor's "Stop after a failed Start made
  a call" comparison is now nil against nil. `TestMustFailFixture` shows the same through `stopHoldsNothing`.
- `deps.go` keeps its name; it now holds the Docker and NATS calls (`readMappedPort`, `inspect`, `containerLogs`,
  `jetStreamReady`, `connect`).

## Shown able to fail

`task mutate:check` with `GOFLAGS=-tags=integration` (the tool has no tags flag; `go test` reads `GOFLAGS`), one
mutant run each, every verdict a detection:

1. `fixture.go` `mappedPort` drops the inspect text: `TestMappedPortFailureCarriesTheInspect` fails on `lacks "(inspect`.
2. `fixture.go` `run` stops turning a cancelled parent into the phase's failure: `TestS1_2CancellationDuringIO` fails
   on `lacks "phase mapped-port"`. A first version of the test, whose held read ran the real read after the cancel,
   survived this mutant (the read failed on the cancelled context anyway); the read now runs before the hold.
3. `fixture.go` `fail` skips the rollback: `TestS1_1PartialStartupCleanup/connect` fails on `still exists`.
4. `restart.go` `restartable` checks only the container: `TestRestartRefusedOnceStopHasBegun` fails (nil pointer in
   the drain of the connection Stop already released).
5. `restart.go` reads the mapped port a second time after a failure: `TestMappedPortFailureCarriesTheInspect` fails on
   `port reads, want one`.
