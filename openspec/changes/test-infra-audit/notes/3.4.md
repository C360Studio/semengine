# Task notes: 3.4

Choices made removing the fixture's lifecycle-floor test and turning the stream helpers into a function (design rows
L14 and L16; `specs/nats-fixture/spec.md` "Bounded test streams" and the removed "Memory-backed owned stream" and
"Fixture satisfies the lifecycle floor") that the design does not spell out.

## Rulings and where they are implemented

| Ruling | Where |
| --- | --- |
| Stream helpers become functions carrying the bounds (L14) | `internal/harness/natsfixture/stream.go`: `CreateStream(ctx, js, storage, name, subjects...)`, with the bounds `streamMaxAge` and `streamMaxBytes` beside it; `Fixture.CreateStream`, `Fixture.CreateMemoryStream`, `createStream` and `started` are gone from `fixture.go` |
| Remove the lifecycle floor on the fixture (L16) | `fixture_integration_test.go`: the `lifecycletest` subtest of `TestS1_7Restart`, `mustFailFixture`, `TestMustFailFixture` and the `owner` adapter are gone, and with them the package's import of `internal/harness/lifecycletest` |

## Choices

- One function, the storage an argument. The spec delta's migration line reads "`CreateMemoryStream` callers call the
  stream function with memory storage", so file and memory streams are one function taking a
  `jetstream.StorageType`, not two near-identical functions. The requirement's "functions ... a file-backed or a
  memory-backed stream" is met by the one function's two storages.
- A nil JetStream is refused by name. A fixture's `JetStream()` is nil before Start and after Stop; the old methods
  refused there, and a nil interface would otherwise panic inside `CreateStream`. A nil context is refused first.
- A failed create wraps the broker's error with the stream name (`natsfixture: create stream <name>: %w`). The
  `create-stream` phase is gone from `phaseError`: a function on a JetStream has no fixture, so it has no container
  to name and no phase of Start or Restart to report. The S1-1 `create-stream` subtest went with it: it proved the
  phase text and that Stop then removes the container, and Stop's removal is proven by `TestFixtureRoundTrip` and
  `TestStopNeedsNoAnswerFromTheServer`, both of which create a stream first. No requirement names a failed create.
- `TestMustFailFixture` existed only to vouch for the floor's must-fail factory. What it showed (a mapped-port failure
  rolls back cleanly and the fixture holds nothing) is S1-1's `mapped-port` row.
- `TestResourceMethodsRefuseBeforeStartAndNilContexts` is now `TestNilContextsAndUnstartedJetStreamAreRefused` and
  checks each refusal's text: the nil-context call also passes the unstarted fixture's nil JetStream, so without the
  text the nil-JetStream refusal would hide a missing nil-context check.
- No contract or boundary test listed the fixture as a lifecycle-floor owner; nothing there changed.
- Callers moved, each keeping its storage: inside natsfixture, `TestFixtureRoundTrip`, `TestStreamsDeclareBounds`,
  `TestRestartKeepsFileStreamLosesMemoryStream`, `TestStopNeedsNoAnswerFromTheServer` and the refusal unit test;
  outside it, 14 calls in integration-tagged test files: `natsclient/integration_test.go` (one file, one memory),
  `natsclient/stream_visibility_integration_test.go`, `natsclient/test_helpers_integration_test.go`,
  `pkg/lifecycle/harness_gate_integration_test.go`, and in `processor/graph-ingest/` `fixture_`, `guard_generation_`
  (two memory, one file), `lifecycle_`, `long_apply_`, `query_verbs_` and `settlement_integration_test.go` (two).
  Each `f.CreateStream(ctx, ...)` became `natsfixture.CreateStream(ctx, f.JetStream(), jetstream.FileStorage, ...)`
  and each `f.CreateMemoryStream` the same with `jetstream.MemoryStorage`. The first commit missed these: the
  untagged build and `go vet` without `-tags integration` do not compile them, and `task verify`'s integration lane
  caught it.
